## 三、改一节内容的标准流程

### 步骤 1：定位

先读覆盖表 `00_知识点总览.md`，确认你要写的东西**属于哪一条条目**（条目号形如 `3.1`、`10.4`），以及它**计划落在哪个文件**。文件名在覆盖表的「计划文件」列里已经定好。

读要改的那一章时，重点看三处：章首目录、你要动的那一节、章末的覆盖对账表。

### 步骤 2：先定结构，再写正文（这一步不能省）

对着 [`笔记与讲义整理规范.md`](../笔记与讲义整理规范.md) 自检：

- 新加的内容，和现有小节是**同一分类轴**吗？（入口 / 共用规则 / 独有能力 / 机制 / 用途 / 特例 / 进阶）
- 它该是新的一节，还是挂在已有节下面？
- 加这一节会不会让原有小节号平移？**平移就必须同步改所有跨章引用与章首目录**（见第六节，这已经翻过车）。

### 步骤 3：写，并且实跑

正文里的可执行 Python 示例按分类实跑；依赖片段组合运行，伪代码与语法模板只做对应检查。跑代码的正确姿势（Windows + 终端编码）：

```powershell

$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"; [Console]::OutputEncoding=[Text.Encoding]::UTF8

```

不加这行，含中文的输出会显示成乱码（终端按 cp936 解码）——**但贴进笔记时要写正常中文，不要贴乱码**。

- 故意展示报错的示例：贴**真实 traceback**，不要凭记忆编。
- 依赖前一个代码块定义的变量这种"片段式"示例是允许的，它单独跑会 `NameError`，属于正常现象（见第五节的基线）。
- 交互式示例（含 `input()`）提供真实输入，或在终端验证；超时单独报告，不以“需要输入”自动免验。

## 六、已知陷阱（都是真实踩过的，不要重新踩）

### 6.1 `check_xref3.py` 会误报 2 处——因为标题里带了高亮标记

它现在报：

```text
--- 06_函数.md ---  引用 01_入门与环境.md 的 3.4 节  -> 目标没有这个号
--- 09_异常处理.md --- 引用 01_入门与环境.md 的 3.4 节 -> 目标没有这个号
```

**这是误报。** `01_入门与环境.md` 第 347 行的真实标题是：

```markdown
### ==3.4 常见运行方式速查==
```

它带了 Obsidian 高亮标记 `==…==`，而 `check_xref3.py` 抽标题号的正则是 `^(#{2,4})\s+(\d+(?:\.\d+)*)\.?\s*(.*)$`，**要求 `#` 后面紧跟数字**，遇到 `==` 就匹配不上，于是认为"1 章没有 3.4 节"。

两处引用本身**是对的**：3.4 节确实讲了 `-i` 和 `-OO`。

**处理方式**：看到它报错，先手工确认目标章是否真有那一节（注意标题可能被 `==`、`**`、反引号包裹）。若确实存在，改脚本而不是改正文。判断"是真错还是误报"的判据是**目标章实际有没有这一节**，而不是脚本有没有报。

### 6.2 `02_基础语法.md` 有 1 处未闭合的代码围栏（真缺陷，尚未修）

第 235 行的 ```` ```python ```` 没有配对的结束围栏，导致它一直吃到第 256 行，**把第 243 行的 `### 2.3 type()、isinstance()、id()` 标题吞进了代码块**。

后果：渲染时这个二级以下的小节标题会消失，章首目录里指向 2.3 的锚点会失效。

检查方式（真正的 markdown 围栏规则：开始用 ≥3 个反引号 + 可选语言；结束用 ≥ 开始长度、且该行只有反引号和空白）：

```powershell
$env:PYTHONUTF8="1"; python tmp\fence_audit.py
```

> 注意：**不能用"数三反引号行数的奇偶"来判断**。`02` 有 177 个围栏行（奇数），但奇偶本身不定位问题；而且 `_写作规范.md` 里故意有 4 个标题写在代码块内部（那是在教模板长什么样），那种"被吞"是**正确的**。判据是：这个标题**本来是打算渲染出来**的吗？

### 6.3 缩进行为不一致的坑已经修过一次

历史上 798 个块里有 **12 个"整块被多缩进"**，成因是**被 markdown 列表项带进去的缩进**（写在列表里，后面接代码块，整块跟着缩进）。读者复制就会 `IndentationError`。现已全部修掉，基线 0 处——**你新写的块不要破坏它**。

### 6.4 跨章引用只能用"章内节号"

**已真实错过 5 次。** 错误形态是把**覆盖表条目号**当成目标章的节号（例：写 `04_控制流.md 2.7 节`，而 2.7 是覆盖表条目号，04 章第 7 节才是条件表达式）。

为什么危险：读者无法自行纠正——他会去 04 章翻 2.7 节，只看到 2.5，然后怀疑自己找错了文件。**这比"没写"更伤信任。**

规矩：写「`04_控制流.md` 第 7 节「条件表达式」」——**带上节号 + 标题**。不确定就先去目标章看实际标题，别拿条目号凑。

### 6.5 加一节会连带重排全章

「补一节」如果插在中间，会导致后续**全章小节号平移**，进而影响：章首目录锚点、章末对账表、所有指向本章的其他章节的引用。所以插入位置要优先选在**章末尾**，或者改完后把上述三样一起过一遍。

### 6.6 DSH 沙箱与 Windows 环境的坑

| 现象 | 原因 / 做法 |
|---|---|
| `tempfile.mkdtemp()` 建的目录写不进去，且**建完删不掉** | 沙箱 ACL 限制。用 `os.makedirs()` 建在**工作区内**被 `.gitignore` 覆盖的路径：`C:\Users\Wang\Desktop\git\tmp\` |

| `open("a.txt","w")` 写出的是 GBK | 本机默认编码是 `cp936` 不是 UTF-8。笔记里反复用这个坑当例子 |

**两个解释器**：系统 `python` = **3.13.15**，仓库 `.venv` = **3.14.7**。涉及版本差异的说法必须标明用的是哪一个。

## 八、汇报格式（干完活这样交代）

用户不喜欢空泛总结和没有下一步的答复。按这个结构写，每一条都要有工具输出支撑：

```text
【改了什么】文件 + 节号 + 一句话说明
【结构决策】为什么这样切分（依据哪条分类轴）
【实测证据】跑了哪个脚本、数字是多少（改前 → 改后）
【没做的事】哪些你判断不该动、为什么
【诚实的空白】哪些没测、怎么测
【下一步】建议做什么，为什么是下一步
```

**不要**写"已全面检查，没有发现问题"这类没有数字的话。要说"`check_parallel.py` 777 块、成功 462、非零 315，与基线一致"。
