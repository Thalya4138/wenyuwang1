## 一、结论先说

三条，按重要性排：

**结论 1：通俗教程对 C++17 几乎是零覆盖。**
cplusplus.com 的教程页自述覆盖范围是 *"up to the newest features introduced by **C++11**"*，
它 26 个章节里没有任何 C++14/17 条目；runoob 的 C++ 教程 40 余个条目同样没有任何 C++17 条目。
**所以"照着一个中文教程写 = 完整"这个前提，在 C++ 上比在 Python 上更不成立。**

**结论 2：真正"最贵"的缺口不是语法点，而是语义模型。**
值类别与移动、特殊成员函数、RAII、`const` 正确性、UB、ODR 与链接性、名字查找与 ADL——
这些不属于草案的某一节，而是**横跨** `[basic]` / `[expr]` / `[dcl]` / `[class]` / `[temp]`。
通俗教程按"语法点"切目录，**必然把它们整段切掉**。

**结论 3：覆盖表应该按「草案条款轴（语言）+ cppreference 头文件分类轴（库）」建立。**
本轮核实到这两条轴**几乎 1:1 对齐**（草案第 17–33 章 ↔ cppreference 的 17 个库分类），
所以它可以合成同一张表，不必维护两套编号。

## 二、源可达性（实测）

**先说本机网络的一个硬事实**（与 Python 笔记 `_HANDOFF.md` 的记录一致，本轮再次确认）：

| 取文档的方式 | 结果 |
|---|---|
| 命令行 `Invoke-WebRequest` | ❌ `The SSL connection could not be established` |
| 命令行 `curl.exe` | ❌ `curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)` |
| **AI 抓取工具 `web_fetch`** | ✅ **可用**，本轮全部源都靠它取得 |

> **结论**：**要核对事实，让我（AI）去取**。命令行那条路在本机是死的，不要再试。

**另一个实用技巧（本轮最关键的发现）**：`web_fetch` 对长页面会截断。
cppreference 是 MediaWiki，可以取**源码**而不是渲染后页面：

```text
https://en.cppreference.com/index.php?title=<页面名>&action=raw
```

去掉了导航栏与样式之后**体积极小且内容完整**。长页面截断问题就是这样绕过的。

## 四、上游二：cppreference 的分类轴

cppreference 是**参考手册**：逐条精确，可当事实来源，但它按"语言构造 + 头文件"组织，**不成体系**。
所以它的用途是核对覆盖，不是照着学。

### 4.1 语言侧（取自其导航模板，完整）

```text
一般主题：预处理器 / 注释 / 关键字 / 转义序列
流程控制：条件（if、switch）
          迭代（for、range-for(C++11)、while、do-while）
          跳转（continue、goto、break、return）
函数：    函数声明 / lambda / inline / noexcept(C++11)
异常：    throw / try / catch
命名空间：命名空间声明 / 别名
类型：    基本类型 / 枚举 / 函数类型 / 类 / 联合
说明符：  const、volatile、decltype、auto、constexpr、
          consteval(C++20)、constinit(C++20)、存储期说明符
初始化：  默认 / 值 / 零 / 拷贝 / 直接 / 聚合 / 列表(C++11) / 常量 / 引用初始化（共 9 种）
表达式：  值类别 / 求值顺序 / 运算符 / 运算符优先级 / 替代表示
          字面量：布尔、整数、浮点、字符、字符串、nullptr、用户定义
工具：    属性 / typedef 与别名 / 转换（隐式、static_cast、const_cast、
          dynamic_cast、reinterpret_cast）/ new 与 delete
类：      类声明 / 构造函数 / this / 访问说明符 / friend
          类特有函数属性：virtual、override、final、explicit、static
          特殊成员函数：默认构造、拷贝构造、移动构造、拷贝赋值、移动赋值、析构
模板：    类模板 / 函数模板 / 模板特化 / 参数包(C++11)
杂项：    内联汇编 / C++ 历史
```

> **注意「初始化」一栏：cppreference 列了 9 种初始化。**
> 这直接支持覆盖表第 1.5 条把"五种初始化形式"单列一节——
> **它是最容易被通俗教程压成一句"`int a = 0;` 就行"的地方，而它们并不等价。**

### 4.2 库侧（17 类，按头文件）

```text
多用途 / 语言支持 / 概念 / 诊断 / 内存管理 / 元编程 / 通用工具 / 容器
迭代器 / 范围 / 算法 / 字符串 / 文本处理 / 数值 / 时间 / 输入输出 / 并发
```

**与草案第 17–33 章几乎 1:1 对齐**（例如 `<filesystem>` 归 `[input.output]`，`<execution>` 归 `[exec]`）。
**所以"语言按条款、库按 cppreference 分类"可以合成同一张覆盖表。**

## 五、上游三：C++ Core Guidelines 的大节结构

Core Guidelines 回答的是**"怎么写更好"**，不是"讲全了没有"。
所以它在覆盖表里的角色是**第 6 个对账源**（工程与坑），不是主源。

文档日期 **Jun 14, 2026**，自述目标 *"modern C++ (currently C++20 and C++17)"*，
三个 profile：**type / bounds / lifetime**。

**主节 16 个**：In 引言 · P 哲学 · I 接口 · F 函数 · C 类与类层次 · **Enum 枚举** ·
R 资源管理 · ES 表达式与语句 · **Per 性能** · CP 并发与并行 · E 错误处理 ·
**Con 常量与不变性** · T 模板与泛型 · CPL C 风格编程 · SF 源文件 · SL 标准库

**支撑节**：A 架构思想 · NR 非规则与迷思 · RF 参考 · Pro profiles · GSL 指南支持库 ·
NL 命名与布局 · FAQ · 附录 A–D · Glossary

> **顺带纠一个常见误解**：**`Enum`、`Per`、`Con` 是独立大节**，而很多二手资料会把它们并进别的节。
> 这本身就是"二手资料也不完整"的又一个例子。

## 六、下游对照：通俗教程漏了什么

**证据强度说明（很重要）**：下表依据的是两份教程的**条目级缺失**（目录层面没有独立主题）。
**"目录层面缺一章"不等于"正文绝不提"**，它证明的是**没有系统覆盖**——而这正是结论 1 需要的强度。
凡目录里有相关章名者，已标注「部分覆盖，正文未核验」。

### 6.1 A 组 · 语义模型（**C++11 起就是基线**，但按语法点切目录必然被切掉）

| # | 知识点 | 为什么重要 | 草案依据 |
|---|---|---|---|
| A1 | **值类别与移动语义**（lvalue/xvalue/prvalue、右值引用、`std::move`） | 决定重载选 `T&&` 还是 `const T&`、拷贝还是移动；不讲它无法解释"`std::move` 只是个 cast"、"移动后对象仍有效但值未指定" | `[basic.lval]`、`[class.copy.ctor]` |
| A2 | **特殊成员函数与规则之五/零**（隐式声明、`=default` / `=delete`） | 决定拷贝/移动/析构何时生成、何时被删除；"为什么我的类不能放进 `vector`"的答案 | `[special]`、`[class.dtor]` |
| A3 | **RAII 与所有权模型** | C++ 最核心的资源管理范式；智能指针/锁/文件流的统一解释框架。不讲 RAII 就只能逐个背 API | `[basic.life]`、`[class.dtor]`、`[except]` |
| A4 | **`const` 正确性**（const 成员函数、`mutable`、顶层/底层 const） | 接口契约 + 重载决议 + 避免拷贝；**并与移动交互**（const 对象不触发移动，是"写了移动却还是拷贝"的根因） | `[dcl.type.cv]`、`[basic.type.qualifier]` |
| A5 | **初始化形式体系与 `{}` 的窄化检查** | `{}` 与 `()` 语义不同（`vector<int> v{1,2}` vs `v(1,2)`）；窄化在 `{}` 里是编译错误、在 `()` 里是隐式转换——**同一行代码两种命运** | `[dcl.init]`、`[dcl.init.list]`、`[dcl.init.aggr]` |
| A6 | **`auto` / `decltype` 与推导细节** | `auto` 会退化（丢 `const` 与引用）导致多余拷贝；`auto` / `auto&` / `const auto&` / `auto&&` 四者语义不同 | `[dcl.spec.auto]`、`[dcl.type.decltype]` |
| A7 | **lambda 与捕获语义** | **两份教程目录都完全没有 lambda**；按引用捕获局部变量是悬垂的第一大来源 | `[expr.prim.lambda]` |
| A8 | **未定义行为（UB）**，与实现定义/未指定的区分 | 越界、悬垂、有符号溢出都是 UB；"本机跑通了"不构成正确性 | `[defns.undefined]`、`[basic.indet]` |
| A9 | **翻译单元、ODR 与链接性**（`inline`/`static`/`extern`、匿名命名空间、前置声明） | 多文件工程里绝大多数"重定义/未定义符号"都出自这里 | `[basic.def.odr]`、`[basic.link]` |
| A10 | **名字查找与 ADL** | 解释"`swap(a,b)` 为什么要写 `using std::swap`"、"`operator<<` 为什么能被找到"；模板报错的常见根因 | `[basic.lookup]`、`[basic.lookup.argdep]` |
| A11 | **异常安全与 `noexcept`** | `noexcept` 直接决定 `vector` 扩容用移动还是拷贝（强异常保证的关键） | `[except]`、`[except.spec]` |
| A12 | **迭代器/算法/容器的配合**（迭代器类别、范围、复杂度要求） | 算法对迭代器类别的要求决定"哪些算法能用" | `[iterators]`、`[algorithms]` |
| A13 | **`std::function` 与可调用对象的统一** | 回调接口的标准写法；类型擦除的代价认知 | `[func.wrap.func]` |
| A14 | **并发与内存模型**（happens-before、数据竞争的定义） | 数据竞争在标准里就是 UB；不懂内存序只能靠试错 | `[intro.multithread]`、`[thread]` |

## 七、⚠️ 一个必须纠正的分类错误

**这条纠正来自本轮核对，修正的是覆盖表起草时的判断。**

起草覆盖表时，我把下面这些知识点当成了"现代 C++ 才有的重点"：

```text
值类别与移动 · RAII · const 正确性 · 引用与指针细节 · 初始化与窄化
auto 推导 · 模板基础 · lambda · 智能指针 · 异常安全 · UB
翻译单元与 ODR · 名字查找与 ADL · inline/static/extern · constexpr
算法与迭代器 · std::function · 并发与内存模型 · 头文件组织 · namespace
```

**但它们全都不是 C++17 新增的，而是 C++11 及更早就有的。** 准确的关系是：

| 类别 | 含义 | 在讲义里怎么摆 |
|---|---|---|
| **语义模型**（C++11 起基线） | 是**现代 C++ 的基线要求**，不写这份讲义就不成立 | 进正文主干，按 `00_知识点总览.md` 的层次逐条展开 |
| **C++17 真新增**（B1–B21 那一组） | 是**相对基线的新增能力** | 出现时必须标注「C++17 起」，并说明基线已含 |
| C++20/23 | 基线之外 | 只在明确标注「C++20 起」的地方出现，本讲义不含 |

**为什么这个区分必须做对**：本项目的硬规矩之一是**区分「原资料内容 / 为讲清而补的解释 / 外部进阶知识」**。
把"C++11 就有的东西"说成"C++17 新特性"，正是**把基线伪装成新增**——
它会让读者以为"不升到 C++17 就学不到移动语义"，那是错的，
而错的方向恰好是**让读者低估自己环境的能力**。

**已按此纠正覆盖表**：见 [`00_知识点总览.md`](00_知识点总览.md) 第三节，
第 1 层（类型）、第 2 层（表达式）等处的条目**不再标注 C++17**；
只有结构化绑定（`10` 第 5 节）、`optional`/`variant`/`any`（`10` 第 6 节）、
`if constexpr`（`11` 第 5 节）、折叠表达式（`11` 第 6 节）等处标注「C++17」。
