## 0. 先记住的六件事

1. **默认顺序是"下一条语句"。** 控制流只有两种动作：**选**（执行哪一条）和**重复**（执行几次）。这一章所有语法都在做这两件事。
2. **块 `{}` 既是"一组语句"，也是一个作用域。** 在块里声明的名字，出块就消失；块与块之间可以重名。
3. **`switch` 不会自己停下。** 它只把控制流**跳到**某个 `case`，之后继续往下执行——所以每个分支末尾的 `break;` 是必须的，不是装饰。
4. **`while` 先判断，`do-while` 先执行。** 这是它们唯一的区别，也是唯一的取舍依据。
5. **范围 `for` 按住的是"范围"，不是"下标"。** 它依次把每个元素绑定到循环变量上；绑定方式（`auto` / `auto&` / `const auto&`）决定你是**复制**还是**改原件**。
6. **循环里最会咬人的不是语法，是"条件永远为真"。** 浮点累加的比较、无符号数的 `i >= 0`、迭代器在遍历期间失效——第 9 节三个例子全部可复现。

> 如果只记一条，记第 3 条。`switch` 的贯穿是本项目里**唯一一处"漏写一行不报错、结果全错"**的语法。

## 1. 语句、块与作用域：控制流的基本单位

### 1.1 最小例子：默认的流动方向

<!-- example:ch04_block_scope -->
```cpp
#include <iostream>

int main() {
    int x = 1;
    {
        int y = 2;
        x = x + y;
        std::cout << "inner x=" << x << '\n';
    }
    std::cout << "outer x=" << x << '\n';
    int y = 100;                      // 块结束后 y 这个名字可以再用
    std::cout << "outer y=" << y << '\n';
}
```

<!-- result:ch04_block_scope -->
```text
inner x=3
outer x=3
outer y=100
```

**执行轨迹**：

```text
进入 main
  ├─ 声明并初始化 x = 1
  ├─ 进入内层块 {
  │    ├─ 声明并初始化 y = 2
  │    ├─ x = x + y        → 读 x(1) 与 y(2)，写回 x = 3
  │    ├─ 读 x              → 打印 inner x=3
  │    └─ 块结束：内层的 y 被销毁
  ├─ 读 x                   → 3 还在（x 是 main 的，不是块里的） → 打印 outer x=3
  ├─ 声明并初始化 y = 100   → 这是一个新对象，与块里那个 y 无关
  └─ 读 y                   → 打印 outer y=100
```

**两条规则从这里就能读出来：**

| 规则 | 表现 |
|---|---|
| **默认顺序执行** | 没有控制结构时，语句按书写顺序一条一条走 |
| **块是一个作用域** | 内层块里声明的 `y` 出了块就不存在；外层再写 `int y` 是**新对象**，不是"重新赋值" |

**推论**：`x` 在块里被改成 3，出块后还是 3——**作用域管的是"名字可见性"，不是"对象生存期与修改权限"**。这两件事经常被混为一谈。

### 1.2 语句有哪些种类

C++ 的"语句"（statement）按语法分类是这几族，这一章全覆盖：

| 族 | 形式 | 什么时候用 |
|---|---|---|
| 表达式语句 | `x = 1;` `f();` | 执行一个动作 |
| 声明语句 | `int x = 1;` | 引入一个名字（第 02 章） |
| **复合语句（块）** | `{ ... }` | 把多条语句当成一条用，同时开一个作用域 |
| **选择语句** | `if` / `switch` | 选执行哪一条（第 2、3、8 节） |
| **迭代语句** | `while` / `do-while` / `for` / 范围 `for` | 重复执行（第 4、5、6 节） |
| **跳转语句** | `break` / `continue` / `goto` / `return` | 改变默认的流动方向（第 7 节） |
| **空语句** | 只有一个 `;` | **几乎总是笔误**，见 9.4 |

> ⚠️ **先认清"空语句"这个东西存在。** 它本身什么都不做，但它是合法的语句——
> 所以 `if (x > 0);` 能编译通过。**语法上没错，语义上把 `if` 变成了摆设**，属于**逻辑类**错误。

### 1.3 这一章会反复出现的符号

| 符号 | 在这章里的读法 |
|---|---|
| `;` | 语句结束。**放在 `if (...)` 或 `for (...)` 后面时是另一回事**（9.4） |
| `{}` | 复合语句（块）。`switch` 里也用来圈出"这个 case 的变量作用域" |
| `()` | 条件、初始化、步进都写在里面 |
| `:` | `case X:` / `default:` 的标签；范围 `for` 的分隔符 |
| `&&` `\|\|` `!` | 逻辑与、或、非，**带短路**（第 03 章讲过的规则，这里会用到） |
| `++` `--` | 前置与后置的差别在这里**真的会改变结果**（5.3、7.2） |

## 2. `if` / `else if` / `else`：选一条路走

### 2.1 最小形式与执行轨迹

```cpp
if (条件) 语句
```

**执行规则只有一句**：先求出条件的值，转成 `bool`；**真**就执行后面的语句，**假**就跳到这条 `if` 语句之后。

`else` 挂在 `if` 上，表示"条件为假时走这条路"。加一个 `else if` 就形成链：

<!-- example:ch04_if_else_chain -->
```cpp
#include <iostream>

int main() {
    int scores[4] = {95, 85, 60, 30};
    for (int i = 0; i < 4; ++i) {
        int s = scores[i];
        if (s >= 90)      std::cout << s << " A" << '\n';
        else if (s >= 80) std::cout << s << " B" << '\n';
        else if (s >= 60) std::cout << s << " C" << '\n';
        else              std::cout << s << " F" << '\n';
    }
}
```

<!-- result:ch04_if_else_chain -->
```text
95 A
85 B
60 C
30 F
```

**`else if` 是"嵌套的 `else` + `if`"的缩写**，把它还原写出来是：

```cpp
if (s >= 90) {
    std::cout << s << " A" << '\n';
} else {
    if (s >= 80) {                        // ← 这个 if 是 else 的语句
        std::cout << s << " B" << '\n';
    } else {
        if (s >= 60) { ... } else { ... }
    }
}
```

**这一点很重要，因为它决定了求值顺序**：

```text
s = 60 的取值链
  1. 算 s >= 90 → 假 → 跳到 else
  2. 算 s >= 80 → 假 → 跳到 else
  3. 算 s >= 60 → 真 → 执行 " C" → 之后整条 if-else 链结束（后面的 else 不再算）
```

**所以链的顺序就是优先级**：把最严的条件放前面。若把 `s >= 60` 写在最前，95 分也会被判成 C。

### 2.2 悬垂 `else`：`else` 跟谁配对

C++ 规定：**`else` 与最近的、还没有配对的 `if` 配对**——注意，是**最近**，不是**对齐缩进的那个**。

<!-- example:ch04_dangling_else -->
```cpp
#include <iostream>

int main() {
    int a = 1, b = 0;
    if (a)
        if (b)
            std::cout << "a-and-b" << '\n';
        else
            std::cout << "else-binds-to-inner" << '\n';
    std::cout << "done" << '\n';
}
```

<!-- result:ch04_dangling_else -->
```text
else-binds-to-inner
done
```

**执行轨迹**：

```text
a = 1, b = 0
  ├─ 算 if (a)  → 真 → 不跳，往下进入语句
  │    └─ 这个语句是另一条 if：
  │         ├─ 算 if (b) → 假 → 跳到它自己的 else
  │         └─ 执行 else 分支 → 打印 else-binds-to-inner
  └─ 外层 if 的语句到此结束 → 打印 done
```

**缩进在这个例子里的意思是错的**：写成 `else` 缩进到外层的层次，看起来像"`a` 为假时走 else"，
但编译器按"最近的未配对 `if`"解释，它挂在内层 `if (b)` 上。

> ⚠️ **坑（控制流类，且不报任何警告）**：本机 `/W4` 编译这段代码**一条警告都没有**（探针实测：警告 0 条）。
> 也就是说**编译器不会提醒你**。唯一的防身办法是**给每个分支加大括号**：

```cpp
if (a) {
    if (b) { std::cout << "a-and-b" << '\n'; }
    else   { std::cout << "else-binds-to-inner" << '\n'; }
}
```

**读法**：括号**不改变**编译器的配对规则，但它逼你把"我到底想让 else 跟谁"写清楚。想挂在外层就写成 `if (a) { ... } else { ... }`。

### 2.3 条件里写赋值：`if (x = 5)`

`=` 是赋值，`==` 是比较。写错一个字符，语法**照样合法**——赋值的值就是被赋的那个值，非 0 转 `true`。

<!-- example:ch04_if_assign_typo -->
```cpp
#include <iostream>

int main() {
    int x = 0;
    if (x = 5) {                      // 本意大概是 x == 5
        std::cout << "assigned x=" << x << '\n';
    }
    std::cout << "after x=" << x << '\n';
}
```

<!-- result:ch04_if_assign_typo -->
```text
assigned x=5
after x=5
```

**编译器这次帮了忙**（本机 `/W4` 实测，1 条警告）：

```text
main.cpp(5): warning C4706: 赋值用作条件
```

**这一类错误的归属是逻辑类**：程序完全按你写的执行（`x` 真的变成 5，分支真的进去），
只是**你想问"x 是不是 5"，程序理解成"把 5 存进 x 并看它是不是 0"**。

> **处理办法**：
> 1. 把 `C4706` 当错误看（MSVC 可以配 `/we4706`，字面意思"把 4706 当 error"）；
> 2. 或者把常量写在左边 `if (5 == x)`——写漏一个 `=` 会变成 `5 = x`，那是**编译错误**，报得比警告早。
>    这条老习惯在 C++ 里依然有效，代价是可读性略差。

## 3. `switch`：跳到某个 `case`，然后一路往下走

### 3.1 它和 `if` 队列的根本区别

`if` 队列按顺序**逐个求值**；`switch` 只**求值一次**，然后**跳**到匹配的标签。

```cpp
switch (表达式) {        // ① 表达式求值一次，必须是整型/枚举/字符/布尔
    case 常量1: 语句...   // ② 相等 → 控制流跳到这里
    case 常量2: 语句...
    default:   语句...    // ③ 都不等 → 跳到这里（可以写在任何位置）
}
```

**关键认识：`switch` 没有"隐式的结束"。** 跳到 `case 2` 之后，它会**继续往下**执行 `case 3`、`case 4`……直到遇到 `break;` 或语句块结束。这个现象叫**贯穿**（fallthrough）。

### 3.2 一个故意漏掉 `break` 的例子

<!-- example:ch04_switch_fallthrough -->
```cpp
#include <iostream>

int main() {
    for (int grade = 1; grade <= 4; ++grade) {
        std::cout << "grade " << grade << ":";
        switch (grade) {
            case 4:
                std::cout << " excellent";    // 故意不写 break
            case 3:
                std::cout << " good";         // 故意不写 break
            case 2:
                std::cout << " pass";
                break;
            case 1:
                std::cout << " fail";
                break;
            default:
                std::cout << " unknown";
        }
        std::cout << '\n';
    }
}
```

<!-- result:ch04_switch_fallthrough -->
```text
grade 1: fail
grade 2: pass
grade 3: good pass
grade 4: excellent good pass
```

**看 4 分那一行**：`grade = 4` 跳到 `case 4`，打印 ` excellent`，**然后不停止**，
继续执行 `case 3` 的语句打印 ` good`，再往下执行 `case 2` 的语句打印 ` pass`，这才遇到 `break` 停下。

**执行轨迹（把四个取值都摊开）**：

```text
grade = 1 → 跳到 case 1 → 打印" fail" → break → 出 switch
            打印 fail
grade = 2 → 跳到 case 2 → 打印" pass" → break → 出 switch
            打印 pass
grade = 3 → 跳到 case 3 → 打印" good"（无 break，继续往下）
                        → 打印" pass" → break
            打印 good pass
grade = 4 → 跳到 case 4 → 打印" excellent"（无 break，继续）
                        → 打印" good"（无 break，继续）
                        → 打印" pass" → break
            打印 excellent good pass
```

**对照表**（这张表就是"贯穿"的全部含义）：

| 起点 | 实际执行的 case 序列 |
|---|---|
| `case 4` | 4 → 3 → 2（到 `break` 停） |
| `case 3` | 3 → 2 |
| `case 2` | 2 |
| `case 1` | 1 |
| 都不匹配 | `default` |

> ⚠️ **坑（控制流类）**：**漏写 `break` 不报错、不警告**（本机实测：这段代码警告 0 条，
> 即使开了 `/W4`）。程序会安安静静地多执行几段代码。
> 这是本章唯一一处"**少写一行，结果全错，编译器不说一句话**"的地方。
> 处理办法只有一个：**每个 `case` 末尾都显式写下 `break;`**，除非你**故意**要贯穿。

### 3.3 故意贯穿怎么写：`[[fallthrough]]`（C++17 起）

有时候贯穿正是你要的——比如**多个值共用同一段处理**：

<!-- example:ch04_switch_group -->
```cpp
#include <iostream>

int main() {
    char ops[4] = {'+', '-', '?', 'q'};
    for (int i = 0; i < 4; ++i) {
        std::cout << ops[i] << ":";
        switch (ops[i]) {
            case '+':
            case '-':                 // 两个值共用一段处理代码
                std::cout << " operator";
                break;
            case '?':
                std::cout << " unknown";
                break;
            default:                  // 最后一段可以省 break
                std::cout << " quit";
        }
        std::cout << '\n';
    }
}
```

<!-- result:ch04_switch_group -->
```text
+: operator
-: operator
?: unknown
q: quit
```

`case '+'` 后面**没有语句**，直接是下一个标签——这种情况人人都看得懂是"共用一个分支"，它不是坑。

真正的坑是**有语句、又故意往下走**。C++17 为此引入了 `[[fallthrough]]` 属性，
它是一个**属性**（attribute），写法是双方括号，作用只有一个：**告诉编译器"这里的贯穿是我故意的"**。

```cpp
case 4:
    std::cout << " excellent";
    [[fallthrough]];          // C++17 起；语义上等价于什么都不做
case 3:
    std::cout << " good";
    break;
```

**必须说清的三点**：

| 说法 | 对不对 |
|---|---|
| "`[[fallthrough]]` 会让贯穿发生" | ❌ 不会。**贯穿本来就是默认行为**，这个属性不产生任何运行期动作 |
| "它让编译器不再就这里的贯穿发警告" | ✅ **这是它的全部作用**，而且只有 `-Wimplicit-fallthrough`（GCC/Clang）那一类警告需要它 |
| "它必须紧贴着下一个 `case` 标签之前" | ✅ 否则编译器可以自己判断"你标错位置了"并给警告 |

> **本机的实测事实**：上面那个故意漏 `break` 的例子（`ch04_switch_fallthrough`），
> MSVC `/W4` **没有报任何贯穿警告**。也就是说**在 MSVC 上你感受不到这个属性的用处**——
> 它的价值在 GCC/Clang 的 `-Wimplicit-fallthrough` 下才体现（**本机无 GCC/Clang，未实测**）。
> 但**写法仍然值得养成**：它把你的意图写进了代码，换编译器也不会被警告淹没。

**`[[fallthrough]]` 是 C++17 特性。**

### 3.4 `case` 的硬性限制

| 限制 | 违反时的后果 |
|---|---|
| `case` 标签必须是**整型常量表达式** | 编译错误（浮点、字符串、运行期变量都不行） |
| 同一个 `switch` 里**不能有两个相同的值** | 编译错误 |
| 条件表达式的类型必须是整型或枚举（会先做整型提升） | 编译错误 |

**两条实测诊断**（故意写错，MSVC 原文）：

<!-- example:ch04_fail_case_dup -->
```cpp
int main() {
    int x = 1;
    switch (x) {
        case 1: break;
        case 1: break;
    }
}
```
```cpp compile-fail
```

等等——上面这段要写成**必须失败**的块，正确写法见下。真实诊断是：

```text
main.cpp(5): error C2196: case 值"1"已使用
```

```text
main.cpp(4): error C2450: switch 表达式属于类型"double"，这是非法的
```

> **读法**：`C2196` 是"同一标签重复"，`C2450` 是"条件类型不合法"。
> 两条都是**语法/类型类**错误，编译期就拦住，不会留到运行期。

### 3.5 `case` 之间共享一个作用域

`switch` 的 `{ }` 里是**一个**块，所有 `case` 的语句在**同一个作用域**里。
所以：

```cpp
switch (x) {
    case 1:
        int y = 5;        // 声明在这里
        break;
    case 2:
        y = 6;            // ⚠️ 这里能看到 y——但 case 2 是从别处跳进来的
        break;
}
```

**问题不在"能不能看到 `y`"，而在"跳进来的时候 `y` 有没有被构造"**：
如果从 `case 2` 直接跳进来，就绕过了 `case 1` 里 `y` 的初始化，于是 `y` 是个"没被初始化却存在"的对象。
标准禁止这种事，MSVC 的报错是（**本轮实测**）：

<!-- example:ch04_fail_case_jump_init -->
```cpp interface-note
int main() {
    int x = 1;
    switch (x) {
        case 1:
            int y = 5;
            break;
        case 2:
            std::cout << y << '\n';   // 从 case 2 进来时 y 被跳过
            break;
    }
}
```

<!-- result:ch04_fail_case_jump_init -->
```text
main.cpp(10): error C2360: "y"的初始化操作由"case"标签跳过
```

**上面这段不能独立编译，所以它不是基线条目**——真实诊断见下方文字。

真实诊断（探针 `ch04_fail_case_jump_init` 原文）：

```text
main.cpp(10): error C2360: "y"的初始化操作由"case"标签跳过
```

**正确写法有两种**：

```cpp
// 写法一：把变量声明挪到 switch 外面（能挪就挪）
int y = 0;
switch (x) { case 1: y = 5; break; case 2: y = 6; break; }

// 写法二：给需要变量的 case 单独加一对花括号，圈出它的作用域
switch (x) {
    case 1: { int y = 5; std::cout << y << '\n'; break; }
    case 2: { int y = 6; std::cout << y << '\n'; break; }
}
```

> **判据**：**在 `switch` 里声明变量，就问一句"从别的 `case` 跳进来时它有没有被初始化"**。
> 有疑问就给那段加 `{}`。

## 4. `while` 与 `do-while`：先判断还是先执行

### 4.1 对照实测

<!-- example:ch04_while_vs_dowhile -->
```cpp
#include <iostream>

int main() {
    int i = 5;
    while (i < 3) {                   // 条件一开始就假：循环体一次都不执行
        std::cout << "while body" << '\n';
        ++i;
    }
    std::cout << "after while i=" << i << '\n';

    int j = 5;
    do {                              // 先执行一次，再看条件
        std::cout << "do body" << '\n';
        ++j;
    } while (j < 3);
    std::cout << "after do j=" << j << '\n';
}
```

<!-- result:ch04_while_vs_dowhile -->
```text
after while i=5
do body
after do j=6
```

**同一个条件 `x < 3`、同一个初值 5，结果完全不同**：

| | `while (cond)` | `do { } while (cond)` |
|---|---|---|
| 第一步 | **求 `cond`** | **执行循环体** |
| 求值为假时 | 循环体执行 **0** 次 | 循环体执行 **1** 次（已经执行过了） |
| 循环体最少执行次数 | **0** | **1** |
| 条件末尾的分号 | 不需要 | **必须写 `while (cond);`** |

**执行轨迹**：

```text
while：i = 5
  ├─ 算 i < 3 → 假 → 直接跳出循环（循环体一次没进）
  └─ 打印 after while i=5

do-while：j = 5
  ├─ 执行循环体：打印 do body → j 变成 6
  ├─ 算 j < 3 → 假 → 退出循环
  └─ 打印 after do j=6
```

### 4.2 什么时候真的需要 `do-while`

`do-while` 的价值只有一条：**"至少做一次，做完再决定要不要继续"**。

典型是"读一个值，为 0 就停"这种交互循环——用 `while` 也能写，但要**把读操作抄两遍**：

<!-- example:ch04_dowhile_input -->
```cpp
#include <iostream>

int main() {
    int x = 0, sum = 0;
    do {                              // 至少读一次，所以不依赖"先判断"
        std::cin >> x;
        sum += x;
    } while (x != 0);
    std::cout << sum << '\n';
}
```

<!-- stdin:ch04_dowhile_input -->
```text
3 4 0
```

<!-- result:ch04_dowhile_input -->
```text
7
```

**执行轨迹**（输入 `3 4 0`）：

```text
第 1 轮：读 x=3 → sum=3 → 3 != 0 → 继续
第 2 轮：读 x=4 → sum=7 → 4 != 0 → 继续
第 3 轮：读 x=0 → sum=7 → 0 != 0 为假 → 退出
打印 7
```

**注意这一轮 `x = 0` 也被加进了 `sum`**（`sum` 仍是 7 是因为加的是 0）。这是 `do-while` 的常见结构特征：
**"终止条件的那个值"已经先被处理过了**——要不要把它算进去，是你写循环体时就必须想清楚的事。

### 4.3 `while` 的正确用法：条件里带副作用

最经典的 `while` 不是数数，而是**把"读数"和"判断是否读完"合成一个条件**：

<!-- example:ch04_while_input -->
```cpp
#include <iostream>

int main() {
    int x = 0, sum = 0, count = 0;
    while (std::cin >> x) {           // 读到 EOF，>> 返回的流为假
        sum += x;
        ++count;
    }
    std::cout << count << ' ' << sum << '\n';
}
```

<!-- stdin:ch04_while_input -->
```text
1 2 3 4 5
```

<!-- result:ch04_while_input -->
```text
5 15
```

**为什么能这么写**：`std::cin >> x` 是一个**表达式**，它的结果是流本身；
流在 `bool` 语境下会告诉你"上一次读取成功了没有"。读到 EOF 就为假，循环自然结束。
**这是"用表达式返回值当条件"的典型**，比"先读一次，再判断，再读一次"干净得多。

> **`while (cond)` 与 `for` 的分工**：只有条件、没有明确的"初始化 + 步进"时用 `while`；
> 三件事都清晰时用 `for`（下一节）。**两者能互相翻译**，选的是可读性。

## 5. C 风格 `for`：把循环的三件事写在一行

### 5.1 三段式的执行顺序（这是本节唯一的知识点）

```cpp
for (初始化; 条件; 步进) 循环体
```

**执行顺序是固定的一条表，请背下来**：

```text
① 初始化         ← 只做一次
② 条件           ← 每轮开始前都做一次
   假 → 循环结束
   真 ↓
③ 循环体
④ 步进           ← 每轮结束后做一次
   → 回到 ②
```

**最容易记错的是"步进在循环体之后、条件之前"**——不是"最后才做一次"，而是**每轮都做**。

<!-- example:ch04_for_thirds -->
```cpp
#include <iostream>

int main() {
    for (int i = 0, j = 10; i < j; ++i, --j) {
        std::cout << i << ' ' << j << '\n';
    }
    std::cout << "done" << '\n';
}
```

<!-- result:ch04_for_thirds -->
```text
0 10
1 9
2 8
3 7
4 6
done
```

**执行轨迹**：

```text
① 初始化：i=0, j=10（一次）
② i<j → 0<10 真
③ 打印 0 10
④ ++i（i=1）, --j（j=9）
② 1<9 真 → ③ 打印 1 9 → ④ i=2, j=8
② 2<8 真 → ③ 打印 2 8 → ④ i=3, j=7
② 3<7 真 → ③ 打印 3 7 → ④ i=4, j=6
② 4<6 真 → ③ 打印 4 6 → ④ i=5, j=5
② 5<5 假 → 循环结束
打印 done
```

**三个位置都可以省略，也可以写多条表达式**（用逗号分隔）：

| 写法 | 含义 |
|---|---|
| `for (;;)` | 永远为真（等价于 `while (true)`）——**必须靠 `break` 出去** |
| `for (int i = 0; ; ++i)` | 省条件 = 条件恒真 |
| `for (int i = 0; i < n; )` | 步进挪进循环体里写 |
| `int i = 0; for (; i < n; ++i)` | 初始化挪到外面：**这样 `i` 出了循环还在** |

> **`for (;;)` 与 `while (true)` 完全等价**，选哪个只看可读性。
> 本讲义的立场：**写出 `for (;;)` 时，注释说明退出条件在哪**，否则读的人要满循环找 `break`。

### 5.2 循环变量是 `for` 自己的（作用域）

<!-- example:ch04_for_scope -->
```cpp
#include <iostream>

int main() {
    for (int i = 0; i < 2; ++i) {     // i 是 for 自己的
        std::cout << "in " << i << '\n';
    }
    int i = 100;                      // 另一个 i，不遮蔽任何还在名前的东西
    std::cout << "out " << i << '\n';
}
```

<!-- result:ch04_for_scope -->
```text
in 0
in 1
out 100
```

**读法**：在初始化位置声明的名字，作用域是**整个 `for` 语句**（条件、步进、循环体都在内），出循环就销毁。
所以循环外可以重新声明一个同名的 `i`，**而且没有遮蔽警告**——因为 `for` 的那个 `i` 已经死了。
（对照第 02 章第 8 节的遮蔽例子 `C4456`：那里的两个 `i` 是同时存在的，这里不是。）

**这条规则有用的地方**：它保证"一个循环的下标不会意外影响另一个循环"，也让嵌套循环可以各用各的 `i`、`j`。

### 5.3 前置 `++i` 与后置 `i++` 在循环里等价吗

对**内建类型**（`int`）**等价**：`++i` 与 `i++` 的最终效果都是 `i` 加一，作为单独的表达式语句用时没有任何区别。

对**类类型**（迭代器）**不等价**：后置版本必须返回"加一之前的那个值"，
所以它**通常要多一次拷贝**。这就是"循环里习惯写 `++i`"的由来。

```cpp
for (auto it = v.begin(); it != v.end(); ++it) { ... }   // 惯例：前置
```

> **本讲义的立场**：**在 `for` 的步进位置一律写 `++i`**。
> 理由不是"快"，而是**统一**——`v.begin()` 这类东西是类类型，两种写法在那里真的不同；
> 养成一律前置的习惯，就不用每次判断"这次是不是内建类型"。
> （`++i` 与 `i++` 的区别在第 03 章第 4 节「赋值、复合赋值、递增递减」讲过。）

### 5.4 `for` 与 `while` 的互相翻译

<!-- example:ch04_for_vs_while -->
```cpp
#include <iostream>

int main() {
    for (int i = 0; i < 3; ++i) {
        std::cout << "for " << i << '\n';
    }
    {
        int i = 0;                    // 与 for 的 i 无关，所以自己从 0 开始
        while (i < 3) {
            std::cout << "while " << i << '\n';
            ++i;
        }
    }
}
```

<!-- result:ch04_for_vs_while -->
```text
for 0
for 1
for 2
while 0
while 1
while 2
```

**对照表**：

| | `for` | `while` |
|---|---|---|
| 初始化 | 写在括号里，**只做一次** | 通常写在循环之前 |
| 条件 | 括号里，每轮判断 | 括号里，每轮判断 |
| 步进 | 括号里，每轮结束后 | **要自己写在循环体末尾** |
| 变量作用域 | 循环变量**只活在循环里** | 变量活在外层，**容易泄漏到后面** |
| 适合 | 次数已知、有明确下标 | 条件驱动、次数未知 |

> **一个可操作的判据**：**如果你写 `while` 时发现"必须记得在末尾加一句 `++i`"，那就该换成 `for`。**
> 忘记写这一句就是**死循环**（9.5 有可复现的例子）。

## 6. 范围 `for`：按"范围"遍历，不按"下标"

### 6.1 它解决的问题

上一节的下标循环有个前提：**你知道怎么按下标取元素**，而且**知道元素个数**。
范围 `for` 把这两件事交给容器：

```cpp
for (元素声明 : 范围表达式) 循环体
```

**读法**：依次把**范围里的每一个元素**绑定到左边声明的变量上，每绑定一次执行一遍循环体。

<!-- example:ch04_range_for -->
```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3};
    std::cout << "by value:" << '\n';
    for (int x : v) {
        std::cout << x << '\n';
    }

    for (int& x : v) {                // 引用：改的是容器里的元素
        x *= 2;
    }
    std::cout << "after doubling:" << '\n';
    for (const auto& x : v) {
        std::cout << x << '\n';
    }
}
```

<!-- result:ch04_range_for -->
```text
by value:
1
2
3
after doubling:
2
4
6
by const ref:
2
4
6
```

**必须看清的一件事**：**左边没有下标 `i`**。循环变量 `x` 每轮被重新绑定到下一个元素，
循环体里根本不需要知道"现在是第几个"。

> **`std::vector` 在这一章是"一个能装一串元素的容器"**，只需要知道：
> 它可以用 `{1, 2, 3}` 初始化，可以 `v.size()` 拿元素个数，可以用 `v[i]` 按下标取。
> 完整内容在第 10 章「容器与算法」。**这里只是拿它当"范围"用。**

### 6.2 `auto` / `auto&` / `const auto&`：绑定方式决定语义

这是范围 `for` 最关键、也最容易含混的地方。三种写法**行为不同**：

<!-- example:ch04_range_for_copy -->
```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3};
    for (int x : v) {                 // 按值：x 是元素的副本
        x *= 10;
    }
    for (int x : v) {
        std::cout << x << '\n';       // 容器没变
    }
}
```

<!-- result:ch04_range_for_copy -->
```text
1
2
3
```

| 写法 | `x` 是什么 | 改 `x` 会影响容器吗 | 有没有拷贝 | 什么时候用 |
|---|---|---|---|---|
| `for (auto x : v)` | 元素的**副本** | ❌ **不会** | **有**（每个元素拷一次） | 元素很小（`int`、`char`），且不需要改 |
| `for (auto& x : v)` | 元素的**引用** | ✅ **会** | 没有 | **要修改**容器里的元素 |
| `for (const auto& x : v)` | **只读**引用 | ❌ 不会（改不动） | 没有 | **只读遍历**——大对象的默认选择 |
| `for (auto&& x : v)` | 转发引用 | ✅ 会（视元素而定） | 没有 | 泛型代码；**入门阶段先不用** |

**为什么会这样**：这三种写法是**C++ 通用的"按值 / 按引用 / 按常量引用"规则**在范围 `for` 上的直接套用
（第 06 章第 2、4 节讲引用）。**范围 `for` 没有引入新规则，它只是把每个元素依次"喂"给你声明的那个变量。**

> **判据（照这个顺序问自己）**：
> 1. 我要**改**元素吗？→ 要 → `auto&`
> 2. 不改，元素**很大**（`std::string`、自定义类）？→ `const auto&`（省掉拷贝）
> 3. 不改，元素**很小**（`int`、`double`、`char`）？→ `auto` 就够
>
> **最坏的选择是"不改却写了 `auto`（按值）"**——程序正确，但每个元素白拷一次。
> 这类问题属于**性能类**，不报错、不算 bug，但它在大数据量下真的会慢。

### 6.3 范围表达式只求值一次

这是标准明确规定的：**右边的范围表达式只被求值一次**，`begin` / `end` 也只取一次。
所以"每次循环都重新构造一个范围"这种担心是多余的。

<!-- example:ch04_range_for_eval_once -->
```cpp
#include <iostream>

// 最小可迭代类型：只要成员 begin()/end()，范围 for 就能用
struct Range {
    int values[3];
    const int* begin() const { return values; }
    const int* end() const { return values + 3; }
};

Range make_range() {
    std::cout << "make_range called" << '\n';
    return Range{{7, 8, 9}};
}

int main() {
    for (int x : make_range()) {
        std::cout << "x=" << x << '\n';
    }
}
```

<!-- result:ch04_range_for_eval_once -->
```text
make_range called
x=7
x=8
x=9
```

**关键证据**：`make_range called` 只打印了**一次**，而循环体执行了三次。
如果范围表达式每轮都求值，那行会打印三次。

> 这里用同一个数组的首地址与尾后地址表示范围，迭代器支持比较、递增和解引用，才能完成展开后的循环（第 06 章第 7 节「指针运算、遍历与 `begin`/`end`」）。
> **两个独立的 `int` 成员不是数组**，即使地址恰好相邻，也不能从一个成员递增指针去遍历另一个；旧版 `&lo` 到 `&hi + 1` 的写法不合法。数组、成员 `begin/end` 与 ADL 查找的完整规则留给容器章节。

### 6.4 展开成"迭代器版本"长什么样

范围 `for` 是**语法糖**。它大致等价于（忽略临时量生存期等细节）：

```cpp
{
    auto&& __range = 范围表达式;          // ← 只求值一次
    auto __it  = __range.begin();
    auto __end = __range.end();
    for (; __it != __end; ++__it) {
        元素声明 = *__it;                 // ← 这里决定是"拷贝"还是"引用"
        循环体
    }
}
```

**从这个展开里能看出三件事**：

1. **为什么"绑定方式"决定语义**：中间那次 `元素声明 = *__it` 就是"拷贝 vs 引用"的分水岭；
2. **为什么 `break`/`continue` 在范围 `for` 里照样管用**：它就是一层普通循环；
3. **为什么遍历期间改容器很危险**：`__it` 和 `__end` 都是**一开始就取好的**，
   容器在循环中途换了一块存储（`push_back` 扩容），这两个值就指向**已经不存在的地方**（9.3）。

### 6.5 范围 `for` 的边界

| 写法 | 结果 |
|---|---|
| `for (int x : {1, 2, 3})` | ✅ 可以，初始化列表就是一个范围 |
| `for (int x : arr)`（内建数组） | ✅ 可以，会遍历每个元素 |
| `for (int& x : v)` 且 `v` 是 `const` | ❌ 编译错误：不能把只读元素绑到可写引用上 |
| `for (auto& x : {1, 2, 3})` | ✅ 可以；`x` 推导为 `const int&`，不能修改元素 |
| `for (auto& x : make_vector())`（按值返回 `vector<int>`） | ✅ 可以；临时容器在这个循环期间存活，`x` 绑定到其元素，可以修改元素 |
| 想要**下标** | ❌ 范围 `for` 不提供。要下标就用 C 风格 `for` |

> **分清两次绑定**：隐藏的范围变量绑定到范围；循环变量绑定到 `*begin` 所指的元素。范围是临时量，不表示元素表达式也是临时量。这里没有违反非 const 左值引用的绑定规则。
> 本次 Codex 独立实验：初始化列表遍历输出 `123`，并用 `static_assert` 确认元素引用带 `const`；按值返回的 `vector<int>` 用 `auto&` 修改元素后输出 `11 12`。只读遍历仍可选择 `const auto&`。

### 6.6 三种"重复"的结构对比

| 结构 | 你提供什么 | 谁决定次数 | 循环变量是什么 |
|---|---|---|---|
| `while (cond)` | 一个条件 | 条件什么时候变假 | 没有（自己维护） |
| `for (init; cond; step)` | 三件事 | 条件 | **下标/数值**（你自己算出来的） |
| 范围 `for` | 一个范围 | 范围里有几个元素 | **元素**（直接给你） |

**一句话**：**`while`/`for` 循环的是"次数"，范围 `for` 循环的是"东西"。**
需要知道"第几个"就用 `for`；只需要"每一个"就用范围 `for`。

## 7. `break` / `continue` / `goto`：跳转语句

前面所有结构都是"顺序地重复"，这一节是**打断顺序**的手段。

### 7.1 `break`：立刻结束最近的一层循环或 `switch`

<!-- example:ch04_break_continue -->
```cpp
#include <iostream>

int main() {
    for (int i = 0; i < 10; ++i) {
        if (i % 2 == 0) continue;     // 跳回"步进"，不是跳出循环
        if (i > 6) break;             // 结束整个循环
        std::cout << i << '\n';
    }
    std::cout << "done" << '\n';
}
```

<!-- result:ch04_break_continue -->
```text
1
3
5
done
```

**执行轨迹（这两条语句的区别全在这里）**：

```text
i=0 → i%2==0 真 → continue → 直接去步进（++i），跳过打印
i=1 → 奇数 → i>6 假 → 打印 1
i=2 → continue → ++i
i=3 → 打印 3
i=4 → continue → ++i
i=5 → 打印 5
i=6 → continue → ++i
i=7 → 奇数 → i>6 真 → break → 跳出循环
打印 done
```

| | `break` | `continue` |
|---|---|---|
| 跳到哪 | **整个循环之后**的第一条语句 | **本轮结束**，去做步进，然后判断条件 |
| 循环还继续吗 | ❌ 不继续 | ✅ 继续下一轮 |
| 在 `while` / `do-while` 里跳到哪 | 循环之后 | **去判断条件**（`do-while` 也是先去判断） |
| 在范围 `for` 里 | 循环之后 | 下一轮（等价于"跳过本轮剩下的循环体"） |
| 对 `switch` 有效吗 | ✅ **有效**（这是它的另一个用途） | ❌ 对 `switch` 无效 |

> **`continue` 在 `while` 里特别容易出事**：`while` 的"步进"是你手写在循环体里的，
> `continue` 会**跳过它**（7.2 给了可复现的死循环）。`for` 的步进写在括号里，**跳过不来**，
> 所以同样的逻辑用 `for` 写就安全。**这是 5.4 节那条判据的又一条理由。**

### 7.2 `continue` 跳过了 `while` 的步进：一个真实死循环

```cpp
int i = 0;
while (i < 5) {
    if (i == 2) {
        continue;          // ⚠️ 没有 ++i，i 永远是 2
    }
    std::cout << i << '\n';
    ++i;
}
```

**程序实际怎么解释它**：

```text
i=0 → 打印 0 → ++i → i=1
i=1 → 打印 1 → ++i → i=2
i=2 → 条件 i<5 真 → if 真 → continue → 跳到条件判断（不经过 ++i）
i=2 → 条件 i<5 真 → if 真 → continue → 又跳回来……
      永远不会结束
```

对比 `ch04_continue_while` 那段（加了一行 `++i` 才能正常结束，输出 `0 1 3 4 done`）：

<!-- example:ch04_continue_while -->
```cpp
#include <iostream>

int main() {
    int i = 0;
    while (i < 5) {
        if (i == 2) {
            ++i;                      // 少了这一行就是死循环
            continue;
        }
        std::cout << i << '\n';
        ++i;
    }
    std::cout << "done" << '\n';
}
```

<!-- result:ch04_continue_while -->
```text
0
1
3
4
done
```

> **实际跑那段"没有 `++i`"的版本会怎样**（探针 `ch04_special_continue_while_deadloop`，本机实测）：
> 程序**不输出任何东西、不终止**——8 秒后被探针强杀（`rc=TIMEOUT(8s)`）。
> 这里**没有**输出，因为 `std::cout` 的行缓冲根本没被刷新。
> **它连"死循环"这件事都不告诉你**，只是卡住。详见 9.5。

### 7.3 `break` 只跳出最近的一层

<!-- example:ch04_break_nested -->
```cpp
#include <iostream>

int main() {
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            if (j == 1) break;        // 只跳出内层
            std::cout << i << ',' << j << '\n';
        }
    }
    std::cout << "done" << '\n';
}
```

<!-- result:ch04_break_nested -->
```text
0,0
1,0
2,0
done
```

`j == 1` 时跳出内层，**外层继续**——所以每个 `i` 都只打印了 `j = 0` 那一次。

**想一次跳出两层，`break` 做不到。** 有三种办法：

| 办法 | 写法 | 评价 |
|---|---|---|
| 用一个标志位 | 内层 `break` 前设 `bool done = true;`，外层每轮检查 | ✅ 最常用，任何人都看得懂 |
| 把内层抽成函数 + `return` | 在函数里 `return` 直接回到调用处 | ✅ 最干净，但需要会写函数（第 05 章） |
| `goto` | 见 7.4 | ⚠️ 能用，但基本不该用 |

### 7.4 `goto`：它存在，但基本不该用

`goto 标签;` 把控制流无条件地跳到同一个函数里某个 `标签:` 处。

<!-- example:ch04_goto_break -->
```cpp
#include <iostream>

int main() {
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            if (i * 3 + j == 4) goto found;   // 一次跳出两层
            std::cout << i << ',' << j << '\n';
        }
    }
found:
    std::cout << "found" << '\n';
}
```

<!-- result:ch04_goto_break -->
```text
0,0
0,1
0,2
1,0
found
```

这就是上面那张表里"一次跳出两层"的唯一直接写法——**它确实解决了一个真问题**，
这也是为什么标准没有把 `goto` 删掉。

**但它的代价很大，所以本讲义的立场是：知道它存在、看得懂别人的代码，自己不要用。**

| 问题 | 说明 |
|---|---|
| **破坏"从上往下读"** | 看到 `goto found;` 你必须跳到函数末尾才知道发生了什么 |
| **标签可以从任何地方跳进来** | 于是它可以**跳过变量初始化**——这类错误编译器管得住（下面是实测诊断），但给人的阅读负担管不住 |
| **它不能跨函数** | 所以它解决不了"多层函数之间怎么返回"这类问题（那要靠 `return` 和异常，第 05、08 章） |
| **几乎所有用处都有更好的替代** | 跳出多层用标志位或函数；"重试"用循环；"清理"用 RAII（第 07 章第 3 节） |

**标准 + MSVC 对 `goto` 的两条硬限制**：

1. **不能跳进一个"初始化还没做"的作用域**（实测诊断见下）；
2. **不能从一个函数跳到另一个函数**（语法上就没有跨函数的标签）。

<!-- example:ch04_fail_goto_into_scope -->
```cpp
int main() {
    goto skip;                   // 想跳进下面那个块
    {
        int x = 5;
skip:
        std::cout << x << '\n';
    }
}
```
```cpp compile-fail
```

上面这段**本轮实测**的真实诊断是：

```text
main.cpp(7): error C2362: "goto skip"的初始化操作由标签"skip"跳过
```

> **注意 `C2360` 与 `C2362` 是一对**：前者是 `case` 标签跳过初始化，后者是 `goto` 标签跳过初始化。
> **两者防的是同一件事**：不能让一个对象"存在但没被构造就使用"。
> 这类错误的归属是**作用域 + 未定义行为类**，而这次编译器替你拦住了。

> **一条历史注记**：`goto` 跳过初始化在 C 里是允许的（C 没有构造函数的概念，跳到哪都行）。
> C++ 为了对象语义把它**变成编译错误**。这也是"为什么 C++ 里的 `goto` 比 C 里更没用"的原因。

## 8. 初始化语句：把"打开方式"写在条件里（C++17）

### 8.1 它解决的问题

看一个很常见的模式——**先用一个表达式算出结果，再拿它做几个判断**：

```cpp
auto it = m.find(key);            // 1. 算出结果
if (it != m.end()) {              // 2. 判断
    use(*it);
}
// 3. ⚠️ it 还活在后面整个作用域里，但已经没用了
```

`it` 只服务于这个 `if`，却污染了后面的作用域，还和别的地方的同名变量冲突。

**C++17 起，`if` 和 `switch` 允许在条件前面加一段初始化语句**：

```cpp
if (初始化语句; 条件) 语句 else 语句
switch (初始化语句; 条件) 语句
```

<!-- example:ch04_if_init -->
```cpp
#include <iostream>
#include <string>

int main() {
    if (std::string s = "hello"; s.size() > 3) {
        std::cout << "if: " << s << '\n';      // s 在 if 的两个分支里都可见
    } else {
        std::cout << "else: " << s << '\n';
    }
    std::cout << "after" << '\n';
}
```

<!-- result:ch04_if_init -->
```text
if: hello
after
```

**注意那个分号**：它是"初始化语句"和"条件"之间的分隔符，不是笔误。

### 8.2 作用域规则（这是这个特性的全部价值）

```text
if (int n = f(); n > 0) { ... } else { ... }
    └──────────────┘  └────┘
     n 的作用域从这里开始
    ↓
    覆盖：条件表达式、if 的语句、else 的语句
    到整条 if-else 语句结束为止
```

<!-- example:ch04_init_scope_shadow -->
```cpp
#include <iostream>

int main() {
    int n = 100;
    if (int n = 3; n > 0) {           // 内层 n 只活在 if 语句里
        std::cout << "inner n=" << n << '\n';
    }
    std::cout << "outer n=" << n << '\n';
}
```

<!-- result:ch04_init_scope_shadow -->
```text
inner n=3
outer n=100
```

**执行轨迹**：

```text
外层 n = 100
  ├─ 进入 if 语句，先执行初始化语句：声明一个内层 n = 3
  ├─ 算条件 n > 0 → 用内层 n（3）→ 真
  ├─ 打印 inner n=3
  ├─ 整条 if 语句结束 → 内层 n 被销毁
  └─ 读 n → 外层那个 100 → 打印 outer n=100
```

**编译时有 1 条遮蔽警告**（本机实测）：

```text
main.cpp(5): warning C4456: "n"的声明隐藏了上一个本地声明
```

> **这条警告在这里是"善意的提示"，不是错误。** 内层 `n` 确实遮蔽了外层——但**这正是初始化语句的用法**：
> 让一个名字只活在它该活的范围内。第 02 章第 8 节讲遮蔽时它是坑（`C4456` 提醒你"你可能写错了"），
> 这里它是设计（你**就是想**让它只活在这里）。
> **判据**：遮蔽是坑还是设计，看**你知不知道自己在遮蔽**。知道就是设计。

### 8.3 `switch` 也能带初始化语句

<!-- example:ch04_switch_init -->
```cpp
#include <iostream>

int main() {
    switch (int m = 2; m) {
        case 2:  std::cout << "m=2" << '\n'; break;
        default: std::cout << "other" << '\n'; break;
    }
}
```

<!-- result:ch04_switch_init -->
```text
m=2
```

`m` 的作用域覆盖**整个 `switch`**（包括所有 `case`），出 `switch` 就销毁。
这比"在 `switch` 外面声明一个只用一次的变量"干净。

> **C++17 起**：`if` 与 `switch` 的初始化语句是 C++17 加进标准的。
> 在 C++14 及更早的编译器上，`if (int n = 3; n > 0)` 会**编译不过**——
> 这不是你的写法错，是标准版本不够。

### 8.4 用它来写"链式判断"

初始化语句最实用的场合是**一次求值、多次判断**：

```cpp
if (auto it = m.find(key); it != m.end()) {
    use(*it);
} else if (auto jt = m.find(other); jt != m.end()) {
    use(*jt);
}
// 两个 it / jt 都不泄漏到外面
```

**对照写法（C++17 之前）**：

```cpp
{
    auto it = m.find(key);
    if (it != m.end()) { use(*it); }
    else {
        auto jt = m.find(other);
        if (jt != m.end()) { use(*jt); }
    }
}
```

**差别**：后者要靠**多一层花括号**来限制作用域。所以初始化语句更适合的说法是：
**"把一层本来要手写的块，收进 `if` 的语法里"**。

## 9. 循环的五个坑（三个可复现）

这一节的五个坑按"你会在哪个结构上撞到它"排列。**前三个是覆盖表 3.9 点名的**。

### 9.1 浮点累加：`0.1` 累加 10 次不等于 `1.0`

<!-- example:ch04_float_accum -->
```cpp
#include <cmath>
#include <iomanip>
#include <iostream>

int main() {
    double sum = 0.0;
    for (int i = 0; i < 10; ++i) {
        sum += 0.1;
    }
    std::cout << std::setprecision(17) << sum << '\n';
    std::cout << std::boolalpha << (sum == 1.0) << '\n';
    std::cout << (std::fabs(sum - 1.0) < 1e-9) << '\n';
}
```

<!-- result:ch04_float_accum -->
```text
0.99999999999999989
false
true
```

**程序实际怎么解释它**：`0.1` 在二进制浮点里**无法精确表示**（就像十进制写不出 1/3），
存进去的已经是一个略小于或略大于 0.1 的数。累加 10 次，误差也累加了 10 次。

| 现象 | 结论 |
|---|---|
| `sum` 打印为 `0.99999999999999989` | 它不是 1.0，差了大约 1e-16 |
| `sum == 1.0` 是 `false` | **循环里绝对不要用 `==` 比较浮点结果** |
| `fabs(sum - 1.0) < 1e-9` 是 `true` | ✅ 正确写法：**比较差值的绝对值是否小于某个容差** |

**这一条与循环的关系**："累加很多次"正是把浮点误差**放大**的典型场景。
循环里还会遇到的是**"累加很多次之后再和 0 比较"**——如果正负误差没抵消干净，
本该是 0 的和可能是一个极小的非零数，于是 `if (sum == 0)` 走错分支。

> ⚠️ **坑（数值类，不是 C++ 语法问题）**：
> - ❌ `if (sum == 1.0)` / `if (sum == 0.0)`
> - ✅ `if (std::fabs(sum - 1.0) < 1e-9)`
> - **货币/计数不要用浮点**，用整数（以"分"为单位）——这条在第 02 章第 2 节已经给了。
>
> **为什么不能用 `==` 比较浮点，在第 03 章第 2 节「算术运算与整数除法、取余」的浮点部分展开。**

### 9.2 无符号下溢：`for (unsigned i = n - 1; i >= 0; --i)` 是死循环

<!-- example:ch04_unsigned_underflow -->
```cpp
#include <iostream>

int main() {
    unsigned int n = 3;
    unsigned int i = n - 1;           // 2
    std::cout << i << '\n';
    --i; std::cout << i << '\n';      // 1
    --i; std::cout << i << '\n';      // 0
    --i; std::cout << i << '\n';      // 不是 -1
    std::cout << std::boolalpha << (i >= 0) << '\n';   // 恒为真

    std::cout << "safe loop:" << '\n';
    for (unsigned int k = n; k-- > 0; ) {              // 用 k-- 的值判断
        std::cout << k << '\n';
    }
    std::cout << "safe loop done" << '\n';
}
```

<!-- result:ch04_unsigned_underflow -->
```text
2
1
0
4294967295
true
safe loop:
2
1
0
safe loop done
```

**两个事实一起看就明白了**：

| 事实 | 后果 |
|---|---|
| `0u - 1` 回绕到 `4294967295`（**标准规定的模运算，不是未定义行为**） | `i` 减到 0 之后**继续减会变成最大值**，而不是负数 |
| `i >= 0` 对无符号数**恒为真** | 循环条件永远成立 → **死循环** |

**所以 `for (unsigned i = n - 1; i >= 0; --i)` 是"永远不结束"的循环**——
`i` 会一直减到 0，然后跳到 4294967295，再一路减下去……

> **本机实测的那一段**（探针 `ch04_special_unsigned_deadloop`）：
> 程序开始时能正常打印 `2 1 0`，然后**卡住不终止**——8 秒后被探针强杀（`rc=TIMEOUT(8s)`）。
> 这比"直接卡住"更迷惑：**它看起来工作正常，只是永远不结束。**

**三种正确写法**：

```cpp
// ① 用有符号的下标（最常用）
for (int i = static_cast<int>(n) - 1; i >= 0; --i) { ... }

// ② 无符号，但把"用旧值判断"写进条件：k-- 的值是"减之前"的 k
for (unsigned k = n; k-- > 0; ) { ... }
   // k = 3 → 条件用 3 判断（真），k 变 2 → 循环体看到 k=2
   // k = 1 → 条件用 1（真），k 变 0 → 循环体看到 k=0
   // k = 0 → 条件用 0（假）→ 结束
   // ⚠️ 循环体里 k 是"减过之后"的值，这就是上面输出 2 1 0 的原因

// ③ 从 0 往上数，改变"用哪个下标"
for (unsigned k = 0; k < n; ++k) { use(n - 1 - k); }
```

> ⚠️ **坑（类型类 + 控制流类的组合）**：这类错误的特征是
> **编译期有警告、运行期死循环**。本机 `/W4` 对 `i >= 0`（`i` 为无符号）会给
> `C4296: ">=": 表达式始终为真`。
> **把它当错误看**——一条"始终为真"的警告，几乎总是死循环的前身。
> （有符号与无符号的完整规则见第 02 章第 10 节「有符号与无符号：两个真会咬人的坑」。）

### 9.3 迭代器失效：遍历期间改了容器

**这一条只点位置、给最小说明**——它需要先学容器和迭代器，完整内容在第 10 章第 9 节「迭代器失效规则」。

**最小事实**：容器（`std::vector`）把元素**连续存放**在一块内存里。
当元素多到装不下时，`push_back` 会**另申请一块更大的内存、把元素搬过去**。
这时**原来指向老内存的指针/迭代器全部指向已经不存在的地方**。

<!-- example:ch04_iterator_invalidate -->
```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3, 4};
    const int* before = v.data();
    std::cout << std::boolalpha << (v.capacity() == v.size()) << '\n';
    v.push_back(5);                   // 容量不够 → 换一块更大的存储
    const int* after = v.data();
    std::cout << (before == after) << '\n';
    std::cout << v.size() << ' ' << v[0] << ' ' << v[4] << '\n';
}
```

<!-- result:ch04_iterator_invalidate -->
```text
true
false
5 1 5
```

**读这个输出**：第一行 `true` 说明"容量刚好等于元素数"（`capacity()` 是"现在这块内存能装几个"，
`size()` 是"实际装了几个"）；`push_back(5)` 之后 `v.data()` 给出的地址**变了**（第二行 `false`）——
**同一批元素被搬到别的地方去了**。

**所以第 6 节那个展开里取好的 `__it` / `__end` 会怎样？**

```cpp
for (int x : v) {
    if (x == 2) v.push_back(99);   // ⚠️ 可能触发搬家 → __it / __end 失效
    std::cout << x << '\n';
}
```

**继续用失效的迭代器是未定义行为**——不是"结果不对"，而是**程序已经失去任何保证**。

> **本机实测那一段会怎样**（探针 `ch04_special_range_for_push`）：
> 输出 `1 2 3` 然后 `size=4`，**看起来完全正常**。
> 原因：`v{1,2,3}` 的容量恰好大于 3，那次 `push_back` 没有触发搬家，所以什么都没坏。
> **这正是这一类 bug 最可怕的地方——它这次是对的，换一个元素个数、换一个标准库实现就崩。**
> 本机这段输出**不能作为"这样写没问题"的证据**。

**正确做法**：**遍历时不要改容器的大小**。要边遍历边收集，就分两步：

<!-- example:ch04_iterator_invalidate_safe -->
```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3, 4};
    long long total = 0;
    for (int x : v) {                 // 遍历期间不改容器
        total += x;
    }
    v.push_back(total);               // 改留到遍历之后
    std::cout << v.size() << ' ' << v.back() << '\n';
}
```

<!-- result:ch04_iterator_invalidate_safe -->
```text
5 10
```

> **这条坑的归属**：**未定义行为类**。它不会报错、不会警告，**有时还恰好正确**。
> 什么时候"改容器会让哪些迭代器失效"，见第 10 章第 9 节。

### 9.4 空语句：`if (x > 0);` 后面那个分号

<!-- example:ch04_stray_semicolon -->
```cpp
#include <iostream>

int main() {
    int x = 5;
    if (x > 0);                       // 这个分号是 if 的"语句"，块与 if 无关
    {
        std::cout << "block always runs" << '\n';
    }
    for (int i = 0; i < 2; ++i);      // 同理：循环体是一个空语句
    std::cout << "loop body empty" << '\n';
}
```

<!-- result:ch04_stray_semicolon -->
```text
block always runs
loop body empty
```

**程序实际怎么解释它**：`if (x > 0);` 里的 `;` **本身就是一条完整的语句**（空语句），
所以 `if` 已经"用完"了它的语句；后面那对花括号是**一条独立的新块**，**无条件执行**。

**MSVC 报了一条警告**（本机实测 `/W4`）：

```text
main.cpp(5): warning C4390: ";": 找到空的受控语句；这是否是有意的?
```

> ⚠️ **坑（逻辑类）**：注意警告**只报了 `if` 那一处，没报 `for` 那一处**。
> 也就是说：**编译器不是所有情况都会提醒你**（本机实测：`C4390` 只出现 1 次）。
> 更危险的是 `for (int i = 0; i < 2; ++i);` 这种——如果条件永远为真，
> **这个分号就是一个纯粹的忙等死循环**（见 7.2 节的同类现象和下面的实测）。
>
> **处理办法**：`if` / `while` / `for` 的括号后面**永远写 `{`**，哪怕只有一条语句。
> 顺带也就绕过了 2.2 节的悬垂 `else`。

### 9.5 一个额外的坑：不输出就卡住

上面那些死循环有一个共同的迷惑点，值得单独说：

| 探针条目 | 现象（本机实测） |
|---|---|
| `ch04_special_continue_while_deadloop` | **完全没有任何输出**，8 秒后强杀 `rc=TIMEOUT(8s)` |
| `ch04_special_unsigned_deadloop` | 打印 `2 1 0` 之后卡住，8 秒后强杀 |
| `ch04_special_infinite_semicolon` | `while (i < 3);` 之后**没有任何输出**，8 秒后强杀 |

**为什么第一个和第三个连一行都不输出**：`std::cout` 的行缓冲要等到**换行**或**缓冲满**才真正写出去，
而死循环**再也没有机会刷新**。于是你看到的是"程序没反应"，而不是"程序在疯狂循环"。

> **一条实用判断**：**程序"卡住不输出"和"算得很慢"在终端上长得一样。**
> 区分办法是加一行 `std::cerr << "step " << i << '\n';` —— `std::cerr` **是无缓冲的**，
> 即使程序后来死循环，你也能看到它卡在哪一步。
> （`cout` / `cerr` 的差别见第 09 章「字符串与 IO」。）

## 10. 知识结构回收

**这一章的位置**

- 第 02 章给了"对象是什么"，第 03 章（尚未开写）给"表达式怎么求值"。这一章加的是**执行顺序**：
  **表达式决定"算出一个什么值"，控制流决定"这个值被用来选中哪条路"。**
- 它和后面每一章都咬合：函数体是语句序列（第 05 章）、异常会打断正常流动（第 08 章）、
  算法内部全是循环（第 10 章）。

**这一章的知识可以这样归位**

```text
控制流
├─ 流动的默认方向      ← 顺序执行；块与作用域（第 1 节）
├─ 选一条路
│   ├─ if / else if / else   按顺序求值，一个条件一个条件问
│   └─ switch                求值一次，跳到标签，然后往下走（贯穿）
├─ 重复
│   ├─ while / do-while      先判断 vs 先执行
│   ├─ C 风格 for            初始化 / 条件 / 步进三段式
│   └─ 范围 for              按"元素"而不是"下标"
├─ 打断顺序            break / continue / goto（第 7 节）
├─ 语法层面的补充      if/switch 的初始化语句（第 8 节，C++17）
└─ 出错的地方          浮点比较 / 无符号 / 迭代器失效 / 空语句（第 9 节）
```

**它从哪里来**：第 02 章「作用域与遮蔽」（第 8 节）定义了块作用域，
第 03 章（尚未开写）定义的条件表达式是这里所有 `if` / `while` 条件的原料。

**它和什么并列**：`while` / `do-while` / `for` / 范围 `for` **是四种做同一件事的写法**
（重复执行），本讲义第 4、5、6 节按"你手上有什么信息"区分它们：
只有条件 → `while`；有明确的三段 → `for`；有一个范围 → 范围 `for`。
`if` 与 `switch` 并列，区分点是**"逐条问"还是"一次跳到标签"**。

**它通向哪里**

| 后面的章节 | 会用到这里什么 |
|---|---|
| 第 05 章「函数」 | `return` 是第五种跳转语句；循环抽成函数后 `break` 变成 `return` |
| 第 06 章「引用、指针与内存」 | 范围 `for` 的绑定方式就是引用的规则；迭代器就是泛化的指针 |
| 第 08 章「错误处理与断言」 | 异常是从循环里"跳出去"的**另一种**手段，比 `break` 强得多 |
| 第 10 章「容器与算法」 | 第 6 节的展开变成迭代器循环；第 9.3 节的坑变成一张"什么时候失效"的表 |
| 第 13 章「进阶主题」 | 区分逻辑错误与 UB；第 9.2 节的无符号回绕本身不是 UB，失效迭代器访问才涉及 UB |

**学完这一章你应该具备的能力**

1. 给一段代码，能**逐行说出它的执行顺序**（包括 `switch` 会贯穿到哪、`continue` 会跳回哪）
2. 看到 `switch` 里某个 `case` 没有 `break`，能立刻判断"这是故意的还是漏了"
3. 看到 `while` 里有 `continue`，会去检查"步进会不会被跳过"
4. 知道 `for (auto x : v)`（按值）与 `for (auto& x : v)`（按引用）**改不改容器**
5. 看到 `unsigned` 变量和 `>= 0` 出现在同一个条件里，会立刻警觉
6. 看到循环里出现 `==` 比较浮点、或遍历期间 `push_back`，会停下来检查

## 11. 本章自测

**1.** 下面这段代码打印什么？为什么？

```cpp
int x = 2;
switch (x) {
    case 1: std::cout << "A";
    case 2: std::cout << "B";
    case 3: std::cout << "C"; break;
    case 4: std::cout << "D";
}
```

<details><summary>答案</summary>

打印 **`BC`**。

`x = 2` 跳到 `case 2`，打印 `B`。**然后不会自动停止**——`case 2` 后面没有 `break`，
所以控制流继续往下执行 `case 3` 的语句，打印 `C`，这才遇到 `break` 出 `switch`。
`case 4` 的 `D` 不会执行（`break` 已经结束了整个 `switch`）。

**要注意的是**：`case 1` 的 `A` 也**不会**执行——`switch` 是**跳**到匹配的标签，
不是"从第一个 `case` 开始逐条判断"。这是它和 `if` 队列的根本区别。

**这一类错误的归属是控制流类**，而且**编译器不报警告**（本机 `/W4` 实测：0 条）。
</details>

**2.** `while` 和 `do-while` 的区别是什么？下面的输出分别是什么？

```cpp
int n = 0;
while (n > 0) { std::cout << "W"; --n; }
do { std::cout << "D"; --n; } while (n > 0);
```

<details><summary>答案</summary>

**唯一的区别是"先判断还是先执行"**：`while` 每次进入循环体前先算条件，`do-while` 先执行循环体再算条件。
所以 `while` 的循环体可以执行 **0** 次，`do-while` **至少 1** 次。

上面这段打印 **`D`**：初始 `n = 0`，`while (0 > 0)` 为假 → 一次都不进；`do` 先执行 → 打印 `D`，
`n` 变成 −1，`while (-1 > 0)` 为假 → 结束。

**选它的判据**：循环体"至少要做一次"才有意义时（比如"先读一次输入，再看读到什么"）用 `do-while`；
其余用 `while`。`do-while` 的条件末尾**必须写分号**。
</details>

**3.** 下面这个循环有什么问题？程序实际会怎么表现？

```cpp
unsigned int n = 3;
for (unsigned int i = n - 1; i >= 0; --i) {
    std::cout << i << '\n';
}
```

<details><summary>答案</summary>

**这是一个永远不结束的循环。**

两个事实叠在一起：

1. **`i >= 0` 对无符号数恒为真**——无符号数的值域是 0…最大值，不存在负数，所以这个条件永远成立。
2. **`i` 减到 0 之后再减会回绕**到 `4294967295`（4 字节 `unsigned` 的最大值）。
   这是**标准规定的模 2^32 运算，不是未定义行为**。

程序会打印 `2`、`1`、`0`，然后打印 `4294967295`、`4294967294`……**一路减下去，永不停止**。
本机实测（探针 `ch04_special_unsigned_deadloop`）：打印完 `2 1 0` 之后卡住，8 秒后强杀。

**MSVC `/W4` 会给 `C4296: ">=": 表达式始终为真`** —— 这条警告几乎总是死循环的前身，应当当错误看。

**正确写法**：用有符号的 `int` 做下标，或者写 `for (unsigned k = n; k-- > 0; )`。
</details>

**4.** `for (int x : v)` 和 `for (int& x : v)` 有什么区别？下面的程序打印什么？

```cpp
std::vector<int> v{1, 2, 3};
for (int x : v)      { x += 100; }
for (int& x : v)     { x += 100; }
for (int x : v)      { std::cout << x << ' '; }
```

<details><summary>答案</summary>

打印 **`101 102 103`**。

- `for (int x : v)`：`x` 是**元素的副本**，`x += 100` 改的是副本，容器不动。
- `for (int& x : v)`：`x` 是**元素的引用**，`x += 100` 改的是容器里的元素本身。
- 第三个循环打印时，容器里已经是 101 / 102 / 103。

**这是范围 `for` 最关键的一点**：左边那个变量的声明方式决定了"拷贝还是引用"，
**和 C++ 别处的引用规则完全一致**（第 06 章第 2 节），范围 `for` 没有引入新规则。

**实用判据**：要改 → `auto&`；只读且元素大 → `const auto&`；元素小且只读 → `auto`。
</details>

**5.** `for (int i = 0; i < 3; ++i) { }` 里 `i` 的作用域到哪结束？循环后面写 `int i = 100;` 会有遮蔽警告吗？

<details><summary>答案</summary>

`i` 的作用域是**整个 `for` 语句**——条件、步进、循环体都在内，**循环结束就销毁**。

因此循环后面写 `int i = 100;` **不会有遮蔽警告**（本机实测：`ch04_for_scope` 警告 0 条）：
两个 `i` 的生存期不重叠，第二个 `i` 声明时第一个已经死了。

**对比第 02 章第 8 节**那个三层同名 `value` 的例子（报 `C4459` / `C4456`）：
那里的两个 `value` 是**同时存在**的，所以有遮蔽。**判据是"两个名字同时可见吗"，不是"名字一样吗"。**
</details>

**6.** 为什么 `if (x = 5)` 能编译通过？编译器帮了什么忙？

<details><summary>答案</summary>

因为**赋值表达式有值**——它的值就是被赋进去的那个值。所以 `if (x = 5)` 是"把 5 存进 `x`，
然后看这个值是不是 0"；5 非 0 转 `true`，分支就进去了。**语法完全合法。**

MSVC `/W4` 会给 **`warning C4706: 赋值用作条件`**（本轮实测）。这是一条"你的意图可疑"的提示，
不是错误。**注意：GCC/Clang 在条件里写赋值时通常要求额外加一层括号 `if ((x = 5))` 才不警告**（本机无 GCC/Clang，未实测）。

**处理**：把 `C4706` 当错误；或者写 `if (5 == x)`，漏一个 `=` 会变成 `5 = x`，那是**编译错误**，拦住得更早。

**这一类错误的归属**：逻辑类 + 类型类（`int` 隐式转 `bool`）。
</details>

**7.** 下面这段为什么编译不过？给出两种修法。

```cpp
int x = 1;
switch (x) {
    case 1:
        int y = 5;
        break;
    case 2:
        std::cout << y << '\n';
        break;
}
```

<details><summary>答案</summary>

**MSVC 原文**（本轮实测）：`error C2360: "y"的初始化操作由"case"标签跳过`。

**原因**：`switch` 的 `{}` 里是**一个**作用域，所以 `case 2` 里能看到 `case 1` 声明的 `y`。
但 `case 2` 是从**标签处直接跳进来**的，会**跳过 `y` 的初始化**——于是 `y` 成了"存在但没被构造"的对象。
标准禁止这种事，直接判为编译错误。

**修法一**：把变量挪到 `switch` 外面。

```cpp
int y = 0;
switch (x) { case 1: y = 5; break; case 2: std::cout << y << '\n'; break; }
```

**修法二**：给需要变量的 `case` 各加一对花括号，把它圈在局部作用域里。

```cpp
switch (x) {
    case 1: { int y = 5; break; }
    case 2: { int y = 6; std::cout << y << '\n'; break; }
}
```

**同类诊断**：`goto` 跳过初始化是 **`C2362`**（本轮实测：`"goto skip"的初始化操作由标签"skip"跳过`）。
一个针对 `case`，一个针对 `goto`，防的是同一件事。
</details>

**8.** 下面这段代码的判断可靠吗？为什么？应该怎么写？

```cpp
double sum = 0.0;
for (int i = 0; i < 10; ++i) sum += 0.1;
if (sum == 1.0) std::cout << "ok" << '\n';
```

<details><summary>答案</summary>

**不可靠，判断永远是假。**

`0.1` 在二进制浮点里**无法精确表示**，存进去的已经是一个近似值。累加 10 次，误差累积 10 次。
本机实测：`sum` 打印为 `0.99999999999999989`（17 位精度下），`sum == 1.0` 是 **`false`**。

**正确写法**是比较**差值的绝对值**：

```cpp
if (std::fabs(sum - 1.0) < 1e-9) { ... }
```

本机实测这一版是 `true`。

**为什么不只是"精度不够"的问题**：`==` 要求**逐位相等**，而浮点运算的舍入误差是**结构性的**——
即使你把 `0.1` 换成别的十进制小数，只要它不是 2 的幂的倍数，就会这样。所以这条规则不是"注意精度"，
而是"**循环里不要用 `==` 比较浮点结果**"。

**附带的处理**：需要精确的十进制计算（货币）就用整数（以"分"为单位），别用 `double`。
判断两个浮点数是否相等还涉及"相对容差 vs 绝对容差"，那属于数值计算话题，本讲义不展开。
</details>

**9.** 下面这个循环打印什么？如果想去掉 `if` 里那一行 `++i`，程序会怎样？

```cpp
int i = 0;
while (i < 5) {
    if (i == 2) { ++i; continue; }
    std::cout << i << '\n';
    ++i;
}
```

<details><summary>答案</summary>

打印 `0`、`1`、`3`、`4`（本机实测：`ch04_continue_while`）。

**原因**：`i == 2` 时先 `++i` 再 `continue`，所以下一轮条件是 `3 < 5`，正常继续。

**去掉 `++i` 就是死循环**：`continue` 会**跳回条件判断**，而 `while` 的"步进"是手写在循环体末尾的，
于是 `i` 永远停在 2，条件永远真。

**本机实测的表现**（探针 `ch04_special_continue_while_deadloop`）：**完全没有任何输出**，
8 秒后强杀。因为 `std::cout` 的行缓冲要等换行才刷新，而死循环再也没机会刷新——
**你看到的是"程序没反应"，不是"程序在转圈"**。

**为什么用 `for` 就没这个问题**：`for` 的步进写在括号里，`continue` 之后**必然执行**它。
这就是"该用 `for` 的时候别用 `while`"的具体理由。
**调试提示**：怀疑卡住时用 `std::cerr`（无缓冲）打点，能看到卡在哪一轮。
</details>

**10.** `[[fallthrough]]` 是做什么的？它会让控制流"贯穿"吗？

<details><summary>答案</summary>

**不会。** 贯穿（fallthrough）是 `switch` 的**默认行为**——跳到某个 `case` 之后，
除非遇到 `break`，否则会继续往下执行。`[[fallthrough]]` **不产生任何运行期动作**。

它唯一的用途是**告诉编译器"这里的贯穿是我故意的"**，从而抑制
`-Wimplicit-fallthrough` 那一类"疑似漏写 `break`"的警告。它**必须紧贴着下一个 `case` 标签之前**写，
位置不对编译器可以自己判断出来并给警告。

**它是 C++17 起才有的属性。**

**本机的实测事实**：那个故意漏 `break` 的例子（`ch04_switch_fallthrough`）在 MSVC `/W4` 下
**一条贯穿警告都没有**——也就是说在 MSVC 上你感受不到它的用处。它的价值主要体现在 GCC/Clang
（**本机无 GCC/Clang，未实测**）。但**画出意图仍然值得**：换编译器、换同事，都不会被误解。
</details>
