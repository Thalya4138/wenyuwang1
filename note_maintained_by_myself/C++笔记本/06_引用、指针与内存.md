## 0. 先记住的七件事

**这一章的分部**（后面每一节都在回答这张图里的一格）：

```text
间接访问
├─ 手段                引用（第 2 节） / 指针（第 3 节）
├─ 手段之间怎么选       对比表（第 4 节）
├─ 给手段加约束         const 组合、顶层 vs 底层（第 5 节）
├─ 被访问的对象是什么   一串连续对象：数组与退化（第 6、7 节）
│                      一块存储：栈与堆、生存期（第 8 节）
└─ 谁负责释放           手动管理 new/delete（第 9 节）
                        失败模式分类（第 10 节）
进阶位置：右值引用（第 11 节）
```

1. **引用是"别名"，不是"对象"。** 它必须一开始就绑定到某个已存在的对象，绑上之后**不能再改绑**；`sizeof(引用)` 得到的是被引用对象的大小。
2. **指针是"对象"，装的是地址。** 它可以为空（`nullptr`）、可以改指别的对象、可以做加减法。
3. **引用和指针在"能不能空、能不能改绑"上正好相反**（第 4 节的对比表），这决定了它们各自适合什么场合。
4. **`const` 修饰的是"谁"要分清**：修饰被指对象（底层 const）还是修饰指针自己（顶层 const）。这是入门材料最容易讲糊的地方，第 5 节给表。
5. **数组名在大多数表达式里会退化成指向首元素的指针**，`sizeof` 会因此从"整个数组"变成"一个指针"。`std::array` 和 `std::vector` 就是用来把这个信息留住的两件工具。
6. **栈对象的生存期由作用域决定，堆对象的生存期由你决定。** 前者的死亡时刻是确定的；后者你不写 `delete` 就永远不死——这正是泄漏的来源。
7. **间接访问的四类错误（悬垂、泄漏、重复释放、越界）里，只有泄漏不是未定义行为。** 其余三类都是 UB：编译能过、运行时不一定马上出错、出了错也不一定报错。

> 如果只记一条，记第 7 条。它是本章唯一"程序不按你想的运行，而且不告诉你"的地方。

## 1. 一个改不动实参的例子：为什么需要间接访问

先从你上一章已经会写的东西开始：函数参数是**按值传递**的——传进去的是副本。

<!-- example:ch06_swap_value_vs_ref -->
```cpp
#include <iostream>

void by_value(int a, int b) { int t = a; a = b; b = t; }
void by_ref(int& a, int& b) { int t = a; a = b; b = t; }

int main() {
    int x = 1, y = 2;
    by_value(x, y);
    std::cout << x << ' ' << y << '\n';
    by_ref(x, y);
    std::cout << x << ' ' << y << '\n';
}
```

<!-- result:ch06_swap_value_vs_ref -->
```text
1 2
2 1
```

**执行轨迹**（本章的规矩：讲清程序到底先做什么）：

```text
by_value(x, y)：
  1. 在 by_value 的栈帧里分配 a、b 两块新存储
  2. 把 x 的值复制进 a，把 y 的值复制进 b      ← 到这里，a/b 与 x/y 再无关系
  3. 交换 a 和 b 的值                          ← 只是换了两块副本
  4. 函数返回，a、b 随栈帧一起消失
  5. 调用方的 x、y 完全没被碰过                → 打印 1 2

by_ref(x, y)：
  1. 在 by_ref 的栈帧里放两个"别名"，分别指向 x 和 y
  2. a = b 是"把 y 的值写进 x 那块存储"
  3. 函数返回，别名消失，x、y 已被真的改过      → 打印 2 1
```

**问题的形状**：函数体里拿到的名字（`a`、`b`）和调用处的对象（`x`、`y`）**是不是同一块存储**。按值传递时不是；要让它变成同一块，就需要**间接访问**——名字不再直接是对象，而是一个"指向对象的东西"。

C++ 提供了两种间接访问的手段：**引用**和**指针**。它们的差别不是"新旧"，而是"能做什么、不能做什么"。第 2、3 节分别讲它们各自的样子，第 4 节把两者摆在一起比较。

> **术语先对齐**：这一章说的"对象"沿用第 02 章第 1 节的定义——一块存储 + 一个类型 + 一个当前值。
> 引用**不是对象**（它没有自己的存储和地址），指针**是对象**（它自己占 8 字节，里面装一个地址）。

## 2. 左值引用：给已存在的对象起第二个名字

**引用（reference）** 最常见的形态叫**左值引用**，写法是在类型后面加 `&`：

```cpp
int a = 1;
int& r = a;      // r 是 a 的第二个名字
```

`int& r = a;` 读作"`r` 是一个绑定到 `a` 的 `int` 引用"。此后凡是用 `r` 的地方，效果和用 `a` 完全一样。

### 2.1 最小例子：引用和原对象是同一块存储

<!-- example:ch06_ref_identity -->
```cpp
#include <iostream>

int main() {
    int a = 7;
    int& r = a;
    std::cout << std::boolalpha << (&r == &a) << '\n';
    std::cout << sizeof(r) << ' ' << sizeof(int) << '\n';
    r = 8;
    std::cout << a << ' ' << r << '\n';
}
```

<!-- result:ch06_ref_identity -->
```text
true
4 4
8 8
```

三行输出各说明一件事：

| 输出 | 说明 |
|---|---|
| `true` | `&r` 取到的就是 `a` 的地址——引用没有自己的地址 |
| `4 4` | `sizeof(r)` 是 **`int` 的大小**，不是"引用的大小"。因为引用不是对象，没有独立的大小 |
| `8 8` | 通过 `r` 写，`a` 就变了；它们是同一块存储 |

> ⚠️ **坑**：把 `sizeof(r) == 4` 理解成"引用占 4 字节"。
> **真相**：`sizeof` 作用在引用上时会**自动换成被引用的对象**去算。
> 这类误解的判别属于**类型类**：你以为 `r` 是"一个装着地址的小东西"，语言却认为 `r` 就是 `a`。

### 2.2 关键符号：`&` 在这一章的三种身份

`&` 是个"一符多用"的符号，必须看它出现在**哪个位置**：

| 出现位置 | 名字 | 例子 | 含义 |
|---|---|---|---|
| 类型的一部分，紧跟在类型后面 | **引用声明符** | `int& r = a;` | 声明一个引用 |
| 一元前缀运算符，作用在表达式上 | **取地址** | `&a` | 求出 `a` 的地址 |
| 二元运算符，两边都是整数 | **按位与** | `x & 1` | 位运算（第 03 章） |

判别顺序：**先看它左边有没有类型**。`int& r` 里的 `&` 左边是 `int`，是引用；
`= &a` 里的 `&` 右边是表达式，是取地址；`x & y` 两边都是值，是按位与。

### 2.3 引用的两条硬规则

**规则一：引用必须初始化。** 不存在"先声明一个引用，稍后再让它指向谁"。

<!-- example:ch06_ref_uninit_FAIL -->
```cpp compile-fail
int main() {
    int& r;
    (void)r;
}
```
```text
main.cpp(2): error C2530: “r”: 必须初始化引用
```

**规则二：引用一旦绑定就不能改绑。** 但"改绑"这个词本身有陷阱——你写不出改绑的代码，
而写出**看起来像改绑**的代码时会得到完全不同的结果：

<!-- example:ch06_ref_rebind -->
```cpp
#include <iostream>

int main() {
    int a = 1, b = 2;
    int& r = a;                 // r 是 a 的别名
    r = b;                      // 不是"让 r 改指 b"，而是 a = b
    std::cout << a << ' ' << b << ' ' << r << '\n';
    r = 99;
    std::cout << a << ' ' << b << '\n';
}
```

<!-- result:ch06_ref_rebind -->
```text
2 2 2
99 2
```

**程序实际怎么解释 `r = b;`**：引用不是对象，所以"给引用赋值"在语言里根本不存在——
这句话被解释成"给 `r` 所引用的那个对象赋值"，也就是 `a = b`。
于是 `a` 变成 2，`b` 没动。三处打印都是 2，因为 `a`、`r` 是同一块存储。

> ⚠️ **坑**：以为 `r = b;` 之后 `r` 就指向 `b` 了。
> **属于哪一类**：不是语法错，也不是类型错——程序完全按语言规则执行，只是规则和你的直觉不同。
> **如果真想"改指"，那需要的是指针**（第 3 节），不是引用。

### 2.4 引用的三种常见用途

| 用途 | 写法 | 得到什么 |
|---|---|---|
| **改实参** | `void f(int& x)` | 函数内改的是调用方的对象 |
| **避免拷贝大对象** | `void f(const std::string& s)` | 不复制，且承诺不改 |
| **让函数调用出现在赋值号左边** | 返回引用的函数 | 见下面的例子 |

第三种最容易让人意外：

<!-- example:ch06_ref_return -->
```cpp
#include <iostream>

int& at_most_one(std::size_t i, int& a, int& b) {
    return i == 0 ? a : b;
}

int main() {
    int x = 1, y = 2;
    at_most_one(1, x, y) = 99;           // 函数调用出现在赋值号左边
    std::cout << x << ' ' << y << '\n';
}
```

<!-- result:ch06_ref_return -->
```text
1 99
```

**为什么能这么写**：`at_most_one(1, x, y)` 返回的是 `y` 的引用，
所以整个表达式就是 `y` 的另一个名字，`= 99` 自然就是给 `y` 赋值。
`std::vector::operator[]`、`std::cout` 的 `<<` 都靠这个机制才能串起来。

> ⚠️ **坑**：**不要返回局部变量的引用**。局部变量在函数返回时就被销毁，
> 返回的引用指向一块已经死掉的存储——这是**未定义行为**，与第 10 节的"悬垂指针"同类。
> 编译器在返回指针时会警告（本机实测 `warning C4172`），返回引用时警告更少。

### 2.5 不允许的写法：非 const 引用接不了临时量

<!-- example:ch06_ref_literal_FAIL -->
```cpp compile-fail
int main() {
    int& r = 42;
    (void)r;
}
```
```text
main.cpp(2): error C2440: “初始化”: 无法从“int”转换为“int &”
```

**为什么不允许**：`42` 是字面量，它没有名字也没有稳定存储。如果允许 `int& r = 42;`，
那么 `r = 5;` 就会去改一个"本来不该存在的东西"。为了堵住这个漏洞，语言规定：
**只有 const 引用才能绑定到临时量**（第 5 节讲它的后果与用途）。

同样地，把字面量传给一个非 const 引用参数也会失败：

<!-- example:ch06_const_ref_rvalue_FAIL -->
```cpp compile-fail
void take(int& x) { x = 1; }

int main() {
    take(5);
}
```
```text
main.cpp(4): error C2664: “void take(int &)”: 无法将参数 1 从“int”转换为“int &”
```

## 3. 指针：把地址本身当成值

**指针（pointer）是一个对象，它的值是一个地址。** 写法是在类型后面加 `*`：

```cpp
int a = 1;
int* p = &a;     // p 里装着 a 的地址
```

`int* p` 读作"`p` 是一个指向 `int` 的指针"。注意 **`*` 贴哪边都行**（`int* p`、`int *p`、`int * p`），
它属于声明符而不是类型名的一部分——这也是 `int* a, b;` 里 `b` 其实是 `int` 的原因。

### 3.1 关键符号：`*` 在这一章的三种身份

和 `&` 一样，`*` 必须靠位置判断：

| 出现位置 | 名字 | 例子 | 含义 |
|---|---|---|---|
| 类型的一部分 | **指针声明符** | `int* p = &a;` | 声明一个指针 |
| 一元前缀运算符 | **解引用** | `*p` | 按 `p` 里的地址找到那个对象 |
| 二元运算符 | **乘法** | `x * y` | 算术乘法 |

判别顺序同样是**看左边有没有类型**：`int* p` 里 `*` 的左边是类型 → 声明；
`= *p` 里 `*` 的右边是个变量 → 解引用；`x * y` 两边都是值 → 乘法。

### 3.2 最小例子：取地址、解引用、改绑

<!-- example:ch06_ptr_basic -->
```cpp
#include <iostream>

int main() {
    int a = 1;
    int* p = &a;                // p 里装的是 a 的地址
    std::cout << *p << '\n';    // 解引用：按地址找到那个对象
    *p = 42;                    // 通过指针改那个对象
    std::cout << a << ' ' << *p << '\n';
    int b = 7;
    p = &b;                     // 指针可以改绑（引用不行）
    std::cout << *p << ' ' << a << '\n';
}
```

<!-- result:ch06_ptr_basic -->
```text
1
42 42
7 42
```

**执行轨迹**：

```text
1. 栈上分配 a（4 字节），写入 1
2. 栈上分配 p（8 字节），写入 a 的地址
3. *p   → 顺着 p 里的地址找到 a 那块存储，读出 1
4. *p = 42 → 顺着地址找到 a，把 42 写进去     → a 变成 42
5. p = &b  → 把 p 这 8 字节的内容改成 b 的地址 ← 指针本身是对象，所以可以改它
6. *p   → 现在顺着 p 找到的是 b，读出 7；a 仍然是 42
```

**第 5 步是引用做不到的事**，也是两者最本质的差别。

### 3.3 空指针：`nullptr`

指针可以不指向任何对象，这样的指针叫**空指针**。C++11 起用 `nullptr` 表示，
不要再用 C 时代的 `NULL` 或 `0`（原因见 3.4）。

<!-- example:ch06_ptr_null -->
```cpp
#include <iostream>

int main() {
    int* p = nullptr;
    if (p) { std::cout << "非空\n"; } else { std::cout << "空\n"; }
    std::cout << std::boolalpha << (p == nullptr) << '\n';
    int v = 3;
    p = &v;
    if (p) { std::cout << *p << '\n'; }
}
```

<!-- result:ch06_ptr_null -->
```text
空
true
3
```

**`if (p)` 的含义**：指针在条件里会被转换成 `bool`——空指针为 `false`，非空为 `true`。
所以 **`if (p)` 与 `if (p != nullptr)` 等价**。这是惯用写法，读代码时要认得。

> ⚠️ **坑**：**空指针"合法"不代表"能解引用"**。`*p` 在 `p` 为空时是**未定义行为**，
> 本机实测直接以 `0xC0000005`（访问违规）终止——但下面 3.5 会说清为什么"没崩"不代表没写错。

### 3.4 指针的大小

<!-- example:ch06_ptr_size -->
```cpp
#include <iostream>

int main() {
    std::cout << sizeof(int*) << ' ' << sizeof(char*) << ' '
              << sizeof(double*) << '\n';
    std::cout << sizeof(int&) << '\n';
}
```

<!-- result:ch06_ptr_size -->
```text
8 8 8
4
```

| 表达式 | 本机结果 | 说明 |
|---|---|---|
| `sizeof(int*)` | 8 | 64 位程序里所有指针都是 8 字节——**指针里装的是地址，不是对象** |
| `sizeof(char*)` | 8 | 指向什么类型不影响指针自身的大小 |
| `sizeof(int&)` | 4 | 引用不是对象，`sizeof` 换成被引用对象去算 |

**为什么建议用 `nullptr` 而不是 `NULL`**：

| 写法 | 类型 | 问题 |
|---|---|---|
| `nullptr` | `std::nullptr_t` | 只能转成指针，不会意外转成整数 |
| `NULL` | 通常是 `0`（整数） | 会参与整数重载决议，导致调错重载 |
| `0` | 整数 | 更糟：读代码的人分不清是"零"还是"空指针" |

本机（MSVC）的 `NULL` 定义为 `0`，所以 `f(NULL)` 会去调 `f(int)` 而不是 `f(int*)`。
**这类错误的归属是重载决议类**，报错位置常常在完全无关的地方。

### 3.5 空指针解引用：能编过，会崩

<!-- example:ch06_null_deref -->
```cpp
#include <iostream>

int main() {
    int* p = nullptr;
    std::cout << *p << '\n';
}
```

这一段**编译成功，警告 0 条**（本机实测）。运行结果：

```text
（stdout 为空；进程以 0xC0000005 = 3221225477 终止）
```

**为什么编译器不拦你**：`p` 是合法声明、`*p` 是合法表达式、`cout << int` 是合法调用——
语法和类型全都没问题。**出错的是运行期的语义**：解引用前指针必须是有效的。
编译器不做（也不该做）这种运行期证明。

**这一段的输出不进自动基线**：它的输出不是"确定但不同"，而是**根本没有保证**。
报告里连一行都没打出来，是因为 stdout 还有内容留在缓冲区里，进程已经死了（第 08 章会讲这个细节）。

## 4. 引用 vs 指针：一张对比表

这是本章最该记牢的一节。两者都能"间接访问一个对象"，但**限制完全不同**，而这些限制正好决定了它们的用途。

### 4.1 逐项对照

| 对照项 | 引用 | 指针 |
|---|---|---|
| **是什么** | 一个别名，**不是对象** | 一个对象，值是一个地址 |
| **能不能为空** | ❌ 不能。必须绑定到某个对象 | ✅ 能。`nullptr` 是合法值 |
| **能不能改绑** | ❌ 不能。绑上就定了 | ✅ 能。`p = &b;` |
| **要不要初始化** | ✅ 必须（`int& r;` 编译失败） | ⚠️ 可以不初始化，但值是垃圾（UB） |
| **声明语法** | `int& r = a;` | `int* p = &a;` |
| **取被指对象** | 直接用 `r` | 要解引用：`*p` |
| **访问成员** | `obj.member` | `p->member`，等价于 `(*p).member` |
| **有没有自己的地址** | ❌ `&r` 得到的是被引用对象的地址 | ✅ `&p` 得到指针自己的地址 |
| **sizeof 得到什么** | 被引用对象的大小 | 指针自身的大小（本机 8） |
| **算术运算** | ❌ 不支持 `r + 1` 这种"移动到下一个对象" | ✅ 支持 `p + 1`（第 7 节） |
| **典型实现** | 通常就是一个常量指针，但标准不要求它有存储 | 就是一块存地址的存储 |
| **数组退化** | 传 `int (&a)[5]` 不退化 | 传 `int a[]` 退化成 `int*` |

> **"典型实现"那一行**：本机实测 `&r == &a` 为 `true`，说明编译器确实让引用指到了同一个地址。
> 但**标准只规定行为，不规定实现**。"引用一定就是指针"这种说法不要当成语言事实来用。

### 4.2 什么时候用哪个

判断顺序建议照下面走：

| 你的需求 | 选择 | 理由 |
|---|---|---|
| 想改调用方的对象 | **引用** | 语法干净，且不可能忘了解引用 |
| 传大对象但不想改它 | **`const` 引用** | 不拷贝、不改，还能接临时量 |
| 想返回"调用方给的对象"本身 | **引用** | 例如 `operator[]`、`operator<<` |
| 可能出现"没有对象"的情况 | **指针** | 引用表达不了"空" |
| 需要改指别的对象 | **指针** | 引用做不到 |
| 需要在一串对象里移动、做算术 | **指针**（或迭代器） | 引用不能做位移 |
| 要跨函数传递"所有权" | **指针**（现代写法是智能指针，第 12 章） | 用引用表达不了"我要负责释放它" |
| 只读、可空、且允许算术 | `const int*` | 三者都要 |

**一句话规则**：**默认用引用，只有引用表达不了你的意思时才退回指针。**
"表达不了"的具体情形就三种：**要表示空**、**要改指**、**要做算术**。

### 4.3 `->` 与 `.` 的关系

```cpp
struct Point { int x; };

Point p{1};
Point* q = &p;

p.x = 2;        // 对象直接用 .
q->x = 3;       // 指针用 ->
(*q).x = 4;     // 完全等价于上面那句
```

| 写法 | 左边是什么 | 含义 |
|---|---|---|
| `p.x` | 对象 | 访问 `p` 的成员 `x` |
| `q->x` | 指针 | 先解引用再访问成员，`->` 是 `(* ).` 的简写 |
| `*q` | 指针 | 解引用得到那个对象（**注意 `*` 与 `.` 的优先级**：`*q.x` 是错的，要先写 `(*q).x`） |

`->` 不是"指针专用的成员运算符"，它只是把"解引用 + 取成员"两步压成一个符号，
让 `q->x` 比 `(*q).x` 少一层括号。

## 5. `const` 与引用/指针的组合：顶层 const 与底层 const

`const` 加在指针上会产生**两种完全不同的意思**，这是入门材料最容易讲糊的地方。
先把两个术语定死：

| 术语 | 修饰谁 | 例子里管住的是 |
|---|---|---|
| **底层 const**（low-level） | **被指向的对象** | 能不能通过这个指针改对象 |
| **顶层 const**（top-level） | **指针自己** | 这个指针能不能改指别人 |

### 5.1 四种组合的读法

**读法：从右往左读，`const` 贴在谁前面就管谁。**

| 声明 | 英文读法 | 顶层 const？ | 底层 const？ | 能做 | 不能做 |
|---|---|---|---|---|---|
| `int* p` | pointer to int | 否 | 否 | 改指向、改对象 | — |
| `const int* p` | pointer to **const** int | 否 | ✅ | 改指向 | `*p = 1` |
| `int* const p` | **const** pointer to int | ✅ | 否 | 改对象 | `p = &b` |
| `const int* const p` | **const** pointer to **const** int | ✅ | ✅ | 只读 | 两样都不行 |
| `const int& r` | reference to **const** int | — | ✅ | 只读 | 改对象 |

> 引用的规则更简单：**引用只有底层 const，没有顶层 const**。
> 原因还是那句——引用不是对象，没有"引用自己"可以加 const。
> 所以 `int& const r = a;` 是非法的（MSVC：`error C2040`，本轮未单独实跑这一行）。

### 5.2 四种组合里合法的写法

<!-- example:ch06_const_ptr_ok -->
```cpp
#include <iostream>

int main() {
    int a = 1, b = 2;

    const int* p1 = &a;         // 底层 const：不能通过 p1 改 a
    std::cout << *p1 << '\n';
    p1 = &b;                    // p1 自己可以改指

    int* const p2 = &a;         // 顶层 const：p2 不能改指
    *p2 = 20;                   // 但可以改它指的对象

    const int* const p3 = &a;   // 两样都是 const

    const int& r1 = a;          // 引用版：const 引用
    std::cout << *p1 << ' ' << *p2 << ' ' << *p3 << ' ' << r1 << '\n';
}
```

<!-- result:ch06_const_ptr_ok -->
```text
1
2 20 20 20
```

**注意第二行全是 20**：`p2`、`p3`、`r1` 都指着 `a`，而 `*p2 = 20` 改了 `a`。
只有 `p1` 指到了 `b`（值 2）。**"底层 const 的指针"完全可以指向一个非 const 的对象**——
它只是承诺"我不通过你改"，不是"你不许被改"。

### 5.3 两种非法写法与真实诊断

<!-- example:ch06_const_ptr_write_FAIL -->
```cpp compile-fail
int main() {
    int a = 1;
    const int* p = &a;
    *p = 5;
}
```
```text
main.cpp(4): error C3892: “p”: 赋值给类型为 'const int *' 的常量限定 变量
```

<!-- example:ch06_const_ptr_rebind_FAIL -->
```cpp compile-fail
int main() {
    int a = 1, b = 2;
    int* const p = &a;
    p = &b;
    (void)p;
}
```
```text
main.cpp(4): error C3892: “p”: 赋值给类型为 'int *const ' 的常量限定 变量
```

两处的错误码**都是 `C3892`**，但诊断里打印的类型不同：

- 第一处：`'const int *'`（底层 const）——你想改的是**被指对象**
- 第二处：`'int *const '`（顶层 const）——你想改的是**指针自己**

**读诊断的技巧**：MSVC 把 `const` 写在类型里的位置直接反映了它是哪种 const。
看到 `const int *` 就往"不能改对象"想，看到 `int *const` 就往"不能改指向"想。

### 5.4 `typedef` / `using` 会把顶层 const 藏起来

这是本节的第二个坑，也是真实项目里会遇到的：

<!-- example:ch06_const_typedef -->
```cpp
#include <iostream>
#include <type_traits>

using IntPtr = int*;

int main() {
    int a = 1, b = 2;
    const IntPtr p = &a;                 // 等价于 int* const p
    std::cout << std::boolalpha;
    std::cout << std::is_same<const IntPtr, int* const>::value << '\n';
    std::cout << std::is_same<const IntPtr, const int*>::value << '\n';
    *p = 10;                             // 可以改被指对象
    std::cout << a << '\n';
    (void)b;
}
```

<!-- result:ch06_const_typedef -->
```text
true
false
10
```

**程序实际怎么解释它**：`const` 作用在**类型别名 `IntPtr` 本身**上，而 `IntPtr` 是一个指针类型，
所以 `const IntPtr` 是"const 的指针" = `int* const`（顶层 const）。**它并没有变成 `const int*`。**

> ⚠️ **坑**：看到 `const IntPtr p` 就以为"p 指向的东西不能改"。
> **属于哪一类**：类型类。这种写法在 STL 头文件里非常常见，读代码时**必须把别名展开**再判断。
> **自检手段**：用 `std::is_same` 比一下，别靠眼睛看。

### 5.5 `const` 引用参数：能接临时量，所以最常用

<!-- example:ch06_const_ref_param -->
```cpp
#include <iostream>
#include <string>

void print(const std::string& s) { std::cout << s << '\n'; }

int main() {
    std::string name = "World";
    print(name);
    print("literal");
}
```

<!-- result:ch06_const_ref_param -->
```text
World
literal
```

**`print("literal")` 发生了什么**：`"literal"` 的类型是 `const char[8]`，
它先隐式转换成一个**临时 `std::string` 对象**，这个临时对象绑定到 `const std::string&`，
函数体里用的是它，函数返回时临时对象被销毁。

**为什么非 const 引用不行**：如果允许 `void print(std::string& s)` 接临时对象，
那么函数里写 `s = "改了"` 就会改一个马上要消失的东西——这个漏洞必须在类型系统里堵住。

> **这就是 `const T&` 成为 C++ 最常用参数写法的原因**：
> 它一份拷贝都不做，又能接左值、右值、字面量、临时量。第 05 章「函数」里讲的
> "传参怎么写"到这里才真正完整。

### 5.6 `auto` 会丢掉顶层 const

<!-- example:ch06_auto_const_strip -->
```cpp
#include <iostream>
#include <type_traits>

int main() {
    const int ci = 42;
    auto a = ci;                 // int
    const int& r = ci;
    auto b = r;                  // int
    auto& c = r;                 // const int&
    std::cout << std::boolalpha;
    std::cout << std::is_same<decltype(a), int>::value << '\n';
    std::cout << std::is_same<decltype(b), int>::value << '\n';
    std::cout << std::is_same<decltype(c), const int&>::value << '\n';
}
```

<!-- result:ch06_auto_const_strip -->
```text
true
true
true
```

| 写法 | 推导结果 | 为什么 |
|---|---|---|
| `auto a = ci;` | `int` | 按值推导：**顶层 const 被丢掉**（拷贝一份当然可以改） |
| `auto b = r;` | `int` | `r` 是 `const int&`，按值推导仍得 `int` |
| `auto& c = r;` | `const int&` | 加 `&` 表示"按引用推导"，这时底层 const 保留 |

**规律**：`auto` 默认按值推导，会把顶层 const 和引用都剥掉；
要保留它们就显式写 `auto&` / `const auto&`。这与第 02 章「`auto` 的三个退化」是同一套规则。

## 6. 数组：一串连续的对象与退化

数组解决的问题和引用/指针不同：不是"指向一个对象"，而是**一串连续存放的同类型对象**。
但它的行为处处受"退化"影响，所以放在这一章讲。

### 6.1 数组是什么

```cpp
int a[5] = {1, 2, 3, 4, 5};
```

这句话做三件事：分配 **5 个连续的 `int`**（本机 20 字节）、用花括号里的值初始化、
把名字 `a` 绑到这一整块存储上（**不是**第一个元素的指针）。

| 项 | 值 |
|---|---|
| `sizeof(a)` | 20（整个数组） |
| `a[0]` | 第一个元素 |
| `a[5]` | **越界**——合法下标是 `0..4`，不是"到 5 为止" |
| `&a` 的类型 | `int(*)[5]`（指向整个数组的指针），不是 `int*` |
| `a` 的类型 | `int[5]`，但在大多数表达式里会**退化**成 `int*` |

**数组不是指针，它是"一个数组类型的对象"。** 只是它几乎总会被转换成指针。

### 6.2 退化：什么时候发生，后果是什么

<!-- example:ch06_array_decay -->
```cpp
#include <iostream>

void by_array_param(int a[]) {   // 等价于 int* a
    std::cout << sizeof(a) << '\n';
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    std::cout << sizeof(a) << '\n';
    by_array_param(a);
    std::cout << (sizeof(a) / sizeof(a[0])) << '\n';
}
```

<!-- result:ch06_array_decay -->
```text
20
8
5
```

**三个数字各说明一件事**：

| 输出 | 含义 |
|---|---|
| `20` | 在 `main` 里，`a` 还是数组，`sizeof` 得到整块存储 |
| `8` | 传进函数后 `a` 已经是指针，`sizeof` 得到指针大小 |
| `5` | 想数元素个数，唯一可靠的办法是**在数组还没退化的地方**算 `sizeof(a)/sizeof(a[0])` |

**`void by_array_param(int a[])` 里的 `[]` 是伪装**：它和 `void by_array_param(int* a)` 完全等价，
**元素个数信息在这里彻底丢失**。这就是为什么标准库要额外传一个长度，或者干脆用容器。

**退化发生在什么时候**：数组名出现在**需要指针的语境**里时（传参、赋给指针、参与算术）。
**不退化**的场合有两个：`sizeof` 和 `&`（取地址），以及绑定到数组引用时。

### 6.3 不让它退化：数组引用

<!-- example:ch06_array_ref_param -->
```cpp
#include <iostream>

void by_ref(int (&a)[5]) {       // 引用不退化
    std::cout << sizeof(a) << ' ' << (sizeof(a) / sizeof(a[0])) << '\n';
}

int main() {
    int a[5] = {1, 2, 3, 4, 5};
    by_ref(a);
}
```

<!-- result:ch06_array_ref_param -->
```text
20 5
```

`int (&a)[5]` 读作"一个绑定到 `int[5]` 的引用"。因为绑定的是**整个数组**而不是首元素，
`sizeof` 和元素个数都还在。**代价是长度必须写成编译期常量**——长度一变函数签名就得改。

### 6.4 `std::array` 与 `std::vector` 的位置

C++ 提供两个容器来解决"C 数组既不安全也不方便"的问题：

| | C 数组 | `std::array<T, N>` | `std::vector<T>` |
|---|---|---|---|
| 长度 | 编译期常量 | 编译期常量（作为类型的一部分） | **运行期可变** |
| 存储位置 | 你在哪声明就在哪 | 你在哪声明就在哪 | **堆上**（对象本身在栈上，元素在堆上） |
| 知道自己的长度 | ❌ 退化后不知道 | ✅ `.size()` | ✅ `.size()` |
| 越界检查 | ❌ 没有 | `.at()` 有检查，`[]` 没有 | `.at()` 有检查，`[]` 没有 |
| 能自动释放 | 栈上的能 | 栈上的能 | ✅ 析构时自动释放内部存储 |
| 能拷贝 | ❌ | ✅ | ✅ |
| 开销 | 无 | 无（就是一层薄封装） | 一次间接 + 堆分配 |

<!-- example:ch06_std_array_vector -->
```cpp
#include <array>
#include <iostream>
#include <vector>

int main() {
    std::array<int, 4> a{1, 2, 3, 4};
    std::vector<int> v{1, 2, 3, 4};
    std::cout << a.size() << ' ' << v.size() << '\n';
    std::cout << sizeof(a) << ' ' << sizeof(v) << '\n';
    v.push_back(5);
    std::cout << v.size() << '\n';
}
```

<!-- result:ch06_std_array_vector -->
```text
4 4
16 24
5
```

| 输出 | 含义 |
|---|---|
| `4 4` | 两个容器都知道自己有多少个元素 |
| `16` | `sizeof(std::array<int,4>)` = 4 × 4，**没有任何额外开销** |
| `24` | `sizeof(std::vector<int>)` = 24：本机实现是"三个指针"（数据首地址、末元素后一位置、容量末尾） |
| `5` | `vector` 能在运行期长大（`array` 不能） |

> ⚠️ **`sizeof(std::vector)` 是 24 这件事是本机实现的产物，不是标准保证的。**
> 标准只要求 `vector` 能动态增长，没规定它内部用几个指针。
> 换一个实现（GCC/Clang 的 libstdc++/libc++）可能还是 24，也可能不是——**本机未实测那些**。

**选型建议**：

- 长度编译期就知道、且不需要动态增长 → **`std::array`**（零开销，且比 C 数组安全）
- 长度运行期才知道、或者会变 → **`std::vector`**（默认选择）
- **C 数组**留给"接口要求"和"初始化列表"这两类场合；自己写新代码时优先用上面两个

**详细用法（构造、增删、迭代器失效等）在第 10 章**，这里只交代它们在内存模型里的位置。

## 7. 指针运算、遍历与 `begin`/`end`

指针能做加减法，这件事只在**指向同一块连续存储**时才有意义。

### 7.1 指针算术的规则

| 表达式 | 含义 |
|---|---|
| `p + n` / `p - n` | 向后 / 向前移动 **n 个元素**（不是 n 个字节） |
| `p++` / `++p` | 移动到下一个元素 |
| `p - q` | 两个指针之间**隔了多少个元素**（类型是 `std::ptrdiff_t`） |
| `p == q`、`p < q` | 比较位置（只在同一块存储内有意义） |
| `*p` | 取 `p` 指的那个元素 |

**关键点：`p + 1` 移动的字节数是 `sizeof(*p)`。** 对 `int*` 是 4 字节，对 `char*` 是 1 字节。
语言用"元素"为单位，就是为了让你不用手算字节。

### 7.2 遍历：尾后指针是合法的

<!-- example:ch06_ptr_arith -->
```cpp
#include <iostream>

int main() {
    int a[5] = {10, 20, 30, 40, 50};
    int* p = a;
    int* last = a + 5;              // 尾后指针：可以取，不能解引用
    int sum = 0;
    while (p != last) { sum += *p; ++p; }
    std::cout << sum << '\n';
    std::cout << *(a + 2) << ' ' << (last - a) << '\n';
    std::cout << (a[2] == *(a + 2)) << '\n';
}
```

<!-- result:ch06_ptr_arith -->
```text
150
30 5
1
```

**两个必须记住的边界规则**：

| 指针位置 | 能不能取到 | 能不能解引用 |
|---|---|---|
| 数组内（`a` … `a+4`） | ✅ | ✅ |
| **尾后**（`a + 5`） | ✅ **合法**，循环靠它终止 | ❌ 不能 |
| 更远（`a + 6`） | ❌ 未定义行为 | ❌ |
| 更前（`a - 1`） | ❌ 未定义行为 | ❌ |

**"尾后指针合法"是 `for` 循环能写成 `p != end` 的前提**，也是标准库所有算法的基础约定。

### 7.3 `a[i]` 就是 `*(a + i)`

最后一行输出 `1` 是在验证这条恒等式。语言里 `a[i]` 的定义就是 `*(a + i)`，
所以 `i[a]` 也是合法的（等价于 `*(i + a)`）——**能写不等于该写**，这只是说明下标运算的本质是指针加法。

### 7.4 `std::begin` / `std::end` 与范围 `for`

C++11 起提供了 `std::begin` / `std::end`，让数组也能用统一的"首 + 尾后"表示：

<!-- example:ch06_begin_end -->
```cpp
#include <iostream>
#include <iterator>
#include <vector>

int main() {
    int a[3] = {1, 2, 3};
    int sum = 0;
    for (int* p = std::begin(a); p != std::end(a); ++p) { sum += *p; }
    std::cout << sum << '\n';

    std::vector<int> v{4, 5, 6};
    for (int& x : v) { x *= 2; }
    for (int x : v) { std::cout << x << '\n'; }
}
```

<!-- result:ch06_begin_end -->
```text
6
8
10
12
```

**范围 `for` 的两种写法，差别全在 `&`**：

| 写法 | 每次迭代的 `x` 是什么 | 改了 `x` 会怎样 |
|---|---|---|
| `for (int x : v)` | 元素的**副本** | 改的是副本，容器不变 |
| `for (int& x : v)` | 元素的**引用** | 改的就是容器里的元素 |
| `for (const int& x : v)` | 元素的 const 引用 | 不拷贝，也不能改 |

**范围 `for` 展开后大约是这样**（伪代码，不是真实语法）：

```text
auto __begin = begin(v), __end = end(v);
for (; __begin != __end; ++__begin) {
    int& x = *__begin;      // 这里的 & 决定了 x 是副本还是引用
    ...循环体...
}
```

> ⚠️ **坑**：在范围 `for` 里**增删 `vector` 元素**。这会让 `__end` 记录的尾后指针失效，
> 循环要么读到已释放的存储，要么直接崩。**这类错误的归属是迭代器失效**，
> 详细规则在第 10 章「容器与算法」。

## 8. 栈与堆：对象存在哪里、活多久

前几节讲的都是"怎么指向一个对象"。这一节讲**被指向的那个对象本身在哪里、什么时候死**。

### 8.1 两种存储

| | 栈（stack） | 堆（heap / free store） |
|---|---|---|
| 谁分配 | 编译器自动（进入作用域就分配） | 你写 `new` 才分配 |
| 谁释放 | 编译器自动（离开作用域就释放） | 你写 `delete` 才释放 |
| 生存期由什么决定 | **作用域** | **你** |
| 大小限制 | 小（本机默认 1 MB 量级） | 大（受可用内存限制） |
| 分配速度 | 极快（只是移动栈指针） | 慢（要在空闲链表里找） |
| 地址形态 | 连续、可预测 | 分散、每次可能不同 |
| 典型用途 | 局部变量、小对象 | 大小运行期才定、或要活过作用域的对象 |

**本机实测一次地址**（这个例子的输出**不进自动基线**，因为地址每次运行都不同）：

```cpp
#include <iostream>

int main() {
    int local = 1;
    int* heap = new int(2);
    std::cout << &local << ' ' << heap << '\n';
    delete heap;
}
```

某一次运行的真实输出：

```text
000000E1E73DFBE0 0000020DAB3C4FF0
```

**为什么这段不能加 `<!-- result: -->` 标记**：地址由操作系统在运行时决定，两次运行就不一样。
按本讲义的规矩，**输出含不确定内容的示例不进自动基线**，只把真实结果贴出来并说明原因。
（对比：前面那些示例的输出是"确定的"，才能逐字比对。）

### 8.2 生存期：什么时候对象就死了

**对象的生存期（lifetime）** 从它被初始化完成开始，到它被销毁为止。这一段结束之后，
**那块存储里就不再是那个对象了**——哪怕字节看起来没变。

栈对象的死亡时刻是**确定的**，规则只有一条：**离开它所在的那个块**。

<!-- example:ch06_lifetime_tracer -->
```cpp
#include <iostream>

struct Tracer {
    const char* name;
    explicit Tracer(const char* n) : name(n) { std::cout << "构造 " << name << '\n'; }
    ~Tracer() { std::cout << "析构 " << name << '\n'; }
};

int main() {
    Tracer outer("outer");
    {
        Tracer inner("inner");
    }
    std::cout << "块已结束\n";
}
```

<!-- result:ch06_lifetime_tracer -->
```text
构造 outer
构造 inner
析构 inner
块已结束
析构 outer
```

> **这里借用了一个带构造函数和析构函数的 `struct`**（第 07 章才正式讲类）。
> 借它的原因很实际：**"对象什么时候死"这件事，只有让对象在死的时候说一句话，你才看得见。**
> 现在只需要读懂"构造"和"析构"两行打印。

**执行轨迹**：

```text
1. 进入 main 的块 → 分配 outer  → 打印"构造 outer"
2. 进入内层块    → 分配 inner  → 打印"构造 inner"
3. 离开内层块    → 销毁 inner  → 打印"析构 inner"   ← inner 的生存期到此结束
4. 执行 cout     → 打印"块已结束"
5. 离开 main     → 销毁 outer  → 打印"析构 outer"
```

**三条规律**（后面第 07 章「RAII」全靠它们）：

1. **销毁顺序与构造顺序相反**——后建的先死。
2. **块的结束就是死亡时刻**，不需要你写任何"释放"语句。
3. **在对象死后继续用它的名字或地址，就是未定义行为**（第 10 节的"悬垂"）。

### 8.3 堆对象的死亡时刻由你决定

堆对象**不在任何作用域里**——它由 `new` 创建，只有 `delete` 能结束它的生存期：

<!-- example:ch06_new_delete -->
```cpp
#include <iostream>

struct Tracer {
    const char* name;
    explicit Tracer(const char* n) : name(n) { std::cout << "构造 " << name << '\n'; }
    ~Tracer() { std::cout << "析构 " << name << '\n'; }
};

int main() {
    Tracer* a = new Tracer("A");
    Tracer* b = new Tracer("B");
    delete a;
    std::cout << "准备结束\n";
    delete b;
}
```

<!-- result:ch06_new_delete -->
```text
构造 A
构造 B
析构 A
准备结束
析构 B
```

**注意两个析构的位置**：`A` 在 `delete a;` 那一行就死了（第 3 行），
`B` 一直活到 `delete b;`（第 5 行）。**它们和任何作用域都没关系**——
`main` 结束前 `delete b;` 已经把 B 处理掉了。

> **这就是"生存期由你决定"的两面**：你可以让对象活得比创建它的函数还久（栈做不到），
> 但**忘记 `delete` 就永远不会有人替你做**（下节 9.2 给可复现的例子）。

## 9. `new` 与 `delete`：手动申请与归还

### 9.1 语法与配对规则

| 表达式 | 做什么 | 对应释放 |
|---|---|---|
| `new T` | 申请一块 `sizeof(T)` 的存储，默认初始化，返回 `T*` | `delete p;` |
| `new T(初值)` | 同上，并初始化 | `delete p;` |
| `new T[n]` | 申请 n 个连续 `T`，返回指向首元素的 `T*` | **`delete[] p;`** |
| `new T[n]{...}` | 同上，并逐个初始化 | `delete[] p;` |

**配对规则（硬规则）**：`new` 配 `delete`，`new[]` 配 `delete[]`。**不能交叉。**

<!-- example:ch06_new_array -->
```cpp
#include <iostream>

int main() {
    int* a = new int[3]{1, 2, 3};
    std::cout << a[0] << a[1] << a[2] << '\n';
    delete[] a;
    std::cout << "已释放\n";
}
```

<!-- result:ch06_new_array -->
```text
123
已释放
```

> ⚠️ **坑**：`new[]` 之后写 `delete`（少了 `[]`）。这是**未定义行为**，
> 但本机 MSVC 实测**编译成功、警告 0 条**，运行时也不一定马上出错——
> 因为 `int` 没有析构函数，编译器"看不出来"。一旦元素类型有析构函数，问题就会暴露。
> **这类错误的归属是未定义行为**，不是语法错。

### 9.2 忘记 `delete`：析构函数根本不会被调用

这是"内存泄漏"最直观的样子——**不是"内存少了"，而是"该执行的清理没执行"**：

<!-- example:ch06_new_no_delete -->
```cpp
#include <iostream>

struct Tracer {
    const char* name;
    explicit Tracer(const char* n) : name(n) { std::cout << "构造 " << name << '\n'; }
    ~Tracer() { std::cout << "析构 " << name << '\n'; }
};

int main() {
    Tracer* a = new Tracer("A");
    (void)a;
    std::cout << "程序结束\n";
}
```

<!-- result:ch06_new_no_delete -->
```text
构造 A
程序结束
```

**只有"构造 A"，没有"析构 A"**——因为 `main` 只销毁了指针变量 `a`（8 字节），
没有销毁 `a` 指向的那个对象。程序正常退出，退出码 0，**没有任何报错**。

**"泄漏"泄漏的是什么**：

- 对象占的那块存储没被归还给分配器（一直占着，直到进程结束）
- **更重要的**：那个对象的析构函数没运行。如果它持有文件句柄、锁、网络连接，
  这些资源也不会被释放——这才是真正难查的后果

> **短期跑的程序泄漏了看不出来**，因为进程一退出操作系统会把整块内存回收。
> 泄漏在**长期运行的程序**（服务器、编辑器、游戏）里才会变成问题。

### 9.3 找泄漏的工具：本机实测的一条路

本机**没有安装任何调试器**（`cdb` / `gdb` / `lldb` / `windbg` 实测均不存在），
但这不代表不能查泄漏。MSVC 的**调试堆**可以在程序结束时打印还活着的分配：

```cpp
#include <iostream>
#include <crtdbg.h>

int main() {
    _CrtSetReportMode(_CRT_WARN, _CRTDBG_MODE_FILE);
    _CrtSetReportFile(_CRT_WARN, _CRTDBG_FILE_STDOUT);
    int* p = new int(5);
    std::cout << *p << '\n';
    _CrtDumpMemoryLeaks();
}
```

用 `/MDd` 编译（`/MDd` 才会链接调试版运行库）后运行，真实输出：

```text
Detected memory leaks!
Dumping objects ->
{145} normal block at 0x0000021433DF7EB0, 4 bytes long.
 Data: <    > 05 00 00 00 
Object dump complete.
5
```

**这段输出里 `0x0000021433DF7EB0` 是运行期地址，所以整段不进自动基线**（同上，落在 9.1 节说的那类）。

不写前两行 `_CrtSetReportMode` / `_CrtSetReportFile` 会怎样？**本机实测只有 `5` 一行**——
报告默认送给调试器，而本机没有调试器，于是它哪儿都没去。这是"工具已经在库里但用不上"的典型。

> **本机实测的两点**：
> 1. `_CrtDumpMemoryLeaks()` 默认不往 stdout 写（无调试器时报告丢失）
> 2. 把报告重定向到 `_CRTDBG_FILE_STDOUT` 后，能在 stdout 看到泄漏块的数量和大小
>
> **`__FILE__` / 行号信息需要额外定义 `_CRTDBG_MAP_ALLOC`**——这一点本轮没实测。

## 10. 常见指针错误分类：悬垂、泄漏、重复释放、越界

这一节把前面散落的坑集中成一张分类表，并给每一个都配上**本机实跑的真实结果**。
先看总表，再逐条展开。

### 10.1 分类总表

| 错误 | 程序实际发生什么 | 编译器会拦吗 | 错误类别 |
|---|---|---|---|
| **悬垂**（用已销毁对象） | 有时"看起来是对的"，有时崩溃 | 少数情形给 `C4172` 警告 | **未定义行为** |
| **泄漏**（忘记释放） | 程序照常跑完，退出码 0 | ❌ 不拦 | 资源管理错误（**不是 UB**） |
| **重复释放** | 堆结构被破坏，进程被杀 | ❌ 不拦 | **未定义行为** |
| **越界** | 读到相邻存储 / 写坏别人的数据 | ❌ 一般情况不拦 | **未定义行为** |
| **空指针解引用** | 立即以 `0xC0000005` 终止 | ❌ 不拦 | **未定义行为** |
| **未初始化指针** | 写进一个随机地址 | ✅ `C4700` 警告 | **未定义行为** |

**这张表最该记的是最后两列**：编译器基本不拦，而"不是 UB"的只有泄漏一种。
**泄漏的可怕之处在于它安静；UB 的可怕之处在于它不知道什么时候发作。**

### 10.2 悬垂：指向已经死掉的对象的指针

**三种来源**：① 返回局部变量的地址；② `delete` 之后继续用；③ 容器扩容后旧迭代器/指针失效。

第一种，编译器**会给警告**（本机实测，但只是警告）：

```cpp
int* make() {
    int local = 42;
    return &local;
}

int main() {
    int* p = make();
    (void)p;
}
```
```text
main.cpp(3) : warning C4172: 返回局部变量的地址或临时 : local
```

加上"真的去读它"之后，警告还在，程序也照样编出来了：

```cpp
#include <iostream>

int* make() {
    int local = 42;
    return &local;
}

int main() {
    int* p = make();
    std::cout << *p << '\n';
}
```

**本机实跑的真实结果**：

```text
42
```

**它打印出了 42——而这正是最危险的地方。** `local` 所在的那块栈存储刚被 `make` 归还，
还没有被别的函数覆盖，所以里面仍然是 42。只要中间插入一个别的函数调用，那块存储就会被改写，
打印出来的东西就完全不同了。

> ⚠️ **坑**：看到"输出是对的"就认为代码没问题。
> **程序实际怎么解释它**：`local` 的生存期在 `make` 返回时就结束了，
> `p` 指向的是一块**不再有对象**的存储。读它属于**未定义行为**。
> **UB 不是"结果随机"，而是"程序已经失去任何保证"**——包括"这次恰好对了"这种保证。
> 优化器有权假设 UB 不会发生，于是可能把这段代码整个删掉，或者让后面的判断直接按错误的前提走。

### 10.3 泄漏：程序跑完了，但少做了该做的事

见 9.2 节那个 `ch06_new_no_delete` 例子。要点重述：

- **表现**：没有任何报错，退出码 0，输出少了几行"析构"
- **不是 UB**：程序的行为完全确定，只是资源没还
- **检测**：见 9.3 节的调试堆方法；`vector` / `string` / 智能指针不会泄漏（它们的析构函数负责释放）

### 10.4 重复释放：`delete` 两次

<!-- example:ch06_double_delete -->
```cpp
#include <iostream>

int main() {
    int* p = new int(5);
    std::cout << *p << '\n';
    delete p;
    delete p;
    std::cout << "还活着\n";
}
```

**编译成功，警告 0 条**（本机实测）。真实运行结果：

```text
（stdout 为空；进程以 0xC0000374 = 3221226356 终止）
```

`0xC0000374` 是 Windows 的 **STATUS_HEAP_CORRUPTION**：分配器发现自己的结构被人破坏了，
主动把进程杀掉。**注意连第一行的 `5` 都没打印出来**——stdout 的内容还在缓冲区里没来得及写出，
进程就没了（第 08 章会讲缓冲区与异常终止的关系）。

**为什么编译器不拦**：`p` 是不是已经被 `delete` 过，属于运行期信息。
编译器无法（在一般情况下也不该）证明这件事。**能证明的少数情形（比如同一条直线上的两次 `delete`）
也只是"优化器恰好发现"，不是语言给你的保证。**

### 10.5 越界：合法下标与"程序居然没崩"

<!-- example:ch06_out_of_bounds -->
```cpp
#include <iostream>

int main() {
    int a[3] = {1, 2, 3};
    std::cout << a[0] + a[1] + a[2] << '\n';
    std::cout << a[3] << '\n';
}
```

**编译成功，警告 0 条**。真实运行结果：

```text
6
32759
```

`a[3]` 是**未定义行为**：它已经越过了数组末尾，读的是相邻栈上的其他字节。
这次读到的是 `32759`（某个残留值），**换一次编译、换一次运行都可能不一样，也可能直接崩**。

| 现象 | 说明 |
|---|---|
| 下标合法范围 | `0` 到 `size - 1`。`a[3]` 越界，不是"读到 0" |
| 为什么是 UB | 语言只保证数组内那 3 个元素是 `a` 的对象；越界访问碰的是别的对象 |
| 为什么没报错 | 运行时没有边界检查（`.at()` 有，`[]` 没有） |
| 后果可以多严重 | 读→拿到垃圾值；**写→破坏相邻变量**，这才是真会出事的 |

> **"读到垃圾值"只是越界的轻症。** 越界**写**会改掉相邻的局部变量、返回地址，或者堆的管理信息，
> 通常表现为"程序在后面某个完全无关的地方崩了"。
> **排查这类问题的第一条经验**：崩溃点往往不是出错点，要从"最近一次不合法的写"去找。

### 10.6 未初始化指针：本机会给警告

```cpp
int main() {
    int* p;
    *p = 1;
}
```
```text
main.cpp(3) : warning C4700: 使用了未初始化的局部变量“p”
```

**这条警告值得当错误看**：`p` 里是垃圾值，`*p = 1` 会往一个随机地址写。
本机给出的 `C4700` 是**编译期能发现的少数情况之一**——一旦中间隔了函数调用或分支，
编译器就发现不了，警告也会消失。

### 10.7 一张"怎么办"的清单

| 遇到什么 | 先做什么 |
|---|---|
| 用了 `new` | 立刻想"谁负责 `delete`"，写在同一屏内 |
| 需要"可空" | 用 `nullptr` 初始化，解引用前判空 |
| 需要"一串会变长的对象" | 用 `std::vector`，不要手写 `new[]` |
| 需要"多个地方共享一个对象" | 用 `std::shared_ptr`（第 12 章） |
| 函数要返回"新对象" | 直接按值返回（第 07 章会看到拷贝会被省略） |
| **绝对不要**返回局部变量的引用/指针 | 改成按值返回 |
| 怀疑泄漏 | 用 9.3 节的调试堆；或把资源换成会自己释放的类型 |

**一条贯穿全书的建议**：**手写 `new`/`delete` 应该是例外而非常态。**
标准库的容器和（第 12 章的）智能指针已经把这套责任封好了。

## 11. 右值引用与 `std::move` 的位置

这一节只做一件事：**让你在看到 `T&&` 和 `std::move` 时不至于把它当成"某种指针"。**
完整内容在第 12 章「移动语义与资源管理」，现在不展开。

### 11.1 三种引用的写法

| 写法 | 名字 | 能绑定到什么 |
|---|---|---|
| `int& r` | 左值引用 | 可绑定的 `int` 左值，包括 `*p` 这样的表达式 |
| `const int& r` | const 左值引用 | 左值 + 临时量 |
| `int&& r` | **右值引用** | 纯右值或将亡值，包括 `std::move(x)`；**不能直接绑左值** |

<!-- example:ch06_rvalue_ref_concept -->
```cpp
#include <iostream>

int main() {
    int a = 1;
    int& lr = a;                 // 左值引用
    const int& cr = 42;          // const 左值引用也能接临时量
    int&& rr = 42;               // 右值引用：专门绑临时量
    std::cout << lr << ' ' << cr << ' ' << rr << '\n';
    rr = 7;
    std::cout << rr << '\n';
}
```

<!-- result:ch06_rvalue_ref_concept -->
```text
1 42 42
7
```

**注意最后两行**：`rr` 虽然叫"右值引用"，**它自己是一个左值**（有名字、有地址），
所以 `rr = 7` 合法。这是最反直觉的一点，第 12 章会在讲 `std::move` 时用到它。

### 11.2 现在只需要建立的三条概念

1. **右值引用是"能绑定临时量"的引用**，写作 `T&&`。它的用途是让函数区分"传进来的是临时量还是有名对象"。
2. **`std::move(x)` 本身不移动任何东西**——它只是把 `x` 这个表达式"标记成右值"，
   好让编译器选到接受 `T&&` 的那个重载。真正"搬走资源"的是那个重载里写的代码。
3. **移动语义的全部意义是"偷走临时量的内部资源，而不是深拷贝一份"**。
   它为什么安全、什么时候不能用、移后对象是什么状态，全部留到第 12 章。

> **本节刻意只到"位置"为止。** 覆盖表对 5.9 的要求就是"概念"。

## 13. 本章自测

**1.** 下面三行 `std::cout` 分别打印什么？为什么第三行打印的不是 3？

```cpp
int a = 1, b = 2;
int& r = a;
r = b;
std::cout << a << b << r;
```

<details><summary>答案</summary>

打印 `2 2 2`（若中间有空格就是 `2 2 2`）。

**关键**：`r = b;` 不是"让 `r` 改指 `b`"。引用不是对象、不能改绑，
所以这句话被解释成"给 `r` 所引用的那个对象赋值"，也就是 `a = b`。
`a` 变成 2，`b` 没动，`r` 仍然指的是 `a`，所以三处都是 2。

要让"改指"成立，必须用指针：`int* p = &a; p = &b;`。

</details>

**2.** 下面四种声明，哪个是顶层 const，哪个是底层 const？各自禁止了什么操作？

```cpp
int* p1;
const int* p2;
int* const p3;
const int* const p4;
```

<details><summary>答案</summary>

| 声明 | 顶层 const | 底层 const | 禁止 |
|---|---|---|---|
| `int* p1` | 否 | 否 | — |
| `const int* p2` | 否 | ✅ | `*p2 = 1`（不能改对象）；但 `p2 = &x` 可以 |
| `int* const p3` | ✅ | 否 | `p3 = &x`（不能改指）；但 `*p3 = 1` 可以 |
| `const int* const p4` | ✅ | ✅ | 两样都不行 |

**读法**：从右往左，`const` 贴在谁前面就管谁。
本机实测两种非法写法的错误码**都是 `C3892`**，区别在诊断里打印的类型：
`'const int *'` 对应底层、`'int *const '` 对应顶层。

</details>

**3.** 这个程序能编译吗？运行结果确定吗？它属于哪一类错误？

```cpp
int* make() {
    int local = 42;
    return &local;
}
int main() {
    int* p = make();
    std::cout << *p << '\n';
}
```

<details><summary>答案</summary>

**能编译**（本机实测只会给一条 `warning C4172: 返回局部变量的地址或临时`），
**运行结果不确定**——这是**未定义行为**，属于"悬垂指针"。

**本机实跑的真实结果恰好是 `42`**，因为那块栈存储刚被归还、还没被别人覆盖。
**这正是最危险的地方**：它"看起来是对的"，但只要中间插入一个函数调用，输出就会变。

**关键认识**：UB 不是"结果随机"，而是"程序已经失去任何保证"。
"这次恰好对了"不是保证的一部分。

**修法**：改成按值返回 `int`，或者用 `new`/智能指针返回堆对象。

</details>

**4.** `sizeof` 在这四行里分别得到什么？（本机 64 位）

```cpp
int a[5] = {1,2,3,4,5};
void f(int a[]) { ... }
int& r = a[0];
int* p = a;
```

<details><summary>答案</summary>

| 表达式 | 本机结果 | 原因 |
|---|---|---|
| `sizeof(a)` | **20** | 在数组自己的作用域里，没退化 |
| `sizeof` 函数参数 `a`（`int a[]`） | **8** | 参数里的 `[]` 等价于 `*`，已经退化成指针 |
| `sizeof(r)` | **4** | 引用不是对象，`sizeof` 换成被引用的 `int` 去算 |
| `sizeof(p)` | **8** | 指针自己是对象，占 8 字节 |

**`sizeof(a)/sizeof(a[0]) == 5` 只能写在数组还没退化的地方**——
一旦传进函数，元素个数信息就丢了，必须额外传长度。

</details>

**5.** 下面这段代码为什么**不是**内存泄漏，但它依然是错的？

```cpp
int* p = new int(5);
delete p;
std::cout << *p << '\n';
```

<details><summary>答案</summary>

**不是泄漏**——内存已经用 `delete` 归还了。

**错在"悬垂"**：`delete p` 之后，`p` 指向的那块存储已经不再是 `p` 的对象，
再读它是**未定义行为**。

**本机实测**：`delete p; delete p;`（重复释放）会以 `0xC0000374`
（`STATUS_HEAP_CORRUPTION`）终止进程。读已经释放的存储同样是 UB，只是分配器不一定立刻发现。

**规范做法**：`delete p;` 之后把 `p = nullptr;`，让"这个指针还能不能用"变成可检查的。

</details>

**6.** 为什么 `void f(int& x)` 不能接 `f(5)`，而 `void f(const int& x)` 可以？

<details><summary>答案</summary>

因为**临时量不能被非 const 引用绑定**。

`5` 是字面量，它没有名字、没有稳定存储。如果允许非 const 引用绑上去，
函数体里的 `x = 1` 就会去改一个"本来不该存在的东西"，而且调用方完全看不到这个改动。
语言直接在类型系统里堵住了这个洞。

`const int&` 则允许绑定临时量（临时对象的生存期会延长到该引用的生存期结束）。
这就是 **`const T&` 成为最常用参数写法**的原因：不拷贝、能接一切。

**本机实测的真实诊断**：
`error C2664: “void take(int &)”: 无法将参数 1 从“int”转换为“int &”`

</details>

**7.** 下面这段代码的输出是什么？为什么？

```cpp
std::vector<int> v{1, 2, 3};
for (int x : v) { x *= 2; }
for (int x : v) { std::cout << x << ' '; }
```

<details><summary>答案</summary>

输出 `1 2 3 `（**没有变化**）。

因为 `for (int x : v)` 里的 `x` 是**元素的副本**。
范围 `for` 展开后等价于 `int x = *it;`，改 `x` 不影响容器。

要真的改容器，写成 `for (int& x : v)`（引用）；
只读且不想拷贝，写成 `for (const int& x : v)`。

**本机验证**：`ch06_begin_end` 里用 `for (int& x : v) { x *= 2; }` 得到 `8 10 12`。

</details>

**8.** 本机 `sizeof(std::vector<int>)` 是 24，而 `sizeof(int*)` 是 8。这说明什么？这个数字可以跨平台依赖吗？

<details><summary>答案</summary>

**24 = 3 × 8**，说明本机实现（MSVC 的 STL）用**三个指针**表示一个 `vector`：
数据首地址、末元素的后一位置、已分配容量的末尾。

**不能跨平台依赖这个数字。** 标准只要求 `std::vector` 能动态增长，
**没有规定它内部用几个指针**。它可以是 24，也可以是 16 或 32。
这类"实现的产物"要用 `sizeof` 现场量，不能照抄别人的数字。

对比：`sizeof(std::array<int,4>)` 是 **16**，这个是**能推导的**——
`array` 保证就是 `int[4]` 加一层薄封装，没有额外开销（标准对聚合布局有要求）。

**这一题的更大意义**：它是本章"平台差异"最直接的例子之一，
与第 02 章 `sizeof(long double)` 在 MSVC 上是 8 是同一类问题。

</details>

**9.** `char* s = "abc";` 这行在本机 MSVC 默认设置下**编译成功、0 条警告**。这说明它是合法 C++ 吗？怎么验证它不是？

<details><summary>答案</summary>

**不是合法 C++。** 字符串字面量的类型是 `const char[4]`，
不允许隐式转换成 `char*`（这是 C++11 起移除的 C 时代遗留转换）。

**本机 MSVC 默认允许它**，是因为默认开了非标准扩展。
加上 `/Zc:strictStrings` 之后，同一段代码给出真实诊断：

```text
main.cpp(2): error C2440: “初始化”: 无法从“const char [4]”转换为“char *”
```

**这一类东西在讲义里叫"实现定义的行为"**：标准说不合法，某个实现出于兼容性放行。
**看到"我这台机器能编过"就认为"这是标准 C++"，是一个真实的误判来源**——
判题机（多用 GCC）常常会直接拒绝。

**正确写法**：`const char* s = "abc";`，或者干脆用 `std::string`。

</details>

**10.** 本机没有装任何调试器，怎么查出"程序结束时还有哪些内存没释放"？

<details><summary>答案</summary>

用 MSVC 的**调试堆**（需要 `/MDd` 编译，链接调试版运行库）：

```cpp
_CrtSetReportMode(_CRT_WARN, _CRTDBG_MODE_FILE);
_CrtSetReportFile(_CRT_WARN, _CRTDBG_FILE_STDOUT);
// ...业务代码...
_CrtDumpMemoryLeaks();
```

**本机实测的真实输出**：

```text
Detected memory leaks!
Dumping objects ->
{145} normal block at 0x0000021433DF7EB0, 4 bytes long.
 Data: <    > 05 00 00 00 
Object dump complete.
```

**注意两点**：

1. **不加前两行会什么都看不到**（本机实测只打印了业务输出那一行）。
   原因：泄漏报告默认送给调试器，而本机没有调试器。
2. **输出里有运行期地址**，所以这段不能进自动基线——按本讲义的规矩，
   输出不确定的示例只贴真实结果、不逐字比对。

**更根本的建议**：把裸 `new`/`delete` 换成会自己释放的类型（容器、智能指针），
从源头上不产生这类问题。

</details>
