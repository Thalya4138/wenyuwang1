## 一、先说一个反直觉的结论

你担心整理得不全，所以容易想"找一个权威教程照着抄一遍就全了"。

**但没有任何单一教程是全的。** 这不是猜测——同仓库的 Python 笔记做过一次实测：
抓下 runoob 的 32 章目录逐条比对，发现它**缺**类型提示、`asyncio`、`venv`、生成器、装饰器、
`match/case`、测试、推导式、包管理，还**讲**了已在 Python 3.13 被移除的 `cgi`。
"照着一个源写 = 完整"这个前提，在 Python 身上已经被证伪了。

C++ 这边的情况更严重，因为有**三份东西**同时叫"C++ 教程"，而它们覆盖的深度差一个数量级：

| 层 | 代表 | 覆盖深度 | 典型缺口 |
|---|---|---|---|
| 通俗教程型 | cplusplus.com、菜鸟教程、各类视频课 | 语法能写，程序能跑 | 值类别、移动语义、RAII、UB、ODR、`const` 正确性几乎整段缺失 |
| 参考手册型 | cppreference | 逐条精确，可当事实来源 | **不成体系**：它按语言构造和头文件组织，不按"人怎么学会"组织 |
| 标准文本 | ISO C++ 工作草案 | 唯一权威 | 不是教学材料，读它学不会编程 |

所以这份讲义的策略是：

> **用 cppreference / 工作草案保证"事实没错、覆盖不漏"，
> 用本文件的分类轴保证"结构能学"，
> 用 MSVC 实跑保证"贴出来的输出是真的"。**

三者分工不能互相替代。详见 [`01a_三源交叉核对.md`](01a_三源交叉核对.md)。

## 二、「完整」怎么定义（三层）

| 层 | 内容 | 能不能做到完整 |
|---|---|---|
| **核心语言** | 语言本身：类型、表达式、控制流、函数、类、模板、资源管理、异常 | ✅ **可以做到 100%**，逐条展开 |
| **标准库** | 数百个组件（头文件为单位） | ✅ 做到**索引级完整**：全部列出 + 一句话 + 官方链接；**常用的讲透** |
| **生态 / 进阶** | GUI、网络、图形、游戏、构建系统、第三方库、C++20/23 新特性 | ❌ **不可能完整**。明确划界比假装覆盖更诚实 |

**你要拿到的是「一张完整的地图」，不是「一片完整的土地」。**
地图的好处是：哪块没画，你一眼看得出来。
