## 0. 怎么用这份索引

**不要从头读。** 正确用法是三种：

| 你的处境 | 怎么用 |
|---|---|
| "我想做 X，标准库有没有现成的？" | 按主题跳到对应分类（比如"排序"→第 10 节算法） |
| "我看到了 `#include <chrono>`，它是干什么的？" | 用编辑器的搜索（Ctrl+F）找头文件名 |
| "我知道有个东西叫 `optional`，在哪个头？" | 同上，搜组件名 |

**每条索引的格式**：

```text
`<header>` —— 一句话用途（关键版本）
```

- **头文件是标准库的组织单位**（不像 Python 按模块分），所以本索引**以头文件为骨架**
- 括号里标 **C++ 版本**表示"这个头/组件从哪个标准开始有"。**本讲义基线是 C++17**，
  所以标 `C++20` / `C++23` 的**本讲义不展开**，只标位置
- 链接统一指向 cppreference（它是**参考手册**，不是教程；用它查事实，不用它学入门）

> **为什么这一章不展开讲用法**：因为标准库有几百个组件，
> 全部展开等于再写十本书。而且**展开讲没有意义**——它们的用法都很浅（看文档就会），
> 真正的难点是"**遇到问题时知不知道有这个东西**"。索引解决的正是后者。

## 1. 收哪些、不收哪些（边界）

| 层 | 做法 |
|---|---|
| **常用组件**（约 40 个） | 在正文 09 / 10 / 11 章**讲透**，本索引只给链接 |
| **全部标准头文件** | ✅ **本索引全部列出** + 一句话 + 链接（索引级完整） |
| **第三方库**（Boost / fmt / spdlog / gtest…） | ❌ 不收。它们在"标准库缺什么"的位置被点过名 |
| **C++20/23 新增头** | ⚠️ **列出并标注版本**，但说明本讲义不含其用法 |

**"索引级完整"的含义**：你问"标准库有没有做 X 的东西"，
**在这份索引里一定能找到落点**（哪怕结论是"没有，要第三方库"）。

## 8. 容器

| 头文件 | 用途 | 复杂度直觉 |
|---|---|---|
| [`<vector>`](https://en.cppreference.com/w/cpp/header/vector) | **动态数组——默认就该先选它** | 随机访问 O(1)，尾部增删均摊 O(1)，中间插删 O(n) |
| [`<array>`](https://en.cppreference.com/w/cpp/header/array) | **定长数组**（大小编译期确定，不退化） | 与 `vector` 同，但无堆分配 |
| [`<deque>`](https://en.cppreference.com/w/cpp/header/deque) | 双端队列，两端插删都是 O(1) | 随机访问 O(1)，中间插删 O(n) |
| [`<list>`](https://en.cppreference.com/w/cpp/header/list) | 双向链表 | 任意位置插删 O(1)，但**遍历慢、缓存不友好** |
| [`<forward_list>`](https://en.cppreference.com/w/cpp/header/forward_list) | 单向链表 | 同上，更省空间 |
| [`<map>`](https://en.cppreference.com/w/cpp/header/map) | **有序**键值映射（红黑树） | 查找/插入 O(log n)，**有序遍历** |
| [`<set>`](https://en.cppreference.com/w/cpp/header/set) | **有序**唯一集合 | 同上 |
| [`<unordered_map>`](https://en.cppreference.com/w/cpp/header/unordered_map) | **哈希**键值映射 | 平均 O(1)，最坏 O(n)，**无序** |
| [`<unordered_set>`](https://en.cppreference.com/w/cpp/header/unordered_set) | **哈希**集合 | 同上 |
| [`<multimap>`](https://en.cppreference.com/w/cpp/header/map) / [`<multiset>`](https://en.cppreference.com/w/cpp/header/set) | 允许重复键的版本 | 同 `map` / `set` |
| [`<stack>`](https://en.cppreference.com/w/cpp/header/stack) | LIFO 适配器（底层默认 `deque`） | 只看栈顶 |
| [`<queue>`](https://en.cppreference.com/w/cpp/header/queue) | FIFO 适配器 | 只看两端 |
| [`<span>`](https://en.cppreference.com/w/cpp/header/span) | 非拥有的连续视图｜**C++20** | 本讲义不含 |
| [`<mdspan>`](https://en.cppreference.com/w/cpp/header/mdspan) | 多维视图｜**C++23** | 科学计算/ML 相关 |
| [`<flat_map>`](https://en.cppreference.com/w/cpp/header/flat_map) / [`<flat_set>`](https://en.cppreference.com/w/cpp/header/flat_set) | 基于有序数组的映射/集合（缓存友好）｜**C++23** | — |
| [`<inplace_vector>`](https://en.cppreference.com/w/cpp/header/inplace_vector) | 定容动态数组｜**C++26** | — |
| [`<hive>`](https://en.cppreference.com/w/cpp/header/hive) | 蜂巢容器｜**C++26** | — |

> **选型判据（第 10 章第 8 节的结论）**：
> **先问"要不要有序遍历"** → 要就用 `map`/`set`，不要就用 `unordered_*`；
> **再问"要不要随机访问"** → 要就用 `vector`/`deque`，不要才考虑 `list`；
> **最后问"大小编译期确定吗"** → 确定就用 `array`。
>
> ⚠️ **`list` 在实践中的陷阱**：它的"任意位置插删 O(1)"听起来好，
> 但**找到那个位置本身是 O(n)**，而且链表节点分散在堆上、**缓存命中率极差**。
> **实测中 `vector` 常常比 `list` 快，即使理论复杂度更差**（常数因子与缓存的影响）。
> 这与第 13 章第 7 节"不要靠感觉优化"是同一条道理。

## 9. 迭代器

| 头文件 | 用途 |
|---|---|
| [`<iterator>`](https://en.cppreference.com/w/cpp/header/iterator) | **迭代器工具**：`begin`/`end`/`size`/`empty`/`data`（**`size`/`empty`/`data` 是 C++17**）、`advance`、`distance`、`next`、`prev`、迭代器类别标签、`std::back_inserter` |

> **迭代器失效规则**是本讲义反复强调的坑（第 10 章第 7 节）。
> 一句话判据：**任何可能改变容器大小或重排元素的操作，都可能让你手上的迭代器/引用失效。**
> `vector` 扩容时**全部**失效（要重新取）；`list`/`map`/`set` 只在被删元素处失效。

## 10. 算法

| 头文件 | 用途 |
|---|---|
| [`<algorithm>`](https://en.cppreference.com/w/cpp/header/algorithm) | **常用组件索引**（正文第 10 章第 8.2 节只展开部分示例）：`sort` / `find` / `find_if` / `count` / `count_if` / `for_each` / `transform` / `copy` / `remove_if` / `unique` / `lower_bound` / `upper_bound` / `min_element` / `max_element` / `all_of` / `any_of` / `none_of` / `clamp`（**C++17**）｜第 10 章第 8.2 节 |
| [`<numeric>`](https://en.cppreference.com/w/cpp/header/numeric) | `accumulate` / `reduce` / `inner_product` / `iota` / `partial_sum`、`gcd` / `lcm`（**C++17**） |
| [`<execution>`](https://en.cppreference.com/w/cpp/header/execution) | 执行策略｜**C++17**（见第 2 节） |

> **`std::sort` 的一个实用判断**：它要求**随机访问迭代器**，
> 所以 `list` 用不了（`list` 有自己的 `sort` 成员函数），`map` 也不用排（它一直是有序的）。
> **"哪些算法能用"取决于迭代器类别**——这是第 10 章第 1 节那条轴的实际用途。
>
> ⚠️ **`std::remove` 不会真的删除元素**（它靠"把要保留的搬到前面"再返回新末尾）。
> 真正的删除要配合 `erase`，这就是所谓 **erase-remove 惯用法**。
> 这是名字最容易误导人的一处。

| 头文件 | 用途 |

> **判据**：`string_view` 适合**函数参数**，不适合**成员变量或返回值**（除非你能保证底层数据活得更久）。

> ⚠️ **`isalpha(c)` 的坑值得背下来**：如果 `c` 是负的 `char`（比如中文字节的某个字节），
> 传进去是**未定义行为**。必须写 `std::isalpha(static_cast<unsigned char>(c))`。
> 这类错误的归属是**类型类 + UB**，而且它**平时看不出来**——只在遇到非 ASCII 输入时炸。

> int roll = dist(gen);
> ```

## 17. C 兼容头

C 标准库的头在 C++ 里有两个版本：

| 形式 | 例 | 特点 |
|---|---|---|
| `c` 前缀版 | `<cstdio>` `<cstring>` `<cstdlib>` | **把名字放进 `std` 命名空间**（**推荐**） |
| `.h` 后缀版 | `<stdio.h>` `<string.h>` | 名字在全局命名空间（**为了兼容老代码**） |

**本讲义一律用 `c` 前缀版**（这样 `std::printf` 之类必须写 `std::`，与 C++ 的习惯一致）。

**几个例外要记住**：

| 头 | 状态 |
|---|---|
| `<ciso646>` `<cstdalign>` `<cstdbool>` | **无意义**（C++ 里这些宏本来就没有） |
| `<ccomplex>` `<ctgmath>` `<complex.h>` `<tgmath.h>` | **空头**（C++ 用 `<complex>` / `<cmath>` 代替） |
| `<stdatomic.h>` `<stdbit.h>` `<stdckdint.h>` | 特殊 C 头（各有对应） |
| `<stdnoreturn.h>` `<threads.h>` | **C++ 不支持** |

> **为什么要知道这个**：因为 `#include <string.h>` 和 `#include <cstring>` 都"能用"，
> 但它们把名字放进**不同的命名空间**。混用会让你在某处写 `strlen` 能用、
> 换个文件写 `strlen` 就报"未声明"——**而原因是包含的头不一样**。
