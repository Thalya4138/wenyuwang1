## 0. 先记住的七件事

**这一章的分部**：

```text
一个类型
├─ 是什么              struct / class、成员、访问控制（第 1 节）
├─ 怎么出生            构造函数 + 成员初始化列表（第 2 节）
├─ 怎么死亡           析构函数 → RAII（第 3 节）        ← 本章核心
├─ 怎么被复制          拷贝构造 / 拷贝赋值 / 三·五法则（第 4 节）
├─ 怎么引用自己        this 与 const 成员函数（第 5 节）
├─ 属于类而非对象      static 成员；谁能看私有 → 友元（第 6 节）
├─ 怎么像内置类型一样用 运算符重载（第 7 节）
└─ 怎么被当成同一种东西  继承 → virtual → 多态（第 8、9、10 节）
                        以及两个真会出错的坑：虚析构、切片
最后：一个设计判断——组合优先于继承（第 11 节）
```

1. **`struct` 和 `class` 的唯一区别是默认访问级别**：`struct` 默认 `public`，`class` 默认 `private`。其它一模一样。
2. **构造函数负责"让对象变成合法状态"，析构函数负责"把资源还回去"。** 两者配对出现，就是 **RAII**。
3. **RAII 是 C++ 最核心的设计**：资源的生存期绑在对象的生存期上，于是**正常返回、提前返回、抛异常**三条路径都不需要你写释放代码。
4. **初始化列表不是"语法糖"**：成员初始化列表是**初始化**（调构造函数），在函数体里赋值是**赋值**（调 `operator=`）。对类类型成员，两者完全不同。
5. **成员的初始化顺序由声明顺序决定，与初始化列表里写的顺序无关。** 本机 MSVC `/W4` **不会为此报警告**（实测 0 条），所以这个坑是安静的。
6. **编译器会自动生成一批特殊成员函数，也会在某些声明下把它们删掉。** 记住"什么时候被删"比记住"什么时候生成"更重要——第 4 节给表。
7. **通过基类指针 `delete` 一个派生类对象时，基类的析构函数必须是 `virtual`。** 否则派生类的析构函数**不会被调用**，而且这是**未定义行为**。第 9 节有可复现例子。

> 如果只记一条，记第 3 条。**RAII 是这一章唯一"学完就能立刻改变你写代码方式"的东西。**

## 1. 从一堆数据到一个类型：`struct`、`class` 与访问控制

上一章我们见过这样的东西：

```cpp
struct Point {
    int x;
    int y;
};
```

这就是一个**类**（class type）。它把几个数据成员打包成一个类型，`Point p{1, 2};` 就能一次创建并初始化。

### 1.1 `struct` 与 `class` 的唯一区别

<!-- example:ch07_struct_public -->
```cpp
#include <iostream>

struct Point {
    int x;
    int y;
    int sum() const { return x + y; }
};

int main() {
    Point p{1, 2};
    std::cout << p.x << ' ' << p.y << ' ' << p.sum() << '\n';
    p.x = 10;
    std::cout << p.sum() << '\n';
}
```

<!-- result:ch07_struct_public -->
```text
1 2 3
12
```

| 写法 | 默认成员访问级别 | 默认继承方式 |
|---|---|---|
| `struct Point { ... };` | **`public`** | `public` |
| `class Point { ... };` | **`private`** | `private` |

**这就是全部区别。** `struct` 也能有成员函数、构造函数、虚函数、继承；
`class` 也能当"纯数据打包"用。选哪个是**习惯**问题，不是能力问题：

- 只有一堆公开数据、没有不变量要维护 → 常用 `struct`
- 有需要保护的内部状态 → 常用 `class`

### 1.2 访问控制：三种级别，三种"谁能看"

<!-- example:ch07_class_private_FAIL -->
```cpp compile-fail
class Point {
    int x;
};

int main() {
    Point p;
    p.x = 1;
}
```
```text
main.cpp(7): error C2248: “Point::x”: 无法访问 private 成员(在“Point”类中声明)
```

| 级别 | 本类的成员函数 | 派生类的成员函数 | 类外的代码 |
|---|---|---|---|
| `public` | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ❌ |
| `private` | ✅ | ❌ | ❌ |

`protected` 的验证：

<!-- example:ch07_protected_ok -->
```cpp
#include <iostream>

class Base {
protected:
    int secret_ = 42;
};

class Derived : public Base {
public:
    int reveal() const { return secret_; }
};

int main() {
    Derived d;
    std::cout << d.reveal() << '\n';
}
```

<!-- result:ch07_protected_ok -->
```text
42
```

而类外直接访问它是不行的：

<!-- example:ch07_protected_FAIL -->
```cpp compile-fail
class Base {
protected:
    int secret_ = 42;
};

int main() {
    Base b;
    b.secret_ = 1;
}
```
```text
main.cpp(8): error C2248: “Base::secret_”: 无法访问 protected 成员(在“Base”类中声明)
```

**注意两处诊断的错误码都是 `C2248`**，只是文字里写了 `private` 还是 `protected`。
读诊断时**要看"无法访问 X 成员"这几个字**，不要只记错误码。

> ⚠️ **坑**：以为 `private` 是"安全"机制。**它不是。**
> `private` 只是**编译期的访问检查**——它防止"写错代码"，不防止"读内存"。
> 用指针算术、`reinterpret_cast` 或直接偏移量依然能碰到私有成员（那是未定义行为）。
> **`private` 的价值是"表达设计意图"和"让编译器帮你守住它"，不是加密。**

### 1.3 关键符号：这一章引入的记号

| 符号 | 出现在哪 | 含义 |
|---|---|---|
| `::` | `Counter::total` | **作用域解析**：指明 `total` 属于 `Counter` 这个类（而不是某个对象） |
| `::` | `std::cout` | 同样，指明 `cout` 属于命名空间 `std`（第 02 章讲过的第一种用法） |
| `:` | `Counter() : n_(0) {}` | 构造函数**初始化列表**的开始 |
| `,` | `: a_(1), b_(2)` | 初始化列表里分隔各个成员 |
| `~` | `~Counter()` | 析构函数名字的前缀 |
| `virtual` | `virtual void f();` | 声明这个成员函数参与动态绑定 |
| `override` | `void f() override;` | 我确实在重写基类的虚函数，写错就报错 |
| `final` | `class A final {};` | 到此为止，不许再被继承/重写 |
| `= 0` | `virtual void f() = 0;` | 纯虚函数，这个类是抽象的 |
| `= default` | `Counter() = default;` | 让编译器生成这一版 |
| `= delete` | `Counter(const Counter&) = delete;` | 明确禁止调用这个函数 |

`::` 在两种场合的读法是一样的：**"右边这个名字属于左边那个作用域"**。
区别只在左边是类名还是命名空间——编译器会自己分辨。

## 2. 构造函数与成员初始化列表

### 2.1 构造函数做什么

**构造函数的任务只有一个：把对象从"一块原始存储"变成"一个合法对象"。**
它没有返回类型（连 `void` 都不写），名字和类名相同。

<!-- example:ch07_ctor_overload -->
```cpp
#include <iostream>

class Counter {
    int n_;
public:
    Counter() : n_(0) { std::cout << "默认构造\n"; }
    explicit Counter(int n) : n_(n) { std::cout << "带参构造\n"; }
    int value() const { return n_; }
};

int main() {
    Counter a;
    Counter b(5);
    Counter c{7};
    std::cout << a.value() << ' ' << b.value() << ' ' << c.value() << '\n';
}
```

<!-- result:ch07_ctor_overload -->
```text
默认构造
带参构造
带参构造
0 5 7
```

**执行轨迹**（创建一个对象时到底发生什么）：

```text
Counter b(5);
  1. 在栈上分配 sizeof(Counter) 字节的原始存储      ← 此时还不是"对象"
  2. 按声明顺序逐个初始化成员：n_(5)               ← 成员初始化列表在这一步生效
  3. 执行构造函数的函数体 { std::cout << ...; }     ← 打印"带参构造"
  4. 到这里，对象构造完成，它的生存期开始
  （如果第 2 步或第 3 步抛出异常，对象不会被创建，已构造好的成员会被回滚——见第 08 章）
```

**顺序很重要**：存储分配 → 成员初始化 → 函数体。函数体是最后一站，
所以**"在函数体里还没执行之前"对象就已经有一半是合法的了**。

**`explicit` 的作用**：禁止"从 `int` 隐式转换出 `Counter`"。

<!-- example:ch07_explicit_FAIL -->
```cpp compile-fail
class Counter {
    int n_;
public:
    explicit Counter(int n) : n_(n) {}
};

int main() {
    Counter c = 5;
    (void)c;
}
```
```text
main.cpp(8): error C2440: “初始化”: 无法从“int”转换为“Counter”
```

去掉 `explicit` 之后 `Counter c = 5;` 就合法了——但那意味着
**任何接受 `Counter` 的函数都能被一个整数意外调用**。单参数构造函数建议默认加 `explicit`。

### 2.2 初始化列表 vs 在函数体里赋值

这是本节最该记的一条。两种写法在基本类型上没区别，在**类类型成员**上调用的是完全不同的函数。

<!-- example:ch07_init_list_vs_assign -->
```cpp
#include <iostream>

struct Part {
    const char* name;
    Part() : name("(空)") { std::cout << "默认构造 Part\n"; }
    explicit Part(const char* n) : name(n) { std::cout << "构造 " << name << '\n'; }
    Part& operator=(const Part& o) {
        name = o.name;
        std::cout << "赋值 " << name << '\n';
        return *this;
    }
};

struct A {
    Part p;
    A() : p("直接初始化") {}
};

struct B {
    Part p;
    B() { p = Part("先默认构造再赋值"); }
};

int main() {
    std::cout << "--- A ---\n";
    A a;
    std::cout << "--- B ---\n";
    B b;
    (void)a; (void)b;
}
```

<!-- result:ch07_init_list_vs_assign -->
```text
--- A ---
构造 直接初始化
--- B ---
默认构造 Part
构造 先默认构造再赋值
赋值 先默认构造再赋值
```

| 写法 | 成员 `p` 经历了什么 | 一共几次函数调用 |
|---|---|---|
| `A() : p("x") {}` | **直接构造** | **1 次**（构造函数） |
| `B() { p = Part("x"); }` | 先**默认构造**，再**赋值** | **3 次**（默认构造 + 临时对象构造 + 赋值） |

**程序实际怎么解释它**：成员**总要被初始化**——你不写初始化列表，编译器也会默认初始化它。
所以 `B` 那种写法不是"省掉了初始化"，而是"先默认初始化一次，再赋值覆盖掉"。
**对贵的类型，这是白干一遍活。**

> ⚠️ **坑（这一条比性能更重要）**：有三种成员**只能在初始化列表里给初值**，函数体里赋值根本写不出来。
>
> | 成员类型 | 为什么 |
> |---|---|
> | `const` 成员 | 常量不能被赋值 |
> | 引用成员 | 引用必须初始化，且不能改绑（第 06 章第 2 节） |
> | 没有默认构造函数的类类型成员 | 它必须先被构造，而你给不出参数 |
>
> **结论：默认就用初始化列表。** 它在任何情况下都不会更差。

### 2.3 初始化顺序：按声明顺序，不按列表顺序

<!-- example:ch07_init_list_order -->
```cpp
#include <iostream>

struct Part {
    const char* name;
    explicit Part(const char* n) : name(n) { std::cout << "构造 " << name << '\n'; }
};

struct Whole {
    Part a;
    Part b;
    Whole() : b("b"), a("a") {}
};

int main() {
    Whole w;
}
```

<!-- result:ch07_init_list_order -->
```text
构造 a
构造 b
```

初始化列表里写的是 `b` 在前，实际**先构造 `a`**——因为 `a` 在类里声明在前。

**本机实测：这个示例编译后警告 0 条。** MSVC `/W4` **不提示**这件事。

> ⚠️ **坑**：以为"初始化列表里的顺序就是初始化顺序"。
> **程序实际怎么解释它**：标准规定**按成员的声明顺序**初始化，初始化列表的书写顺序被忽略。
> **危险在哪**：若两个 `int` 成员按 `a`、`b` 的顺序声明，却写 `Whole() : b(1), a(b + 1) {}`，
> 实际仍先初始化 `a`，此时读了尚未初始化的 `b`，属于**未定义行为**。反过来，`b(a + 1), a(1)` 在这个声明顺序下会先把 `a` 初始化为 1，不是上述错误。
> **这一类错误的判别是"类型/初始化类"，不是语法错**，编译器不会拦，警告也没有。
>
> **处理习惯**：**让初始化列表的顺序和声明顺序一致。** 这样即使规则被忽略，结果也和你的预期相同。

## 3. 析构函数与 RAII

### 3.1 析构函数做什么

**析构函数的任务是"把对象持有的东西还回去"。** 名字是 `~类名`，没有参数、没有返回类型。

它**什么时候被调用**，第 06 章第 8 节已经量过了：

| 对象的存储在哪 | 析构时刻 |
|---|---|
| 栈上（局部变量） | 离开所在的作用域时 |
| 栈上（函数参数） | 函数返回时 |
| 堆上（`new` 出来的） | **`delete` 时**（不 `delete` 就永远不调用） |
| 全局 / 静态 | 程序结束时 |

**销毁顺序与构造顺序相反**——第 06 章第 8.2 节和本章第 8.4 节都有实测。

### 3.2 RAII：这一章的核心

**RAII** = Resource Acquisition Is Initialization（资源获取即初始化）。
名字不太好，实质只有两句话：

> **在构造函数里获取资源，在析构函数里释放资源。**
> 这样"资源的生存期"就自动绑在"对象的生存期"上了。

<!-- example:ch07_raii_scope -->
```cpp
#include <iostream>

class FileLike {
    const char* name_;
public:
    explicit FileLike(const char* n) : name_(n) { std::cout << "打开 " << name_ << '\n'; }
    ~FileLike() { std::cout << "关闭 " << name_ << '\n'; }
};

int main() {
    FileLike f("data.txt");
    std::cout << "使用中\n";
}
```

<!-- result:ch07_raii_scope -->
```text
打开 data.txt
使用中
关闭 data.txt
```

**没有任何一行"关闭"的调用代码**——`main` 结束，`f` 离开作用域，析构函数自动运行。
这就是 RAII 的全部机制。**它不难，难的是意识到它有多重要。**

### 3.3 为什么它重要：三条退出路径全都不用管

一个函数结束时可能有三条路：**正常走到末尾**、**中途 `return`**、**抛出异常**。
手写"释放"语句只能覆盖前两条，而且一旦有人在中途加了一个 `return` 就会漏掉。

<!-- example:ch07_raii_early_return -->
```cpp
#include <iostream>

class FileLike {
    const char* name_;
public:
    explicit FileLike(const char* n) : name_(n) { std::cout << "打开 " << name_ << '\n'; }
    ~FileLike() { std::cout << "关闭 " << name_ << '\n'; }
};

void work(bool fail_early) {
    FileLike f("data.txt");
    if (fail_early) { std::cout << "提前返回\n"; return; }
    std::cout << "正常走到末尾\n";
}

int main() {
    work(true);
    work(false);
}
```

<!-- result:ch07_raii_early_return -->
```text
打开 data.txt
提前返回
关闭 data.txt
打开 data.txt
正常走到末尾
关闭 data.txt
```

**两次调用都打印了"关闭"**，而代码里一处"关闭"都没写。

**那第三条路（抛异常）呢？** 异常栈展开到匹配处理器时，会把沿途已构造的自动局部对象逐个销毁，
这个过程叫**栈展开（stack unwinding）**。它是第 08 章「错误处理与断言」第 3 节的主题，
那里有一个和这里几乎一样的例子，只是把 `return` 换成了 `throw`。

> **这就是"异常安全"的真相**：C++ 不需要 `finally` 块，**因为析构函数就是 `finally`。**
> 前提是资源由对象持有，并且控制流确实执行析构；`std::exit` 不析构自动局部对象，`std::abort` 不执行这类清理，`std::terminate` 不保证完成栈展开（第 12 章第 7 节「RAII：为什么异常也安全」）。
> 手写的 `new`/`delete`、`malloc`/`free` 没有这个保证，异常一来就泄漏。

### 3.4 RAII 在标准库里的样子

| 资源 | 谁在管 | 构造函数 | 析构函数 |
|---|---|---|---|
| 动态数组 | `std::vector` | 分配存储 | 释放存储 |
| 字符串 | `std::string` | 分配缓冲 | 释放缓冲 |
| 文件 | `std::fstream`（第 09 章） | 打开文件 | 关闭文件 |
| 独占所有权指针 | `std::unique_ptr`（第 12 章） | 接管裸指针 | `delete` |
| 共享所有权指针 | `std::shared_ptr`（第 12 章） | 增加引用计数 | 计数归零时 `delete` |
| 互斥锁 | `std::lock_guard`（第 13 章） | 加锁 | 解锁 |

**看懂这张表的规律**：每一个"需要配对操作"的东西，标准库都给它包了一个类型。
**你自己写代码时也该这么做**——需要配对，就写一个类。

> ⚠️ **坑**：析构函数里抛出异常。默认情况下析构函数是 `noexcept` 的，
> 抛出会直接 `std::terminate`。更糟的是**在栈展开过程中抛出**——那会让"正在清理"变成"直接终止"。
> **规则：析构函数里不要抛异常。** 本机实测（第 08 章有例子）以 `0xC0000409` 终止进程。

## 4. 拷贝构造、拷贝赋值与三/五法则

### 4.1 两个不同的函数

**"用另一个同类型对象造出一个新对象"** 和 **"把一个已有对象的内容改成另一个对象的"** 是两件事：

| 写法 | 调用的函数 | 对象状态 |
|---|---|---|
| `Counter b = a;` / `Counter b(a);` | **拷贝构造函数** | `b` 是新对象，刚出生 |
| `b = a;`（`b` 已存在） | **拷贝赋值运算符** | `b` 早就存在，只是内容被改 |

<!-- example:ch07_copy_ctor_assign -->
```cpp
#include <iostream>

class Counter {
    int id_;
public:
    explicit Counter(int i) : id_(i) { std::cout << "构造 " << id_ << '\n'; }
    Counter(const Counter& o) : id_(o.id_) { std::cout << "拷贝构造 " << id_ << '\n'; }
    Counter& operator=(const Counter& o) {
        id_ = o.id_;
        std::cout << "拷贝赋值 " << id_ << '\n';
        return *this;
    }
    ~Counter() { std::cout << "析构 " << id_ << '\n'; }
};

int main() {
    Counter a(1);
    Counter b = a;
    Counter c(3);
    c = b;
    std::cout << "--- 作用域结束 ---\n";
}
```

<!-- result:ch07_copy_ctor_assign -->
```text
构造 1
拷贝构造 1
构造 3
拷贝赋值 1
--- 作用域结束 ---
析构 1
析构 1
析构 1
```

**注意最后三行的顺序**：`c`、`b`、`a` —— 与构造顺序 `a`、`b`、`c` 相反。

**为什么拷贝构造的参数是 `const Counter&`**：

| 如果写成 | 会怎样 |
|---|---|
| `Counter(Counter o)` | 传参本身要拷贝 → 又要调拷贝构造 → **无限递归** |
| `Counter(Counter& o)` | 不能拷贝 `const` 对象，也不能拷贝临时量 |
| **`Counter(const Counter& o)`** | ✅ 能接一切，且不拷贝 |

> **顺带一条**：`Counter b = a;` 里的 `=` **不是赋值**，它是**拷贝初始化**——
> 对象正在被创建，所以调的是构造函数。**判据：看这个对象是不是刚出生。**

### 4.2 C++17 起：返回值不再拷贝

<!-- example:ch07_copy_elision -->
```cpp
#include <iostream>

class Counter {
    int id_;
public:
    explicit Counter(int i) : id_(i) { std::cout << "构造 " << id_ << '\n'; }
    Counter(const Counter& o) : id_(o.id_) { std::cout << "拷贝构造 " << id_ << '\n'; }
    ~Counter() { std::cout << "析构 " << id_ << '\n'; }
};

Counter make() {
    return Counter(7);
}

int main() {
    Counter c = make();
    (void)c;
}
```

<!-- result:ch07_copy_elision -->
```text
构造 7
析构 7
```

**连一次"拷贝构造"都没有。** `Counter(7)` 直接构造在 `c` 的存储里。

| 标准 | 保证 |
|---|---|
| C++14 及以前 | 允许编译器省略这次拷贝（大多数编译器都会省），但**拷贝构造函数必须存在且可访问** |
| **C++17 起** | **保证**省略（这叫"保证的拷贝省略"）。有些代码在 C++17 下能编过、在 C++14 下编不过，就是差在这一条 |

**实践意义**：**按值返回对象不再需要担心性能。** 不要为了"避免拷贝"而写出返回指针、
或者传输出参数的函数——直接返回就好。（完整规则见第 12 章「移动语义与资源管理」。）

### 4.3 编译器自动生成的版本：逐成员拷贝

你不写拷贝构造和拷贝赋值时，编译器会生成两个：**把每个成员逐个拷贝过去**。

对 `int` 这类成员，这完全正确。对**持有裸指针的成员**，这是灾难：

<!-- example:ch07_shallow_copy -->
```cpp
#include <iostream>

class Holder {
public:
    int* p;
    explicit Holder(int v) : p(new int(v)) {}
};

int main() {
    Holder a(5);
    Holder b = a;
    std::cout << std::boolalpha << (a.p == b.p) << '\n';
    *b.p = 9;
    std::cout << *a.p << '\n';
}
```

<!-- result:ch07_shallow_copy -->
```text
true
9
```

**两行输出说明同一件事**：`b.p` 和 `a.p` **指向同一块堆内存**（`true`），
所以通过 `b` 改，`a` 也变（打印 `9`）。

这叫**浅拷贝**：编译器只复制了"地址"这个值，没有复制"地址指向的东西"。
而这个例子还没有崩，是因为它**没有写析构函数**（只泄漏，不重复释放）。

加上析构函数试试：

<!-- example:ch07_double_free -->
```cpp
#include <iostream>

class Holder {
public:
    int* p;
    explicit Holder(int v) : p(new int(v)) {}
    ~Holder() { delete p; }
};

int main() {
    Holder a(5);
    Holder b = a;
    std::cout << std::boolalpha << (a.p == b.p) << '\n';
}
```

**编译成功，警告 0 条**。真实运行结果：

```text
（stdout 为空；进程以 0xC0000374 = 3221226356 终止）
```

**程序实际发生什么**：作用域结束时先析构 `b`（`delete p` 释放了那块内存），
再析构 `a`（对同一块内存再 `delete` 一次）。

- 这是**重复释放**（第 06 章第 10.4 节），属于**未定义行为**
- 本机表现为 `0xC0000374`（`STATUS_HEAP_CORRUPTION`）：分配器发现自己的结构被破坏，主动杀掉进程
- **连那行 `true` 都没打印出来**——stdout 还在缓冲区里（第 08 章会讲）

**规律**：**只要一个类在析构函数里"释放"了什么，就必须想清楚"拷贝它意味着什么"。**

### 4.4 三法则与五法则

**三法则（Rule of Three）**：如果你需要写**析构函数**、**拷贝构造函数**、**拷贝赋值运算符**中的
任何一个，那么**三个你都需要**。

理由是一致的：这三个函数都在处理"资源的所有权"，你手写了其中一个，说明默认的逐成员语义不适合这个类，
那么另外两个也一定不适合。

**五法则（Rule of Five）**：C++11 起多了**移动构造**和**移动赋值**两个，于是变成五个。
（移动版的写法与用途是第 12 章的主题，这里只要知道它们存在。）

**补齐三个之后的正确版本**：

<!-- example:ch07_rule_of_three_fixed -->
```cpp
#include <iostream>

class Holder {
    int* p_;
public:
    explicit Holder(int v) : p_(new int(v)) { std::cout << "构造\n"; }
    Holder(const Holder& o) : p_(new int(*o.p_)) { std::cout << "拷贝构造\n"; }
    Holder& operator=(const Holder& o) {
        if (this != &o) {
            *p_ = *o.p_;
        }
        std::cout << "拷贝赋值\n";
        return *this;
    }
    ~Holder() { delete p_; std::cout << "析构\n"; }
    int value() const { return *p_; }
};

int main() {
    Holder a(1);
    Holder b = a;
    Holder c(3);
    c = a;
    std::cout << a.value() << ' ' << b.value() << ' ' << c.value() << '\n';
}
```

<!-- result:ch07_rule_of_three_fixed -->
```text
构造
拷贝构造
构造
拷贝赋值
1 1 1
析构
析构
析构
```

| 函数 | 关键点 |
|---|---|
| 拷贝构造 | **新分配一块内存**再拷贝内容（深拷贝），不是复制指针 |
| 拷贝赋值 | ① 不能自己给自己赋值（`this != &o` 检查）；② **不重新分配**，只把值拷进去 |
| 析构 | 释放自己持有的那块 |

**那个 `this != &o` 检查是干什么的**：如果 `a = a;`，先 `delete` 自己的内存再去读
`*o.p_`（就是自己刚释放的那块），会读到已释放的内存。**这就是"自我赋值"这个经典坑。**

### 4.5 什么时候自动生成，什么时候被删除

这一张表比"三法则"更值得记，因为它能解释**编译错误 `C2280`**：

| 特殊成员函数 | 什么时候**自动生成** | 什么时候**被隐式删除** |
|---|---|---|
| 默认构造 | 没有用户声明的任何构造函数时 | 声明了任一带参构造且没写默认构造 → **没有默认构造** |
| 析构函数 | 总是 | — |
| **拷贝构造** | 没有用户声明的拷贝构造、移动构造、移动赋值时 | 声明了**移动构造或移动赋值** → 被删除 |
| **拷贝赋值** | 同上 | 声明了**移动构造或移动赋值** → 被删除 |
| 移动构造 | 没有用户声明的拷贝构造、拷贝赋值、析构、移动赋值时 | 声明了**拷贝构造/拷贝赋值/析构** → 不生成（退化为拷贝） |
| 移动赋值 | 同上 | 同上 |

"拷贝构造被移动构造删掉"这一条有实测：

<!-- example:ch07_move_deletes_copy_FAIL -->
```cpp compile-fail
class S {
public:
    S() = default;
    S(S&&) noexcept {}
};

int main() {
    S a;
    S b = a;
    (void)b;
}
```
```text
main.cpp(9): error C2280: “S::S(const S &)”: 尝试引用已删除的函数
```

> **读 `C2280` 的方法**：诊断里写的是"**尝试引用已删除的函数**"，
> 而那个函数（这里是 `S::S(const S&)`）**你根本没写**。
> 这就是"隐式删除"的样子——**编译器删掉了它，但报错时的语气像是你写的**。
> 遇到 `C2280` 就问：**我是不是声明了移动函数（或析构函数），把拷贝给挤掉了？**

**处理办法有两种**：

```cpp
class S {
public:
    S() = default;
    S(S&&) noexcept {}
    S(const S&) = default;      // ← 明确要回拷贝
};
```

或者用 `= delete` **明确禁止**，把意图写进代码：

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};
```

`= delete` 比"不写"好，因为**它把"这是有意为之"和"这是隐式后果"区分开了**。

## 5. `this` 指针与 `const` 成员函数

### 5.1 `this` 是什么

每个**非静态成员函数**都有一个隐藏参数：指向"调用它的那个对象"的指针，名字叫 `this`。

```cpp
class Counter {
    int n_ = 0;
public:
    void inc() { ++n_; }
};
```

`inc` 里的 `n_` 其实是 `this->n_` 的简写。`this` 的类型是 `Counter*`（非 const 成员函数里）。

**`this` 的三个常见用途**：

| 写法 | 用途 |
|---|---|
| `return *this;` | 让 `+=` 这类运算符支持链式调用（第 7 节） |
| `if (this != &o)` | 自我赋值检查（第 4.4 节） |
| `Counter::total` 或 `this->n_` | 名字冲突时显式指明（成员名与参数名相同） |

### 5.2 `const` 成员函数：给 `this` 加底层 const

在成员函数声明的**末尾**写 `const`，表示"这个函数承诺不改本对象"：

<!-- example:ch07_this_const -->
```cpp
#include <iostream>

class Counter {
    int n_ = 0;
public:
    void inc() { ++n_; }
    int get() const { return n_; }
    const Counter& show() const { std::cout << n_ << '\n'; return *this; }
};

int main() {
    Counter c;
    c.inc();
    c.inc();
    const Counter& r = c;
    std::cout << r.get() << '\n';
    r.show();
}
```

<!-- result:ch07_this_const -->
```text
2
2
```

在 `const` 成员函数里，`this` 的类型是 **`const Counter*`**。
所以 `inc()` 里那个 `++n_` 在 `get()` 里根本写不出来——**这就是"承诺不改"的执行机制**。

反过来，在 `const` 对象上调用非 `const` 成员函数会失败：

<!-- example:ch07_this_const_FAIL -->
```cpp compile-fail
class Counter {
    int n_ = 0;
public:
    void inc() { ++n_; }
};

int main() {
    Counter c;
    const Counter& r = c;
    r.inc();
}
```
```text
main.cpp(10): error C2662: “void Counter::inc(void)”: 不能将“this”指针从“const Counter”转换为“Counter &”
```

**读这条诊断的方法**：它说的不是"`inc` 不存在"，而是
**"`this` 指针要从 `const Counter` 转成 `Counter&` 才行，这一步不允许"**。
这个说法直接对应第 06 章第 5 节的"底层 const"——`const` 对象只能调用不修改它的成员函数。

### 5.3 什么时候该加 `const`

| 函数做什么 | 加 `const` 吗 |
|---|---|
| 只读成员、算一个值返回 | ✅ 加 |
| 修改任何成员 | ❌ 不加 |
| 返回成员的引用（调用方可能改） | ⚠️ 谨慎；通常返回 `const` 引用 |

**为什么该加就加**：`const` 对象（包括 `const T&` 参数指向的对象）**只能调用 `const` 成员函数**。
漏加一个 `const`，那个函数就没法用在 `const` 对象上，**错误会出现在调用点，而不是定义点**。
第 06 章第 5.5 节说过 `const T&` 是最常用的参数写法——这两件事是配套的。

## 6. `static` 成员与友元

这两个机制解决相反的问题：**`static` 让某些东西"不属于任何对象"，友元让某些东西"能看私有成员"。**

### 6.1 `static` 数据成员：属于类，不属于对象

<!-- example:ch07_static_member -->
```cpp
#include <iostream>

class Counter {
public:
    static int total;
    int id;
    Counter() : id(++total) {}
};

int Counter::total = 0;

int main() {
    Counter a, b, c;
    std::cout << Counter::total << '\n';
    std::cout << a.id << ' ' << c.id << '\n';
    std::cout << sizeof(Counter) << '\n';
}
```

<!-- result:ch07_static_member -->
```text
3
1 3
4
```

| 输出 | 说明 |
|---|---|
| `3` | 三个对象都加了同一个 `total`——**它只有一份，不是每个对象一份** |
| `1 3` | 每个对象有自己的 `id` |
| `4` | **`static` 成员不占对象的大小**：`sizeof(Counter)` 只算非静态成员 `id` |

**注意类外那句定义**：

```cpp
int Counter::total = 0;      // 必须有，且只能有一处
```

类里的 `static int total;` 只是**声明**——它不分配存储。
存储要在类外定义一次（`Counter::total = 0;` 那句里的类型名和名字都不能省）。
**这条规则和第 02 章第 4 节"声明 vs 定义"是同一件事**，只是在类的语境里。

> ⚠️ **坑**：只写类里的 `static int total;` 就使用 `Counter::total` →
> **链接错误**（`LNK2001: 无法解析的外部符号`），不是编译错误。
> **为什么是链接错误**：编译期只需要"有这么个名字、它是什么类型"（声明够用），
> 到链接时才发现"没有任何一个翻译单元给出它的存储"。**归属：链接类**。

### 6.2 `static` 成员函数：不需要对象就能调用

<!-- example:ch07_static_function -->
```cpp
#include <iostream>

class Counter {
public:
    static int total;
    static int get_total() { return total; }
    Counter() { ++total; }
};

int Counter::total = 0;

int main() {
    Counter a, b;
    std::cout << Counter::get_total() << '\n';
    (void)a; (void)b;
}
```

<!-- result:ch07_static_function -->
```text
2
```

**`static` 成员函数没有 `this`**，所以：① 调用时不需要对象（`Counter::get_total()`）；
② 它**不能访问非静态成员**（那些成员需要通过 `this` 才能找到）。

### 6.3 友元：开一个受控的后门

`private` 挡住了所有人，但有时确实需要"只让某一个函数或类看到"：

<!-- example:ch07_friend -->
```cpp
#include <iostream>

class Box {
    int v_;
public:
    explicit Box(int v) : v_(v) {}
    friend int peek(const Box& b);
    friend std::ostream& operator<<(std::ostream& os, const Box& b);
};

int peek(const Box& b) { return b.v_; }
std::ostream& operator<<(std::ostream& os, const Box& b) {
    return os << "Box(" << b.v_ << ")";
}

int main() {
    Box b(7);
    std::cout << b << ' ' << peek(b) << '\n';
}
```

<!-- result:ch07_friend -->
```text
Box(7) 7
```

`friend` 的规则：

| 项 | 说明 |
|---|---|
| 谁授予 | **类自己**（写在类里面），不是"外面强行闯进去" |
| 双向吗 | ❌ **不双向**。`Box` 让 `peek` 看自己，不代表 `peek` 所属的类也让 `Box` 看 |
| 传递吗 | ❌ 不传递。朋友的朋**友不是朋友** |
| 继承吗 | ❌ 基类的友元不是派生类的友元 |
| 放在哪个访问级别下 | 无所谓——`friend` 声明不受 `public`/`private` 影响 |

> ⚠️ **坑**：用 `friend` 当成"懒得设计接口"的捷径。
> 友元的代价是**把封装打了一个洞**：那个函数从此可以改私有状态，类的内部规则不再由类自己保证。
> **建议**：优先想"是不是该提供一个公开的成员函数"。
> 友元最正当的用途是**运算符重载**（尤其是 `operator<<`，因为它的左操作数是流，不是本类对象，
> 没法写成成员函数——见第 7 节）。

## 7. 运算符重载：够用为止

**运算符重载不是新语法**，它只是"给运算符指定一个函数"。
`a + b` 在编译器眼里就是 `operator+(a, b)` 或 `a.operator+(b)`。

### 7.1 一个够用的例子

<!-- example:ch07_operator_vec2 -->
```cpp
#include <iostream>

class Vec2 {
public:
    double x = 0, y = 0;
    Vec2 operator+(const Vec2& o) const { return Vec2{x + o.x, y + o.y}; }
    Vec2& operator+=(const Vec2& o) { x += o.x; y += o.y; return *this; }
    bool operator==(const Vec2& o) const { return x == o.x && y == o.y; }
    double operator[](int i) const { return i == 0 ? x : y; }
};

std::ostream& operator<<(std::ostream& os, const Vec2& v) {
    return os << '(' << v.x << ", " << v.y << ')';
}

int main() {
    Vec2 a{1, 2}, b{3, 4};
    std::cout << (a + b) << '\n';
    a += b;
    std::cout << a << '\n';
    std::cout << std::boolalpha << (a == b) << ' ' << a[1] << '\n';
}
```

<!-- result:ch07_operator_vec2 -->
```text
(4, 6)
(4, 6)
false 6
```

**注意最后一行是 `false 6`**：`a += b` 之后 `a` 变成 `(4, 6)`，所以 `a[1]` 是 6；
而 `a == b` 比较 `(4,6)` 与 `(3,4)` 得 `false`。

### 7.2 从例子里读出的四条规律

| 运算符 | 写成什么 | 为什么 |
|---|---|---|
| `+` | 成员函数，**返回新对象**（按值） | 加法不改变操作数，要产生一个新值 |
| `+=` | 成员函数，**返回 `*this` 的引用** | 修改自己并支持链式调用 `(a += b) += c` |
| `==` | 成员函数，**加 `const`** | 比较不该改对象；且要能比较 `const` 对象 |
| `<<` | **非成员函数**（通常是友元） | 左操作数是 `std::ostream`，不是 `Vec2`，没法写成 `Vec2` 的成员 |
| `[]` | 成员函数 | 必须是成员（语言规定） |

**`operator<<` 为什么必须写成非成员**：

```text
表达式：  std::cout << v
两种解释：1. operator<<(std::cout, v)        ← 非成员函数：左操作数当第一个参数 ✅
          2. std::cout.operator<<(v)          ← 成员函数：要改 std::ostream 的定义 ❌
```

`std::ostream` 是标准库的类，你不能往里加成员函数，所以只能选第 1 种。

### 7.3 哪些能重载，哪些不能

| 类别 | 例子 |
|---|---|
| ✅ 能重载 | 算术 `+ - * / %`、比较 `== != < >`、逻辑 `! && \|\|`、位运算、`+=` 等复合赋值、`++ --`、`[] () ->`、`<<  >>`、`new delete`、`,` |
| ❌ 不能重载 | `.`（成员访问）、`::`（作用域解析）、`?:`（三目）、`sizeof`、`typeid`、`.*` |
| ❌ 不能改变 | 优先级、结合性、操作数个数（`+` 永远是二元的） |
| ❌ 不能发明 | 不能造一个 `**` 或者 `<>` 出来 |

### 7.4 什么时候不该重载

| 情形 | 为什么不要 |
|---|---|
| 运算符的含义不显然 | `a + b` 如果表示"合并两个网络连接"，读者猜不到 |
| `&&` / `\|\|` 会失去短路 | 重载后两个操作数**一定都会被求值**，`if (p && p->f())` 这种写法就废了 |
| `,` 会失去求值顺序保证 | C++17 起未重载的 `,` 有顺序保证，重载后没有 |
| `&`（取地址）会让人取不到真地址 | `&obj` 变成调用你的函数 |
| **你只是想"看起来简洁"** | 用普通函数名，别改运算符 |

**一条经验**：**运算符重载要"像内置类型一样让人不意外"。**
`Vec2 + Vec2` 不意外；`File + File` 就让人猜。

## 8. 继承、`virtual` 与多态

前面七节都在讲"一个类自己"。这一节开始讲"类与类之间"。

### 8.1 派生：`class Derived : public Base`

```cpp
class Base {
public:
    int a;
};

class Derived : public Base {
public:
    int b;
};
```

`Derived` 的对象里**包含一个完整的 `Base` 子对象**，所以 `Derived` 能用 `a` 和 `b` 两个成员。

**三种继承方式**（很少用后两种）：

| 写法 | 基类的 `public` 成员在派生类里的可见性 |
|---|---|
| `class D : public B` | `public`（"是一个"关系，**99% 的场合用这个**） |
| `class D : protected B` | `protected` |
| `class D : private B` | `private`（"用 B 实现"关系） |

> `struct D : B` 的默认继承方式是 `public`，`class D : B` 是 `private`——
> **这是 `struct`/`class` 的默认继承方式差异，和第 1 节那张表是同一件事**。

### 8.2 多态：同一句话，不同对象有不同行为

先看**没有** `virtual` 会怎样：

<!-- example:ch07_virtual_nonvirt -->
```cpp
#include <iostream>

class Base {
public:
    void who() const { std::cout << "Base\n"; }
};

class Derived : public Base {
public:
    void who() const { std::cout << "Derived\n"; }
};

int main() {
    Derived d;
    Base* p = &d;
    p->who();
    d.who();
}
```

<!-- result:ch07_virtual_nonvirt -->
```text
Base
Derived
```

**`p->who()` 打印的是 `Base`**，尽管 `p` 指的确实是一个 `Derived` 对象。

**程序实际怎么解释它**：`p` 的**静态类型**是 `Base*`，`who` 不是虚函数，
所以编译器在**编译期**就把这次调用绑到 `Base::who` 上了。这叫**静态绑定**。

加上 `virtual`：

<!-- example:ch07_virtual_virt -->
```cpp
#include <iostream>

class Base {
public:
    virtual void who() const { std::cout << "Base\n"; }
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void who() const override { std::cout << "Derived\n"; }
};

int main() {
    Derived d;
    Base* p = &d;
    p->who();
    Base& r = d;
    r.who();
    std::cout << sizeof(Base) << '\n';
}
```

<!-- result:ch07_virtual_virt -->
```text
Derived
Derived
8
```

| 输出 | 说明 |
|---|---|
| `Derived` | 通过指针调用，按**对象的实际类型**选函数（**动态绑定**） |
| `Derived` | 通过引用调用也一样 |
| `8` | **有虚函数之后对象里多了一个指针**（指向"虚函数表"），所以 `sizeof(Base)` 是 8 而不是 1 |

**"多态"这个词的操作含义**：**同一句 `p->who()`，运行时可能执行不同的函数**。
它的实现机制（虚函数表、一次间接跳转）是本节的 Under the hood，入门阶段知道"多了一个指针"就够了。

**两个必要条件的组合**：多态需要 ① 通过**指针或引用**调用；② 被调用的函数是 `virtual`。
缺任何一个都会退回静态绑定：

| 写法 | 绑定方式 |
|---|---|
| `Base* p = &d; p->who();`（`who` 是虚函数） | 动态 |
| `Base b = d; b.who();` | 静态（而且对象已经被切片，见第 9 节） |
| `d.who();`（`d` 是 `Derived` 对象） | 静态（编译期就知道是 `Derived`） |

### 8.3 派生类对象的构造与析构顺序

<!-- example:ch07_ctor_dtor_order -->
```cpp
#include <iostream>

class Part {
    const char* name_;
public:
    explicit Part(const char* n) : name_(n) { std::cout << "构造 " << name_ << '\n'; }
    ~Part() { std::cout << "析构 " << name_ << '\n'; }
};

class Whole : public Part {
    Part member_;
public:
    Whole() : Part("基类"), member_("成员") {
        std::cout << "构造 Whole 的函数体\n";
    }
    ~Whole() { std::cout << "析构 Whole 的函数体\n"; }
};

int main() {
    Whole w;
}
```

<!-- result:ch07_ctor_dtor_order -->
```text
构造 基类
构造 成员
构造 Whole 的函数体
析构 Whole 的函数体
析构 成员
析构 基类
```

**这就是完整的顺序规则**：

```text
构造：基类 → 成员（按声明顺序）→ 自己的函数体
析构：自己的函数体 → 成员（逆序）→ 基类
```

**正好相反**，和"栈"是一样的道理：后建的先拆。
构造时如果基类部分还没构造好，你用到的"继承来的成员"就是垃圾——**所以基类必须在最前面**。

### 8.4 名字隐藏：派生类的同名函数会挡住基类的所有重载

这是继承里最容易踩、且**编译器会给线索**的一个坑：

<!-- example:ch07_name_hiding -->
```cpp
#include <iostream>

class Base {
public:
    void f(int) { std::cout << "Base::f(int)\n"; }
    void f(double) { std::cout << "Base::f(double)\n"; }
};

class Derived : public Base {
public:
    void f(int) { std::cout << "Derived::f(int)\n"; }
};

int main() {
    Derived d;
    d.f(1);
    d.f(1.5);
}
```

编译时会有**一条警告**（本机实测）：

```text
main.cpp(17): warning C4244: “参数”: 从“double”转换到“int”，可能丢失数据
```

运行结果：

<!-- result:ch07_name_hiding -->
```text
Derived::f(int)
Derived::f(int)
```

**`d.f(1.5)` 没有调到 `Base::f(double)`**，而是把 `1.5` 转成 `int` 调了 `Derived::f(int)`。

**程序实际怎么解释它**：**派生类里声明了一个叫 `f` 的名字，就在这个名字上把基类的全部 `f` 都遮住了。**
（这叫**名字隐藏**，不是重载——重载只发生在同一个作用域里。）

**那条 `C4244` 警告是唯一的线索**：它在说"有一个 `double` 被转成了 `int`"。
如果你的重载里有 `double` 版本，这条警告就是在提醒你"你可能想调的是它"。

**修法：用 `using` 声明把基类的名字重新引进来。**

<!-- example:ch07_name_hiding_using -->
```cpp
#include <iostream>

class Base {
public:
    void f(int) { std::cout << "Base::f(int)\n"; }
    void f(double) { std::cout << "Base::f(double)\n"; }
};

class Derived : public Base {
public:
    using Base::f;
    void f(int) { std::cout << "Derived::f(int)\n"; }
};

int main() {
    Derived d;
    d.f(1);
    d.f(1.5);
}
```

<!-- result:ch07_name_hiding_using -->
```text
Derived::f(int)
Base::f(double)
```

加了一行 `using Base::f;`，编译警告也消失了（本机实测 0 条）。
**`using Base::f;` 的作用是"把 `Base::f` 这两个重载名引进 `Derived` 的作用域"**，
于是它们和 `Derived::f(int)` 一起参与重载决议。

> **一条判断**：**在派生类里写和基类同名的函数时，先想"我是想重写它（虚函数），还是想加一个重载"。**
> 想加重载 → 必须写 `using Base::名字;`。想重写 → 检查基类那个是不是 `virtual`（第 10 节的 `override` 会帮你查）。

## 9. 虚析构与切片：两个真会出错的地方

这两件事是 C++ 里出了名的"写的时候看不出来，出问题的时候看不懂"。两处都有可复现的例子。

### 9.1 虚析构：通过基类指针 `delete` 时少了派生类的析构

**先看正确的版本**——基类析构函数是 `virtual`：

<!-- example:ch07_virtual_dtor_ok -->
```cpp
#include <iostream>

class Base {
public:
    virtual ~Base() { std::cout << "~Base\n"; }
};

class Derived : public Base {
    int* buf_;
public:
    Derived() : buf_(new int[8]) { std::cout << "Derived 分配资源\n"; }
    ~Derived() override { delete[] buf_; std::cout << "~Derived 释放资源\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;
}
```

<!-- result:ch07_virtual_dtor_ok -->
```text
Derived 分配资源
~Derived 释放资源
~Base
```

**注意 `delete p;` 这一句**：`p` 的静态类型是 `Base*`，但两个析构函数**都运行了**，
而且是派生类先、基类后。**这就是虚析构函数的作用。**

**再看漏写 `virtual` 的版本**：

<!-- example:ch07_virtual_dtor_bad -->
```cpp
#include <iostream>

class Base {
public:
    ~Base() { std::cout << "~Base\n"; }
};

class Derived : public Base {
    int* buf_;
public:
    Derived() : buf_(new int[8]) { std::cout << "Derived 分配资源\n"; }
    ~Derived() { delete[] buf_; std::cout << "~Derived 释放资源\n"; }
};

int main() {
    Base* p = new Derived;
    delete p;
}
```

**编译成功，警告 0 条**。真实运行结果：

```text
Derived 分配资源
~Base
```

**`~Derived` 一次都没运行，`buf_` 那块内存永久泄漏。**

**为什么编译器不提醒你**：`Base` 里**一个虚函数都没有**，所以 MSVC 不会给出
"这个类有虚函数但析构不是虚的"那类警告（`C4265` 的触发条件不成立）。
**它安安静静地编译通过。**

**更严重的一点**：这**不只是泄漏**——标准规定，当 `delete` 的静态类型与动态类型不同、
而静态类型没有虚析构函数时，行为是**未定义行为**。本机这次"只是没调 `~Derived`"，
换个编译器、换个子对象布局就可能直接崩。

> ⚠️ **坑（这一条要背下来）**：
> **只要一个类会被"通过基类指针删除"，它的析构函数就必须是 `virtual`。**
>
> 判别方法：**如果一个类里出现了任何 `virtual` 函数，就顺手把析构函数也标上 `virtual`。**
> 代价是对象里多一个指针（8 字节）；比起"派生类资源不释放"，这个代价可以忽略。
>
> **例外**：如果这个类**从不**被多态删除（比如它只是个接口的基类但你保证栈上使用），
> 可以不加——但那需要你在整个项目里坚持这个约定，风险很高。**默认就加。**

### 9.2 切片：按值接收基类会切掉派生部分

**切片（slicing）** 指的是：把一个派生类对象**按值**赋给/传给基类类型时，
只有基类那部分被拷贝过去，派生类新增的成员被"切掉"。

<!-- example:ch07_slicing -->
```cpp
#include <iostream>
#include <vector>

class Base {
public:
    virtual void who() const { std::cout << "Base\n"; }
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void who() const override { std::cout << "Derived\n"; }
};

void by_value(Base b) { b.who(); }

int main() {
    Derived d;
    by_value(d);
    std::vector<Base> v;
    v.push_back(d);
    v[0].who();
    Base& r = d;
    r.who();
}
```

<!-- result:ch07_slicing -->
```text
Base
Base
Derived
```

| 写法 | 结果 | 为什么 |
|---|---|---|
| `by_value(d)`（参数是 `Base` 按值） | `Base` | **切片**：`b` 是一个真正的 `Base` 对象 |
| `v.push_back(d)`（`vector<Base>`） | `Base` | 同上，容器里存的只能是 `Base` |
| `Base& r = d;`（引用） | `Derived` | 引用不拷贝，不发生切片 |

**程序实际怎么解释它**：`by_value(Base b)` 的参数 `b` 是一个**货真价实的 `Base` 对象**——
它的存储大小就是 `sizeof(Base)`，装不下 `Derived` 多出来的成员。
所以调用 `b.who()` 时，对象里**根本没有 `Derived` 的那部分**，虚函数表也是 `Base` 的。

> ⚠️ **坑**：把"多态"和"按值传递"混在一起写。
> **切片本身不是未定义行为**（标准明确规定它就是这个意思），但它**几乎总是写错了**：
> 你以为在用多态，实际上多态的能力在传参那一刻就被切掉了。
>
> **修法**：
>
> | 别写 | 写成 |
> |---|---|
> | `void f(Base b)` | `void f(const Base& b)` 或 `void f(Base* b)` |
> | `std::vector<Base> v; v.push_back(d);` | `std::vector<std::unique_ptr<Base>> v;`（第 12 章） |
> | `Base b = d;` | `Base& b = d;` 或 `Base* b = &d;` |
>
> **一句话**：**要保留多态，就必须通过指针或引用，不能按值。**

## 10. 抽象类、纯虚函数与 `override`/`final`

### 10.1 纯虚函数与抽象类

有时候基类表达的是一个**概念**（比如"形状"），它本身没有"面积"可算：

<!-- example:ch07_abstract -->
```cpp
#include <iostream>

class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

class Square : public Shape {
    double side_;
public:
    explicit Square(double s) : side_(s) {}
    double area() const override { return side_ * side_; }
};

int main() {
    Square q(3);
    const Shape& s = q;
    std::cout << s.area() << '\n';
}
```

<!-- result:ch07_abstract -->
```text
9
```

`= 0` 表示"这个函数没有实现，派生类必须给出实现"。含纯虚函数的类是**抽象类**，
**不能创建对象**：

<!-- example:ch07_abstract_FAIL -->
```cpp compile-fail
class Shape {
public:
    virtual double area() const = 0;
};

int main() {
    Shape s;
    (void)s;
}
```
```text
main.cpp(7): error C2259: “Shape”: 无法实例化抽象类
```

| 能用 `Shape` 做什么 | 不能做什么 |
|---|---|
| 声明 `Shape*` / `Shape&` | **创建 `Shape` 对象** |
| 作为函数参数/返回值（指针或引用） | 放进 `std::vector<Shape>`（会切片） |
| 被继承 | — |

**抽象类的价值**：它把"接口"写成了类型系统的一部分。
编译器会检查每个具体类有没有实现全部纯虚函数——**漏一个，那个类就还是抽象的，实例化时报错**。

### 10.2 `override`：把"我以为重写了"变成编译错误

<!-- example:ch07_override_typo_FAIL -->
```cpp compile-fail
class Base {
public:
    virtual int f() const { return 1; }
};

class Derived : public Base {
public:
    int ff() const override { return 2; }
};

int main() {
    Derived d;
    (void)d;
}
```
```text
main.cpp(8): error C3668: “Derived::ff”: 包含重写说明符“override”的方法没有重写任何基类方法
```

**如果把 `override` 去掉**，这段代码会**编译通过**——然后 `Derived::ff` 就只是一个新函数，
基类的 `f` 依然是 `Base::f`。**多态悄悄地失效了。**

**换成另一个常见错误**（忘了 `const`）：

```cpp
class Base { public: virtual int f() const; };
class Derived : public Base {
    int f() override;        // ← 少了 const：参数列表不同，不是重写
};
```

这同样会被 `override` 抓到（错误信息一样是 `C3668`）。

> **规则**：**写重写函数时，永远写 `override`。**
> 它只在一种情况下会"多打几个字白费"——就是你写对了。**写对了的代价是零，写错了能救命。**

### 10.3 `final`：到此为止

`final` 有两个位置，含义不同：

| 写法 | 禁止什么 |
|---|---|
| `class Base final { };` | **不能被继承** |
| `void f() final;` | 这个虚函数**不能在更下层被重写** |

<!-- example:ch07_final_FAIL -->
```cpp compile-fail
class Base final {
};

class Derived : public Base {
};

int main() {
    Derived d;
    (void)d;
}
```
```text
main.cpp(4): error C3246: "Derived": 无法从 "Base" 继承，因为它已声明为 "final"
```

**`final` 的用途不是"安全"，而是"表达设计决定 + 让编译器帮你守住它"**，
有时还能让编译器做去虚化优化。**但不要为了微优化就给类加 `final`。**

### 10.4 一张"关键字该写在哪"的小表

| 我想表达 | 写什么 |
|---|---|
| 这个函数可以被派生类改写 | `virtual`（只写在基类） |
| 我在重写基类的虚函数 | `override`（写在派生类，**总是写**） |
| 这个类/函数不许再被继承/重写 | `final` |
| 这个函数没有实现，派生类必须实现 | `= 0`（纯虚） |
| 用编译器生成的版本 | `= default` |
| 明确禁止这个函数 | `= delete` |
| 多态删除时要正确析构 | `virtual ~类名()` |

## 11. 组合优先于继承

最后是一节**设计判断**，不是语法。

### 11.1 两种复用方式

```text
继承（is-a）：   Car is-a Vehicle          "汽车是一辆交通工具"
组合（has-a）：  Car has-a Engine          "汽车有一个引擎"
```

组合在 C++ 里就是"把一个对象当成另一个对象的成员"：

<!-- example:ch07_composition -->
```cpp
#include <iostream>

class Engine {
public:
    void start() const { std::cout << "引擎启动\n"; }
};

class Car {
    Engine engine_;
public:
    void drive() const { engine_.start(); std::cout << "车开走\n"; }
};

int main() {
    Car c;
    c.drive();
}
```

<!-- result:ch07_composition -->
```text
引擎启动
车开走
```

### 11.2 为什么建议优先用组合

| 对比项 | 继承 | 组合 |
|---|---|---|
| 表达的关系 | is-a | has-a |
| 耦合程度 | **强**：派生类知道基类的全部接口与实现细节 | 弱：只用到对方公开的那几个函数 |
| 改动的影响 | 基类改一个成员的可见性/行为，**所有派生类都可能受影响** | 被组合的类改内部实现，外层不受影响 |
| 运行时替换 | 需要虚函数 + 指针/引用 | 直接换一个成员对象（或换成模板参数） |
| 能不能多选 | ❌ 只能继承一个类（**单继承**） | ✅ 想有几个成员就有几个 |
| 典型代价 | 对象里塞进基类子对象、虚函数表指针 | 没有额外开销 |

**判断方法（`is-a` 测试）**：

> 说一句"**Derived 是一个 Base**"。如果这句话在**任何**语境下都成立 → 可以是继承；
> 只要有一种语境不成立 → 用组合。

反例：`Stack` 继承 `std::vector`——
"栈是一个 vector"在"栈不该让你随机访问中间元素"这个语境下就不成立。
正确做法是**组合**一个 `vector` 成员，只暴露 `push`/`pop`/`top`。

### 11.3 继承真正的用途：多态，不是复用代码

**如果只是为了复用代码，用组合。** 继承真正的价值在于**第 8、10 节那种"同一段代码处理多种类型"**：

```text
vector<unique_ptr<Shape>> shapes;
for (auto& s : shapes) { total += s->area(); }   // 不知道也不关心具体是哪种形状
```

**这里的继承是不可替代的**——组合做不到"用一个容器装不同具体类型，然后统一调用"。
**"为了少写几行代码"而继承，几乎总是错的。**

## 13. 本章自测

**1.** `struct` 和 `class` 有什么区别？`private` 能防止别人读到对象里的数据吗？

<details><summary>答案</summary>

**唯一的区别是默认访问级别**（以及默认继承方式）：
`struct` 默认 `public`，`class` 默认 `private`。能力完全相同——
`struct` 也能有构造函数、虚函数、继承。

**`private` 不能防止"读到内存"**，它只是**编译期的访问检查**：
写 `p.x` 会报 `C2248`，但用指针偏移、`reinterpret_cast` 等方法依然能碰到那块数据（那是未定义行为）。

**`private` 的价值是"表达设计意图 + 让编译器帮你守住它"，不是加密。**

</details>

**2.** 下面两个构造函数，`B` 的成员 `p` 各经历了几次函数调用？为什么？

```cpp
struct A { Part p; A() : p("x") {} };
struct B { Part p; B() { p = Part("x"); } };
```

<details><summary>答案</summary>

**`A`：1 次**（`Part` 的构造函数），因为初始化列表直接构造了 `p`。

**`B`：3 次**——默认构造 `p`、构造临时 `Part("x")`、调用拷贝赋值把值写进 `p`。

**关键**：成员**总是会被初始化**（你不写初始化列表，编译器就默认初始化它）。
`B` 的写法不是"省掉初始化"，而是"先默认初始化一次，再覆盖掉"。

**本机实测输出**（`ch07_init_list_vs_assign`）：

```text
--- A ---
构造 直接初始化
--- B ---
默认构造 Part
构造 先默认构造再赋值
赋值 先默认构造再赋值
```

**比性能更重要的一点**：`const` 成员、引用成员、没有默认构造函数的类类型成员
**只能在初始化列表里给初值**，函数体里根本写不出来。

</details>

**3.** 下面这个类的成员初始化顺序是什么？MSVC `/W4` 会警告吗？

```cpp
struct Whole {
    Part a;
    Part b;
    Whole() : b("b"), a("a") {}
};
```

<details><summary>答案</summary>

**初始化顺序是 `a` 然后 `b`**——按**成员的声明顺序**，初始化列表的书写顺序被忽略。

**本机实测：警告 0 条。** MSVC `/W4` 不提示这件事，所以这个坑是**安静的**。

**危险情形**：`Whole() : b(a + 1), a(1) {}`。读代码的人以为 `a` 已经就绪，
实际 `b` 先初始化，此时 `a` 还没初始化——读到垃圾值，属于**未定义行为**。

**处理习惯**：**让初始化列表顺序与声明顺序一致**，这样结果与你的预期相同。

**本机实测输出**：`构造 a` / `构造 b`。

</details>

**4.** 这个程序输出什么？为什么它属于未定义行为而不是"内存泄漏"？

```cpp
class Holder {
public:
    int* p;
    explicit Holder(int v) : p(new int(v)) {}
    ~Holder() { delete p; }
};
int main() {
    Holder a(5);
    Holder b = a;
}
```

<details><summary>答案</summary>

**本机实测**：stdout 为空，进程以 **`0xC0000374`（`STATUS_HEAP_CORRUPTION`）** 终止。

**为什么**：编译器生成的拷贝构造是**逐成员拷贝**，所以 `b.p == a.p`（浅拷贝）。
作用域结束时先析构 `b`（`delete p`），再析构 `a`（**对同一块内存再 `delete` 一次**）。

**为什么是 UB 而不是泄漏**：泄漏是"该释放的没释放"，程序行为完全确定；
这里是**对已经释放的内存再释放一次**，程序已经失去任何保证——标准没有规定会发生什么。
本机表现为堆管理器主动杀进程。

**修法**：按三法则补齐拷贝构造（深拷贝）与拷贝赋值，见 `ch07_rule_of_three_fixed`。

</details>

**5.** 下面这段代码**编译成功、0 条警告**。它错在哪？运行时会发生什么？

```cpp
class Base { public: ~Base() { } };
class Derived : public Base {
    int* buf_;
public:
    Derived() : buf_(new int[8]) {}
    ~Derived() { delete[] buf_; }
};
int main() {
    Base* p = new Derived;
    delete p;
}
```

<details><summary>答案</summary>

**错在基类的析构函数不是 `virtual`。**

`delete p;` 里 `p` 的静态类型是 `Base*`，动态类型是 `Derived`。
因为 `Base::~Base` 不是虚函数，**只有 `~Base` 被调用**，`~Derived` 一次都没运行，
`buf_` 永久泄漏。

**本机实测输出**：

```text
Derived 分配资源
~Base
```

**更严重的是**：标准规定这种"静态类型与动态类型不同、而静态类型没有虚析构函数"的 `delete`
是**未定义行为**——不只是泄漏。

**为什么没警告**：`Base` 里一个虚函数都没有，MSVC 的 `C4265`
（"类有虚函数但析构不是虚的"）触发条件不成立，所以它安安静静地编过。

**修法**：`virtual ~Base() { }`。**只要类里出现任何 `virtual`，就顺手给析构函数也加上。**

</details>

**6.** 下面三次 `who()` 调用各打印什么？为什么？

```cpp
Derived d;
Base b = d;         // Base 有 virtual void who()，Derived override 了它
Base& r = d;
Base* p = &d;
b.who();  r.who();  p->who();
```

<details><summary>答案</summary>

依次是 **`Base`、`Derived`、`Derived`**。

- `Base b = d;` —— **切片**。`b` 是一个真正的 `Base` 对象，`sizeof(Base)` 装不下 `Derived` 的部分，
  虚函数表也是 `Base` 的。**多态在传值那一刻就没了。**
- `Base& r = d;` —— 引用不拷贝，`r` 指的还是 `d`，动态绑定生效。
- `Base* p = &d;` —— 同上。

**本机实测**（`ch07_slicing`）：`Base` / `Base` / `Derived`——前两个分别是按值传参和
`vector<Base>::push_back`，最后一个是通过引用。

**规则**：**要保留多态，就必须通过指针或引用，不能按值。**

</details>

**7.** 写了这行之后，为什么 `S b = a;` 会报 `C2280`？怎么修？

```cpp
class S {
public:
    S() = default;
    S(S&&) noexcept {}
};
```

<details><summary>答案</summary>

**因为"声明了移动构造函数"会让编译器把拷贝构造函数定义为 deleted。**

本机真实诊断：

```text
main.cpp(9): error C2280: “S::S(const S &)”: 尝试引用已删除的函数
```

**注意诊断的语气**：它报的是 `S::S(const S&)`——一个你**根本没写**的函数。
这就是"隐式删除"的样子。

**修法**（两种）：

```cpp
S(const S&) = default;      // 明确要回拷贝
// 或者
S(const S&) = delete;       // 或者明确禁止，把意图写进代码
```

**为什么规则是这样**：一个类既然实现了移动（说明它可能持有资源），
编译器就不敢再替你生成"逐成员拷贝"——那多半是错的（见第 4 题）。
**"宁可报错，不要默默生成错的"。**

</details>

**8.** 为什么 `ostream& operator<<(ostream&, const Vec2&)` 不能写成 `Vec2` 的成员函数？

<details><summary>答案</summary>

因为**运算符重载时，左操作数对应成员函数的 `this`**。

`std::cout << v` 若写成成员函数，就等价于 `std::cout.operator<<(v)` ——
那需要**修改 `std::ostream` 这个标准库类，往里加一个成员函数**。做不到。

写成非成员函数时，左操作数变成**第一个参数**：

```text
std::cout << v    →    operator<<(std::cout, v)
```

于是它可以是自由函数（需要看私有成员时加 `friend`）。

**同理**：任何"左操作数不是你自己的类型"的运算符（如 `2 * vec`）都必须写成非成员函数。
而 `operator[]`、`operator=`、`operator()` 语言规定**必须是成员**。

</details>

**9.** `sizeof(Counter)` 是 4，而 `Counter` 里有一个 `static int total` 和一个 `int id`。为什么不是 8？类外那句 `int Counter::total = 0;` 能省吗？

<details><summary>答案</summary>

**`static` 数据成员不属于对象**——整个程序里只有一份，放在静态存储区，不占对象的空间。
所以 `sizeof(Counter)` 只算非静态成员 `id`，是 **4**（本机实测）。

**类外那句不能省。** 类里的 `static int total;` 只是**声明**（告诉编译器"有这么个名字"），
存储必须在**类外定义一次**（`int Counter::total = 0;`）。

省掉的后果是**链接错误**（`LNK2001: 无法解析的外部符号`），**不是编译错误**：
编译期只需要声明，链接时才发现没有任何翻译单元提供这块存储。
**归属：链接类。**

</details>

**10.** 本机实测数据：`sizeof(Base)` 在 `Base` 有一个虚函数时是 8，没有虚函数时是 1。这个 8 是什么？为什么"有虚函数"会让对象变大？

<details><summary>答案</summary>

**那 8 字节是一个指针**，指向该类对应的**虚函数表**（vtable）。
有了它，`p->who()` 才能在运行时根据对象的实际类型找到该调哪个函数——这就是动态绑定的实现方式。

**代价**：

| 项 | 代价 |
|---|---|
| 每个对象 | 多一个指针（本机 8 字节） |
| 每个类 | 一张虚函数表 |
| 每次虚调用 | 一次间接跳转（通常不能内联） |

**本文实测**：`ch07_virtual_virt` 里 `sizeof(Base)` = 8，而 `ch07_virtual_nonvirt` 里
`Base` 没有虚函数、只有一个空类，`sizeof` 是 1（本机对空类给 1 字节，保证不同对象地址不同）。

**这一题的更大意义**：它把第 8 节的"多态"落到了一个可以量的数字上——
**多态不是免费的，代价就在每个对象里。**

</details>
