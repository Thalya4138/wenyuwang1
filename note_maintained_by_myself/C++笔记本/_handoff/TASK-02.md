## 一、为什么这一轮的活是"横向审计"

这份讲义由**多个 agent 分头写**：DSH 侧写了 `01` / `02` / `12` / `13`，
另外三个 agent 分簇写了 `03`–`05`、`06`–`08`、`09`–`11`。

**分头写书有一个必然的副作用，而且写作者自己看不见**：

> **同一个概念在不同章节里的说法可能不一致。**

具体表现有五种，**每一种都只有"横向读"才看得出来，纵向读（一章一章读）看不出来**：

| 类型 | 例子 |
|---|---|
| **术语不一致** | 同一个东西，A 章叫"将亡值"，B 章叫"过期值" |
| **边界重复或冲突** | 同一个知识点两章都讲，且**讲的深度/结论不同** |
| **交叉引用指错** | 写"见第 07 章第 3 节"，而第 07 章第 3 节根本不是那个内容 |
| **分层口径不一致** | 同一件事，A 章说"必须掌握"，B 章说"知道即可" |
| **前后判断矛盾** | A 章的某条断言被 B 章的实测推翻，但两边都没改 |

**DSH 侧做不了这件事**：它刚写完这些章，**看不到自己的一致性错误**。
换一个模型视角是**最便宜的检查手段**——这也是你在这个项目里的核心价值。

## 四、你的四项任务（**按优先级排序，至少完成前两项**）

### 任务 1（**最高优先**）：横向一致性审计

**方法**：不要按章读。**按概念读**——挑出贯穿全书的几个概念，把它们在各章的段落抽出来并排看。

**必须审的六个概念**（每个都跨了至少两章）：

| 概念 | 出现在 | 要查什么 |
|---|---|---|
| **值类别**（左值/右值/将亡值） | `02` 第 6 节、`03` 第 1 节、`12` 第 1 节 | 术语、分类图、判据是否一致；有没有一章说得更容易引起误解 |
| **RAII** | `07` 第 3 节、`08` 第 2 节、`12` 第 7 节 | 定义口径是否一致；"栈展开"的说法有没有冲突 |
| **`const`** | `02` 第 7 节、`06` 第 4 节、`07` 第 5 节 | 顶层/底层 const 的表述；`constexpr` 与 `const` 的关系说法 |
| **未定义行为（UB）** | `02` 第 5.4 节、`03` 第 8 节、`13` 第 1–3 节 | **最容易冲突**：UB 与"实现定义"的对照表口径；"UB 会不会在优化下爆炸"的说法（`13` 第 3.1 节有一条**未能复现**的诚实记录，别章不能与之矛盾） |
| **移动语义** | `02` 第 6 节、`03` 第 1 节、`12` 全章 | `02`/`03` 有没有**提前展开**了 `12` 的内容（覆盖表规定 `12` 才讲）；`std::move` 的表述是否一致 |
| **初始化** | `02` 第 5 节、`07` 第 2 节、`10` 第 5 节 | 初始化形式的分级说法；`{}` 的窄化检查在例子里的表现 |

**输出要求**：每个概念给一张表

```text
| 章·节 | 原文关键句（引号摘录，不要大段复制） | 与其它章是否一致 | 若不一致，哪个对/该怎么改 |
```

**判据**：**"一致"要有依据**。不能只写"看起来一致"——要么两边引原文对比，要么用编译验证。

### 任务 2：交叉引用完整性审计

全书有大量"见第 NN 章第 M 节"的引用。**这类错误在 Python 笔记里真实发生过 5 次**，
读者无法自行纠正，**比不写更伤信任**。

**做法**：

1. 用**你自己的脚本**（不要用 DSH 侧的，独立实现更可信）抽出所有形如
   `第 NN 章`、`第 NN 章第 M 节`、`NN_xxx.md 第 M 节` 的引用
2. 对每一条：
   - **章号**是否存在对应文件
   - 若写了**节号**，去目标章看那个 `##` 标题**是不是**被引用的内容
   - 若引用的章**还没写**（`99_标准库索引.md` 等），确认原文有没有**明确说明"尚未开写"**
3. 产出**逐条清单**：引用位置 → 引用内容 → 目标实际内容 → 结论（✅/❌）

**特别注意**：覆盖表条目号（`1.5`、`12.3`）**不是**节号。
把条目号当节号写进正文是本项目已记录过 5 次的错误形态。

### 任务 3：覆盖对账的**反向**核查

每章末都有一张「本章覆盖对账」表，声称"覆盖表条目 → 本文小节"。
**DSH 侧只核了"表里写了"，没核"正文里真找得到"。**

**你要做的**：对每一章，**从正文往回核**——

- 表里指的**那个小节号，正文里真的存在吗**
- 那个小节的**内容真的对应那个覆盖表条目吗**（不是"提了一句"就算覆盖）
- 有没有**覆盖表条目声称覆盖、正文实际没讲**的（**幽灵条目**）
  - 已知历史案例：`01` 章曾声称 `0.3` 覆盖"注释"，但正文没有专节（已修）

**产出**：每章一张表，列出"幽灵条目"与"名不副实"。

### 任务 4：找出"依赖具体实现"却被写成"普遍成立"的说法

逐章把技术断言分三类，**特别抓那些没标的**：

- **标准保证**（换编译器也成立）
- **实现定义 / 未指定**（标准允许不同）
- **未定义行为**（程序已失去任何保证）

**重点怀疑对象**：

- `sizeof` 的具体数值（`long double` 在本机是 8，在 GCC 上是 16）
- `char` 是否有符号
- `std::string` 被移后的状态（`12` 第 8 节已标"本机是空串但标准不保证"——**别章不能与之矛盾**）
- 崩溃退出码（`0xC0000005` 是 Windows 的说法，Linux 是信号）
- 任何"优化器会/不会做 X"的说法
