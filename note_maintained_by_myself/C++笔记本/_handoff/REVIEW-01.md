## 四、`FIX-01`：需要处理的具体缺陷

### FIX-01-1：第 1 章代码块未进验证基线（**最高优先级**）

- **位置**：`01_从源代码到运行.md` 全文
- **现象**：`python tmp/verify_cpp.py <目录>` 报 `01_从源代码到运行.md : 0 块`
- **判据**：与 `AGENTS.md` 第 5 节约定不符；属"静默假通过"（脚本报 0 不符合，实际一个块没验）
- **修法**：把本章**所有可独立编译运行**的示例改成带标记形式：

  ```markdown
  <!-- example:ch01_hello -->
  ```cpp
  #include <iostream>
  int main() { std::cout << 3 + 4 << '\n'; }
  ```

  <!-- result:ch01_hello -->
  ```text
  7
  ```
  ```

  不可独立运行的（片段、伪代码、汇编、诊断文本）**保持原样，不要加标记**——
  它们不是"可验证示例"，加标记反而会在基线里制造假失败。
- **不许动**：正文的叙述、结构、章首目录、对账表

> **实际修法补充（第二轮）**：只给 **8 个**块加了标记，并把
> "不超过行、只断言稳定前缀"的需求做成了新标记 `<!-- run-expect:key -->`（前缀匹配），
> 用在 `ch01_argv_return3` 上——因为它第二个输出行是 `argv[0]` 的完整路径，逐字比对必然假失败。
> 验证脚本已同步支持该标记，并用自己的自测样板验证过（`t_prefix_ok` 通过 / `t_prefix_bad` 被抓）。

### FIX-01-2：0.3 条目声称覆盖"注释"，正文缺专节 ✅ 已修

- **位置**：第 6.2 节（逐符号交代）附近
- **现象**：对账表写"0.3 第一个程序：`main`、标准输出、注释"，但正文只在符号表里提了一句 `//`
- **判据**：覆盖对账表指向的内容必须在正文找得到（`_写作规范.md` 第 10 节）
- **修法**：**实际做法**——在第 6 节内部新增 `### 6.4 注释：两种形式，以及一个不能嵌套的坑`，
  并把原 6.4/6.5 顺延为 6.5/6.6。**作为 `###` 插入，`##` 级节号未平移**，章首目录不受影响。
  新增内容含 `//` 与 `/* */` 对照表、**块注释不能嵌套的坑及其词法层原因**、
  以及"注释在翻译阶段被替换为一个空格"这条与第 3 节呼应的机制。
  已验证示例 `ch01_comments`。
- **不许动**：其余小节编号（若插入新 `##` 节会平移全部节号并影响章首目录——**优先插在 6 节内部作为 `###`，避免平移**）

### FIX-01-3：编译器版本号有两套，正文只写了一处 ✅ 已修

- **位置**：第 6.3 节（"MSVC 14.51.36231"）
- **现象**：实测发现两个数字：`vcvars` 所在目录名是 **14.51.36231**，而 `cl` 自己打印的

  并在 `_维护须知.md` 5.3 节立为"已知陷阱"（**不要把其中一个"改对"**）
- **不许动**：不要把其中一个"改对"——两个都对，只是含义不同

```cpp
#include <iostream>
struct Probe {
    int id;
    Probe(int i) : id(i) { std::cout << "ctor " << id << '\n'; }
    ~Probe() { std::cout << "dtor " << id << '\n'; }
};
Probe g{1};                    // 全局
int main() { static Probe s{2}; std::cout << "main body\n"; }   // 不写 return
Probe g2{3};                   // 全局
```

真实输出（退出码 **0**）：

```text
ctor 1
ctor 3
ctor 2
main body
dtor 2
dtor 3
dtor 1
```

**它一次证实三件事**：全局对象在 `main` 前构造；函数内 `static` 在**首次经过声明时**构造（所以排在两个全局之后）；
**析构严格逆序**。所以"省略 `return`"的准确含义是"**先逆序析构静态对象，再把 0 交给运行库**"，
而不是"跳过一条 return 语句"。
