
| 脚本 | 通过判据 | ⚠️ 陷阱 |
|---|---|---|
| `verify_cpp.py` | **块数 > 0 且不符合 0** | **不是"不符合 0"就算过**。标记写错时会扫到 **0 块**并报"0 处不符合"——**静默假通过**，已真实发生过一次 |
| `check_anchors.py` | 0 处问题 | 规则经 Obsidian 本体源码核实：`replace(/ /g,"%20").replace(/([()])/g,"\\$1")` |
| `check_links.py` | 0 处失效链接 | 计划中但未写的章节文件会被报出，那是**进度**不是缺陷 |

> **并行安全**：三个脚本都可并发运行（`verify_cpp.py` 按 PID 隔离工作区）。
> 但**不要共用** `tmp/probe_chNN.py` / `tmp/chNN_probe_result.txt` 文件名——按章号分开。

### 三个已踩过的工具坑（**别再踩**）

| 现象 | 正确做法 |
|---|---|
| `PermissionError [WinError 5]`，目录建完还删不掉 | **不要用 `tempfile.mkdtemp()`**，用 `os.makedirs()` 建在 `tmp/` 下 |

## 四、这份讲义最值得知道的三条实测事实

这三条是**别人做同类讲义时最容易搞错**的地方，都有本轮真实输出支撑。

### 1. 不加 `/utf-8`，含中文的源文件**直接编译失败**

```text
warning C4819: 该文件包含不能在当前代码页(936)中表示的字符
error C2001: 字符串字面量中的换行符          ← 报错信息与"中文"毫无关系
error C3688: 文本后缀"..."无效
error C2143: 语法错误: 缺少";"
```

**教训**：编译器报错的位置和原因**可能离真正的问题很远**。判据是"这错误在这行根本没道理"时，
先怀疑**环境/编码/包含关系**。

### 2. 编译器对未定义行为**基本沉默**

一段同时踩了**六个 UB**（未初始化、越界、空指针解引用、有符号溢出、悬垂、双重释放）的代码，
`/W4` 下只报三条，**其中两条说的是"变量没用"**。
数组越界、空指针解引用、有符号溢出、双重释放——**一条警告都没有**。

**教训**：**"编译过了、跑起来了"完全不能证明程序是对的。**

### 3. "UB 在优化下会爆炸"这句话，我**没能复现**

试了有符号溢出、越界两类，`/Od` `/O1` `/O2` 输出**全部一致**（MSVC 未利用这两处 UB）。
**已如实写进第 13 章第 3.1 节。**

**教训**：**UB 的危险不是"一定会出事"，而是"有时会、有时不会"**——这比必然崩溃难查得多。
所以**不要用"它崩溃了"判定 UB，也不要用"它没崩溃"判定不是 UB**。

## 五、协作机制（见完整协议：[`_协作规范.md`](_协作规范.md)）

### 关键约束：Codex 无法在 DSH 沙箱内运行（已实测）

试过 5 种调用方式，全部失败于同一处：

```text
failed to open daemon operation lock C:\Users\Wang\.codex\app-server-daemon\daemon.lock
Caused by: 拒绝访问。 (os error 5)
```

放宽沙箱（`danger-full-access`）也没用——**证明不是文件权限问题，是运行模型冲突**。

**所以协作是「文件交接」，不是「两个 agent 通话」**：Codex 在你的普通终端跑，通过 `_handoff/` 与 DSH 侧交换文件。

### 从上一轮实战中学到的两条硬规矩（已写进协议）

1. **交付物不全 = 本轮未完成。** 即使正文全绿。因为**全绿只说明"已写的没写错"，不说明"该写的都写了"**。
2. **中间产物一律放 `tmp/`**，不得落在正文目录（否则让所有"文件清单类"检查产生假阳性，
   而**假阳性会训练人忽略警告**）。
