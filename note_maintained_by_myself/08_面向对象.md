## 0. 先记住六件事

1. **类是模板，实例是按模板造出来的具体东西。** `class Student:` 是模板，`Student("小明")` 是实例。
2. **`self` 不是关键字，只是第一个位置参数的名字。** 写 `def f(this):` 也能跑，只是没人这么干。
3. **实例属性在实例上，类属性在类上。** 读的时候实例优先；但**改类属性会影响所有没自己那份的实例**。
4. **可变对象当类属性 = 所有实例共享一份**（第 1.6 节，最危险的坑）。
5. **Python 没有"私有成员"机制。** `_x` 是约定，`__x` 是名字改写，都不是访问控制（第 5 节）。
6. **`__str__` 给人看，`__repr__` 给调试看**；没有 `__str__` 时会回退到 `__repr__`。

## 1. `class` / 实例 / 属性 / `self`（覆盖 6.1）

### 1.1 先看没有类时怎么写

```python
s1 = {"name": "小明", "age": 18, "score": 91}
print(s1["name"])                        # 小明


def add_score(stu, n):
    stu["score"] = stu["score"] + n


add_score(s1, 1)
print(s1["score"])                       # 92

s2 = {"nmae": "小红", "age": 17}          # nmae 是错字
print(s2)                                # {'nmae': '小红', 'age': 17} —— 打错了不报错
```

三个真实的不舒服：**键名是裸字符串**（打错了 Python 不报错）；
**函数不知道传进来的是什么形状的数据**（`add_score` 期待里面有 `"score"`，
这个期待只存在于你脑子里）；**数据和操作是分开的**（看到 `s1` 看不出它能做哪些事）。

### 1.2 类的定义：把数据和操作绑在一起

```python
class Student:
    pass


a = Student()
b = Student()
print(type(a))                            # <class '__main__.Student'>
print(isinstance(a, Student), a is b)     # True False

a.name = "小明"  # 直接给实例加属性，不需要事先声明
a.age = 18
b.name = "小红"
print(a.__dict__)                         # {'name': '小明', 'age': 18}
print(b.__dict__)                         # {'name': '小红'}
print(sorted(k for k in Student.__dict__ if not k.startswith("__")))   # []
```

- `class Student:` 建了一个**类对象**，`Student` 这个名字指向它（它本身也是值，能 `print`、能传参）。
- `Student()` **调用类对象**，得到新实例。`a` 和 `b` 互不相干。
- **`__init__` 之外也能设属性**：`a.name = "小明"` 直接给实例加了属性。
  Python 对象默认带一个 `__dict__`（字典），实例属性就存在里面。
- 最后一行输出 `[]`：这个类除了自动给的成员，自己什么都没定义。

### 1.3 `self` 到底是什么

```python
class Student2:
    def set_name(whatever, name):
        whatever.name = name

    def get_name(whatever):
        return whatever.name


s = Student2()
s.set_name("小刚")
print(s.get_name())                        # 小刚

s2 = Student2()
Student2.set_name(s2, "小美")               # 等价于 s2.set_name("小美")
print(s2.get_name())                       # 小美
print(Student2.set_name)   # <function Student2.set_name at 0x...>
print(s2.set_name)         # <bound method Student2.set_name of ...>
```

我把第一个参数叫 `whatever`，照样跑——**证明 `self` 不是语法关键字**。
真正的规则：**定义在类里的函数是普通函数；通过实例取它时，Python 把它变成"绑定方法"，
自动把实例作为第一个参数塞进去。**

**不写 `self` 会报什么错**（真实运行，文件叫 `no_self.py`）：

```python
# no_self.py
class Bad:
    def set_name(name):
        print("我收到了：", name)


b = Bad()
b.set_name("小明")
```

```
Traceback (most recent call last):
  File "no_self.py", line 8, in <module>
    b.set_name("小明")
    ~~~~~~~~~~^^^^^^^^
TypeError: Bad.set_name() takes 1 positional argument but 2 were given
```

读法：`set_name` 声明收 1 个参数（`name`），但实际给了 2 个（`b` 自己 + `"小明"`）。

> ⚠️ **坑**：报错里的数字是"参数个数"，不是"你少写了 `self`"。
> 初学者会去数自己传了几个实参，数出来明明只有 1 个。
> **记住：通过实例调方法，永远多一个隐式参数。**

### 1.4 实例属性 vs 类属性

```python
class Student:
    school = "第一中学"          # 类属性：定义在 class 里、方法外

    def __init__(self, name):
        self.name = name          # 实例属性


a = Student("小明")
b = Student("小红")
print(a.school)                            # 第一中学
print(a.__dict__)                          # {'name': '小明'} —— school 不在 a 身上
print(Student.__dict__["school"])           # 第一中学

a.school = "第二中学"                       # 这【不是】改类属性
print(a.school, Student.school, b.school)   # 第二中学 第一中学 第一中学
print(a.__dict__)   # {'name': '小明', 'school': '第二中学'}

Student.school = "第三中学"                  # 改类属性才影响大家
print(a.school, b.school)                   # 第二中学 第三中学
```

**查找顺序**：实例 `__dict__` → 类 `__dict__` → 父类 → `object`。
所以 `a.school` 读得到，但**它不在 `a` 身上**。
`a.school = ...` 是给实例 `a` 新加一个同名属性，把类属性遮住。

> **判断依据**：值**每个实例都可能不同**（名字、分数）→ 实例属性，写在 `__init__` 里。
> 值**所有实例共享同一份**（学校名、常量）→ 类属性。只有一个例外：共享的是可变的，见 1.6。

`__dict__` 是观察对象最直接的工具：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y


p = Point(1, 2)
print(p.__dict__)          # {'x': 1, 'y': 2}
p.z = 3                    # 随时能加
print(p.__dict__)          # {'x': 1, 'y': 2, 'z': 3}
```

**Python 对象默认就是一个"属性名 → 值"的字典包装**，能随时加属性、删属性。
别的语言里对象的形状在编译期定死，这里不是。想禁止就加 `__slots__`：

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y


p = Point(1, 2)
print(p.x, p.y)                                 # 1 2
print(p.__dict__)
# AttributeError: 'Point' object has no attribute '__dict__'
p.z = 3
# AttributeError: ... has no attribute 'z' and no __dict__ for setting new attributes
print(Point.__slots__)                          # ('x', 'y')
```

代价是失去灵活性（不能加属性、多继承受限），收益是**省内存**（不用给每个实例配字典）。
写几百万个对象才有意义，日常不用管。

### 1.5 ⚠️ 可变类属性：最危险的坑

```python
class ClassRoom:
    students = []          # 可变对象当类属性


r1 = ClassRoom()
r2 = ClassRoom()
r1.students.append("小明")
print(r1.students)                          # ['小明']
print(r2.students)                          # ['小明'] ← 串味了
print(r1.students is r2.students)           # True
print(r1.__dict__, r2.__dict__)             # {} {}
r2.students.append("小红")
print(ClassRoom.students)                   # ['小明', '小红']
```

**现象**：往 `r1.students` 加东西，`r2.students` 也变了。
**原因**：`r1.students` 只是**读到**类属性那个列表（`r1.__dict__` 是空的），
`.append()` 是**原地修改共享的那个列表**，没有给 `r1` 赋值。
**处理**：可变默认值一律放进 `__init__`，每个实例造一份：

```python
class ClassRoom2:
    def __init__(self):
        self.students = []


x = ClassRoom2()
y = ClassRoom2()
x.students.append("小明")
print(x.students, y.students)               # ['小明'] []
print(x.students is y.students)             # False
```

> ⚠️ **同一个坑的另一种形态**：函数默认参数 `def f(students=[])`。
> 那个 `[]` 是**函数对象的一部分，只创建一次**，所有不传参的调用共享它。
> 普通函数不会拦你，`dataclass` 会（第 8.3 节）。
>
> **规律**：只要一个值是可变的（`list` / `dict` / `set` / 自定义对象），
> "共享"就一定意味着"互相污染"。想共享就共享不可变的（`tuple` / `str` / `int` / `frozenset`）。

## 2. `__init__` 与对象初始化（覆盖 6.2）

### 2.1 `__init__` 不是构造函数

| 方法 | 负责 | 谁调它 |
|---|---|---|
| `__new__` | **造出**一个空对象（分配） | `类(...)` 时 Python 先调它 |
| `__init__` | 往**已经造好的**对象里装数据 | `__new__` 返回的实例随后被传给它 |

```python
class Point:
    def __new__(cls, x, y):
        print("__new__ 先跑，负责造出对象")
        return super().__new__(cls)

    def __init__(self, x, y):
        print("__init__ 后跑，装数据")
        self.x, self.y = x, y


print(Point(1, 2).x)     # 1
```

```
__new__ 先跑，负责造出对象
__init__ 后跑，装数据
1
```

`__init__` 拿到的 `self` 就是 `__new__` 造出来、返回的那个对象——**它自己造不出对象**。
99% 的代码只写 `__init__`；`__new__` 只在写不可变类型的子类、单例/对象池时用。

### 2.2 `__init__` 有返回值会怎样（实测）

`__init__` 的返回值必须是 `None`——它返回的东西没人接，Python 直接当错误处理。

```python
# init_return.py
class Bad:
    def __init__(self):
        return 42


Bad()
```

```
Traceback (most recent call last):
  File "init_return.py", line 7, in <module>
    Bad()
    ~~~^^
TypeError: __init__() should return None, not 'int'
```

注意报错位置是**调用处** `Bad()`，因为返回值是 Python 在调用结束的瞬间检查的。
想在 `__init__` 里"提前退出"时写 `return`（不带东西）或不写，**不要 `return 值`**。

### 2.3 在 `__init__` 里做参数校验

`__init__` 是**唯一能保证"任何实例都经过"的地方**：

```python
class Student:
    def __init__(self, name, score):
        if not isinstance(name, str) or not name:
            raise ValueError(f"名字必须是非空字符串，收到 {name!r}")
        if not 0 <= score <= 100:
            raise ValueError(f"分数必须在 0~100，收到 {score}")
        self.name = name
        self.score = score


print(Student("小明", 91).score)     # 91
Student("", 91)      # ValueError: 名字必须是非空字符串，收到 ''
Student("小红", 120)  # ValueError: 分数必须在 0~100，收到 120
```

**为什么抛 `ValueError` 不抛 `assert`**：`assert` 在 `python -O` 下会被整条删掉，
校验就失效了（实测见 `09_异常处理.md` 第 4 节）。
校验的意义不是"我不信任调用者"，而是"**校验一次，后面所有方法都不用再想这件事**"。

## 3. 继承与 `super()`（覆盖 6.3）

### 3.1 单继承最小例子

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."


class Dog(Animal):
    def speak(self):
        return f"{self.name}：汪汪"


class Cat(Animal):
    def speak(self):
        return f"{self.name}：喵"


d = Dog("大黄")
print(d.speak(), Cat("咪咪").speak())        # 大黄：汪汪 咪咪：喵
print(d.name)                                # 大黄
print(isinstance(d, Animal), issubclass(Dog, Animal))   # True True
print(issubclass(Animal, Dog), isinstance(Dog, Animal)) # False False
```

`Dog` 里**没写 `__init__`**，但 `Dog("大黄")` 能用——`__init__` 是从 `Animal` 继承来的。

- `isinstance(对象, 类)`：这个**对象**是不是这个类（或子类）的实例。
- `issubclass(子, 父)`：这个**类**是不是那个类的子类。
- 最后一行是 `False`：`Dog` 是**类对象**，它是 `type` 的实例，不是 `Animal` 的实例。

### 3.2 ⚠️ 不调 `super().__init__()` 会怎样

这是继承里最常踩的坑，因为**它不报错，只是少了一半属性**：

```python
class Base:
    def __init__(self, name):
        self.name = name
        self.tags = []


class Child(Base):
    def __init__(self, name, age):
        # 故意不调 super().__init__(name)
        self.age = age


class Child2(Base):
    def __init__(self, name, age):
        super().__init__(name)      # 调了
        self.age = age


c = Child("小明", 18)
print(c.__dict__)                # {'age': 18}
print(c.name)
# AttributeError: 'Child' object has no attribute 'name'
print(c.tags)
# AttributeError: 'Child' object has no attribute 'tags'
print(Child2("小明", 18).__dict__)
# {'name': '小明', 'tags': [], 'age': 18}
```

对象**造出来了、也没报错**，但 `name` 和 `tags` 从来没人设过。
错误会延后爆发——`c.name` 可能在几百行之外才被访问。

**规则：只要子类写了 `__init__`，第一件事就是 `super().__init__(...)`，
把父类需要的参数原样传上去。** 漏了参数时报错很直接：

```
Traceback (most recent call last):
  File "super_wrong.py", line 10, in <module>
    Child()
    ~~~~~^^
  File "super_wrong.py", line 7, in __init__
    super().__init__()
    ~~~~~~~~~~~~~~~~^^
TypeError: Base.__init__() missing 1 required positional argument: 'name'
```

### 3.3 方法重写（override）

```python
class Logger:
    def log(self, msg):
        print(f"[基础日志] {msg}")


class TimeLogger(Logger):
    def log(self, msg):
        print("[加时间戳] ", end="")
        super().log(msg)


class UpperLogger(TimeLogger):
    def log(self, msg):
        super().log(msg.upper())


UpperLogger().log("hello")
# [加时间戳] [基础日志] HELLO
```

调用链 `UpperLogger.log` → `TimeLogger.log` → `Logger.log`：
**每一层只做自己那一件事，然后交下去。**

> ⚠️ **坑**：不要写 `super(self.__class__, self)` 这种老写法，三层以上继承会死循环。
> **Python 3 里一律写无参数的 `super()`。**

### 3.4 多继承与 MRO

```python
class A:
    def hello(self):
        print("A.hello")

    def who(self):
        return "A"


class B(A):
    def hello(self):
        print("B.hello")
        super().hello()


class C(A):
    def hello(self):
        print("C.hello")
        super().hello()


class D(B, C):
    def hello(self):
        print("D.hello")
        super().hello()


print(" / ".join(c.__name__ for c in D.__mro__))   # D / B / C / A / object
D().hello()
print("D().who() =", D().who())                    # A
```

```
D / B / C / A / object
D.hello
B.hello
C.hello
A.hello
D().who() = A
```

**MRO = Method Resolution Order（方法解析顺序）**：方法找不到时，Python 按什么顺序去各个父类翻。
`D.__mro__` 就是那个顺序，可以直接打印。逐行走一遍：

- `D()` 调 `hello()` → 先看 `D` → 打印 `D.hello`
- `D` 里 `super().hello()` → MRO 里 `D` 的**下一个** → `B` → `B.hello`
- `B` 里 `super().hello()` → `C`（`B` 的父类是 `A`，但 MRO 里 `A` 排在 `C` 后面）→ `C.hello`
- `C` 里 `super().hello()` → `A` → `A.hello`

**`super()` 的真实含义是"MRO 里的下一个"，不是"父类"。** 这是本节最该带走的一句话。

上面是**菱形继承**（`B`、`C` 都从 `A` 来，`D` 继承两者），好处是 `A.hello` 只跑一次。
MRO 用的是 **C3 线性化**算法（**具体推导本节不展开**，它不是日常写代码要掌握的东西）。
你只需要知道：MRO 是一个**确定的列表**（`类.__mro__` 打得出来）；
继承关系自相矛盾时 **Python 在定义类的时候就报错**：

```python
class X: pass
class Y: pass
class P(X, Y): pass
class Q(Y, X): pass
class R(P, Q): pass    # X 要在 Y 前，Y 又要在 X 前 —— 矛盾
# TypeError: Cannot create a consistent method resolution order (MRO) for bases X, Y
```

> **实用建议**：日常代码**尽量单继承 + 少量 mixin**（只提供几个方法、不存状态的小类）。
> 真要多继承时，先 `print(类.__mro__)` 确认顺序再写 `super()`。

## 4. 多态与鸭子类型（覆盖 6.4）

### 4.1 同一句话，不同的回答

```python
class Dog:
    def speak(self):
        return "汪汪"


class Cat:
    def speak(self):
        return "喵"


class Robot:
    def speak(self):
        return "滴——我是机器人"


class Stone:
    pass


def make_noise(thing):
    return thing.speak()          # 不检查类型，直接调


for animal in (Dog(), Cat(), Robot()):
    print(make_noise(animal))
# 汪汪 / 喵 / 滴——我是机器人

make_noise(Stone())
# AttributeError: 'Stone' object has no attribute 'speak'
```

三个**没有共同父类**的类，同一个调用写法得到不同行为——这就是多态。
`make_noise` 的签名里没有任何类型约束，传什么都行，**只要那东西有 `speak`**。
传没有 `speak` 的对象时，错误发生在**调用 `thing.speak()` 的那一刻**，不是传参那一刻。

**"如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。"**
Python 的检查标准不是"你是不是继承自某个类"，而是"**你有没有那个方法**"。

### 4.2 鸭子类型和"接口"的关系

静态类型语言里，想让函数接受多种类型，得先声明一个接口
（`interface Speaker { String speak(); }`），再让 `Dog`、`Robot` 都 `implements` 它。

Python 不需要这一步：**"有没有 `speak` 方法"这个事实本身就构成接口**，
不需要提前声明。这种隐式接口叫**协议（protocol）**，鸭子类型就是它在动态语言里的实现。

代价：**编译器读不出你的意图。** 看 `make_noise(thing)` 的签名不知道 `thing` 该长什么样。
所以 Python 用类型注解 + 文档 + 测试来补：

```python
def make_noise(thing: "任何有 speak() 的对象") -> str:
    return thing.speak()
```

### 4.3 `isinstance` 检查的取舍

```python
def make_noise_strict(thing):
    if not isinstance(thing, Dog):
        raise TypeError(f"我只接受 Dog，收到 {type(thing).__name__}")
    return thing.speak()


print(make_noise_strict(Dog()))          # 汪汪
make_noise_strict(Robot())
# TypeError: 我只接受 Dog，收到 Robot
print(isinstance(Robot(), (Dog, Robot)))  # True —— 元组表示"这几种都行"
```

**换来的**：报错更早、更清楚。**失去的**：`Robot`（明明有 `speak`）被拒之门外——
**鸭子类型的好处被你自己关掉了。**

> **判断依据**：
>
> | 场合 | 建议 |
> |---|---|
> | 校验外部输入（用户、网络、配置文件） | **用**，类型不对要立刻报清楚 |
> | 在几种内置类型之间分派（`int` / `str` / `list`） | **用**，这是 Python 自己的惯例 |
> | 判断"这对象能不能做某件事" | **别用**，直接试 + `try/except AttributeError`（EAFP） |
> | 判断"它是不是某个业务类" | **尽量别用**，改成调用方法，让鸭子类型工作 |
>
> **为什么社区倾向鸭子类型**：① 标准库和内置类型（`list`、`str`、文件对象、生成器）
> 不参与你的继承树，要求 `isinstance` 就等于全部重新包一层；
> ② 多一处要同步改的地方（新写 `Robot` 得回头改每个 `isinstance`）；
> ③ `isinstance` 常常检查错了对象——你真正要的是"能 `speak`"，写成了"是 `Dog`"。
>
> ⚠️ **坑的反面**：`make_noise(Stone())` 的报错**没说清"你应该传一个能 speak 的东西"**。
> 所以：**公开 API 上加类型注解 + 文档，内部调用放心用鸭子类型。**

## 5. 封装与命名约定 `_` / `__`（覆盖 6.5）

### 5.1 Python 没有 `private`

别的语言里 `private int balance;` 是**编译器强制**的。Python 里**没有任何机制阻止你访问任何属性**。
整个体系靠两样东西：**命名约定**（告诉读代码的人"这是内部实现，别依赖"）
和**名字改写 name mangling**（给双下划线开头的名字改名，避免继承时撞车）。

```python
class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        self._balance = balance          # 单下划线：内部用
        self.__pin = "1234"              # 双下划线：会被改名

    def _recalc(self):
        return self._balance * 1.0

    def __secret(self):
        return self.__pin


a = Account("小明", 100)
print(a._balance)          # 100 —— 单下划线能直接读，只是"别依赖"
print(a._recalc())         # 100.0
print(a.__dict__)
# {'owner': '小明', '_balance': 100, '_Account__pin': '1234'}

print(a.__pin)             # AttributeError: 'Account' object has no attribute '__pin'
print(a._Account__pin)     # 1234 —— 改写后的真名
print(a._Account__secret())  # 1234 —— 方法也一样
```

真实输出的第三行（**本节最该亲眼看的一行**）：我写的是 `self.__pin`，
存进去的键是 **`_Account__pin`**——**Python 把 `__pin` 改成了 `_类名__pin`。**
它只是改名，不是加密，知道规则就能访问。

还有一件容易搞混的事：**从类外面写 `a.__pin = ...` 不会被改名**，
所以它加的是一个**全新的、跟原来那个无关的属性**：

```python
a.__pin = "外面设的"
print(a.__pin)                 # 外面设的
print(a._Account__pin)         # 1234 —— 没被改名的那个还在
print(a.__dict__)
# {'owner': '小明', '_balance': 100, '_Account__pin': '1234', '__pin': '外面设的'}
```

> ⚠️ **坑**：`__pin` 和 `_Account__pin` 在 `__dict__` 里**同时存在**，是两个不同的属性。
> 你以为"改了私有的那个"，其实新加了一个。

### 5.2 名字改写的真正意义：防撞车

继承时父子类各写一个 `self.__x`，因为它们被改成 `_Base__x` 和 `_Child__x`，**互不覆盖**：

```python
class Base:
    def __init__(self):
        self.__x = "Base 的 x"

    def get(self):
        return self.__x          # 改写为 self._Base__x


class Child(Base):
    def __init__(self):
        super().__init__()
        self.__x = "Child 的 x"   # 改写为 self._Child__x

    def get_child(self):
        return self.__x


c = Child()
print(c.__dict__)
# {'_Base__x': 'Base 的 x', '_Child__x': 'Child 的 x'}
print(c.get(), "/", c.get_child())     # Base 的 x / Child 的 x
```

**这是名字改写真正解决的问题**：它是给**库作者**用的，
让自己内部属性不会被使用者的子类意外覆盖。

### 5.3 三者对比表 + `name_`

| 写法 | 官方叫法 | 访问得到吗 | 会被改名吗 | 给谁看 |
|---|---|---|---|---|
| `name` | public | ✅ | 否 | 谁都能用，是你承诺的 API |
| `_name` | "内部用"（非语言机制） | ✅ 能，但别依赖 | 否 | 模块/类内部；`from m import *` 不导入它 |
| `__name` | private name（会改写） | 间接能：`obj._类名__name` | **是** | 只给**本类内部**，主要防子类撞名 |
| `__name__` | dunder / magic | ✅ | 否 | Python 自己用，**不要自己造** |
| `name_` | public，`_` 只是避让 | ✅ | 否 | 名字和关键字/内置名撞了时的退路 |

尾部下划线用在**你想要的名字已经被 Python 占用了**的时候：

```python
class Person:
    def __init__(self, name, type_):
        self.name = name
        self.type_ = type_       # type 是内置函数名，加 _ 避开

    def summary(self):
        return f"{self.name} / {self.type_}"


p = Person("小明", "学生")
print(p.summary())                        # 小明 / 学生
print(type(p).__name__)                   # Person —— 内置 type 没被盖住
```

常见例子：`type_`（避 `type`）、`id_`（避 `id`）、`list_`（避 `list`）、`class_`（避关键字 `class`）。
注意它和"首尾双下划线"完全是两回事：`type_` 是普通人名，`__init__` 是 Python 定义的钩子。

### 5.4 为什么"没有 private"是设计选择

如果有真 private，这些事都做不了或要绕路：**测试**（看内部状态）、**调试**、
**序列化**（`pickle` 要读所有属性）、**交互式探索**（REPL 里 `dir(obj)`）。

Python 的取舍：**用"约定 + 文档 + 测试"代替"编译器强制"，
换来"任何东西都能被看见和改动"**。代价是你**可能改错**——
但那种错误是显式的（代码里明写着 `obj._balance`），
比"绕不过去于是整个设计烂掉"便宜得多。
社区里概括这个取舍的说法是：**"我们都是成年人"（we're all consenting adults here）。**

## 6. 魔术方法（覆盖 6.6）

**魔术方法 = 名字首尾都是双下划线、由 Python 在特定语法发生时自动调用的方法。**
你不用手写 `obj.__len__()`，写 `len(obj)` 时 Python 自动帮你调。

### 6.1 `__str__` 与 `__repr__` 的区别（实测）

```python
class Book:
    def __init__(self, title, pages):
        self.title, self.pages = title, pages


print(Book("Python 入门", 320))
# <__main__.Book object at 0x...> —— 对调试几乎没有用


class Book2:
    def __init__(self, title, pages):
        self.title, self.pages = title, pages

    def __repr__(self):
        return f"Book2(title={self.title!r}, pages={self.pages!r})"

    def __str__(self):
        return f"《{self.title}》共 {self.pages} 页"


class Book3:
    def __repr__(self):        # 只写 __repr__
        return "Book3(...)"


b2 = Book2("Python 入门", 320)
print(b2)          # 《Python 入门》共 320 页   ← 走 __str__
print(repr(b2))    # Book2(title='Python 入门', pages=320)  ← 走 __repr__
print([b2])        # [Book2(title='Python 入门', pages=320)]  ← 容器里走 __repr__
print(f"{b2}")     # 《Python 入门》共 320 页   ← 走 __str__
print(Book3(), str(Book3()))   # Book3(...) Book3(...)  ← 回退到 __repr__
```

| 触发方式 | 走哪个 |
|---|---|
| `print(obj)` / `str(obj)` / `f"{obj}"` | `__str__` |
| 交互式里直接敲 `obj` / `repr(obj)` / 容器里（`[obj]`） | `__repr__` |
| 只定义了 `__repr__` 时的 `print(obj)` | 回退到 `__repr__` |

**分工**：`__str__` 给人看（可以中文、可以省略细节、可以不唯一）；
`__repr__` 给开发者和调试看（尽量唯一、尽量能重建对象，所以字符串用 `!r` 带引号）。

> **实践建议**：**只写 `__repr__` 是不会后悔的最小投入。** 每个类都值得有一个，
> `__str__` 在需要给人看的场合再补。

### 6.2 ⚠️ `__eq__` 与 `__hash__` 的联动

```python
class P1:
    def __init__(self, x, y):
        self.x, self.y = x, y


class P2:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)


class P3(P2):
    def __hash__(self):
        return hash((self.x, self.y))     # 用和 __eq__ 同一组字段


print(P1(1, 2) == P1(1, 2))              # False —— 默认比身份
print(len({P1(1, 2), P1(1, 2)}))         # 2 —— set 去重不生效
print(P2(1, 2) == P2(1, 2))              # True
print(P2.__hash__)                       # None
hash(P2(1, 2))
# TypeError: unhashable type: 'P2'
print(hash(P3(1, 2)) == hash(P3(1, 2)))  # True
print(len({P3(1, 2), P3(1, 2)}))         # 1
```

**现象**：定义了 `__eq__` 之后，`hash()` 报 `TypeError: unhashable type`。
**原因**：Python 认为"能判等"和"能哈希"必须**配套**，
所以在你定义 `__eq__` 时**自动把 `__hash__` 设成 `None`**（表示不可哈希）。
**处理**：需要放进 `set` / 当 `dict` 键时自己补一个（`P3` 那样）。
**必须遵守的约定**：

> **`a == b` 为真 ⟹ `hash(a) == hash(b)` 必须为真。**
> 反之不要求（不同对象可以同哈希，那叫"哈希碰撞"，正常）。

违反约定的后果是**静默的**：

```python
class P4:
    def __eq__(self, other):
        return True          # 所有实例都"相等"

    def __hash__(self):
        return id(self)      # 但哈希按身份算


print(P4() == P4())            # True
print(len({P4(), P4()}))       # 2 ← 两个"相等"的对象各占一个位置
```

不报错，但结果没有意义。

> ⚠️ **坑**：只想让对象能比较、不需要放 `set` 时，**不要为了消掉报错随便写
> `__hash__ = object.__hash__`**。那等于宣布"相等但哈希不同"，正好踩上面的约定。
> 正确做法是让 `__hash__` 基于**和 `__eq__` 同一组字段**。

### 6.3 容器类：`__len__` / `__getitem__` / `__iter__` / `__contains__`

```python
class Playlist:
    def __init__(self, songs):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        print(f"  [__getitem__ index={index!r}]")
        return self._songs[index]

    def __contains__(self, item):
        print(f"  [__contains__ item={item!r}]")
        return item in self._songs


class Playlist2:                 # 只写 __getitem__，不写 __contains__ / __iter__
    def __init__(self, songs):
        self._songs = list(songs)

    def __len__(self):
        return len(self._songs)

    def __getitem__(self, index):
        return self._songs[index]


pl = Playlist(["歌A", "歌B", "歌C"])
print(len(pl))               # 3
print(pl[0])                 # 歌A
print(pl[-1])                # 歌C
print(pl[0:2])               # ['歌A', '歌B']
print("歌B" in pl)           # True

pl2 = Playlist2(["歌A", "歌B", "歌C"])
print("歌B" in pl2, list(pl2))    # True ['歌A', '歌B', '歌C']
print(list(iter(pl2)) == list(pl2))   # True —— for 循环也能用
```

```
3
  [__getitem__ index=0]
歌A
  [__getitem__ index=-1]
歌C
  [__getitem__ index=slice(0, 2, None)]
['歌A', '歌B']
  [__contains__ item='歌B']
True
True ['歌A', '歌B', '歌C']
True
```

两件事：切片传进来的是一个 **`slice` 对象**，不是两个整数；
**只写 `__getitem__` 时 `in` / `for` / `list(...)` 也自己工作了**——
Python 找不到 `__contains__` / `__iter__` 时会**退回到用 `__getitem__` 从 `0` 开始一直取，
遇到 `IndexError` 就停**（旧式迭代协议）。方便，但成员判断是 **O(n)**（一个个比）。
数据量大时自己实现 `__iter__`：

```python
class Playlist3:
    def __init__(self, songs):
        self._songs = list(songs)

    def __iter__(self):
        print("  [__iter__ 被调用]")
        return iter(self._songs)


print(list(Playlist3(["歌A", "歌B"])))
#   [__iter__ 被调用]
# ['歌A', '歌B']
```

> 迭代器与生成器的完整机制见 `11_进阶主题.md`（覆盖表 9.1、9.2）。
> 这里只记：**`__getitem__` 是偷懒路线，`__iter__` 是正式路线。**

### 6.4 运算符重载与 `__call__`

```python
class Money:
    def __init__(self, amount):
        self.amount = amount

    def __repr__(self):
        return f"Money({self.amount})"

    def __add__(self, other):
        return Money(self.amount + other.amount)

    def __rmul__(self, k):                 # 左边不是 Money 时用这个
        print("  [__rmul__ 被调用]")
        return Money(self.amount * k)

    def __eq__(self, other):
        return self.amount == other.amount

    def __lt__(self, other):
        return self.amount < other.amount

    def __hash__(self):
        return hash(self.amount)

    def __call__(self, times):             # 让实例能像函数一样调
        return Money(self.amount * times)


a, b = Money(10), Money(25)
print(a + b)                 # Money(35)
print(3 * a)                 # Money(30)（先打印 [__rmul__ 被调用]）
print(a == Money(10), a < b) # True True
print(sorted([b, a]))        # [Money(10), Money(25)]
print(a(2))                  # Money(20)
print(callable(a), callable(3))   # True False
```

- `self + other` → `self.__add__(other)`；
  `3 * a`（左边不是 `Money`）→ 调 `a.__rmul__(3)`（**r** = reflected，"反射"版）。
- `a < b` → `__lt__`；`sorted(...)` 靠它。
- `__call__` 让实例能像函数一样调用，`callable(a)` 为 `True` 就是因为它有 `__call__`。
  适合"有状态的可调用对象"——闭包能做的事它都能做，而且状态更显式。

> ⚠️ **坑**：`__eq__` 里直接写 `other.amount`，如果 `other` 是别的类型（比如 `None`），
> 会抛 `AttributeError` 而不是返回 `False`。稳妥写法是先
> `if not isinstance(other, Money): return NotImplemented`——
> 注意是 `NotImplemented`（告诉 Python "我不认识它，你换别人试试"），
> 不是返回 `False`，更**不要 `raise NotImplementedError`**（那是另一回事）。

### 6.5 `with` 背后的 `__enter__` / `__exit__`

```python
class Managed:
    def __enter__(self):
        print("[__enter__] 进入 with 块")
        return self

    def __exit__(self, exc_type, exc, tb):
        print(f"[__exit__] 离开 with 块，异常类型 = {exc_type}")
        return False        # 返回 False = 不吞异常


with Managed() as m:
    print("  在 with 里面")
```

```
[__enter__] 进入 with 块
  在 with 里面
[__exit__] 离开 with 块，异常类型 = None
```

`with` 块的代码等价于：`mgr = Managed()` → `m = mgr.__enter__()` →
`try: ...里面的代码...` → `finally: mgr.__exit__(异常类型, 异常, traceback)`。
所以出错时 `__exit__` 拿到的 `exc_type` 就是异常类（没出错是 `None`），
**返回 `True` 会吞掉异常**。完整原理、`contextlib.contextmanager` 等细节，
见 `10_文件与IO.md`（覆盖表 8.3 节）。

### 6.6 常用魔术方法速查

| 你写的代码 | 调的方法 | 什么时候最有用 |
|---|---|---|
| `str(x)` / `print(x)` / f-string | `__str__` | 给人看的输出 |
| `repr(x)` / 交互式 / 容器里 | `__repr__` | 调试、日志 |
| `len(x)` | `__len__` | 自定义容器 |
| `x[k]` / `x[a:b]` | `__getitem__` | 下标、切片，顺带白拿迭代 |
| `x[k] = v` / `del x[k]` | `__setitem__` / `__delitem__` | 可写/可删容器 |
| `k in x` | `__contains__` | 成员判断（不写就退化成线性扫描） |
| `for i in x` | `__iter__` | 自定义迭代（→ `11_进阶主题.md`） |
| `x == y` | `__eq__` | 值相等 |
| `hash(x)` / `{x}` / `{x: 1}` | `__hash__` | 可哈希（和 `__eq__` 绑在一起） |
| `x < y` / `sorted(...)` | `__lt__` | 排序、比较 |
| `x + y` / `x * k` | `__add__` / `__mul__` / `__rmul__` | 数值型、字符串型对象 |
| `if x:` | `__bool__` | 真值判断（不写就回退到 `__len__`） |
| `x(...)` | `__call__` | 有状态的可调用对象 |
| `with x:` | `__enter__` / `__exit__` | 资源管理（→ `10_文件与IO.md`） |

**不要试图一次背完。** 需要给某个类加"看起来像内置类型"的行为时回来查这张表就够了。
**"常用部分完整"比"穷尽"有用。**

> ⚠️ **坑**：**不要自己发明新的双下划线名字**（比如 `__my_helper__`）。
> Python 保留将来使用它们的权利，你的代码可能某天因为新版本而行为变化。

## 7. 类方法 / 静态方法 / `@property`（覆盖 6.7）

### 7.1 不加 `property`：只能写成 `get_x()` / `set_x()`

```python
class Person0:
    def __init__(self, age):
        self._age = age

    def get_age(self):
        return self._age

    def set_age(self, value):
        if value < 0:
            raise ValueError("年龄不能为负")
        self._age = value


p0 = Person0(18)
print(p0.get_age())          # 18
p0.set_age(20)
print(p0.get_age())          # 20
print(p0.get_age)            # <bound method Person0.get_age of ...>
```

三个不舒服：**用起来啰嗦**、**忘了括号不报错**（`p0.get_age` 拿到方法对象，
`if p0.get_age:` 永远为真）、**改名成本高**（想换成属性 `age` 时所有调用点都得改）。

### 7.2 `@property`：看起来像属性，实际跑逻辑

```python
class Person:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):
        print("  [age 的读逻辑跑了]")
        return self._age

    @age.setter                      # 名字必须和上面那个方法同名
    def age(self, value):
        print(f"  [age 的写逻辑跑了，value={value}]")
        if value < 0:
            raise ValueError("年龄不能为负")
        self._age = value


class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):                  # 只读：不给 setter
        return 3.14159 * self.r ** 2


p = Person(18)
print(p.age)          # 18
p.age = 20
print(p.age)          # 20
p.age = -1            # ValueError: 年龄不能为负
print(p.age)          # 20 —— 校验失败后还是旧值
print(Person.age)     # <property object at 0x...>
print(p.__dict__)     # {'_age': 20}

print(Circle(2).area)  # 12.56636
Circle(2).area = 100
# AttributeError: property 'area' of 'Circle' object has no setter
```

- **`@property` 装的是一个"描述符对象"**，它拦住 `p.age` 这个访问动作，转去调你写的函数。
- **真正的数据存在 `_age` 里**（`p.__dict__` 只有 `_age`）。
  所以读方法里千万不能写 `return self.age`——那会无限递归：

```python
class Boom:
    @property
    def x(self):
        return self.x          # 自己调自己


Boom().x    # RecursionError: maximum recursion depth exceeded
```

> ⚠️ **坑**：`@property` 的名字和背后的存储属性**必须不同**（`age` / `_age`）。
> 这是本节最容易写出无限递归的地方。

`Circle.area` 那种"算出来的属性"是 `property` 最值得用的场合：
`area` 不作为数据存着（改了 `r` 就失效），而是每次现算，并且**故意不给 setter**，
让 `c.area = 100` 直接报错而不是悄悄无效。

### 7.3 `@classmethod` 与 `@staticmethod`

```python
class Temperature:
    unit = "摄氏度"

    def __init__(self, value):
        self.value = value

    def show(self):
        return f"{self.value} {self.unit}"          # 实例方法：收 self

    @classmethod
    def from_fahrenheit(cls, f):                     # 类方法：收 cls
        print(f"  [from_fahrenheit 收到的 cls = {cls.__name__}]")
        return cls(round((f - 32) / 1.8, 2))

    @classmethod
    def rename_unit(cls, new_name):
        cls.unit = new_name

    @staticmethod
    def is_freezing(v):                              # 静态方法：谁也不收
        return v <= 0


class Animal:
    def __init__(self, name):
        self.name = name

    @classmethod
    def make(cls, name):
        print(f"  [make 收到的 cls = {cls.__name__}]")
        return cls(name)


class Dog(Animal):
    pass


t = Temperature(25)
print(t.show())                                  # 25 摄氏度
print(Temperature.from_fahrenheit(98.6).value)    # 37.0
print(Temperature.is_freezing(-5), t.is_freezing(10))   # True False
Temperature.rename_unit("摄氏")
print(Temperature.unit, t.unit)                  # 摄氏 摄氏

Animal.make("某个动物")                           # [make 收到的 cls = Animal]
Dog.make("大黄")                                  # [make 收到的 cls = Dog]
```

从对象上看它们分别是什么：

```
Temperature.show            -> <function Temperature.show at 0x...>
t.show                      -> <bound method Temperature.show of ...>
Temperature.from_fahrenheit -> <bound method Temperature.from_fahrenheit of <class '...Temperature'>>
Temperature.is_freezing     -> <function Temperature.is_freezing at 0x...>
```

- 实例方法：**从类取出来还是普通函数**，从实例取出来才变绑定方法。
- `classmethod`：**从类取出来就已经是绑定方法**，绑的是"类"。
- `staticmethod`：**从哪取都是普通函数**，没有隐式参数。

**`cls` 永远是"实际被调用的那个类"。** 如果 `make` 写成 `@staticmethod` 并在里面硬写
`Animal(name)`，那 `Dog.make()` 造出来永远 `Animal`——**这就是工厂方法里
`classmethod` 优于 `staticmethod` 的根本原因。**

### 7.4 三者对比表

| | 第一个参数 | 从实例调用 | 从类调用 | 访问实例属性 | 改类属性 | 典型场合 |
|---|---|---|---|---|---|---|
| 实例方法 `def m(self)` | `self`（实例） | ✅ | ✅（手动传实例） | ✅ | ✅ | 绝大多数方法 |
| `@classmethod def m(cls)` | `cls`（类） | ✅ | ✅ | ❌ | ✅ | 备用构造器、读/改类级配置 |
| `@staticmethod def m()` | 无 | ✅ | ✅ | ❌ | ❌ | 逻辑上属于这个类、但不用任何状态的工具函数 |
| `@property def m(self)` | `self` | ✅ 当属性用 | ✅（返回 property 对象） | ✅ | ✅ | 算出来的属性、需要校验的读 |

**怎么选**：① 要用 `self` → **实例方法**（默认）。
② 要造对象、且希望子类继承这个造法 → **`@classmethod`**（命名 `from_xxx` / `parse_xxx`）。
③ 既不用 `self` 也不用 `cls` → 先问"**它真的属于这个类吗**"：只是碰巧放这儿 → 放模块级当普通函数；
确实和类是一套概念 → `@staticmethod`。④ "读的时候要算/要校验" → `@property`。

> 实例方法：`list.append`；类方法：`dict.fromkeys`、`datetime.now`。

### 7.5 `property` 和直接暴露属性的取舍

| | 直接 `self.age` | `@property` |
|---|---|---|
| 写法 | 少 | 多（读 + 写两个方法） |
| 校验 / 只读 / 算出来的值 | 做不到 | 都能 |
| 调试 | `p.age = 1` 一眼看懂 | 可能有隐藏逻辑（读一下会跑代码） |
| 性能 | 最快 | 每次访问多一次函数调用 |

**判断依据**：**一开始就直接写 `self.age`。** `property` 的存在意义正是
"**以后需要加逻辑时，调用方代码不用改**"，不需要提前防御。
出现下面三种需求之一时**再改成 `property`**：赋值要校验或转换、
值是从别的数据算出来的、要对外只读对内可写。

> ⚠️ **坑**：`property` 让"读属性"**可能有副作用**（跑代码、抛异常、变慢）。
> 循环里访问几百万次 `obj.x` 时开销会显出来。循环内先 `x = obj.x` 取出来再用。

## 8. `dataclass`（覆盖 6.8）

### 8.1 先看手写有多繁琐

```python
class StudentManual:
    def __init__(self, name, age, score=0):
        self.name, self.age, self.score = name, age, score

    def __repr__(self):
        return (f"StudentManual(name={self.name!r}, age={self.age!r}, "
                f"score={self.score!r})")

    def __eq__(self, other):
        if not isinstance(other, StudentManual):
            return NotImplemented
        return (self.name, self.age, self.score) == (other.name, other.age, other.score)

    def __hash__(self):
        return hash((self.name, self.age, self.score))


a, b = StudentManual("小明", 18, 91), StudentManual("小明", 18, 91)
print(a)              # StudentManual(name='小明', age=18, score=91)
print(a == b)         # True
```

**问题**：3 个字段写了 15 行样板。字段加到 8 个，`__eq__` 会变成一长串元组，
而且**加字段时你必须记得同步改三处**（`__init__`、`__repr__`、`__eq__`/`__hash__`），
忘一处就出隐 bug。

### 8.2 `@dataclass`：按字段声明自动生成

```python
from dataclasses import dataclass


@dataclass
class Student:
    name: str
    age: int
    score: int = 0


c, d = Student("小明", 18, 91), Student("小明", 18, 91)
print(c)                        # Student(name='小明', age=18, score=91)
print(c == d)                   # True
print(c.name, c.age, c.score)   # 小明 18 91
```

**字段写法就是类型注解**（`name: str`）——`@dataclass` 靠读类里的 `__annotations__`
知道有哪些字段、顺序如何。**类型注解本身不做校验**（写 `name: int` 再传 `"小明"` 也不报错），
它只是"字段声明"的载体。

> `@dataclass` 生成的 `__eq__` 按字段比值，所以它**同样会把 `__hash__` 设成 `None`**
> （和 6.2 节同一条规则），默认的 dataclass 实例**不可哈希**、不能放 `set`。
> 需要时用 `frozen=True`。**`unsafe_hash` 等参数本节未实测，不声称行为。**

### 8.3 ⚠️ `field(default_factory=list)` 解决可变默认值

第 1.5 节的坑在普通类里长这样：

```python
class CourseBad:
    def __init__(self, name, students=[]):    # ← 危险
        self.name, self.students = name, students


c1, c2 = CourseBad("数学"), CourseBad("语文")
c1.students.append("小明")
print(c1.students, c2.students)     # ['小明'] ['小明']  ← 串味了
```

`dataclass` **直接把这种写法当成错误**，并要求你用 `field(default_factory=...)`：

```python
from dataclasses import dataclass, field


@dataclass
class CourseBad2:
    name: str
    students: list = []      # ValueError: mutable default <class 'list'> for field
                             # students is not allowed: use default_factory


@dataclass
class Course:
    name: str
    students: list = field(default_factory=list)   # 每次新建实例时才调一次 list()


x, y = Course("数学"), Course("语文")
x.students.append("小明")
print(x.students, y.students)                    # ['小明'] []
print(x.students is y.students)                  # False
```

`default_factory=list` 的意思是"**默认值不是一个列表，而是一个"造列表的函数"**，
每次需要默认值时调它一次"。`dict` / `set` 同理。

### 8.4 `frozen=True` 与 `order=True`

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Point:
    x: int
    y: int


@dataclass(order=True)
class Version:
    major: int
    minor: int


p = Point(1, 2)
print(p)                        # Point(x=1, y=2)
p.x = 10
# FrozenInstanceError: cannot assign to field 'x'
print({Point(1, 2): "原点旁边"}[Point(1, 2)])          # 原点旁边
print(hash(Point(1, 2)) == hash(Point(1, 2)))          # True

print(Version(1, 2) < Version(1, 10))    # True（先 major，相等再 minor）
print(sorted([Version(2, 0), Version(1, 2)]))
# [Version(major=1, minor=2), Version(major=2, minor=0)]
Version(1, 0) < 5
# TypeError: '<' not supported between instances of 'Version' and 'int'
```

`FrozenInstanceError` 是 `AttributeError` 的子类。**`frozen=True` 会自动生成基于字段的
`__hash__`**，所以实例能进 `set`、能当 `dict` 键。用它表示"不该变的值对象"：坐标、版本号、配置项。
`order=True` 按**字段声明顺序**生成 `<` `<=` `>` `>=`，顺序由字段顺序决定，不能通过参数调整；
比较是**同类之间**的，跨类型比会抛 `TypeError`（不是返回 `False`）。

> ⚠️ **坑**：`frozen=True` 只**禁止重新赋值**，不禁止里面的可变对象被改：
> ```python
> @dataclass(frozen=True)
> class Bag:
>     tags: list = field(default_factory=list)
>
> b = Bag()
> b.tags.append("x")     # 成功！
> print(b.tags)          # ['x']
> b.tags = ["别的"]      # FrozenInstanceError: cannot assign to field 'tags'
> ```
> 真正的"完全不可变"要求所有字段本身也不可变（用 `tuple` / `frozenset`）。

### 8.5 `asdict()` / `fields()` / `__post_init__`

```python
from dataclasses import dataclass, field, asdict, fields


@dataclass
class Course:
    name: str
    students: list = field(default_factory=list)


@dataclass
class Student:
    name: str
    score: int

    def __post_init__(self):
        if not 0 <= self.score <= 100:
            raise ValueError(f"分数必须在 0~100，收到 {self.score}")


print(asdict(Course("数学")))              # {'name': '数学', 'students': []}
print([f.name for f in fields(Course)])    # ['name', 'students']
print(Student("小明", 91))                 # Student(name='小明', score=91)
Student("小红", 120)
# ValueError: 分数必须在 0~100，收到 120
```

- **`asdict(obj)`**：递归转成普通 `dict`（嵌套 dataclass 也转）。
  **注意是深拷贝**：里面的 `list` 也是新列表，改它不会影响原对象。
- **`fields(类)`**：字段元数据（名字、类型、默认值）。写通用序列化/校验/表单时有用。
  还有 `astuple(obj)`。
- **`__post_init__`**：在自动生成的 `__init__` **末尾**被调用，字段已经就位，
  适合放"生成的 `__init__` 干不了的事"（校验、派生字段）。

### 8.6 `@dataclass` 与普通类的取舍

| 需求 | 用哪个 |
|---|---|
| 主要是**装数据**（配置、DTO、坐标、解析结果、测试夹具） | **`@dataclass`** |
| 需要"值相等"语义（字段一样就该 `==`） | **`@dataclass`** |
| 需要不可变的值对象 | **`@dataclass(frozen=True)`** |
| 需要排序 | **`@dataclass(order=True)`** |
| 有大量行为、状态机、复杂不变量 | **普通类**（或 `@dataclass` + `__post_init__`） |
| 要精细控制 `__init__` 的签名和参数处理 | **普通类** |
| 字段存进去就要加密/改形 | **普通类**（或 `property`） |

> **判断依据**：**主要工作是"记住几个值" → `@dataclass`；主要工作是"做一件事" → 普通类。**
> 分界线是数据还是行为占主导，不是代码行数。

**`dataclass` 继承**的规则是"父类有默认值的字段不能排在子类无默认值字段前面"
（和函数默认参数的规则一样）——**这条我按逻辑推断，本节没有实测反例，遇到报错时按这个方向排查。**

## 9. 抽象基类 `abc`（覆盖 6.9）

### 9.1 问题：约定靠自觉

回到第 3 节。假设你希望**每个图形子类都实现 `area()`**。纯靠约定时：

```python
class Shape:
    def area(self):
        raise NotImplementedError("子类必须实现 area")


class Rect(Shape):
    pass          # 忘了实现
```

`Rect()` 能造出来，`Rect().area()` 直到被调用才炸。**"必须实现"只存在于你的注释里。**

### 9.2 `ABC` + `@abstractmethod`：把约定变成检查

```python
from abc import ABC, abstractmethod


class Shape(ABC):
    @abstractmethod
    def area(self): ...

    @abstractmethod
    def perimeter(self): ...

    def describe(self):                 # 非抽象方法，子类直接继承
        return f"图形，面积 {self.area()}，周长 {self.perimeter()}"


class Rect(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h

    def area(self):
        return self.w * self.h

    def perimeter(self):
        return 2 * (self.w + self.h)


class HalfShape(Shape):
    def area(self):
        return 0                        # 只实现一半


print(Rect(3, 4).describe())            # 图形，面积 12，周长 14
print(Rect.__abstractmethods__)         # frozenset()

HalfShape()
# TypeError: Can't instantiate abstract class HalfShape without an implementation
# for abstract method 'perimeter'

Shape()
# TypeError: Can't instantiate abstract class Shape without an implementation
# for abstract method 'area', 'perimeter'
```

`frozenset()` 是空集合，意思是"一个抽象方法都没剩，可以实例化"。
**检查发生在实例化的那一刻**，不是调用方法的那一刻，而且报错点名缺哪个方法。

### 9.3 抽象基类解决什么、代价是什么

**解决的**：把"你必须实现这几个方法"从注释变成**实例化时的硬检查**。
好处是**错误提前**（写代码时而不是上线时），而且**报错点名缺哪个方法**。

**代价（和鸭子类型的冲突）**：想用你的 `Shape`，**必须继承它**。
而鸭子类型说"有 `area()` 就行"——第 4 节那个 `Robot` 明明有 `speak`，
但不继承你的抽象基类就会被挡住。

| 场合 | 建议 |
|---|---|
| 你**提供框架**、别人写插件（插件必须遵守一组方法名） | 用 `ABC`，报错清楚 |
| 你写内部代码，调用者和被调用者都在同一仓库 | 鸭子类型 + 测试，别加抽象层 |
| 想要"有这个方法就行"的静态检查 | `Protocol` |
| 只想表达"这个类不该被直接使用" | 一个 `NotImplementedError` 往往就够 |

> **`Protocol`（结构化子类）** 是另一条路：用类型检查器（mypy / pyright）实现
> "**有这些方法就算符合这个协议**"，不需要真的继承——正好把鸭子类型的意图写进类型注解里。
> 具体用法见 `11_进阶主题.md`（覆盖表 9.5 节）。**本节不展开，也不声称实测过它的运行时行为。**

> ⚠️ **坑**：`@abstractmethod` **只在被 `ABCMeta` 处理过的类上生效**。
> 如果你的类继承的不是 `ABC`（也没写 `metaclass=ABCMeta`），
> `@abstractmethod` 就只是个普通装饰器，**不会拦住实例化**。

   `Stone` 的情况下错误发生在**函数内部执行 `thing.speak()` 的那一刻**，
   抛 `AttributeError: 'Stone' object has no attribute 'speak'`。
8. 键是 **`_Account__pin`**（name mangling 把 `__pin` 改成 `_类名__pin`）。
   从外面 `a.__pin = "x"` **不改名**，所以 `__dict__` 里**同时有两个**：
   `'_Account__pin': '1234'` 和 `'__pin': 'x'`，是两个不相干的属性。
9. 报 `TypeError: unhashable type: 'P2'`——Python 在你定义 `__eq__` 时
   **自动把 `__hash__` 设成 `None`**。
   硬塞的话是 **2 个**：`set` 先用哈希分桶，两个对象哈希不同就永远不会做相等比较。
   这违反"相等则同哈希"的约定，结果没有意义。
10. | 写法 | 走哪个 |
    |---|---|
    | `print(obj)` | `__str__` |
    | 交互式敲 `obj` | `__repr__` |
    | `[obj]` / `f"{obj!r}"` | `__repr__` |
    | `f"{obj}"` | `__str__` |

    只写了 `__repr__` 时 **`print(obj)` 回退到 `__repr__`**——
    所以"只写 `__repr__`"是性价比最高的选择。

</details>
