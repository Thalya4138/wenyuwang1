## 0. 先记住六件事

1. **变量是名字，不是盒子。** 赋值是"把名字贴到对象上"，不是"把值装进变量"。
   这条决定了 `a = b`、传参、默认参数三处坑。
2. **类型属于对象，不属于名字。** 同一个名字可以先指 `int` 再指 `str`，Python 不拦。
3. **`bool` 是 `int` 的子类。** 所以 `True == 1`、`True + True == 2`、`sum([True, True]) == 2`。
4. **`0.1 + 0.2 != 0.3`。** 不是 bug，是二进制浮点的固有性质。等值判断用 `math.isclose()`。
5. **`+=` 在不同类型上做的事不一样。** 列表就地改，元组 / 字符串 / 整数造新对象。
6. **`input()` 永远返回字符串。** 想拿数字必须自己转，转了就可能 `ValueError`。

本章所有输出都在本机 **Python 3.13.15** 上实测。运行环境统一：

```powershell
# PowerShell
$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"; [Console]::OutputEncoding=[Text.Encoding]::UTF8
python your_script.py
```

```bash
# Git Bash
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8
```

不加这两行，本机终端编码是 `cp936`，中文输出会乱码——见 `01_入门与环境.md` 第 6 节和本章 7.6 节。

## 1. 注释（覆盖 1.1）

### 1.1 `#` 的三条规则

```python
# 整行注释
print("这行会执行")   # 行尾注释，从 # 到行尾全被忽略
s = "# 我在字符串里，不是注释"
print(s)              # → # 我在字符串里，不是注释
```

| 规则 | 说明 |
|---|---|
| 从 `#` 到**行尾** | 后面全忽略，包括引号、括号 |
| 可以被字符串包住 | `"#"` 里的是普通字符 |
| **没有块注释** | 没有 `/* ... */`，多行注释就写多个 `#` |

### 1.2 三引号字符串**不是**注释

```python
def has_doc():
    """我是文档字符串。"""
    x = 1
    return x


def no_doc():
    x = 1
    """我不是文档字符串，只是一条没用的字符串表达式。"""
    return x


print(repr(has_doc.__doc__))   # → '我是文档字符串。'
print(repr(no_doc.__doc__))    # → None
```

三引号文字是**货真价实的 `str` 对象**，只是没人接住、算完丢掉。REPL 里立刻能看出差别——
注释不可能有值：

```
>>> """我不是注释"""
'我不是注释'
```

**硬证据**：同样的字面量放在函数体**第一条**会被存进 `__doc__`，放在别处什么都不是。

### 1.3 docstring 与 `#` 的本质区别

| | `#` 注释 | docstring |
|---|---|---|
| 解释器保留吗 | ❌ 编译时丢掉 | ✅ 存进 `__doc__` |
| 运行期能读吗 | 不能 | 能，`f.__doc__` |
| 出现在 `help()` 里吗 | 不会 | 会 |
| `python -OO` 会去掉吗 | 本来就没了 | ✅ 会变成 `None`（本机实测） |
| 写法 | `# ...` | 函数 / 类 / 模块第一条语句位置的 `"""..."""` |

`help(has_doc)` 的真实输出：

```
Help on function has_doc in module __main__:

has_doc()
    我是文档字符串。
```

`__doc__` 是**普通属性，能被改**：`has_doc.__doc__ = "改过了"` 之后就真的读到 `'改过了'`。
所以 `help()` 出来的东西可能和源码不一致——有框架会在运行时批量改写它。

**怎么选**：这段文字需不需要在**运行期**被程序拿到？需要 → docstring；不需要 → `#`。
临时屏蔽一段代码用 `#`（三引号会真构造字符串，还占 `__doc__`）。

> 官方词法定义：<https://docs.python.org/3/reference/lexical_analysis.html>
> 这份文档规定"什么算注释、什么算字符串字面量"。值得注意的一条是：
> docstring 的识别发生在**编译期**，所以它是语法概念，不是命名约定。

### 1.4 `# TODO` 约定（以及它其实没人管）

`TODO` / `FIXME` / `XXX` / `HACK` 是**人的约定**，Python 不认识。
写法是"标记 + 冒号 + 说明"，可选作者或 issue 号：

```python
# TODO: 把硬编码路径改成从配置读取
# TODO(alice): 加个失败重试
# TODO(#142): 等上游修了再删掉这段
# FIXME: 空列表时这里会除零
```

**它能不能被自动检查？** 本机 `.venv` 里的 `ruff 0.16.8` 有 `TD` 规则组，**默认不开**。对上面那个文件实测：

```
$ ruff check demo.py
All checks passed!                      ← 默认根本不管 TODO

$ ruff check --select TD --statistics demo.py
3	TD003	missing-todo-link
2	TD002	missing-todo-author
1	TD001	invalid-todo-tag
1	TD004	missing-todo-colon
```

两个反直觉的点：**`FIXME` 会被 `TD001` 判成"非法标记"**（`ruff rule TD001` 原文说只有 `FIXME` 和 `XXX`
会被这条报出来，建议统一写成 `TODO`）；**不开 `--select TD` 就没人管**。
所以"写了 TODO 就是留了债"这句话，只在你真的开了检查时成立。

### 1.5 注释的坑

> ⚠️ **坑 1**：`#` 会吃掉后面**所有**内容，包括看起来像代码的括号。
> `print(1)  # 说明一下 print(2)` 只打印 `1`。现象是"我明明写了却没执行"，原因是它根本在注释里。
> 处理：别在注释里写像真代码的东西。

> ⚠️ **坑 2**：docstring 里写 Windows 路径会炸。`"""C:\Users\Wang"""` 里的 `\U` 被当成 Unicode 转义开头。
> 处理：用 `r"""..."""`（见 `03_字符串.md` 第 4 节）。

## 2. 变量与赋值、动态类型（覆盖 1.2）

### 2.1 赋值 = 把名字贴到对象上

```python
a = b = c = 1
print(a, b, c)          # → 1 1 1

x, y = 10, 20
print(x, y)             # → 10 20
x, y = y, x             # 交换，不需要中间变量
print(x, y)             # → 20 10

m = n = [1, 2]
print(m is n)           # → True        ← 同一个对象，不是复制两份
m.append(3)
print(n)                # → [1, 2, 3]   ← n 也跟着变了
```

`a = b = c = 1` **不是**"把 1 复制三份"。它是：先算出右边的对象，然后把三个名字**依次贴到同一个对象**上。
`=` 从来不是复制。

`x, y = 10, 20` 的完整含义是元组解包：右边先构成 `(10, 20)`，再按顺序分发。所以下面四种写法等价：

```python
x, y = 10, 20
x, y = (10, 20)
(x, y) = 10, 20
(x, y) = (10, 20)
```

**交换为什么安全**：右边**先完整求值**成 `(20, 10)`，求值发生在任何赋值之前。个数对不上会报错（实测）：

```
ValueError: too many values to unpack (expected 2)
ValueError: not enough values to unpack (expected 3, got 2)
```

### 2.2 动态类型：名字没有类型，对象才有

```python
z = 1
print(type(z))          # → <class 'int'>
z = "现在是字符串"
print(type(z))          # → <class 'str'>
```

**这不是"变量的类型变了"，而是"名字换了个对象贴"。** 名字从不携带类型信息，类型存在**对象**上。

| 好处 / 代价 | 说明 |
|---|---|
| ✅ 灵活 | 一个函数可以接受任何"长得像"的对象 |
| ❌ 错误推迟到运行期 | `"a" + 1` 只有真跑到那行才炸 |
| ❌ 大项目难维护 | 所以后来有了类型注解（`06_函数.md`），它是可选的可读性工具 |

> 官方数据模型：<https://docs.python.org/3/reference/datamodel.html>
> 最该记住的一句：对象有 **identity（身份）、type（类型）、value（值）** 三样，
> 而名字只是"命名空间里 名字 → 对象 的一条映射"。记住这句，第 6 节的可变性就顺理成章。

### 2.3 `type()`、`isinstance()`、`id()`

```python
print(type(1))                          # → <class 'int'>
print(isinstance(True, int))            # → True
print(isinstance(1, float))             # → False
print(isinstance(1, (float, complex)))  # → False   ← 第二个参数可以是元组

v = 42
print(id(v))                            # → 140713070930120（每次运行都可能不同）
w = v
print(id(w) == id(v))                   # → True
```

| | `type(x) is T` | `isinstance(x, T)` |
|---|---|---|
| 考虑子类吗 | ❌ 不考虑 | ✅ 考虑 |
| 用在哪 | 极少（要求"恰好是这个类型"） | **绝大多数情况** |
| 翻车例子 | `type(True) is int` → `False`，尽管 `True` 就是整数 | 无 |

`id()` 的三条性质：**每次运行都可能不同**（它是地址不是稳定编号，所以永远别写进业务逻辑）；
**`id` 相同 ⇒ 一定是同一个对象**（这是 `is` 的实现基础）；**对象回收后 `id` 会被复用**，
所以"记下 id 等会儿再比"无效。

> ⚠️ **坑**：别用 `type(x) == int` 做整数校验。
> 现象：传 `True` 进去判断失败。原因：`bool` 是 `int` 子类但不是 `int` 本身。
> 处理：用 `isinstance(x, int)`；确实要排除 `bool` 就写 `isinstance(x, int) and not isinstance(x, bool)`。

### 2.4 变量不是盒子——一个能推翻它的实验

```python
t = [1, 2, 3]
print(id(t))            # → 2123512393408
t = t + [4]
print(id(t))            # → 2123512348224   ← 变了
print(t)                # → [1, 2, 3, 4]

u = [1, 2, 3]
before = id(u)
u += [4]
print(id(u) == before)  # → True   ← 没变
print(u)                # → [1, 2, 3, 4]
```

**两段最终值一模一样，但发生的事完全不同。** 盒子模型解释不了：如果 `u` 是个盒子，
`+=` 改了盒子里的东西，那 `t = t + [4]` 也该改同一个盒子——可它的 `id` 变了。

| 写法 | 发生了什么 | 名字指向 |
|---|---|---|
| `t = t + [4]` | 造**新列表**，再让 `t` 指过去 | 新对象 |
| `u += [4]` | 在**原列表上**追加 | 老对象（内容变了） |

**正确模型**：`名字 ──贴──> 对象`。`=` 只动贴纸；`+=` / `.append()` / `.sort()` 这类**可能**动对象本身。
对象会不会被就地改，取决于它是**可变**还是**不可变**——第 6 节。

名字不存在时（真实 traceback）：

```
Traceback (most recent call last):
  File "demo.py", line 1, in <module>
    print(undefined_name)
          ^^^^^^^^^^^^^^
NameError: name 'undefined_name' is not defined
```

## 3. 数字：`int` `float` `complex` `bool`（覆盖 1.3）

### 3.1 `int`：任意精度，不会溢出

```python
print(2 ** 100)                             # → 1267650600228229401496703205376
print(len(str(2 ** 1000)))                  # → 302
print(type(2 ** 100))                       # → <class 'int'>
print(10 ** 100 * 10 ** 100 == 10 ** 200)   # → True
```

`2 ** 1000` 是 302 位十进制数，算得出来。**Python 的 `int` 没有固定宽度，不会整数溢出。**
代价是越大的整数越慢（按需分配内存），所以"不溢出"不等于"免费"。

```python
print(7 / 2)            # → 3.5    ← / 永远返回 float！
print(7 // 2)           # → 3
print(-7 // 2)          # → -4     ← 向下取整，不是向零取整
print(7 % 3, -7 % 3)    # → 1 2    ← 结果符号跟除数一致
print(divmod(7, 3))     # → (2, 1) ← 一次拿商和余数
print(4 / 2, str(4 / 2))  # → 2.0 '2.0'
```

> ⚠️ **坑 1**：`/` 永远返回 `float`，即使整除。
> `4 / 2` 是 `2.0`；`4 / 2 == 2` 为 `True`，但 `str(4 / 2)` 是 `'2.0'`。要整数用 `//`。

> ⚠️ **坑 2**：`//` 是**向下**取整（floor），不是向零截断。
> `-7 // 2` 在 Python 里是 `-4`，在 C / Java 里是 `-3`。
> 原因是 Python 坚持 `a == (a // b) * b + a % b`（实测 `-7 == (-7 // 3) * 3 + (-7 % 3)` 为 `True`），
> 为此 `%` 的符号必须跟除数走。要"向零截断"用 `int(a / b)` 或 `math.trunc`。

### 3.2 `float`：64 位双精度，有边界

```python
print(2 ** 0.5)       # → 1.4142135623730951
print(1e3)            # → 1000.0
print(1e308 * 10)     # → inf     ← 上溢，不报错
print(5e-324 / 2)     # → 0.0     ← 下溢到 0，不报错
print(int(3.9), int(-3.9))        # → 3 -3   ← int() 向零截断
nan = float("nan")
print(nan == nan, nan != nan, bool(nan))   # → False True True
```

`float` 就是 **IEEE 754 binary64**（等价 C 的 `double`）：1 位符号 + 11 位指数 + 52 位尾数。
**溢出得 `inf`、下溢得 `0.0`，都不报错**——金融 / 科学计算里这是要人命的。
判 `nan` 要用 `math.isnan(x)`，或者用 `x != x`（不需要 `import`）。

> ⚠️ **坑**：`inf` / `nan` 会**一路传播**，不报错。
> `1e308 * 10` 得到 `inf`，之后所有运算都是 `inf` 或 `nan`，程序会"正常"跑完并给出一个错的答案。
> 处理：关键计算后检查 `math.isfinite(x)`。

精度边界可以直接问解释器：

```python
import sys
print(sys.float_info.epsilon)   # → 2.220446049250313e-16
print(sys.float_info.dig)       # → 15
print(1e16 + 1 == 1e16)         # → True
print(float(2 ** 53) == float(2 ** 53 + 1))   # → True
```

`dig = 15` 的含义：**十进制下约 15 位有效数字可靠**。`2**53 = 9007199254740992` 是
**能精确表示连续整数的上界**（尾数 52 位 + 隐含 1 位），超过它相邻整数之间就有表示不出来的。

> 官方 `sys` 文档：<https://docs.python.org/3/library/sys.html>
> `sys.float_info` 有本机浮点格式的全部参数（`max` `min` `epsilon` `dig` `mant_dig`），
> 需要判断"这个计算还剩几位精度"时直接查，不用背。

### 3.3 `complex`：内置但少用

```python
cn = 3 + 4j
print(cn, type(cn))       # → (3+4j) <class 'complex'>
print(cn.real, cn.imag)   # → 3.0 4.0      ← 都是 float，只读
print(abs(cn), cn.conjugate())   # → 5.0 (3-4j)
print(complex(1, 2))      # → (1+2j)
```

虚部单位是 **`j` / `J`**，不是数学上的 `i`；`cn.real` 是 `float` 不是 `int`（`3` 存进去读出来 `3.0`），
而且**只读**（`cn.real = 5` 报 `AttributeError`）。它是**内置类型**，不需要 `import`。
日常 Web / 数据处理见不到，信号处理、FFT、电路阻抗里常见。

### 3.4 `bool`：`True` / `False` 就是 `1` / `0`

```python
print(True == 1, False == 0)            # → True True
print(True is 1)                        # → False   ← 相等但不是同一个对象
print(True + True, type(True + True))   # → 2 <class 'int'>   ← 相加后降级成 int
print(sum([True, True, False]))         # → 2
print(isinstance(True, int))            # → True    ← bool 是 int 的子类
print([1, 2][True])                     # → 2       ← True 能当索引
print(sum(s > 60 for s in [88, 45, 92, 60]))   # → 3   ← 数"满足条件的个数"不用写计数器
```

| 结论 | 证据 |
|---|---|
| `bool` 是 `int` 的**子类** | `isinstance(True, int)` → `True` |
| `True == 1` 但 `True is 1` 为 `False` | 两个对象，值相等 |
| `bool` 参与算术会**降级**成 `int` | `type(True + True)` 是 `int` |
| 所以布尔值能当真值累加 | `sum([True, True, False])` → `2` |

> ⚠️ **坑**：`True` 和 `1` 在字典里会**互相覆盖**。
> 实测 `{1: "a", True: "b"}` 得到 `{1: 'b'}`，长度是 `1`。
> 原因：`hash(1) == hash(True)` 且 `1 == True`，字典认为是同一个键。
> 同理 `{1: "a"}[1.0]` 得到 `'a'`、`True in {1: "a"}` 为 `True`。
> 处理：别把布尔值和数字混在同一个字典里当键。

### 3.5 进制字面量与转换

```python
print(0b1010, 0o17, 0xFF, 1_000_000)   # → 10 15 255 1000000
print(bin(10), oct(10), hex(255))      # → 0b1010 0o12 0xff
print(int("ff", 16), int("1010", 2))   # → 255 10
print(int("0b1010", 0))                # → 10   ← base=0 让 Python 从前缀猜
```

`0b` / `bin()` 二进制，`0o` / `oct()` 八进制，`0x` / `hex()` 十六进制。
**没有"八进制类型"**——它们都是 `int`，只是字面量写法不同。

**下划线分隔符**是纯书写层面的分隔，对求值没有任何影响（本机实测）：

```python
print(1_000_000)                       # → 1000000
print(0x_FF)                           # → 255       ← 下划线紧跟进制前缀之后也允许！
print(0b_1010_1010, 0o_777)            # → 170 511
print(10_000.000_1)                    # → 10000.0001   ← 小数点两侧都可以
print(1_0j)                            # → 10j          ← 复数也可以
print(1_000_000 == 1000000)            # → True         ← 纯粹是写法，值不变
```

**最容易讲错的一点**：下划线不是只能跟在数字后面，**紧跟进制前缀之后（`0x_FF`）也合法**。

**位置限制**：不能放在开头、结尾，也不能连着写两个。

```
>>> 1__0
SyntaxError: invalid decimal literal
>>> 1_
SyntaxError: invalid decimal literal
>>> _100
NameError: name '_100' is not defined      ← 这个不报语法错，被当成变量名了
```

注意报错文本是 **`invalid decimal literal`**，不是笼统的 `invalid syntax`——
看到这条消息基本就是数字字面量写坏了。

> ⚠️ **坑 1**：`int("3.5")` 报 `ValueError`（`int()` 不认小数点），`int("4 2")` 也报错，
> 但 `int("  42  ")` 可以（只剥**两端**空白）。

> ⚠️ **坑 2**：全角数字也能转。实测 `int("４２")` → `42`、`"１２３".isdigit()` → `True`。
> 所以**不要**用 `isdigit()` 校验"是不是合法的 ASCII 数字串"。

## 4. 运算符与优先级（覆盖 1.4）

### 4.1 运算符速查与优先级

| 运算符 | 含义 | 例子 → 结果 |
|---|---|---|
| `+` | 加 / 拼接 | `2 + 3` → `5`；`"ab" + "cd"` → `"abcd"` |
| `-` | 减 | `5 - 2` → `3` |
| `*` | 乘 / 重复 | `3 * 4` → `12`；`"ab" * 3` → `"ababab"` |
| `/` | 除（**永远 float**） | `7 / 2` → `3.5` |
| `//` `%` `**` | 整除 / 取余 / 幂 | `-7 // 2` → `-4`；`-7 % 3` → `2`；`2 ** 10` → `1024` |

**优先级从高到低**（够用版）：`(...)` `x[i]` `x.attr` → `**` → 一元 `+ - ~` → `* / // %` →
`+ -` → `<< >>` → `&` → `^` → `|` → 比较 `== < > <= >= != is in` → `not` → `and` → `or`。

```python
print(2 + 3 * 4)                  # → 14
print(2 ** 3 ** 2)                # → 512   ← ** 右结合，是 2**(3**2)，不是 64
print(-2 ** 2)                    # → -4    ← 一元负号优先级低于 **
print(10 - 2 - 3)                 # → 5     ← - 左结合
print(2 * 3 ** 2)                 # → 18
print(not 1 == 1)                 # → False ← 先 == 后 not
print(True or False and False)    # → True  ← and 先于 or
print((True or False) and False)  # → False
print(1 < 2 == True)              # → False ← 链式比较，等价 (1<2) and (2==True)
print(1 | 2 & 3)                  # → 3     ← & 先于 |
```

> 官方完整优先级表：<https://docs.python.org/3/reference/expressions.html>
> "Operator precedence" 一节是唯一权威的优先级表。
> 但**实用建议是：记不住就加括号**。括号不花钱，猜错优先级要花时间。

### 4.2 链式比较

```python
x = 5
print(1 < x < 10, 1 < x > 3, 1 > x > 3, 1 < x < 3)   # → True True False False
```

**`1 < x < 10` 不是 `(1 < x) < 10`**（那是 C 的语义，会退化成 `True < 10`，碰巧也常常是 `True`，
所以 C 里的 bug 很难发现）。Python 的语义是数学连写：`a < b < c` 等价于 `(a < b) and (b < c)`。

**中间那个操作数只求值一次**，而且后面会短路（实测）：

```python
log = []
def g(v):
    log.append(v); return v

log.clear(); g(1) < g(2) < g(3);  print(log)   # → [1, 2, 3]
log.clear(); print(1 > g(2) < g(3), log)       # → False [2]   ← g(3) 根本没被调用
```

比较也能用在其他类型上：`"abc" < "abd"` → `True`；`"Z" < "a"` → `True`（大写字母码位在小写之前）；
`[1, 2] < [1, 3]` → `True`（列表按元素比）。

> ⚠️ **坑 1**：`"10" < "9"` 是 `True`。
> 原因：从第一个字符按 Unicode 码位比，`'1'`(49) < `'9'`(57) 就出结果了。
> 这是"从文件 / 输入读来的数字忘了转 `int`"的经典症状——排序诡异但程序不报错。

> ⚠️ **坑 2**：链式比较的中间值只求值一次，但读代码时容易以为求值两次。
> 有副作用（`pop()`、读文件）的表达式别放进链式比较——
> `items.pop() < 3 < items.pop()` 到底 pop 几次取决于短路，非常难读。

### 4.3 `and` / `or` 返回**操作数**，不是布尔值

```python
print(1 and 2, 0 and 2, 1 or 2, 0 or 2)          # → 2 0 1 2
print("" or "default")                           # → default
print("a" and "b" or "c")                        # → b
print([] or {} or () or 0 or None or "最后")      # → 最后
print(not [])                                    # → True
```

| 表达式 | 返回 |
|---|---|
| `a and b` | `a` 为假 → 返回 `a`；否则返回 `b` |
| `a or b` | `a` 为真 → 返回 `a`；否则返回 `b` |
| `not a` | **永远**返回真正的 `bool` |

实用模式：`name = user_input or "匿名"`；`value = obj and obj.attr`。

**短路求值**是防御性写法的基石，顺序不能反：

```python
def boom():
    raise RuntimeError("我被求值了")

print(False and boom())   # → False（不抛）
print(True or boom())     # → True （不抛）
print(True and boom())    # RuntimeError: 我被求值了

if divisor != 0 and total / divisor > 0.5: ...   # 先判再除
if items and items[0] == "x": ...                # 空列表时不会 IndexError
```

> ⚠️ **坑 1**：`a and b or c` 这个"伪三元"在 `b` 本身为假时会出错。
> `1 and 0 or "兜底"` 得到 `"兜底"`，但你想要的可能是 `0`。
> 处理：用真正的条件表达式 `b if a else c`（`04_控制流.md` 2.7 节）。

> ⚠️ **坑 2**：`x and y` 的结果可能是**任意对象**，不是 `bool`。
> `if x and y:` 没问题（`if` 会做真值测试），但 `result = x and y` 之后 `result` 可能是 `0` / `""` / `None`。
> 真要布尔值就套 `bool(...)`。

### 4.4 位运算

```python
print(6 & 3, 6 | 3, 6 ^ 3)   # → 2 7 5    （110&011=010；110|011=111；110^011=101）
print(~6)                    # → -7
print(1 << 10, -8 >> 1)      # → 1024 -4
```

用途：权限位（`READ = 0b001`；`if perm & READ:`）、判断奇偶（`n & 1`）、快速乘除 2 的幂
（`n << 3` = `n * 8`）、哈希 / 加密 / 协议解析。日常业务代码里用得很少，读底层代码绕不开。

> 💡 **和 C 不一样的地方（实测）**：C 里 `a & 1 == 1` 被解析成 `a & (1 == 1)`，是著名的坑。
> **Python 里不存在这个坑**——`&` 优先级**高于**比较运算符：
>
> ```
> x = 2
> x & 2 == 2      -> True     ← 就是 (x & 2) == 2
> x & (2 == 2)    -> 0        ← 按 C 的优先级会得到这个
> 7 & 1 == 1      -> True
> 6 & 1 == 1      -> False
> ```
> 所以 `x & 1 == 1` 这种奇偶判断在 Python 里是**正确**的。下面两条才是真坑。

> ⚠️ **坑 1**：`~` 不是"按位取反得到一个正数"，它恒等于 `-x - 1`。
> 实测 `~-1=0`、`~0=-1`、`~1=-2`、`~6=-7`、`~255=-256`；`bin(~255)` 是 `'-0b100000000'`。
> 原因：`int` 是任意精度，没有固定字长，"取反"没有自然终点，语言按补码语义定义成 `-x-1`。
> 处理：要固定宽度的取反就自己掩码，`(~x) & 0xFF`。

> ⚠️ **坑 2**：`&` / `|` 对 `bool` 也能用，但**两边都会求值**，不短路。
> 实测 `1 & 2` → `0`（位运算），`1 and 2` → `2`（返回操作数）。
> 处理：逻辑判断用 `and` / `or`，位操作用 `&` / `|`，别混。

### 4.5 `is` vs `==`

| | 比较什么 | 用在哪 |
|---|---|---|
| `==` | **值**是否相等（调 `__eq__`） | 几乎所有场合 |
| `is` | 是否**同一个对象**（比 `id`） | 只跟 `None` / `True` / `False` / 自造哨兵比 |

```python
print([1, 2] == [1, 2])     # → True
print([1, 2] is [1, 2])     # → False   ← 两个不同的列表对象
aa = [1, 2]; bb = aa
print(bb is aa)             # → True
print(256 is 256)           # → True
print(1000 is 1000)         # → True    ← 不代表"1000 是单例"！
print(int("1000") is 1000)  # → False
```

`1000 is 1000` 为 `True` 是因为**同一个代码块里的相同字面量被编译器折叠成一个常量对象**；
`int("1000")` 是运行期算出来的，会新建对象。所以那是**优化的副产品，不是语言保证**。

> ⚠️ **坑**：**绝不要用 `is` 比较数字或字符串字面量。**
> 现象：`1000 is 1000` 是 `True` 让你以为可以这么写，
> 但 `int("1000") is 1000` 是 `False`，`"abc" is "".join(["a","b","c"])` 也是 `False`。
> 原因：小整数（`-5..256`）和短字符串会被缓存 / 驻留，超出范围就不保证。
> 处理：比数值用 `==`。解释器对 `is` 配字面量会发警告（本机实测，起始版本**未实测**）：
>
> ```
> SyntaxWarning: "is" with 'int' literal. Did you mean "=="?
> ```
> 出现这个警告说明**你写错了**，不是风格问题。

`is` 的一个真实好处：它**不能**被重载。自定义类把 `__eq__` 写错了，`x is None` 仍然可靠。

### 4.6 真值测试：falsy 全表（实测）

```python
from decimal import Decimal
from fractions import Fraction
falsy = [False, None, 0, 0.0, 0j, Decimal(0), Fraction(0, 1),
         "", [], (), {}, set(), range(0), b""]
print([bool(v) for v in falsy])
# → [False, False, False, False, False, False, False, False, False, False, False, False, False, False]

print(bool("0"), bool("False"), bool([0]), bool((0,)), bool({"a": 0}), bool(-1))
# → True True True True True True
```

**判定规则**（记住这条就不用背表）：

> **数字看是不是 0；容器 / 序列看是不是空；`None` 和 `False` 恒为假。其他一切对象默认都是真。**

> ⚠️ **坑 1**：`bool("0")` 和 `bool("False")` 都是 `True`。
> 现象：从命令行 / 配置文件读来的 `"False"` 在 `if` 里为真，程序走了错误分支。
> 原因：非空字符串恒为真，跟内容无关。
> 处理：显式解析，`raw.strip().lower() in ("1", "true", "yes", "y")`。

> ⚠️ **坑 2**：`if x:` 和 `if x is not None:` **语义完全不同**。
> `x` 是 `0` / `""` / `[]` 时前者为假、后者为真。
> 场景：函数用 `None` 表示"没传"，但合法值可能是 `0`：
> `if not value: value = default` 会把用户明确传的 `0` 也覆盖掉。处理：用 `is None`。

> ⚠️ **坑 3**：`float("nan")` 的真值是 `True`（实测），但它不代表有效数值。
> 校验有效性要用 `math.isnan` / `math.isfinite`，不能靠 `if x:`。

### 4.7 海象运算符 `:=`

解决的问题：**"先算一个值、判断它、然后还要用它"**，普通写法要算两遍或嵌套两层。

```python
data = [1, 2, 3, 4]
if (k := len(data)) > 3:
    print(k)          # → 4

n = 5
while (n := n - 1) > 0:
    print(n)          # → 4 3 2 1

squares = [y * y for y in range(5) if (z := y * y) > 4]
print(squares, z)     # → [9, 16] 16   ← z 泄漏到外层，值留在最后一次

import re
if (m := re.search(r"\d+", "abc123")):
    print(m.group())  # → 123
```

**括号很要紧**，因为 `:=` 优先级比比较运算符低（实测）：

```python
data = [1, 2, 3, 4]
print(len(data))             # → 4

if (n := len(data)) > 3:     # ✅ n 拿到 4，比较也成立
    print(n)                 # → 4

if n := len(data) > 3:       # ✅ 语法合法，但 n 拿到 True（比较结果），不是长度
    print(n)                 # → True
```

第二条**不报错**，只是语义完全不对。这种"能跑但意思错了"最危险——**用 `:=` 一律加括号**。

> ⚠️ **坑**：`:=` 会把变量**泄漏到外层作用域**。上面推导式结束后 `z` 还能读到 `16`。
> 处理：给海象变量取个只在附近用的名字，别指望它出作用域消失。

> 官方 PEP：<https://peps.python.org/pep-0572/>
> 这份 PEP 定义了 `:=`，并解释了为什么有些位置禁止使用它
> （比如不能在 `x = (y := 1)` 这种平级赋值里裸用）。**引入版本未实测**——本机 3.13.15 可用。

## 5. 浮点精度问题（覆盖 1.5）

### 5.1 先看反例

```python
print(0.1 + 0.2)                  # → 0.30000000000000004
print(0.1 + 0.2 == 0.3)           # → False
print(0.1 + 0.2 - 0.3)            # → 5.551115123125783e-17
print(repr(0.1))                  # → 0.1        ← Python 的最短还原表示，骗你的
print(format(0.1, ".20f"))        # → 0.10000000000000000555
print(format(0.3, ".20f"))        # → 0.29999999999999998890
print((0.1).hex())                # → 0x1.999999999999ap-4
print((0.3).hex())                # → 0x1.3333333333333p-2
```

### 5.2 为什么：二进制表示

`float` 用**二进制**存分数：`值 = 符号 × 1.尾数(52 位) × 2^指数`。
**只有分母是 2 的幂的分数才能被二进制有限表示。**

| 十进制 | 二进制 |
|---|---|
| `0.5` | `0.1` ✅ 有限 |
| `0.25` | `0.01` ✅ 有限 |
| `0.1` | `0.000110011001100110011...` ❌ 无限循环 |
| `0.3` | `0.010011001100110...` ❌ 无限循环 |

`0.1 = 1/10`，分母含因子 5，存不下，只能截断到 52 位尾数——`0x1.999999999999ap-4` 里那个 `a`
就是截断的痕迹。所以 `0.1` 存的是**略大于** 0.1 的数，`0.2` 也是，两个"略大"相加得到
`0.30000000000000004`；而 `0.3` 存的是**略小于** 0.3 的数。两者自然不相等。

**这不是 Python 的问题**，任何用 IEEE 754 的语言（C / Java / JavaScript）都一样。
Python 唯一多做的是 `repr()` 用了最短还原表示，所以打印好看。

### 5.3 判断相等：`math.isclose()`

```python
import math
print(math.isclose(0.1 + 0.2, 0.3))                 # → True
print(math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-20))  # → False
print(math.isclose(1e-10, 0.0))                     # → False
print(math.isclose(1e-10, 0.0, abs_tol=1e-9))       # → True
print(abs(0.1 + 0.2 - 0.3) < 1e-9)                  # → True
```

判断条件是（`rel_tol` 默认 `1e-9`，`abs_tol` 默认 `0.0`）：

```
|a - b| <= max(rel_tol * max(|a|, |b|), abs_tol)
```

| 参数 | 管什么 | 什么时候必须调 |
|---|---|---|
| `rel_tol` | 与数值大小成比例的容差 | 数值可能很大时 |
| `abs_tol` | 与数值大小无关的容差下限 | **跟 0 比较时必须设** |

第三行说明得很清楚：`1e-10` 和 `0` 的差距是 `1e-10`，而容差是 `1e-9 * 1e-10 = 1e-19`，
比差距还小，所以判不相等。**跟 0 比必须给 `abs_tol`。**

> 官方 `math` 文档：<https://docs.python.org/3/library/math.html>
> 这里有 `math.isclose` 的完整签名和默认值，也解释了"为什么 `abs(a-b) < 1e-9` 处理不了大数"。
> 同文档的 `math.ulp()` 能给出"这个数量级上的最小间隔"，做精细浮点判断时用得上。

### 5.4 `decimal`：要精确十进制时用它

```python
from decimal import Decimal, getcontext

print(Decimal("0.1") + Decimal("0.2"))                    # → 0.3
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))  # → True
print(Decimal("0.1"))     # → 0.1
print(Decimal(0.1))       # → 0.1000000000000000055511151231257827021181583404541015625

print(getcontext().prec)  # → 28   ← 默认 28 位有效数字
getcontext().prec = 50
print(Decimal(1) / Decimal(3))
# → 0.33333333333333333333333333333333333333333333333333

Decimal("0.1") + 0.2      # TypeError: unsupported operand type(s) for +: 'decimal.Decimal' and 'float'
```

**两条必须记住**：`Decimal` 内部是**十进制**的，所以 `Decimal("0.1")` 就是精确的 `0.1`；
**一定用字符串构造**（`Decimal(0.1)` 会把 `float` 的二进制误差原封不动带进来）。
代价是比 `float` 慢很多（**未实测倍数**），而且不能和 `float` 混算。

| 场景 | 用什么 |
|---|---|
| 金额、发票、账目；需要"十进制四舍五入" | ✅ `Decimal` |
| 科学计算、图形、机器学习、大量数值循环 | ❌ 用 `float`（必要时上 NumPy） |

顺带一个相关模块：`fractions` 能存**精确分数**，`Fraction(1, 10) + Fraction(2, 10)` 得到 `3/10`。
也不快、也不能直接和 `float` 混算，但做数学推导很好用。

> 官方 `decimal` 文档：<https://docs.python.org/3/library/decimal.html>
> 开头解释了"为什么需要十进制浮点"；最有实用价值的是 "Rounding modes" 一节，列出 8 种舍入模式，
> 其中 `ROUND_HALF_UP` 是普通人理解的"四舍五入"，`ROUND_HALF_EVEN` 是默认的银行家舍入。

### 5.5 `round()` 的银行家舍入

```python
for v in [0.5, 1.5, 2.5, 3.5, -0.5, -1.5, -2.5]:
    print(round(v), end=" ")
# → 0 2 2 4 0 -2 -2
```

`round(2.5)` 是 `2`，`round(0.5)` 是 `0`。**规则叫"银行家舍入"（round half to even）**：
恰好落在中间（`.5`）时往**最近的偶数**舍——`0.5→0`、`1.5→2`、`2.5→2`（2 是偶数，不是"往上"）、`3.5→4`。

**为什么这么设计**：`.5` 一律向上会让误差**单向累积**（1000 个数各多 0.5 就多 500），
往偶数舍让误差正负抵消。金融和统计普遍用这个规则。

**更重要的第二条坑**——这个**不是**银行家舍入造成的：

```python
print(round(2.675, 2))    # → 2.67   ← 你以为是 2.68
print(round(1.005, 2))    # → 1.0
print(round(0.125, 2), round(0.375, 2))   # → 0.12 0.38

from decimal import Decimal
print(repr(2.675))       # → 2.675   ← repr 骗你的
print(Decimal(2.675))    # → 2.67499999999999982236431605997495353221893310546875
```

`2.675` 实际存的是 `2.6749999...`，"比 2.675 小一点"，舍到 2 位当然是 `2.67`。`1.005` 同理。

**要"人理解的"四舍五入，必须用 `Decimal` + 显式舍入模式**：

```python
from decimal import Decimal

print(Decimal("2.675").quantize(Decimal("0.01")))                            # → 2.68
print(Decimal("2.675").quantize(Decimal("0.01"), rounding="ROUND_HALF_UP"))  # → 2.68
print(Decimal("1.005").quantize(Decimal("0.01"), rounding="ROUND_HALF_UP"))  # → 1.01
```

> ⚠️ **坑 1**：`round()` 返回类型跟输入有关：`round(2.5)` 是 `int`，`round(2.5, 2)` 是 `float`（实测）。
> 更要紧的是 `round(1.005, 2)` 返回 `1.0` 而不是 `1.01`——不是 bug，是输入本身不精确。
> 现象 → 结果少一分钱；原因 → `float` 存不下 `1.005`；处理 → 金额用 `Decimal`。

> ⚠️ **坑 2**：`round()` 不能当"格式化"用。想显示两位小数用 f-string `f"{2.675:.2f}"`（实测 `'2.67'`），
> 至少结果是**字符串**，不会让你以为"数值已经精确到分"了。

> ⚠️ **终极坑**：`if a == b:` 处理 `float`。
> 现象：数学上相等，程序走了 `else`。原因：二进制舍入误差。
> 处理：`math.isclose(a, b)`；如果业务上"精确相等"是必须的，那说明你不该用 `float`。

## 6. 可变 vs 不可变（覆盖 1.10）

> **这一节是整章最重要的。** 前五节都可以忘，这一节不行。

### 6.1 定义、分类、以及为什么要区分

- **可变（mutable）**：创建后**内容**能改，`id` 不变
- **不可变（immutable）**：内容**永远**不能改；"改"只能造新对象

"不可变"是**语言层面的保证**，不是约定——你**做不到**改它，不是"你不该改它"。

| 可变 ✅ | 不可变 ❌ |
|---|---|
| `list` `dict` `set` `bytearray` | `int` `float` `complex` `bool` `str` `bytes` `tuple` `frozenset` `range` |
| 自定义类实例（默认） | |

**为什么语言要区分**：因为"可变"是一切别名的根源。两个名字指同一个对象，通过一个名字改，
另一个名字那边也变了——这既是最有用的特性，也是最容易出 bug 的地方。

### 6.2 同样的 `+=`，两种命运

```python
lst = [1, 2]; before = id(lst)
lst += [3]
print(id(lst) != before, lst)   # → False [1, 2, 3]   ← id 没变

tup = (1, 2); before = id(tup)
tup += (3,)
print(id(tup) != before, tup)   # → True (1, 2, 3)    ← id 变了

s = "ab"; before = id(s); s += "c"
print(id(s) != before, s)       # → True abc

i = 1; before = id(i); i += 1
print(id(i) != before, i)       # → True 2
```

**同一条语句 `x += y`，行为完全不同。** 原因是 Python 规定的求值顺序：

1. 先试 `x = x.__iadd__(y)`（"就地加"）
2. 没有 `__iadd__` 就退回 `x = x.__add__(y)`（"造新的再加"）
3. 都没有再试 `x = x + y`

| 类型 | 有 `__iadd__` 吗（实测） | `+=` 的行为 |
|---|---|---|
| `list` | ✅ `True` | **改原对象**，`id` 不变 |
| `tuple` | ❌ `False`（有 `__add__`） | 造新对象，`id` 变 |
| `str` | ❌ `False` | 造新对象，`id` 变 |
| `int` | ❌ `False` | 造新对象，`id` 变 |

**杀伤力在别名上**：

```python
p = [1, 2]; q = p; p = p + [3]
print(p, q, p is q)     # → [1, 2, 3] [1, 2] False

p = [1, 2]; q = p; p += [3]
print(p, q, p is q)     # → [1, 2, 3] [1, 2, 3] True   ← q 被"顺带"改了
```

**一字之差，副作用范围完全不同。**

> ⚠️ **坑**：函数参数上用 `+=` 会改到调用者的对象。

```python
def add_item(items, x):
    items += [x]         # 等价 items.extend([x])，改了外面那个列表
    return items


def add_item_safe(items, x):
    items = items + [x]  # 造新列表，外面不受影响
    return items
```

> 现象：调用者发现自己的列表被函数改了，尽管没用到返回值。
> 原因：列表 `+=` 是就地修改，参数名和外面的名字指着同一个列表。
> 处理：**明确你要哪种**，并在 docstring 里写清楚。

### 6.3 `a = b` 不复制对象，副本的三种做法

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a, a is b)                        # → [1, 2, 3, 4] True

a = [1, 2, 3, 4]
c = list(a); c.append(5); print(a, c)   # → [1, 2, 3, 4] [1, 2, 3, 4, 5]
d = a[:];    d.append(6); print(a, d)   # → [1, 2, 3, 4] [1, 2, 3, 4, 6]
```

`b = a` 只做了一件事：把名字 `b` 贴到 `a` 指的那个对象上。**没有第二个列表。**
对不可变对象看不出区别（因为没法改），对可变对象立刻现形。

`list(a)`、`a[:]`、`a.copy()` 三个都是**浅拷贝（shallow copy）**：只复制**最外层容器**，
里面的元素还是原来那些对象。

```python
import copy

inner = [1, 2]; outer = [inner, 3]
shallow = list(outer); shallow[0].append(99)
print(outer)                                       # → [[1, 2, 99], 3]   ← 里层被改了
print(shallow is outer, shallow[0] is outer[0])    # → False True        ← 里层是同一对象

inner2 = [1, 2]; outer2 = [inner2, 3]
deep = copy.deepcopy(outer2); deep[0].append(100)
print(outer2, deep)                                # → [[1, 2], 3] [[1, 2, 100], 3]
```

`copy.deepcopy` 递归复制所有层级，代价是慢、可能很慢、可能遇到不能拷的对象。
完整讨论见 `05_数据结构.md` 3.5 节。

> ⚠️ **坑**：`b = a` 之后你以为有两个列表，其实只有一个。
> 现象：改 `b` 影响了 `a`。原因：赋值只绑名字。
> 处理：要独立副本用 `a.copy()`；要完全独立用 `copy.deepcopy(a)`。**关键是你知道自己选的是哪个。**

### 6.4 函数默认参数的经典坑

```python
def bad(item, box=[]):
    box.append(item)
    return box

print(bad("a"))            # → ['a']
print(bad("b"))            # → ['a', 'b']     ← 不是 ['b']！
print(bad("c"))            # → ['a', 'b', 'c']
print(bad.__defaults__)    # → (['a', 'b', 'c'],)   ← 铁证
```

**原因**：

> **默认值表达式只在 `def` 语句执行的那一次求值，结果存进函数的 `__defaults__`，
> 之后每次调用都复用同一个对象。**

**正确写法**：用 `None` 当哨兵，在函数体内造新对象。

```python
def good(item, box=None):
    if box is None:
        box = []
    box.append(item)
    return box

print(good("a"), good("b"))   # → ['a'] ['b']
print(good.__defaults__)      # → (None,)
```

**通用形态**：任何**可变**默认值都有问题——`[]` `{}` `set()` 以及大多数自定义类实例。
不可变的（`None` `0` `""` `()`）没问题。

**这个坑有时是故意的**（函数级缓存）：`def fib(n, cache={})` 利用"默认值只造一次"做记忆化。
现代写法更清楚，用 `functools.lru_cache`。**判断依据**：默认值"只求值一次"这个特性，
你是**依赖**它还是**被**它坑？依赖它就是缓存技巧（要注释说明），不小心被坑就是 bug。
**默认选 `None`。**

### 6.5 不可变 ≠ 内容永远不变

```python
t = (1, [2, 3])
t[1] += [4]
```

真实报错：

```
Traceback (most recent call last):
  File "n.py", line 2, in <module>
    t[1] += [4]
TypeError: 'tuple' object does not support item assignment
```

**但报错之后，里面的列表已经被改了**——`print(t)` 得到 `(1, [2, 3, 4])`。

原因：`t[1] += [4]` 分两步。第一步 `t[1].__iadd__([4])` **就地改了列表**（成功）；
第二步把结果**赋回** `t[1]`，元组不支持元素赋值（失败抛异常）。副作用已经发生了。

**"不可变"的准确含义**：

> 不可变指的是**这个对象保存的引用不能被替换或删除**，
> **不是**指它引用的对象内部不能变。

所以 `(1, [2, 3])` 不能当字典键（里面的列表不可哈希），但 `(1, 2)` 可以：

```python
print({(1, 2): "x"})     # → {(1, 2): 'x'}
print({[1, 2]: "x"})     # TypeError: unhashable type: 'list'
```

**为什么键必须可哈希**：字典按**哈希值**分桶存储，查找时先算哈希找桶、再用 `==` 确认是同一个键。
如果键能变，哈希可能在存进去之后变化 → 之后**再也找不到它**。所以语言要求
**能当键的对象必须"哈希值在整个生命周期内不变"**。

| 能当键 | 不能当键 |
|---|---|
| `int` `float` `str` `bool` `None`；`frozenset` | `list` `dict` `set` |
| `tuple`（元素都可哈希） | 定义了 `__eq__` 却没定义 `__hash__` 的实例 |

> ⚠️ **坑 1**：`t[1] += [4]` 会**抛异常的同时改掉数据**。
> 现象：异常处理里以为"什么都没发生"，其实数据已经脏了。
> 原因：`+=` 的"就地改"和"赋回"是两步，第一步先成功了。
> 处理：别在元组元素上用 `+=`。想改就先取出来、改完、再构造新元组，或者干脆用列表。

> ⚠️ **坑 2**：自定义类里定义了 `__eq__` 之后，`__hash__` 会被自动设成 `None`，实例**不能**再当字典键。
> 本机实测：普通类的 `__hash__` 是 `object` 的槽包装器，加了 `__eq__` 的类 `__hash__` 是 `None`，
> 拿去当键报 `TypeError: unhashable type: 'WithEq'`。
> 这是防止"相等的东西哈希不同"的保护机制，要同时用必须自己实现 `__hash__`（`08_面向对象.md` 6.6 节）。

### 6.6 传参语义：传的是对象引用

准确说法是 **"传对象引用，按赋值语义绑定"**（call by object reference），不是"传值"也不是"传引用"。

```python
def try_reassign(x):
    x = x + 1        # 只改本地名字的绑定

def try_mutate(x):
    x.append(99)     # 改了传入的那个对象

num = 1
try_reassign(num)
print(num)           # → 1        ← 外面没变

outer = [1]
try_mutate(outer)
print(outer)         # → [1, 99]  ← 外面变了
```

**一句话规则**：

> 函数**改不了**调用者的名字绑定（`x = ...` 只影响函数内部），
> 但**能改**传进来的那个对象的**内容**（如果它是可变的）。

| 函数里写了 | 调用者的变量会变吗 |
|---|---|
| `x = 新对象` | ❌ 不会 |
| `x += ...`（`x` 是 list）、`x.append(...)`、`x[0] = ...`、`x.sort()` | ✅ 会 |
| `x += ...`（`x` 是 tuple / str / int） | ❌ 不会 |

**标准库自己就是这么区分的**：`sorted(x)` 返回新列表，`x.sort()` 就地排——名字就是文档。

### 6.7 `id` 观察不可变对象的复用

```python
a1 = "abc"; a2 = "ab" + "c"
print(a1 is a2)               # → True   ← 编译期常量折叠
a3 = "".join(["a", "b", "c"])
print(a1 is a3)               # → False  ← 运行期算出来的
print(10 ** 6 is 10 ** 6)     # → True
print(int("100") is 100)      # → True   ← 小整数缓存
```

三件事：**小整数缓存**（`-5..256`）、**字符串驻留**、**常量折叠**。它们让 `is` 在小数值上
"看起来能用"，从而写出依赖实现细节的代码。**它们是优化，不是保证**——换解释器（PyPy）
或换数值范围，行为就变。**唯一结论**：比较值用 `==`；`is` 只对 `None` / `True` / `False` / 自造哨兵用。

### 7.1 `print` 的 `sep` / `end` / 返回值

完整签名：`print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)`。
默认行为：**每个参数转字符串、用 `sep` 连接、末尾加 `end`**。

```python
print("a", "b", "c")            # → a b c
print("a", "b", "c", sep="-")   # → a-b-c
print("a", "b", "c", sep="")    # → abc
print("第一行", end="")
print("接在后面")                # → 第一行接在后面
print("第一行", end=" | ")
print("第二行")                  # → 第一行 | 第二行
print(*["a", "b", "c"], sep=",") # → a,b,c         ← 逐行写 CSV 用这个
print("\r处理中", end="", flush=True)   # 进度条效果（\r 回到行首）
r = print("看 print 返回什么")
print("print 返回 ->", r)        # → print 返回 -> None
```

`sep` / `end` **必须是字符串或 `None`**（`None` 表示用默认值）。REPL 里试一下：

```
>>> print("a", "b", sep=1)
TypeError: sep must be None or a string, not int
```

本机实测报错就是这句；`end=None` 是合法的，等价于默认的 `"\n"`。
（这种 `>>>` 是 REPL 记录，直接存成 `.py` 文件会语法错误——见 `01_入门与环境.md` 第 2 节。）

### 7.2 `print` 用 `str()` 转换，不是 `repr()`

```python
print("字符串", "带引号吗")   # → 字符串 带引号吗    ← 没有引号
print(["列表", "用 str"])     # → ['列表', '用 str']  ← 但里面的元素有引号
print(repr("字符串"))         # → '字符串'
print("a\tb")                 # → a	b              ← 看不出来
print(repr("a\tb"))           # → 'a\tb'             ← 一目了然
```

| | 用途 | `"abc"` 显示成 |
|---|---|---|
| `str(x)` | 给人读 | `abc` |
| `repr(x)` | 给开发者读、尽量能还原 | `'abc'` |

`print` 对**顶层**参数用 `str()`，但容器内部的元素用**各自的 `repr()`**。
调试时用 `repr`，因为只有它能让不可见字符现形。

### 7.3 `print` 的 `file` 参数

```python
import sys

with open("out.txt", "w", encoding="utf-8") as f:
    print("这行写进了文件，不在终端", file=f)
    print("第二行", file=f)
print("终端这行照常显示")

with open("out.txt", encoding="utf-8") as f:
    print(f.read(), end="")

print("直接写 stderr：", file=sys.stderr)
sys.stderr.write("用 write 写 stderr 不会自动换行\n")
```

实测输出：

```
终端这行照常显示
这行写进了文件，不在终端
第二行
直接写 stderr：
用 write 写 stderr 不会自动换行
```

要点：`file=` 接受**任何有 `write` 方法的对象**（文件、`sys.stderr`、`io.StringIO`）；
用 `file=f` 写文件时**别忘 `encoding="utf-8"`**（`01_入门与环境.md` 6.2 节）；
`print(..., file=sys.stderr)` 会**跟着 `end` 加换行**，而 `sys.stderr.write(...)` **不会**——
这是两者最容易搞混的地方。

**为什么错误信息写 `stderr`**：`stdout` 常被重定向到文件（`python x.py > out.txt`），`stderr` 不会。
这样错误提示仍然显示在屏幕上，不污染数据文件。

> 官方内置函数文档：<https://docs.python.org/3/library/functions.html#print>
> 这里有 `print` 的完整签名和"`sep` / `end` 为 `None` 时按默认值处理"这条细节。
> 同页面还有 `input`、`round`、`isinstance`、`len` 等全部内置函数的签名，值得存书签。

### 7.4 `input` 永远返回字符串

```python
# 交互示例：需要你在终端里手动输入才能跑（直接丢给 python 会 EOFError）
line = input("请输入一个数字：")
print(repr(line), type(line))
```

实测（喂进去 `100`）：

```
请输入一个数字：input() 返回 -> '100' type = <class 'str'>
```

**不管用户敲什么，`input()` 返回的都是 `str`**——敲 `100` 得到 `'100'`，敲空行得到 `''`。
`input` 压根不解析内容：

```python
# 交互示例：跑的时候手动敲 42（或者用 echo 42 | python 这个脚本）
raw = input()                          # 喂进去 42
print(repr(raw), type(raw))            # → '42' <class 'str'>
print(int(raw), type(int(raw)))        # → 42 <class 'int'>
```

### 7.5 `int(input())` 的 `ValueError`

用户不会照着你的提示敲。真实报错（喂 `abc`）：

```
请输入你的年龄：Traceback (most recent call last):
  File "py02_input_err.py", line 4, in <module>
    age = int(raw)
ValueError: invalid literal for int() with base 10: 'abc'
```

喂进去**空行**（用户直接按回车，最常见的输入）：

```
ValueError: invalid literal for int() with base 10: ''
```

**处理方式三种，按健壮性递增**（都是交互示例，需要有输入；直接跑会因为读不到输入而报
`EOFError`）：

```python
# 1. 最简：不管，让它炸（学习阶段可以，生产不行）
age = int(input("年龄："))

# 2. 循环重问（命令行小工具够用）
while True:
    raw = input("年龄：").strip()
    if raw.isdigit():
        age = int(raw)
        break
    print("请输入一个整数。")

# 3. try/except（最通用，能处理负数、空格、任意异常输入）
while True:
    try:
        age = int(input("年龄："))
        break
    except ValueError:
        print("那不是个整数，再试一次。")
```

方案 2 的 `isdigit()` 有坑：它**不接受** `-5`，却**接受**全角数字 `１２３`
（实测 `"１２３".isdigit()` 为 `True`）。**方案 3 最稳。**

> ⚠️ **坑**：`input()` 会**吃掉行尾换行**，但**不会去掉其他空白**。
> `int(input())` 对 `" 42 "` 能工作（`int` 自己去空白），但 `input() == "42"` 对 `" 42 "` 是 `False`。
> 处理：拿到的字符串先 `.strip()` 再比较。

### 7.6 Windows 下的编码问题（**本机实测**）

**这台机器上默认不是 UTF-8**，这是中文乱码的根源。

```python
import sys
print(sys.stdin.encoding, sys.stdout.encoding, sys.flags.utf8_mode)
```

不带 `PYTHONUTF8` 时是 `gbk gbk 0`；加上 `PYTHONUTF8=1` 后是 `utf-8 utf-8 1`，
并且 `sys.getdefaultencoding()` 也是 `utf-8`。

**后果一：输出乱码。** 直接 `print("中文测试：你好世界")` 在这台机器上得到：

```
���Ĳ��ԣ��������
```

**后果二：输入被错误解码，而且可能不报错。** 这个更隐蔽。把 UTF-8 字节的 `你好`
（`e4 bd a0 e5 a5 bd`）喂进去，而解释器按 `gbk` 解码，实测解出来的码位是：

```
stdin.encoding  = gbk
code points = ['0x6d63', '0x72b2', '0x30bd']
```

`0x6d63` 是"浣"、`0x72b2` 是"犲"、`0x30bd` 是"ソ"——合起来就是那个著名的乱码 `浣犲ソ`。
**它没有报错**，长度也从期望的 2 变成了 3。字节数不巧时才会抛异常
（反向情形：输入是 GBK 字节，解释器按 UTF-8 解码）：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc4 in position 0: invalid continuation byte
```

**处理**：

```powershell
# PowerShell：只影响当前窗口
$env:PYTHONUTF8 = "1"; $env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [Text.Encoding]::UTF8
python your_script.py
setx PYTHONUTF8 1      # 永久生效，设完要重开终端
```

```bash
# Git Bash
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8
```

> 官方命令行文档：<https://docs.python.org/3/using/cmdline.html>
> "UTF-8 mode" 一节说明 `PYTHONUTF8` 到底改了哪些行为
> （`stdin`/`stdout`/`stderr` 编码、`open()` 默认编码、文件系统编码）。
> 关键结论：**它改的是"默认值"，不改你显式写下的 `encoding=`**。

> ⚠️ **坑**：`input("提示语")` 里的提示语是写到 **`stdout`** 的。
> 把 stdout 重定向到文件（`python x.py > out.txt`）时，提示语进文件、屏幕上看不到，
> 程序看起来像卡住了。处理：交互提示改用 `print(..., file=sys.stderr, end="")` 再 `input()`。

### 7.7 f-string 最小介绍（完整版在 `03_字符串.md`）

先看问题：逗号分隔会多插空格，`+` 拼接又要求两边都是字符串。

```python
age = 18
print("我今年", age, "岁")     # → 我今年 18 岁     ← 多了空格
print("我今年" + age + "岁")   # TypeError: can only concatenate str (not "int") to str
```

**f-string** 解决这个问题：字符串前加 `f`，用 `{}` 直接嵌表达式。实测三种写法输出相同：

```python
name, age = "王小明", 18
print(f"{name}今年{age}岁")                     # → 王小明今年18岁
print(f"{age + 1}")                             # → 19
print(f"{'成年' if age >= 18 else '未成年'}")    # → 成年
print("{name}今年{age}岁".format(name=name, age=age))   # → 王小明今年18岁
print("%s今年%d岁" % (name, age))                # → 王小明今年18岁

x = 42
print(f"{x=}")      # → x=42      ← 连变量名和等号一起打出来，打日志神器
print(f"{x = }")    # → x = 42
```

三条最要紧的：`f` 前缀不能少（少了就是普通字符串，`{}` 原样显示）；
`{}` 里可以放**任意表达式**；格式控制写在变量后面的冒号里（`{pi:.2f}`）。
完整用法见 `03_字符串.md` 第 3 节。

## 8. 本章自测

1. 为什么说"变量是盒子"这个模型会出错？用 `id()` 设计一个实验说明。
2. 下面两段的最终值一样吗？`q` 会不会变？为什么？

```python
p = [1]; q = p; p = p + [2]
```

3. `0.1 + 0.2 == 0.3` 的结果是什么？为什么会这样？该怎么正确比较？
4. `round(2.675, 2)` 返回什么？是"银行家舍入"导致的吗？
5. `def f(x=[])` 有什么问题？改成什么写法？这个特性有没有正当用途？
6. 写一个函数打印"参数个数"，但要求**不改动**调用者传进来的列表。
7. `bool("0")` 和 `bool("False")` 分别是什么？说出一个因此出 bug 的场景。
8. `a = b = [1, 2]` 和 `a = [1, 2]; b = [1, 2]` 有什么区别？各举一个能观察到的现象。
9. `int(input())` 在用户直接按回车时会发生什么？给出两种处理方案。
10. 为什么 `x & 1 == 1` 在 Python 里是**对的**，而在 C 里是错的？

<details>
<summary>答案</summary>

**1.** 因为赋值是"把名字贴到对象上"，不是"把值装进盒子"。

```python
t = [1, 2, 3]; print(id(t))
t = t + [4];   print(id(t))    # id 变了（造了新对象）
u = [1, 2, 3]; before = id(u)
u += [4];      print(id(u) == before)   # True（就地改，没换对象）
```

两段最终值都是 `[1, 2, 3, 4]`，但一个换了对象一个没换；盒子模型解释不了。

**2.** 值都是 `[1, 2]`。第一段 `q` 还是 `[1]`（`p = p + [2]` 造了新列表，`p` 改贴到新对象）；
第二段 `q` 变成 `[1, 2]`（`+=` 对 list 是就地 `extend`，`p` 和 `q` 一直指着同一个列表）。

**3.** `False`（表达式的值是 `0.30000000000000004`）。因为 `float` 是 IEEE 754 二进制浮点，
`0.1`、`0.2` 在二进制里是无限循环小数，只能截断到 52 位尾数；两个截断值的和与 `0.3`
的截断值不相等。正确做法：`math.isclose(0.1 + 0.2, 0.3)` 或 `abs(a - b) < 1e-9`。

**4.** 返回 `2.67`。**不是**银行家舍入导致的——`2.675` 在 `float` 里存不下，实际值是
`2.674999999999999822...`，本来就该舍成 `2.67`。想要十进制四舍五入：

```python
from decimal import Decimal
Decimal("2.675").quantize(Decimal("0.01"), rounding="ROUND_HALF_UP")   # → 2.68
```

**5.** 默认值 `[]` 只在 `def` 那一行求值一次，之后每次调用复用**同一个列表**，
于是越攒越多（`f('a')` → `['a']`，`f('b')` → `['a', 'b']`）。
改成 `def f(x=None):` 再在函数体里 `if x is None: x = []`。
正当用途：函数级缓存（`def fib(n, cache={})`），但那不如 `functools.lru_cache` 清楚。

**6.** 只读就不改：

```python
def show_count(items):
    print(len(items))          # 只读不改
```

需要加工就先返回新对象：

```python
def show_sorted(items):
    items = sorted(items)      # 返回新列表，不动原列表
    print(len(items), items)
```

关键是**别用 `items.sort()` / `items.append()` / `items += [...]`**——这三个都会改到调用者的列表。

> 这两个函数可以直接跑，输出是 `0` 和 `0 []`（空列表）——想看到效果就传个列表进去。

**7.** 都是 `True`。非空字符串恒为真，跟内容无关。
场景：从配置文件 / 命令行读到 `"False"`，写 `if flag:` 就进了"真"分支，行为和预期相反。
处理：显式解析 `raw.strip().lower() in ("1", "true", "yes")`。

**8.** `a = b = [1, 2]` 只有一个列表，`a is b` 是 `True`；
`a = [1, 2]; b = [1, 2]` 有两个内容相同的列表，`a is b` 是 `False`。
现象：`a.append(3)` 之后——第一种写法 `b` 变成 `[1, 2, 3]`（被连坐）；第二种 `b` 还是 `[1, 2]`。

**9.** 抛出 `ValueError: invalid literal for int() with base 10: ''`。两种处理：

```python
# (1) 循环重问 + isdigit 校验
while True:
    raw = input("年龄：").strip()
    if raw.isdigit():
        age = int(raw)
        break
    print("请输入整数")
```

```python
# (2) try/except（更通用，也能处理 -5 这种）
while True:
    try:
        age = int(input("年龄："))
        break
    except ValueError:
        print("那不是整数")
```

> 这两段是**交互示例**，需要有终端输入才能跑；直接丢给 `python` 会因读不到输入而报
> `EOFError`（`int(input())` 那一版还可能一直循环）。

**10.** 因为两个语言的**优先级表不同**。C 里 `==` 比 `&` 结合得紧，`x & 1 == 1` 被解析成
`x & (1 == 1)`，也就是 `x & 1`——对 `x = 2` 得到 `0`，和 `(x & 2) == 2` 的 `True` 不同。
Python 把 `&` 放在比较运算符**之上**，所以 `x & 1 == 1` 就是 `(x & 1) == 1`
（实测 `x = 2` 时是 `True`）。这是 Python 有意修掉 C 的经典坑。

</details>
