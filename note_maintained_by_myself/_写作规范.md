# 写作规范（给每个章节共用）

> 这份文件不属于学习内容，它只是保证各章风格一致。
> 读者可以跳过；维护这份笔记的人（或 AI）必须遵守。

---

## 一、硬性要求

### 1. 只用自己话写

- **禁止逐字复制**任何教程、书籍、博客的正文。runoob、官方文档、CSDN 都一样。
- 知识点、章节结构、语言事实**不受版权保护**，可以照着结构用自己话重写。
- 示例代码必须自己写，不要照抄别人的例子（哪怕改了变量名）。
- 需要引用原文时，**给链接 + 一句话概括**，不要把正文搬过来。

### 2. 官方链接怎么用

**关于网络，2026-10 的实测结论（已被 `01a_三源交叉核对.md` 第 1 节验证并纠正过一次）：**

| 取文档的方式 | 结果 |
|---|---|
| 命令行 `curl` / `Invoke-WebRequest` | ❌ 连不上（SSL 失败、HTTP 000） |
| AI 工具的 `web_fetch` | ✅ **能取到，HTTP 200** |

所以：

- **链接照常写**（`https://docs.python.org/3/...`），它是永久定位符，你以后换了网络就能用
- **不要写"详见文档第 X 节"这种依赖联网才能兑现的话**——本章里讲不清的，本章就要讲清
- 链接旁边必须有一句本文件里的解释，不能只有链接
- **需要核对事实时，可以让我（AI）去取官方文档**——这条路是通的，别再说"取不到"

### 3. 版本与事实

- 本机用于验证的解释器：**`python` = 3.13.15**（系统安装），仓库 `.venv` = 3.14.7
- 涉及"某版本新增/移除"的说法，**没实测过的要标注出来**，不要把记忆当事实
- 可以在章末放一段"诚实标注"，说明哪部分没验证过、怎么验证

### 4. 代码块必须能跑

- 所有示例代码块在写完后**实际运行一遍**，把真实输出贴进 `# 注释` 或代码块下方
- 报错示例也要跑，贴真实的 traceback，不要凭记忆编
- 输出里的中文在 Windows 终端可能显示成乱码（这是终端编码问题，见 `01_入门与环境.md` 第 6 节）——
  **贴输出时用正常中文**，不要贴乱码，但在讲编码的章节里要专门说明这个现象

### 5. 平台

- 用户是 **Windows 11 + Git Bash / PowerShell**
- 命令示例要区分 PowerShell 与 Git Bash 时，明确标注
- Windows 特有坑（路径分隔符、编码、执行策略、`python` vs `python3`）必须写进去

## 二、风格要求

### 6. 读者是谁

- **编程初学者（实现层面）**：没写过代码，但思维层面能讨论抽象概念
- 所以：**先给最小具体例子，再抽象**。不要用纯符号开场
- 每引入一个新概念，先让读者看到"它解决什么问题"，再给定义

### 7. 不要空泛

- 禁止"XX 非常重要，大家要熟练掌握"这类没有信息量的话
- 每段要么给事实，要么给例子，要么给判断依据
- 有取舍的地方**给出取舍**（什么场合用哪个、为什么），不要只说"两者都可以"

### 8. 该有"坑"的地方必须有坑

每章至少要有几处**真实存在的陷阱**，格式：

> ⚠️ **坑**：现象 → 原因 → 处理。

陷阱要具体到能复现，不要讲"要注意细节"这种废话。

### 9. 结构模板

每个章节文件按这个骨架（可按内容增减小节，但骨架必须在）：

```markdown
# NN · 章节标题

> 覆盖表条目：X.1 xxx ｜ X.2 xxx ｜ ...
>
> 一句话说明这一章要解决什么。

---

## 0. 先记住的 N 件事        ← 可选，但推荐。给整章的"锚点"

## 1. ...                    ← 按覆盖表条目顺序展开，每个条目至少一节

## N. 本章自测               ← 必写。5-10 题 + <details> 折叠答案

## N+1. 本章覆盖对账          ← 必写。覆盖表条目 → 本文小节 的映射表

**下一章**：`NN_xxx.md` —— 一句话预告。
```

### 10. 覆盖对账表（必写）

章末必须有这张表，格式固定：

```markdown
| 覆盖表条目 | 本文章节 |
|---|---|
| 0.1 安装 Python 与解释器 | 第 1 节 |
```

**这张表是"完整性可验证"的兑现方式。**
读者拿它跟 `00_知识点总览.md` 一对，就知道漏没漏。
所以：**覆盖表里列到的条目，一个都不能少**；没覆盖到的要明确写"本节不展开，原因是什么"。

### 10.1 ⚠️ 跨章引用必须用「章内节号」，不能用「覆盖表条目号」

**这个错误已经真实发生过 3 次，每次都让读者找不到地方：**

| 错误写法 | 问题 | 正确写法 |
|---|---|---|
| 见 `04_控制流.md` **2.7 节** | `2.7` 是**覆盖表条目号**（条件表达式），但 04 章的第 2 节是 `while` 循环，2.7 节不存在 | 见 `04_控制流.md` **第 7 节** |
| 见 `12_并发与网络.md` **10.4 节** | 同上（10.4 是覆盖表条目号） | 见 `12_并发与网络.md` **第 4 节** |
| 见 `10_文件与IO.md` **8.2 节** | 同上 | 见 `10_文件与IO.md` **第 2 节** |

**为什么会错**：`00_知识点总览.md` 和 `01a_三源交叉核对.md` 都用覆盖表条目号
（`0.1`、`2.7`、`10.4`…）指代内容，那是**计划口径**；
而每章实际的小节号是自己排的（`## 7. 条件表达式（三元）`），两套编号并不对应。

**规矩**：

1. **指别章内容时，写目标章的实际节号 + 标题**，例如
   「`04_控制流.md` 第 7 节「条件表达式（三元）」」——带上标题，读者一次就能找到
2. 不确定目标节号时**先去看那章的实际标题**，不要拿覆盖表条目号凑
3. 每章写完自查一遍：把所有 `N.M 节` 形式的引用抽出来，逐个确认目标存在

### 11. 本章自测

- 5～10 题，题目本身要有区分度（能区分"背过"和"懂了"）
- 答案放 `<details><summary>答案</summary>` 折叠块
- 至少一题是"为什么会这样"而不是"是什么"

## 三、长度

**参考量级：1200～2500 行。** 这**不是硬指标**。

- 早期版本这里写的是"700～900 行"。**执行下来被推翻了**：
  02 章 1454 行、03 章 1268 行、04 章 2473 行、05 章 3308 行、06 章 2422 行、
  08 章 1632 行、09 章 1541 行、10 章 2504 行 —— 全部超出，而**没有一章是在灌水**。
- 超出的原因是硬性要求直接产生的成本：**每个代码块都必须实跑并贴真实输出**，
  代码块本身就占正文的一半左右。
- 所以判定标准是：**内容多就长，内容少不要灌水**。
  宁可短而实，不要长而空。**不要为了凑行数删掉已验证的示例，也不要为了压行数把子条目改成"指路"。**

> 这一条本身是个记录：起初的指标是拍脑袋定的，实测把它纠正了。
> 同类情况（指标与实测冲突）一律按"实测优先、并把这个冲突写下来"处理。

---

## 四、写完之后

1. 实际运行所有代码示例，把真实输出填进去
2. 检查每个覆盖表条目都有对应小节
3. 检查章末对账表与本文小节号一致
4. 检查没有逐字复制的段落
