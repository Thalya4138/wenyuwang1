## 0. 先记住五件事

1. **索引从 0 开始，负数从末尾倒着数。** `s[0]` 是第一个，`s[-1]` 是最后一个。
2. **切片 `s[a:b:c]` 有三个参数、三条独立规则**，而且**越界不报错**——这和索引正好相反。
3. **字符串不可变。** 所有字符串方法都**返回新字符串**，原串一个字都不改。
   忘了接住返回值，是初学者最常见的"为什么没生效"。
4. **`join` 的接收者是分隔符，不是列表**：`sep.join(列表)`。
   写成 `列表.join(sep)` 会报 `AttributeError`。
5. **`\` 在字符串里是转义开关。** 写 Windows 路径或正则时，要么写两个反斜杠，要么用 `r"..."`。

本章所有输出都在本机 **Python 3.13.15** 上实测，运行方式：

```powershell
# PowerShell
$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"; [Console]::OutputEncoding=[Text.Encoding]::UTF8
python your_script.py
```

```bash
# Git Bash
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8
```

不加这两行，本机默认编码是 `cp936`，中文会乱码——第 4.7 节有实测演示。

## 1. 字面量、索引、切片（覆盖 1.6）

### 1.1 四种引号写法

```python
a = '单引号'
b = "双引号"
c = '''三个单引号'''
d = """三个双引号"""
print(a, b, c, d)                 # → 单引号 双引号 三个单引号 三个双引号
print('他说"你好"')                # → 他说"你好"      ← 单引号里可以放双引号
print("it's ok")                  # → it's ok         ← 双引号里可以放单引号
print('it\'s ok')                 # → it's ok         ← 同种引号要转义
```

**四种写法在功能上完全等价**，区别只是"里面能直接放哪种引号"。
`'...'` 和 `"..."` 是**单行**字符串；`'''...'''` 和 `"""..."""` 可以跨行。

选择依据（PEP 8 的建议）：**优先双引号 `"..."`**，除非字符串里有双引号。两者混用才是问题。

### 1.2 三引号：跨行与"原样保留"

```python
s = """第一行
第二行
第三行"""
print(repr(s))          # → '第一行\n第二行\n第三行'
print(s.count("\n"))    # → 2

t = """第一行
   第二行缩进
"""
print(repr(t))          # → '第一行\n   第二行缩进\n'   ← 行首空格和末尾换行都保留了
```

两个必须知道的点：

- **三引号里的换行和缩进全部是内容**。上面 `t` 的结尾多了一个 `\n`，因为闭合引号独占一行。
  写 SQL、HTML 模板时这正是想要的；写成普通字符串时这就是 bug。
- **三引号字符串本身不是注释**（见 `02_基础语法.md` 1.2 节）。放在函数体第一条位置时，
  它会被解释器存进 `__doc__`。

### 1.3 相邻字面量自动拼接（以及它引出的语法错误）

```python
v = "abc" "def"
print(repr(v))          # → 'abcdef'
print(["abc" "def"])    # → ['abcdef']

u = ("aaa"
     "bbb")
print(repr(u))          # → 'aaabbb'
w = "ccc" \
    "ddd"
print(repr(w))          # → 'cccddd'
```

**只有字面量之间**才能这样拼。写成变量就炸（真实报错）：

```python
name = "世界"
print("你好" name)
```

```
  File "n5.py", line 2
    print("你好" name)
          ^^^^^^^^^
SyntaxError: invalid syntax. Perhaps you forgot a comma?
```

注意报错位置指向**整个 `"你好" name`**，提示也很客气地猜"你是不是忘了逗号"。
跨行拼接（`("aaa" "bbb")`）是长 SQL 的常见写法，但**每行都要有引号**，
漏一个就变成上面这种报错。

### 1.4 索引：从 0 开始

```python
s = "Python"
print(len(s))                                # → 6
print(s[0], s[1], s[2], s[3], s[4], s[5])    # → P y t h o n
print(s[-1], s[-2], s[-6])                   # → n o P
```

| 写法 | 含义 |
|---|---|
| `s[0]` | 第一个字符 |
| `s[len(s) - 1]` | 最后一个字符 |
| `s[-1]` | 最后一个字符（等价的简洁写法） |
| `s[-len(s)]` | 等同 `s[0]` |

**为什么负数索引能用**：Python 把 `s[i]` 中的负数解释成 `s[len(s) + i]`。
所以 `s[-1]` 就是 `s[5]`，`s[-6]` 就是 `s[0]`。

### 1.5 索引越界会报错

```python
s = "Python"
print(s[6])
```

真实 traceback：

```
Traceback (most recent call last):
  File "n4.py", line 2, in <module>
    print(s[6])
          ~^^^
IndexError: string index out of range
```

`s[-7]` 和 `""[0]` 报的是同一个错（实测）。**索引必须落在 `-len(s)` 到 `len(s)-1` 之间。**

### 1.6 切片：`s[a:b:c]` 的三步语义

先说结论，再用例子验证：

> `s[a:b:c]` 的意思是——**从下标 `a` 出发，沿着步长 `c` 走，一直走到（不含）下标 `b` 之前停下。**

- `a` 是**起点**（包含），默认 `0`
- `b` 是**终点**（不包含），默认到末尾
- `c` 是**步长**，默认 `1`
- **负数下标先换算**，然后才应用上面三条

```python
s = "0123456789"
print(s[2:5])      # → 234
print(s[:5])       # → 01234
print(s[5:])       # → 56789
print(s[:])        # → 0123456789
print(s[-3:])      # → 789
print(s[:-3])      # → 0123456
print(s[-5:-2])    # → 567
print(s[2:5:2])    # → 24
print(s[::2])      # → 02468
print(s[1::2])     # → 13579
print(s[::-1])     # → 9876543210     ← 反转
print(s[5:2:-1])   # → 543
print(s[::-2])     # → 97531
```

`print(s[0], s[1], ...)` 那种循环取字符的写法几乎永远不该出现——直接用切片或迭代。

**步长为负时规则不变，只是"走"的方向反过来**：
`s[5:2:-1]` 是"从 5 出发往左走，走到 2 之前停下"，所以是 `543`。
注意**起点 5 本身包含在内**，这是最容易记反的地方。

步长不能是 0（REPL 记录）：

```
>>> s[::0]
ValueError: slice step cannot be zero
```

### 1.7 切片越界**不报错**

这是切片和索引最重要的行为差异（实测）：

```python
s = "0123456789"
print(s[100:])         # → ''            ← 不报 IndexError
print(s[:100])         # → 0123456789
print(s[5:2])          # → ''            ← 起点在终点右边，得到空串
print(s[-100:3])       # → '012'         ← 负数越界被截到开头
print(s[0:1000000])    # → '0123456789'
print(s[100:200])      # → ''
```

**原因**：切片的设计目标是"粗略地取一段"，不是"精确地取一个位置"。
所以它把越界下标**夹到合法范围**（clamp），而不是抛异常。

**实用后果**：切片可以安全地用在"取前 N 个字符"这种场景，不用先判长度：

```python
def head(text, n=10):
    return text[:n]      # 短于 n 也不会炸
```

> ⚠️ **坑**：`s[5:2]` 是 `''` 而**不是**报错，所以"起点写反了"这种 bug 会静默产生空串，
> 后面再到别处炸（比如 `IndexError` 或一个空的结果被写进文件）。
> 现象：取到空字符串，程序不报错。原因：切片不检查起止顺序。处理：对切出来的空串做显式判断。

### 1.8 切片是不是"新对象"？——要分情况

先看 `id` 实测：

```python
s = "abcdef"
print(s[0:3])                 # → abc
print(s is s[:])              # → True     ← 整体切片复用了原对象！
print(s[0:6] is s)            # → True
print(s[0:2] is s)            # → False    ← 部分切片是新对象
print(s[:0] is "")            # → True     ← 空串是单例

l = [1, 2, 3]
print(l[:] is l)              # → False    ← 列表整体切片一定造新对象
```

**这里有个反直觉的事实**：对**不可变**的 `str`，CPython 会把"整体切片"直接返回原对象
（反正改不了，复制没意义）。对**可变**的 `list`，`l[:]` **一定**是新列表。

**所以"切片产生新对象"这句话要分两种理解**：

| 说法 | 严格程度 |
|---|---|
| "切片让你拿到一个**独立可用**的字符串，改它不影响原串" | ✅ 永远成立（因为字符串不可变） |
| "切片一定产生**新对象**" | ⚠️ 对 `str` 是**实现细节**，不要依赖 |

**为什么这个区别重要**：依赖 `s[:] is s` 的 True/False 写逻辑（比如用它判断"有没有发生复制"），
换个解释器或换个版本就可能变。**但如果你只是想拿到一份可以随便用的字符串，切片永远安全**——
因为字符串不可变，不存在"改了副本影响原串"的可能。

> ⚠️ **坑**：`l[:]` 常被当成"复制列表"的标准写法，而 `s[:]` 有时**不**复制。
> 现象：你以为用 `[:]` 做了一次强制复制，其实没有。原因：CPython 对不可变类型的切片优化。
> 处理：字符串根本不需要担心复制问题（不可变）；列表要复制就写 `l.copy()`，语义更明确。

> 官方内置类型文档：<https://docs.python.org/3/library/stdtypes.html>
> 这份文档的 "Common Sequence Operations" 一节给出了切片的完整语义表
> （含 `a` / `b` / `c` 的默认值和负数处理），是切片行为的唯一权威描述。

### 1.9 字符串不可变：`s[0] = 'x'` 会报错

```python
s = "hello"
s[0] = "H"
```

真实 traceback：

```
Traceback (most recent call last):
  File "n3.py", line 2, in <module>
    s[0] = "H"
    ~^^^
TypeError: 'str' object does not support item assignment
```

另外两种改法也都不行（实测）：

```
s[0:1] = "H"   → TypeError: 'str' object does not support item assignment
del s[0]       → TypeError: 'str' object doesn't support item deletion
```

**想做修改，只能造一个全新字符串**：

```python
s = "hello"
print("H" + s[1:])          # → Hello
print(s.replace("h", "H"))  # → Hello
print(s.upper())            # → HELLO
print(s)                    # → hello     ← 原串一个字都没变
```

**为什么语言要这样设计**：

- 字符串可以安全地**共享**（多个名字指同一个串不会有别名问题）
- 所以能**驻留 / 缓存**，字典键用字符串才会又快又安全
- 代价是"改一个字符"要复制整串，拼接大量字符串很慢（用 `join`，见 2.3 节）

> ⚠️ **坑**：所有字符串方法都**返回新值**，原串不变。忘了接住返回值就没效果：

```python
s = "  hello  "
s.strip()
print(repr(s))        # → '  hello  '   ← 你以为去掉了空白
s = s.strip()         # ✅ 必须接住
print(repr(s))        # → 'hello'
```

> 现象：调了方法没反应。原因：字符串不可变，方法只能返回新串。
> 处理：接住返回值，或者链式调用（`s.strip().lower()`）。

### 1.10 字符串比较与 `ord` / `chr`

```python
print("abc" < "abd")     # → True
print("abc" < "ab")      # → False   ← 前缀更短的小
print("Z" < "a")         # → True    ← 大写字母码位在小写之前
print("" < "a")          # → True
print("10" < "9")        # → True    ← 不是数值比大小！
print(ord("A"), ord("a"), ord("中"))     # → 65 97 20013
print(chr(65), chr(0x4E2D))              # → A 中
```

**比较规则**：从第一个字符开始，逐个比 **Unicode 码位**（`ord` 的返回值），
第一次分出大小就出结果；一方走完了还没分出，**短的更小**。

> ⚠️ **坑**：`"10" < "9"` 是 `True`。
> 原因：`'1'`(49) < `'9'`(57)，第一个字符就分出结果了。
> 这是"从文件 / `input()` 读来的数字忘了转 `int`"的经典症状——排序结果诡异但程序不报错。
> 处理：要按数值排序就先 `int(...)`，或者用 `key=int`。

### 1.11 长度是"字符数"，不是"字节数"

```python
s = "中文abc"
print(len(s))                     # → 5
print(s.encode("utf-8"))          # → b'\xe4\xb8\xad\xe6\x96\x87abc'
print(len(s.encode("utf-8")))     # → 9
print(len(s.encode("gbk")))       # → 7
print([hex(ord(c)) for c in "中文"])   # → ['0x4e2d', '0x6587']

b"abc" + "abc"
# TypeError: can't concat str to bytes
```

**`str` 是字符序列，`bytes` 是字节序列，两者不能直接相加**——必须显式 `.encode()` / `.decode()`。
中文在不同编码下占的字节数不同（UTF-8 三字节、GBK 两字节），
所以**用 `len(s)` 估算"传输大小"是错的**，要 `len(s.encode(...))`。

### 1.12 本节小结：字符串能用的通用序列操作

```python
s = "hello"
print(len(s), s[0], s[1:3], "ell" in s)   # → 5 h el True
print(list(s))                            # → ['h', 'e', 'l', 'l', 'o']
print(list(reversed(s)))                  # → ['o', 'l', 'l', 'e', 'h']
print(sorted("cba"), max("cba"), min("cba"))   # → ['a', 'b', 'c'] c a
print(*"abc", sep="-")                    # → a-b-c
print(list(enumerate("ab")))              # → [(0, 'a'), (1, 'b')]
```

凡是**序列**能用的（`len` / 索引 / 切片 / `in` / 迭代 / `reversed` / `sorted` / `max` / `min` / 解包），
字符串都能用。这是"字符串是一种序列"带来的免费能力。

## 2. 字符串方法（覆盖 1.7）

### 2.1 一切方法都返回新字符串

这是本节的主线，先立在这里：**下面所有方法都不改原串**。

```python
s = "  Hello  "
r = s.strip()
print(repr(s), repr(r))    # → '  Hello  ' 'Hello'
print("  Hello World  ".strip().lower().replace(" ", "-"))   # → hello-world
```

最后一行是**链式调用**——每个方法返回新字符串，直接接着调下一个。

### 2.2 `split`：不带参数和带参数是两套规则

```python
s = "  a  b\tc\nd  "
print(s.split())          # → ['a', 'b', 'c', 'd']
print(s.split(" "))       # → ['', '', 'a', '', 'b\tc\nd', '', '']
print(s.split(None))      # → ['a', 'b', 'c', 'd']

print("a,b,,c".split(","))        # → ['a', 'b', '', 'c']     ← 空字段保留
print("a b  c".split(" "))        # → ['a', 'b', '', 'c']
print("a b  c".split())           # → ['a', 'b', 'c']         ← 连续空白当一个分隔符
print("a,b,c".split(",", 1))      # → ['a', 'b,c']            ← 最多切 1 次
print("a,b,c".rsplit(",", 1))     # → ['a,b', 'c']            ← 从右边切
print("l1\nl2\n".splitlines())    # → ['l1', 'l2']
print("".split(), "".split(","))  # → [] ['']
```

**两套规则的区别**（这是 `split` 最关键的一点）：

| 写法 | 分隔依据 | 连续分隔符 | 首尾空白 | 空串输入 |
|---|---|---|---|---|
| `s.split()` | **任意连续空白**（空格 / `\t` / `\n` / `\r` / `\f` / `\v`） | 当一个 | 自动丢弃 | `[]` |
| `s.split(" ")` | **恰好一个空格** | 产生空字段 | 产生空字段 | `['']` |
| `s.split(",")` | 恰好一个逗号 | 产生空字段 | 不适用 | `['']` |

**所以解析用户输入 / 分行分列时，几乎永远该用不带参数的 `s.split()`**——
它替你处理了"多敲了几个空格""行尾有 `\t`"这些事。

反过来，**解析 CSV 时必须带参数**（`line.split(",")`），因为空字段是有意义的，
不能被折叠掉。`"a,b,,c"` 里第三列是空值，不是不存在。

> ⚠️ **坑**：`"a,b,,c".split(",")` 得到 `['a', 'b', '', 'c']`（长度 4），
> 而 `"a b  c".split()` 得到 `['a', 'b', 'c']`（长度 3）。
> 现象：解析出来的列数对不上。原因：用了不带参数的 `split()` 去解析定宽数据，
> 或者用了带参数的 `split(" ")` 去解析自由文本。处理：**明确数据格式再选**。

### 2.3 `join`：为什么是 `sep.join(列表)`

```python
parts = ["2026", "06", "01"]
print("-".join(parts))                    # → 2026-06-01
print("".join(parts))                     # → 20260601
print(", ".join(["x", "y"]))              # → x, y
print("-".join(str(n) for n in range(5))) # → 0-1-2-3-4   ← 也能接生成器

"-".join([1, 2, 3])
# TypeError: sequence item 0: expected str instance, int found
print("-".join(str(n) for n in [1, 2, 3]))   # → 1-2-3
```

**`sep.join(seq)` 的读法**：`sep` 是**分隔符**（接收者），`seq` 是**要被拼起来的序列**（参数）。
结果是把 `seq` 的元素用 `sep` 连起来。

**为什么不能写成 `列表.join(sep)`？** 两个理由：

1. **技术上**：`join` 定义在 `str` 类型上，`list` 类型根本没有这个方法。
   写 `[1, 2].join("-")` 报 `AttributeError: 'list' object has no attribute 'join'`。
2. **设计上**（更本质）：如果写成 `列表.join(sep)`，那 `list` 就得知道"分隔符是什么类型"。
   但分隔符可以是任意字符串（`""`、`","`、`"\n"`、`" | "`），
   而 `str` 才是"知道怎么把一堆字符串缝起来"的那一方。
   **所以让它当接收者，序列当参数。**

**为什么该用 `join` 而不是 `+=`**：字符串不可变，每次 `+=` 都要造一个新串、复制全部内容，
循环 N 次就是 O(N²)。`join` 会先算出总长度、一次分配、一次填满。实测（各拼 20000 次）：

```
+= 拼 20000 次：0.005764 秒
join 拼 20000 次：0.000700 秒
```

这个量级差异不大，但字符串越长、次数越多，差距越明显。**习惯性用 `join` 就行**。

> ⚠️ **坑**：`join` 只接受**全是字符串**的序列。
> `"-".join([1, 2, 3])` 报 `TypeError: sequence item 0: expected str instance, int found`。
> 现象：拼数字列表就炸。原因：`join` 不做隐式类型转换。
> 处理：先转——`"-".join(map(str, nums))` 或 `"-".join(str(n) for n in nums)`。

### 2.4 `strip` / `lstrip` / `rstrip`：参数是"字符集合"

```python
s = "  \t 你好 \n "
print(repr(s.strip()))        # → '你好'
print(repr(s.lstrip()))       # → '你好 \n '
print(repr(s.rstrip()))       # → '  \t 你好'

print(repr("xxhixx".strip("x")))     # → 'hi'
print(repr("xxhixxy".strip("xy")))   # → 'hi'
print(repr("abcba".strip("ab")))     # → 'c'      ← 不是去子串 "ab"！
print(repr("  a b  ".strip()))       # → 'a b'    ← 只去两端，不动中间

print(repr("www.example.com".removeprefix("www.")))   # → 'example.com'
print(repr("a.txt".removesuffix(".txt")))             # → 'a'
```

**`strip("ab")` 不是"去掉子串 `'ab'`"，而是"从两端不断剥掉属于 `{'a','b'}` 的字符"**。
`"abcba"` 从左剥 `a`、从右剥 `a`，再从左剥 `b`、从右剥 `b`，剩下 `c`。

**想要"去掉前缀 / 后缀"用 `removeprefix` / `removesuffix`**（比 `strip` 语义清楚得多）：

| 目标 | 用哪个 |
|---|---|
| 去掉两端空白 | `s.strip()` |
| 去掉指定的两端字符 | `s.strip("0")`（字符集合） |
| 去掉确定的前缀 | `s.removeprefix("http://")` |
| 去掉确定的后缀 | `s.removesuffix(".csv")` |

### 2.5 `replace`

```python
print("a-b-c".replace("-", "+"))          # → a+b+c
print("a-b-c".replace("-", "+", 1))       # → a+b-c     ← 第三个参数是"最多替换几次"
print("aaa".replace("a", "b"))            # → bbb
print("abc".replace("x", "y"))            # → abc       ← 没找到就原样返回
print("a-b-c".replace("-", ""))           # → abc       ← 替换成空串 = 删除
```

`replace` **总是返回新串**：

```python
s = "a-b"
s.replace("-", "+")
print(s)          # → a-b    ← 没接住返回值，白调了
```

第三个参数（`count`）值得记住——"只替换第一处"不用写正则。

### 2.6 `find` / `index` / `count`

```python
s = "banana"
print(s.find("an"), s.rfind("an"))       # → 1 3
print(s.find("z"))                       # → -1        ← 找不到返回 -1
print(s.find("an", 2))                   # → 3         ← 从下标 2 开始找
print(s.find("an", 2, 4))                # → -1        ← 在 [2, 4) 范围内找
print(s.count("an"), s.count("a"))       # → 2 3
print(s.count(""))                       # → 7         ← 空串的计数很反直觉
print("aaa".count("aa"))                 # → 1         ← 不重叠计数
print("an" in s, "z" in s)               # → True False
```

```python
s = "banana"
s.index("z")
# ValueError: substring not found
```

**`find` 和 `index` 的区别只有一处**：找不到时 `find` 返回 `-1`，`index` 抛 `ValueError`。

| 用哪个 | 什么时候 |
|---|---|
| `find` | 找不到是**正常情况**（比如"有就用，没有就算"）→ 判 `!= -1` |
| `index` | 找不到是**异常情况**（数据本该有）→ 让它抛，暴露问题 |
| `in` | 只想知道**在不在**，不关心位置 |

`s.count("")` 得到 `7`（长度 6 的串）——空串在每个字符之间都"出现"，包括开头和结尾之后。
记不住无所谓，别用 `count("")` 就行。

### 2.7 `startswith` / `endswith`

```python
f = "report_2026.csv"
print(f.startswith("report"), f.endswith(".csv"))      # → True True
print(f.startswith(("a", "r")))                        # → True    ← 可以传元组，任一命中
print("x.txt".endswith((".txt", ".md")))               # → True
```

```python
f = "report_2026.csv"
f.startswith("a", "r")
# TypeError: slice indices must be integers or None or have an __index__ method
```

**第二个参数是"起始位置"，不是"另一个候选前缀"。** 想给多个候选就传**元组**。
（这是设计上的一个历史包袱，报错信息也看不出来，所以值得单独记一下。）

### 2.8 大小写

```python
print("AbC".upper(), "AbC".lower())            # → ABC abc
print("abc".capitalize())                      # → Abc        ← 只把首字母大写
print("hello world".title())                   # → Hello World
print("aB cD".swapcase())                      # → Ab Cd
print("ß".upper(), "ß".lower(), "ß".casefold())   # → SS ß ss
print("123".isdigit(), "½".isdigit(), "½".isnumeric())   # → True False True
print("   ".isspace(), " abc ".isspace())      # → True False
```

**`casefold()` 和 `lower()` 的区别**：`casefold` 做的是**无语言偏好的彻底小写化**，
专门为"比较两个字符串是否相等"设计。典型例子是德语 `ß`：`lower()` 保持 `ß`，
`casefold()` 变成 `ss`。

**判断依据**：要**显示**小写用 `lower()`；要**比较**是否同一个词用 `casefold()`。

> ⚠️ **坑**：`isdigit()` 不是"是不是合法数字串"。
> `"½".isdigit()` 是 `True`（它属于 Unicode 的 `Nd`/数字类别），
> 但 `int("½")` 直接报 `ValueError`；反过来 `"-5".isdigit()` 是 `False`。
> 现象：用 `isdigit()` 校验通过，`int()` 却失败了（或反之）。
> 处理：**要转数字就直接 `try: int(x)`**，别先用 `isdigit()` 做预检。
> （全角 `"１２３".isdigit()` 也是 `True`，且 `int("１２３")` 真的能转成 `123`——这些边界很难背。）
> 见 `02_基础语法.md` 7.5 节。

### 2.9 `partition` / `rpartition`：保留分隔符

```python
s = "key=value=extra"
print(s.partition("="))      # → ('key', '=', 'value=extra')
print(s.rpartition("="))     # → ('key=value', '=', 'extra')
print("abc".partition("="))  # → ('abc', '', '')     ← 没找到也返回三元组
print(len(s.partition("="))) # → 3                   ← 永远 3 个元素
print("a=b".split("="))      # → ['a', 'b']          ← 对比：split 丢掉分隔符
```

**`partition` 相对 `split` 的优势**：**分隔符本身被保留在结果里**，
而且**返回值个数永远固定为 3**，不用检查长度就能安全解包：

```python
key, sep, value = "key=value=extra".partition("=")
# key='key'  sep='='  value='value=extra'   ← 用 split 的话 value 会被切成两半
```

**解析 `key=value` 一定用 `partition`**，因为 `value` 里可能还有 `=`。
用 `split("=", 1)` 也能做，但 `partition` 更明确（不用记"限制次数"这回事）。

### 2.10 对齐与填充

```python
print(repr("42".zfill(5)), repr("-42".zfill(5)))     # → '00042' '-0042'
print(repr("ab".center(6, "*")))                     # → '**ab**'
print(repr("ab".ljust(5, ".")), repr("ab".rjust(5, ".")))   # → 'ab...' '...ab'
```

`zfill` 会**正确处理负号**（`-42` → `-0042`），这是它比 `rjust(5, "0")` 好的地方
（后者会得到 `00-42`）。格式化数字更推荐用格式说明符（第 3.4 节）。

### 2.11 方法速查表

| 目标 | 方法 | 返回 |
|---|---|---|
| 切分 | `split()` / `split(sep)` / `rsplit` / `splitlines` | `list` |
| 拼接 | `sep.join(seq)` | `str` |
| 去两端 | `strip` / `lstrip` / `rstrip` / `removeprefix` / `removesuffix` | `str` |
| 替换 | `replace(old, new[, count])` | `str` |
| 查找位置 | `find` / `rfind`（找不到 `-1`）；`index` / `rindex`（抛异常） | `int` |
| 计数 | `count(sub)` | `int` |
| 判断前后缀 | `startswith` / `endswith`（可传元组） | `bool` |
| 切一刀 | `partition` / `rpartition` | `tuple`（永远 3 元） |
| 大小写 | `upper` / `lower` / `capitalize` / `title` / `swapcase` / `casefold` | `str` |
| 对齐填充 | `zfill` / `center` / `ljust` / `rjust` | `str` |

> ⚠️ **坑**：**所有方法都不改原串**，而且**大部分方法"找不到"时返回原串 / `-1` / `False` 而不是报错**。
> `"abc".replace("x", "y")` 得到 `"abc"`，不报错；
> `"abc".find("x")` 得到 `-1`，不报错。
> 现象：方法调用看起来"成功了"但结果没变。原因：没找到匹配，静默返回原样。
> 处理：需要区分"替换成功"和"没找到"时，先 `in` / `find` 判断，或比较返回值和原串。

## 3. 格式化（覆盖 1.8）

### 3.1 三种写法，同一个结果

```python
name, age, pi = "王小明", 28, 3.14159
print(f"{name}今年{age}岁")            # → 王小明今年28岁
print("{}今年{}岁".format(name, age))  # → 王小明今年28岁
print("%s今年%d岁" % (name, age))      # → 王小明今年28岁
```

三种写法能力上都能覆盖绝大多数需求，差别在**可读性、出错方式和历史**。

### 3.2 f-string：新代码的默认选择

字符串前加 `f`，`{}` 里放**任意表达式**：

```python
name, age = "王小明", 28
print(f"{1 + 1}")                                  # → 2
print(f"{name.upper()}")                           # → 王小明（中文没大小写）
print(f"{'yes' if age > 18 else 'no'}")            # → yes
print(f"{len(name)}, {age * 12}")                  # → 3, 336
print(f"{ {'a': 1}['a'] }")                        # → 1
print(f"{'单引号在里面'}")                          # → 单引号在里面
```

**引号嵌套**：本机 3.13 实测下面这行合法（外层双引号、内层也是双引号）：

```python
print(f"{ "双引号在里面" }")   # → 双引号在里面
```

这个能力是某个版本放宽 f-string 语法之后才有的——**具体版本未实测**。
在 3.13 之前的解释器上会直接 `SyntaxError`，所以**跨版本共享代码时别这么写**。
稳妥做法是内层用另一种引号：`f"{'双引号在里面'}"`。

### 3.3 `f"{x=}"`：调试语法

```python
x = 42
name = "王小明"
print(f"{x=}")              # → x=42
print(f"{x = }")            # → x = 42
print(f"{name=}")           # → name='王小明'
print(f"{x + 1 = }")        # → x + 1 = 43
print(f"{name.upper() = }") # → name.upper() = '王小明'
print(f"{x=:5}")            # → x=   42      ← 后面还能接格式说明符
print(f"{x=:05d}")          # → x=00042
```

**它做的事是：把 `=` 左边的源码文本原样打印出来，再加上 `=`，再加上值。**
打日志时不用再写 `print("x =", x)`，省掉一半手误（变量名和值不可能对不上）。

**值用 `repr()` 而不是 `str()`**：注意 `name='王小明'` 带引号。
这是有意的——调试输出需要区分字符串 `"42"` 和整数 `42`。

### 3.4 格式说明符：

`{值:[填充][对齐][符号][#][0][宽度][,][.精度][类型]}`

**浮点**：

```python
pi = 3.14159
print(f"{pi:.2f}")           # → 3.14
print(f"{pi:.0f}")           # → 3
print(f"[{pi:10.3f}]")       # → [     3.142]     ← 默认右对齐，宽度 10
print(f"[{pi:<10.3f}]")      # → [3.142     ]     ← 左对齐
print(f"[{pi:>10.3f}]")      # → [     3.142]
print(f"[{pi:^10.3f}]")      # → [  3.142   ]     ← 居中
print(f"{pi:e}", f"{pi:.2e}")     # → 3.141590e+00 3.14e+00
print(f"{pi:g}")             # → 3.14159          ← 自动选定点或科学计数
print(f"{pi:%}")             # → 314.159000%      ← 乘 100 加百分号
print(f"{0.5:.1%}")          # → 50.0%
```

**整数与进制**：

```python
n = 255
print(f"{n:d}", f"{n:b}", f"{n:o}", f"{n:x}", f"{n:X}")   # → 255 11111111 377 ff FF
print(f"{n:#x}", f"{n:#b}")                               # → 0xff 0b11111111
print(f"{n:08b}")                                         # → 11111111   （8 位，前面补 0）
print(f"{1234567890:,}")                                  # → 1,234,567,890
print(f"{1234567890:_}")                                  # → 1_234_567_890
```

**字符串对齐与截断**：

```python
print(f"[{'左':<10}]")        # → [左         ]
print(f"[{'中':^10}]")        # → [    中     ]
print(f"[{'右':>10}]")        # → [         右]
print(f"[{'填充':*^10}]")     # → [****填充****]
print(f"{'abcdef':.3}")       # → abc          ← 精度对字符串是"截断到 N 个字符"
```

**符号与动态宽度**：

```python
print(f"{42:+d} {42:-d} {42: d}")     # → +42 42  42
print(f"{-42:+d}")                    # → -42
print(f"{3.14:+.2f}")                 # → +3.14
w = 8
print(f"[{'hi':>{w}}]")               # → [      hi]     ← 宽度可以是变量
```

**这些说明符在 `str.format` 和内置 `format()` 里完全一样**，因为它们共用同一套迷你语言。

> 官方格式说明符语法：<https://docs.python.org/3/library/string.html#format-specification-mini-language>
> 这份文档是格式说明符（`:.2f` `:>10` `:,` `:%` `:b` 等）的**完整权威定义**，
> 也是"哪个类型支持哪个类型码"的查询表（比如 `:d` 只对整数有效，对 `float` 会报错）。
> 表里的 `[[fill]align][sign][#][0][width][,][.precision][type]` 就是上面那串顺序。

> ⚠️ **坑**：格式说明符**类型不匹配会抛异常**，不像 `%` 那样静默转换。

```python
f"{3.9:d}"
# ValueError: Unknown format code 'd' for object of type 'float'
```

> 对比老写法：`"%d" % 3.9` 得到 `'3'`（**静默截断**）。
> 现象：老代码算出来的数字悄悄少了小数部分。原因：`%d` 会转。
> 处理：新代码用 f-string，它**拒绝**而不是猜。

### 3.5 `str.format()`：需要"模板"时用

```python
print("{0} {1} {0}".format("A", "B"))          # → A B A      ← 位置可以重复
print("{name} {age}".format(name="王", age=28)) # → 王 28      ← 关键字
print("{0}-{k}".format("A", k="B"))            # → A-B
print("{}-{}".format("A", "B"))                # → A-B        ← {} 自动编号
print("{:.2f}".format(3.14159))                # → 3.14
print("|{:>8}|".format("hi"))                  # → |      hi|
print("{0[0]}-{0[1]}".format(["a", "b"]))      # → a-b        ← 按下标取
print("{p[0]}".format(p=["x", "y"]))           # → x
print("{{}}".format())                          # → {}        ← 双大括号表示字面量
```

它相对 f-string 的**唯一优势**：**模板和数据可以分开**。

```python
TEMPLATE = "尊敬的 {name}，您本月账单为 {amount:.2f} 元。"
# 模板可以来自配置文件、数据库、翻译文件……
print(TEMPLATE.format(name="王", amount=128.5))
```

f-string 做不到这一点——它的模板**写死在源码里**，因为 `{}` 里的表达式需要在编译期解析。

**所以选型很清楚**：

| 场景 | 用哪个 |
|---|---|
| 格式串写死在代码里 | **f-string**（最短、最快、能放任意表达式） |
| 格式串来自外部（配置 / i18n / 模板文件） | `str.format()` |
| 维护老代码 | `%`（认识就行，别新增） |

`format()` **内置函数**和 `str.format()` **方法**是两回事，但共用同一套说明符：

```python
print(format(3.14159, ".2f"))   # → 3.14
print(format(255, "x"))         # → ff
print(repr(format("hi", ">8"))) # → '      hi'
```

**关系**：`f"{x:spec}"` 和 `"{:spec}".format(x)` 最终都调用 `x.__format__("spec")`。
内置 `format(x, spec)` 就是这一步的**直接暴露**。实测自定义 `__format__` 能收到说明符：

```python
class Show:
    def __format__(self, spec):
        return f"<收到说明符 {spec!r}>"

print(f"{Show()}")          # → <收到说明符 ''>
print(f"{Show():.2f}")      # → <收到说明符 '.2f'>
print("{:>10}".format(Show()))   # → <收到说明符 '>10'>
```

**这条链说明**：三种格式化写法不是三套机制，而是"**一种协议 + 三种前端语法**"。
理解了 `__format__`，三种写法就都通了。

### 3.6 `%` 格式化：过时但必须认识

```python
print("%s / %d / %f" % ("文本", 7, 3.14159))   # → 文本 / 7 / 3.141590
print("%.2f" % 3.14159)                        # → 3.14
print("[%10.2f]" % 3.14159)                    # → [      3.14]
print("[%-10.2f]" % 3.14159)                   # → [3.14      ]     ← - 表示左对齐
print("[%05d]" % 42)                           # → [00042]
print("%s-%s" % ("a", "b"))                    # → a-b
print("%s" % "单独一个")                        # → 单独一个        ← 一个值可以不用元组
print("%(name)s" % {"name": "王"})              # → 王
print("100%%" % ())                            # → 100%
```

**`%` 已经过时，理由是它的出错方式**：

```python
"%d" % "abc"
# TypeError: %d format: a real number is required, not str

"%s %s" % ("只有一个",)
# TypeError: not enough arguments for format string

"%d" % 3.9
# → '3'        ← 这个最阴：不报错，静默截断
```

- 类型和值**分两处写**，参数一多就对不上，而且报错发生在**运行期**
- `%d` 遇到浮点**静默截断**（`"%d" % 3.9` 是 `'3'`），而 f-string 的 `f"{3.9:d}"` 会
  直接抛 `ValueError`——**现代写法拒绝猜**

**结论**：新代码用 f-string。但**读老代码绕不开 `%`**——十几年前的代码、大量第三方库的日志格式、
`logging` 模块的 `%` 风格参数都还在用它。上表够你读懂它们。

### 3.7 三者对比与选型

| | f-string | `str.format()` | `%` |
|---|---|---|---|
| 引入 | 3.6（**版本号未实测**） | 2.6 | Python 早期 |
| 可读性 | 最好（表达式就地写） | 一般 | 最差（类型码和值分离） |
| 模板可外置 | ❌ | ✅ | ❌ |
| 能放任意表达式 | ✅ | ❌（只能放参数、下标、属性） | ❌ |
| 类型不匹配 | 抛异常 | 抛异常 | 常常静默转换 |
| 新代码该用吗 | ✅ 默认 | 模板场景 | ❌ 不要新增 |

## 4. 转义字符与原始字符串（覆盖 1.9）

### 4.1 转义表

```python
print(repr("\n"), repr("\t"), repr("\\"))       # → '\n' '\t' '\\'
print(repr("\'"), repr("\""))                   # → "'" '"'
print(repr("\r"), repr("\b"), repr("\f"), repr("\v"), repr("\a"))
# → '\r' '\x08' '\x0c' '\x0b' '\x07'
print(repr("\0"), len("\0"), bool("\0"))        # → '\x00' 1 True
```

| 写法 | 含义 | 备注 |
|---|---|---|
| `\n` | 换行 | 最常用 |
| `\t` | 制表符 | 对齐用，但列宽依赖终端 |
| `\\` | 一个反斜杠 | Windows 路径 |
| `\'` `\"` | 引号 | 同种引号才需要 |
| `\r` | 回车（回到行首） | 做进度条：`print("...", end="\r")` |
| `\b` `\f` `\v` `\a` | 退格 / 换页 / 垂直制表 / 响铃 | 现代代码基本不用 |
| `\0` | 空字符 | 长度是 1，**真值也是 `True`** |

`repr` 帮你看清它们：`print("a\tb")` 输出的是真实制表符（看不出是什么），
`print(repr("a\tb"))` 输出 `'a\tb'` 一目了然。

```python
print("姓名\t年龄")
print("王小明\t28")
# →
# 姓名	年龄
# 王小明	28
```

### 4.2 `\xhh`：一字节十六进制

```python
print(repr("\x41"))            # → 'A'          （0x41 = 65 = 'A'）
print(repr("\x7f"))            # → '\x7f'
print(repr("\xe4\xb8\xad"))    # → 'ä¸\xad'     ← 不是"中"！
print(len("\xe4\xb8\xad"))     # → 3            ← 三个字符
print(repr(b"\xe4\xb8\xad".decode("utf-8")))   # → '中'   ← 必须解码才是"中"
```

**这是最容易搞错的一处**：`\xhh` 产生的是**码位等于 hh 的字符**（U+00E4 是 `ä`），
**不是"一个 UTF-8 字节"**。所以把 UTF-8 的 `中`（三个字节 `e4 b8 ad`）写成
`"\xe4\xb8\xad"` 得到的是**三个拉丁字符**，不是"中"。

**要用字节就用 `bytes` 字面量 `b"..."`，然后 `.decode()`。**

### 4.3 `\uhhhh` 与 `\Uhhhhhhhh`：直接写码位

```python
print(repr("\u4e2d"))            # → '中'      （U+4E2D）
print(repr("\u0041"))            # → 'A'
print(repr("\U0001F600"))        # → '😀'      （U+1F600，需要 8 位）
print(len("\U0001F600"))         # → 1         ← emoji 是单个字符
print(repr("\U0001F600"[0]))     # → '😀'
```

| 写法 | 位数 | 能表示的范围 |
|---|---|---|
| `\xhh` | 2 位十六进制 | U+00～U+FF |
| `\uhhhh` | **恰好 4 位** | U+0000～U+FFFF（基本多文种平面） |
| `\Uhhhhhhhh` | **恰好 8 位** | 到 U+10FFFF（含 emoji、罕见汉字） |

**位数是硬性的**：`\u12`（只有 2 位）和 `\U0001F60`（只有 7 位）都是 `SyntaxError`（见 4.6 节实测）。

### 4.4 `\N{名字}`：用 Unicode 官方名字写字符

```python
print(repr("\N{GREEK SMALL LETTER ALPHA}"))              # → 'α'
print(repr("\N{CJK UNIFIED IDEOGRAPH-4E2D}"))            # → '中'   ← 汉字的名字就是码位
print(repr("\N{SNOWMAN}"))                               # → '☃'
print(repr("\N{BULLET}"))                                # → '•'
print(repr("\N{LATIN SMALL LETTER E WITH ACUTE}"))       # → 'é'
```

**名字必须是 Unicode 官方英文名**，而**汉字没有语义化的名字**——
它的官方名字就是 `CJK UNIFIED IDEOGRAPH-XXXX`（XXXX 是码位）。
所以 `\N{中文名}` 这种写法不存在，写了直接语法错误。

**反查名字用 `unicodedata`**（本机实测）：

```python
import unicodedata
for ch in "中α☃é":
    print(f"{ch}  U+{ord(ch):04X}  {unicodedata.name(ch)}")
# 中  U+4E2D  CJK UNIFIED IDEOGRAPH-4E2D
# α  U+03B1  GREEK SMALL LETTER ALPHA
# ☃  U+2603  SNOWMAN
# é  U+00E9  LATIN SMALL LETTER E WITH ACUTE

print(repr(unicodedata.lookup("SNOWMAN")))   # → '☃'
unicodedata.lookup("汉字")
# KeyError: "undefined character name '汉字'"
```

`unicodedata.name()` 从字符查名字，`unicodedata.lookup()` 从名字查字符——
后者就等价于源码里写 `\N{...}`。

> 官方 `unicodedata` 文档：<https://docs.python.org/3/library/unicodedata.html>
> 这份文档列出了 `name` / `lookup` / `category` / `normalize` 等函数。
> 做"两个看起来一样的字符串为什么不相等"的排查时，`name()` 和 `normalize()` 是关键工具
> （比如 `"é"` 可能是单码位 U+00E9，也可能是 `e` + 组合重音符两个码位，长得一样但 `!=`）。

### 4.5 八进制转义（知道有这回事）

```python
print(repr("\101"))     # → 'A'    （八进制 101 = 十进制 65）
```

`\ooo`（1～3 位八进制）现在几乎不在新代码里出现。`"\0"` 是它的常见特例。

### 4.6 原始字符串 `r"..."`

```python
print(repr(r"\n"))                # → '\\n'      ← 反斜杠 + n，两个字符
print(repr("\n"))                 # → '\n'       ← 一个换行
print(len(r"\n"), len("\n"))      # → 2 1
print(repr(r"C:\Users\Wang"))     # → 'C:\\Users\\Wang'
print(repr(r"\\"))                # → '\\\\'
print(repr(r"\d{3}-\d{4}"))       # → '\\d{3}-\\d{4}'   ← 正则里必须这么写
print(repr("\\d{3}-\\d{4}"))      # → '\\d{3}-\\d{4}'   ← 不用 r 就得写两遍
```

**`r` 前缀唯一的规则**：**反斜杠不再是转义开关**，它就是普通字符。

**但引号的转义仍然生效**（这是唯一例外）：

```python
print(repr(r"it\'s"))     # → "it\\'s"    ← 反斜杠被保留了！
```

对比普通字符串 `"it\'s"` 得到 `"it's"`（反斜杠被吃掉）。
**所以 `r` 字符串里 `\'` 会留下一个多余的反斜杠**——里面想放引号就用另一种引号，
或者干脆不用 `r`。

### 4.7 原始字符串的边界：结尾不能是奇数个反斜杠

这是 `r` 字符串**唯一的硬限制**。用 `compile()` 一次测多条（本机实测）：

```python
cases = ['r"\\"', 'r"C:\\Users\\"', '"\\N"', '"\\N{汉字}"',
         '"\\xZZ"', '"\\x1"', '"\\u12"', '"\\U0001F60"']
for src in cases:
    try:
        compile(src, "<test>", "eval")
        print("OK      ", src)
    except SyntaxError as e:
        print("SyntaxError", src, "->", e.msg)
```

输出：

```
SyntaxError r"\"                   -> unterminated string literal (detected at line 1); perhaps you escaped the end quote?
SyntaxError r"C:\Users\"           -> unterminated string literal (detected at line 1); perhaps you escaped the end quote?
SyntaxError "\N"                   -> (unicode error) 'unicodeescape' codec can't decode bytes in position 0-1: malformed \N character escape
SyntaxError "\N{汉字}"             -> (unicode error) 'unicodeescape' codec can't decode bytes in position 0-23: unknown Unicode character name
SyntaxError "\xZZ"                 -> (unicode error) 'unicodeescape' codec can't decode bytes in position 0-1: truncated \xXX escape
SyntaxError "\x1"                  -> (unicode error) 'unicodeescape' codec can't decode bytes in position 0-2: truncated \xXX escape
SyntaxError "\u12"                 -> (unicode error) 'unicodeescape' codec can't decode bytes in position 0-3: truncated \uXXXX escape
SyntaxError "\U0001F60"            -> (unicode error) 'unicodeescape' codec can't decode bytes in position 0-8: truncated \UXXXXXXXX escape
```

**为什么 `r"C:\Users\"` 会炸**：`r` 字符串里反斜杠**仍然是"引用下一个字符"的**——
只是"引用"的结果被原样保留。所以 `\"` 表示"一个被引用的引号"，
于是这个字符串**永远没有结束**。报错信息说得很直白：*"perhaps you escaped the end quote?"*

真实文件里的报错长这样：

```
  File "n2.py", line 1
    p = r"C:\Users\"
        ^
SyntaxError: unterminated string literal (detected at line 1); perhaps you escaped the end quote?
```

`\N{汉字}` 也一样（真实 traceback）：

```
  File "n1.py", line 1
    print("\N{汉字}")
          ^^^^^^^^
SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes in position 0-23: unknown Unicode character name
```

**注意这类错误是 `SyntaxError`，所以整个文件一行都不执行**——
连文件里第一个 `print` 都不会运行（见 `01_入门与环境.md` 3.2 节）。

### 4.8 Windows 路径的五种写法（本机实测都得到同一个路径）

```python
import os, pathlib

print(repr("C:\\Users\\Wang\\Desktop"))                      # → 'C:\\Users\\Wang\\Desktop'
print(repr(r"C:\Users\Wang\Desktop"))                        # → 'C:\\Users\\Wang\\Desktop'
print(repr("C:/Users/Wang/Desktop"))                         # → 'C:/Users/Wang/Desktop'
print(repr(os.path.join("C:\\Users", "Wang", "Desktop")))     # → 'C:\\Users\\Wang\\Desktop'
print(repr(str(pathlib.Path("C:/Users") / "Wang" / "Desktop")))# → 'C:\\Users\\Wang\\Desktop'

print(repr(os.sep), repr(os.altsep), repr(os.linesep))        # → '\\' '/' '\r\n'
```

| 办法 | 写法 | 评价 |
|---|---|---|
| 双反斜杠 | `"C:\\Users"` | ✅ 到处都能用，但容易漏写一个 |
| 原始字符串 | `r"C:\Users"` | ✅ **最可读**，但**结尾不能有反斜杠** |
| 正斜杠 | `"C:/Users/"` | ✅ Windows 上 Python 认，跨平台首选 |
| `os.path.join` | `os.path.join("C:\\", "Users")` | ✅ 自动补正确分隔符 |
| `pathlib` | `pathlib.Path("C:/Users") / "Wang"` | ✅ 现代写法，`/` 运算符拼路径 |

**推荐**：临时调试用 `r"C:\Users"`（最像人想的路径）；写正式代码用 `pathlib`
（它能正确处理跨平台、能 `.exists()`、能 `.read_text()`，见 `10_文件与IO.md`）。

**注意 `os.linesep` 在 Windows 上是 `'\r\n'`**，这是文本文件行尾差异的来源；
`open()` 默认会做换行转换（`newline=None`），所以一般不用手动处理。

> ⚠️ **坑**：`r"C:\Users\"` 报 `SyntaxError: unterminated string literal`。
> 现象：整个脚本一行都不执行，报错位置还很奇怪。原因：`r` 字符串里 `\"` 仍被当成"转义后的引号"，
> 导致字符串没结束。处理：**去掉结尾反斜杠**（`os.path.join` / `pathlib` 会帮你加），
> 或者不用 `r`：`"C:\\Users\\"`，或者拼接 `r"C:\Users" + "\\"`。

### 4.9 无效转义序列：只是警告，但早晚会变错误

```python
v = "\d"
```

本机实测输出（程序照常跑完）：

```
'\d' 的实际值 = '\\d'
C:\...\py03_i.py:106: SyntaxWarning: invalid escape sequence '\d'
```

**`"\d"` 不会报错**，Python 保留原样（得到 `\d` 两个字符），但发一条 `SyntaxWarning`。

**为什么危险**：这个警告**默认情况下在第一次编译时才显示，而且很多人根本不看**。
更关键的是官方已经说明这类写法**将来会变成错误**（具体版本**未实测**）。

**规则**：**写正则一律用 `r"..."`**。

```python
import re
print(re.findall(r"\d+", "a12b345"))    # → ['12', '345']
print(re.findall(r"\w+", "hi there"))   # → ['hi', 'there']
```

需要转义的字符里，**只有一小部分是非法的**：`\d` `\w` `\s` `\.` `\-` 这些在字符串里没有定义，
会警告；而 `\n` `\t` `\\` `\x41` 是合法的转义，**用了 `r` 反而会改变含义**——
`r"\n"` 是两个字符，不是换行。**这就是"写正则必须用 r"和"路径不能无脑用 r"并存的原因。**

### 4.10 Windows 终端编码与中文（**本机实测**）

前面的内容默认你能看到正常中文。**这台机器上默认看不到**：

```python
import sys
print(sys.stdout.encoding, sys.flags.utf8_mode)
# 不带 PYTHONUTF8 时 → gbk 0
# 带上 PYTHONUTF8=1 时 → utf-8 1
```

直接 `print("中文测试：你好世界")` 在这台机器上得到：

```
���Ĳ��ԣ��������
```

**字符串在 Python 内部永远是 Unicode，问题出在"写出去的那一刻"**：

| 层 | 是什么 | 这台机器上 |
|---|---|---|
| 源文件编码 | Python 怎么读你的 `.py` | UTF-8（Python 3 固定） |
| 字符串本体 | 内存里的码位序列 | 不受终端影响 |
| **标准输出编码** | Python 往终端写字节时用什么 | 默认 **`gbk`** |

**所以"`len(s)` 算对了但 `print` 出来是乱码"不矛盾**——`len` 看的是字符串本身，
乱码发生在写字节的时候。

**处理**（三选一，可以叠加）：

```powershell
# PowerShell：只影响当前窗口
$env:PYTHONUTF8 = "1"; $env:PYTHONIOENCODING = "utf-8"
[Console]::OutputEncoding = [Text.Encoding]::UTF8
python your_script.py

setx PYTHONUTF8 1        # 永久生效，设完要重开终端
chcp 65001               # 把终端代码页切到 UTF-8
```

```bash
# Git Bash
export PYTHONUTF8=1 PYTHONIOENCODING=utf-8
```

> 官方命令行文档：<https://docs.python.org/3/using/cmdline.html>
> "UTF-8 mode" 一节说明 `PYTHONUTF8` 到底改了哪些默认行为
> （`stdin`/`stdout`/`stderr` 编码、`open()` 默认编码、文件系统编码）。
> 关键结论：**它改的是"默认值"，不改你显式写下的 `encoding=`**。

> ⚠️ **坑**：读文件时同样的错会出现得更隐蔽。
> 本机 `open("a.txt")` 不写 `encoding` 时用的是 `cp936`（`01_入门与环境.md` 6.2 节实测），
> 于是你写出的 UTF-8 文件、别人用默认设置读会乱码或 `UnicodeDecodeError`。
> 处理：**读写文本文件永远显式写 `encoding="utf-8"`**，无论终端怎么设。

## 5. 本章自测

1. `s = "Python"`，`s[-1]` 和 `s[5:100]` 分别是什么？为什么一个越界会报错、一个不会？
2. `s[5:2]` 返回什么？这个行为可能掩盖什么 bug？

5. 为什么 `join` 写成 `sep.join(列表)` 而不是 `列表.join(sep)`？写反了报什么错？
6. `"abcba".strip("ab")` 返回什么？为什么不是 `'cba'` 或 `'abc'` 之类？
7. `"key=value=extra".partition("=")` 和 `"key=value=extra".split("=")` 有什么区别？
   解析 `key=value` 该用哪个？
8. `r"C:\Users\"` 为什么是语法错误？给出两种改法。
9. `"\xe4\xb8\xad"` 是"中"吗？为什么？怎么写才能得到"中"？
10. `f"{3.9:d}"` 和 `"%d" % 3.9` 的行为差别是什么？这个差别为什么重要？

<details>
<summary>答案</summary>

1. `s[-1]` 是 `'n'`；`s[5:100]` 是 `'n'`（切片越界被夹到合法范围，返回能取到的部分）。
   索引是"精确定位一个位置"，越界没有合理结果，所以必须报 `IndexError`；
   切片是"大致取一段"，设计上允许范围超出，所以夹到边界即可。

2. 返回 `''`（空字符串），不报错。它掩盖的 bug 是"起点和终点写反了"——
   代码看起来在取东西，实际得到空串，一直传到下游才炸（或者被当成合法空值写进结果）。

3. 因为 `str` 不可变：整体切片复用原对象是安全的（反正改不了），CPython 就这么优化了；
   `list` 可变，`l[:]` 必须造新列表，否则 `l[:].append(x)` 会改到原列表。
   **不能依赖这个差异**——它是实现细节。但字符串切片"可以安全独立使用"这一点永远成立。

4. `"a b  c".split()` → `['a', 'b', 'c']`；`"a b  c".split(" ")` → `['a', 'b', '', 'c']`。
   解析 CSV 用带参数的 `split(",")`——空字段是有意义的数据，不能被折叠掉；
   解析自由文本（用户输入、按空白分列）用不带参数的 `split()`。

5. 因为 `join` 是 `str` 类型的方法，`list` 根本没有这个方法；更本质的原因是
   "知道怎么缝合字符串"的是分隔符（`str`），不是被缝合的序列。
   写反了报 `AttributeError: 'list' object has no attribute 'join'`。

6. 返回 `'c'`。`strip(chars)` 的参数是**字符集合**不是子串：它从两端不断剥掉
   属于 `{'a','b'}` 的字符，直到遇到不属于集合的字符为止。`abcba` 剥掉两端各两个，剩 `c`。

7. `partition` 返回 `('key', '=', 'value=extra')`（三元组，分隔符保留）；
   `split` 返回 `['key', 'value', 'extra']`（分隔符丢掉，且被切成 3 段）。
   解析 `key=value` 用 `partition`，因为 `value` 里可能还有 `=`——
   用 `split("=", 1)` 也行，但 `partition` 的返回值个数固定，解包更安全。

8. 因为 `r` 字符串里反斜杠**仍然是"引用下一个字符"的**，只是结果被原样保留。
   所以 `\"` 是一个"被转义引号"，字符串永远不会结束。
   改法一：去掉结尾反斜杠，用 `os.path.join("C:\\Users", "")` 或 `pathlib.Path(r"C:\Users")`；
   改法二：不用 `r`，写 `"C:\\Users\\"`；改法三：拼接 `r"C:\Users" + "\\"`。

9. 不是。`\xhh` 产生的是**码位等于 hh 的字符**，所以 `"\xe4\xb8\xad"` 是三个拉丁字符
   （`ä` + `¸` + 一个控制字符），不是"中"。要得到"中"要么写 `"\u4e2d"`，
   要么写字节串再解码：`b"\xe4\xb8\xad".decode("utf-8")`。

10. `f"{3.9:d}"` 抛 `ValueError: Unknown format code 'd' for object of type 'float'`；
    `"%d" % 3.9` 静默返回 `'3'`。这个差别重要是因为——
    老写法的错误是**静默的数据损失**（金额的小数部分被悄悄丢掉，程序不报错），
    新写法**拒绝猜**，让错误在第一次运行时就暴露出来。
