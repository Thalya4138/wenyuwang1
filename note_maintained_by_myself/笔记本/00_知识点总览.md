## 一、先说一个反直觉的结论

你担心我整理得不全，所以想**照着 runoob 逐字复制**来保证完整。

**但 runoob 的目录本身就不全。** 我把它的 32 章目录抓下来逐条看了：

### runoob 缺的东西（这些在 2026 年的 Python 里是必修或常用）

| 缺失的知识点 | 为什么重要 |
|---|---|
| 类型提示 / `typing` | 现代 Python 代码处处都是，读别人的代码绕不开 |
| `asyncio` / 异步编程 | 网络、爬虫、AI 应用的基本盘 |
| 虚拟环境 `venv` | 只讲 `pip` 不讲 `venv`，等于教你在系统里乱装包 |
| 上下文管理器 `with` | 只在文件那一章顺带一提，没有系统讲 |
| 生成器 / 迭代器 | Python 最核心的设计之一，完全没有独立章节 |
| 装饰器 | 同上，框架里到处都是 |
| `match / case`（3.10+） | 现在的主流分支写法 |
| 测试（`unittest` / `pytest`） | 写完代码不测等于没写 |
| 推导式（comprehensions） | 没有独立章节，藏在数据结构里 |
| 包管理 / 项目管理 | 只有 `pip` 一条，没有工程视角 |

### runoob 里有、但已经过时或不该先学的东西

| 章节 | 问题 |
|---|---|
| `cgi-programming` | **CGI 模块已在 Python 3.13 被移除**（PEP 594）。现在学它 = 学一门死掉的技术 |
| `mysql`（CGI 时代写法） | 老派内容，不是入门阶段该碰的 |
| `smtp` | 同上 |

**结论：**

> 「忠实于某一个源」不等于「完整」。不管那个源是 runoob、是我、还是某本书。
> **完整性只能来自多源交叉。**

## 二、「完整」怎么定义（三层）

| 层 | 内容 | 能不能做到完整 |
|---|---|---|
| **核心语法** | 语言本身：类型、控制流、函数、类、异常、模块 | ✅ **可以做到 100%** |
| **标准库** | 200+ 个模块 | ✅ 做到**索引级完整**：全部列出 + 一句话 + 官方链接 |
| **生态 / 进阶** | 框架、数据科学、AI、爬虫、部署… | ❌ **不可能完整**。明确划界比假装覆盖更诚实 |

**你要拿到的是「一张完整的地图」，不是「一片完整的土地」。**
地图的好处是：哪块没画，你一眼看得出来。
