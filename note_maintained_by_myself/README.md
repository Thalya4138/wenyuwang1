## Python 怎么读

**第一次来，按这个顺序：**

1. [`00_知识点总览.md`](Python笔记本/00_知识点总览.md) — 先看「快速入口」和「完整的三层定义」，知道这份笔记的边界在哪
2. [`01_入门与环境.md`](Python笔记本/01_入门与环境.md) — 把环境弄对。**这一章跳过的话，后面 80% 的"为什么我这跑不通"都会找上门**
3. `02` → `12` 顺次读。每章开头都有「先记住的 N 件事」作为锚点
4. 遇到"这功能归谁管"就去 [`99_标准库索引.md`](Python笔记本/99_标准库索引.md) 查

**每章固定的四个部分**（知道结构能省很多时间）：

| 部分 | 作用 |
|---|---|
| 开头 blockquote | 本章负责覆盖表的哪几条 |
| `## 0. 先记住的 N 件事` | 全章锚点，忘了细节回来看这里 |
| 正文章节 | 先给最小可运行的例子，再抽象 |
| **章末「本章自测」** | 5～10 题，答案折叠在 `<details>` 里。**题目是验收工具，不是练习册** |

## 这套笔记的几条原则

1. **不逐字复制任何教程的正文。** 知识点、章节结构、语言事实不受版权保护，可以照着结构讲；
   但正文和代码示例都是自己写的。这个选择的理由是**可维护**——抄来的文本你改不动、也学不会。
2. **每个代码块都实际运行过**，贴的是真实输出。故意展示报错的示例贴的是**真实 traceback**。
3. **没实测的话必须标出来。** 各章章末的「诚实标注」表就是干这个的。
4. **完整性可验证，不靠口头保证。** 覆盖表 + 章末对账表 + 三源交叉核对，三样凑起来才敢说"全"。
5. **标准库只做索引级完整**（全列出 + 一句话 + 链接），不展开教程。
   **生态与进阶明确不展开**——假装覆盖了比承认没覆盖更害人。

## 关于"完整"的三层定义

| 层 | 内容 | 能做到吗 |
|---|---|---|
| **核心语法** | 语言本身：类型、控制流、函数、类、异常、模块 | ✅ 做到 100% 逐条展开 |

写明"不做什么"和写明"做了什么"一样重要。见 [`00_知识点总览.md`](Python笔记本/00_知识点总览.md) 第四节。

## 环境说明

- 写作与验证环境：**Windows 11 + CPython 3.13.15**（系统安装）
- 本仓库的 `.venv` 是 **3.14.7**（由 `uv` 管理），与系统解释器不同版本——
  文中凡涉及版本差异的地方都标了是哪一个
- 有两条 Windows 特有的坑在这套笔记里被反复提到，因为它们真的会咬人：
  - **`open()` 不写 `encoding` 时用的是 `cp936`，不是 UTF-8**（见 `01` 第 6 节）
  - **`multiprocessing` 用的是 `spawn`，所以必须写 `if __name__ == "__main__"`**（见 `12` 第 2 节）
