## 0. 这份文件是什么，怎么用

**它是一张地图，不是一片土地。**

用它的方式是三步：

> **想做什么 → 查哪一行 → 点链接**

1. 你脑子里有个需求（"我想把两个文件夹同步一下"），但不知道 Python 里归谁管。
2. 在下面的分组表里扫一眼"一句话"，找到负责这事的模块（`shutil`）。
3. 表里告诉你**本仓库哪个正文文件真的讲了它**；讲了就去读正文，没讲就点最后的官方链接。

### 「索引级完整」是什么意思

`00_知识点总览.md` 第二节把"完整"分成三层。标准库这一层能做到的是：

| 做到 | 没做到 |
|---|---|
| 覆盖表第 11 层点名的**每一个**模块都在表里，一个不漏 | 不保证每个模块的每个函数都讲到 |
| 每个模块有一句**能和别的模块区分开**的说明 | 不展开教程 |
| 每个模块有一个官方链接 | 不保证你以后能连上（见下） |

**这份文件不干什么：** 不教用法，不给示例代码，不解释函数签名。用法在正文各章（01～12）。
这里唯一的承诺是"**不漏**"——你缺什么，一眼看得出来。

### 关于官方链接，一句实话

`_写作规范.md` 第 2 条记录的实测结论是：`docs.python.org` 在用户网络环境下**直连不通**
（只有 runoob.com 正常）。所以：

- 链接照常给，因为它是**永久定位符**，而且换了网络环境就能用；
- **别把链接当成本章的内容**——正文各章已经把常用部分用中文讲清了，真要查官方文档时再点。

> **一处诚实的例外**：写这份文件时我为了核对链接是否真实存在，用工具抓了
> `smtplib.html` 和 `contextlib.html` 两个页面，**都返回 HTTP 200**。
> 也就是说"直连不通"这个结论**至少对当前这个环境不成立**。
> 我没有逐个验证全部 52 条链接，所以：链接格式以官方模块名为准（这部分我逐条核过拼写），
> 但"能不能打开"请以你自己当时的网络为准。**规范里那句话我不改，但它和我这次的观测有出入，两边都摆在这里。**

| 说法 | 含义 |
|---|---|
| **正文里没有** | 表里「本仓库展开在哪」是 `—`，这份笔记从头到尾不会讲它 |

## 12. 内置函数总表（覆盖表条目 10.7）

### 12.1 这张表是怎么来的（可复现）

**表不是凭记忆写的，是跑出来的。** 在本机 Python 3.13.15 上执行：

```powershell
python -c "import builtins; names=[n for n in dir(builtins) if not n.startswith('_')]; print(len(names)); print('\n'.join(sorted(names)))"
```

实测结果：

```
151
```

即 `dir(builtins)` 里**不以 `_` 开头的名字共 151 个**。按类型再拆一次：

| 类别 | 数量 | 说明 |
|---|---|---|
| 异常类（`BaseException` 的子类） | **71** | 见 12.5 |
| 其余名字 | **80** | 其中 5 个是不可调用的常量（见 12.6），75 个可调用（见 12.2、12.3） |
| 合计 | **151** | 71 + 80 = 151 ✅ |

外加 9 个以 `_` 开头的名字（`__import__`、`__debug__` 等，见 12.7），
`dir(builtins)` 全部条目共 160 个。

> 口径说明：所谓"内置函数"在 Python 里其实混了**三种东西**——
> 真函数（`len`、`print`）、类型（`int`、`list`、`slice`）、异常类（`ValueError`）。
> 官方叫 "Built-in Functions" 的表也把它们混在一起，但本文档按"能不能拿来当异常 `except`"分开列，
> 因为这是初学者最容易搞混的地方：`except int:` 能写但毫无意义。

### 12.4 完整性怎么自查（可复现）

这一段的话不是"我检查过了"，而是**你自己能再跑一遍**。
把本文档 12.2 的六组名单和实测的 `dir(builtins)` 求差集，差集为空才算没漏：

```powershell
python -c "
import builtins
names={n for n in dir(builtins) if not n.startswith('_')}
exc={n for n in names if isinstance(getattr(builtins,n),type) and issubclass(getattr(builtins,n),BaseException)}
rest=names-exc
const={n for n in rest if not callable(getattr(builtins,n))}
call=rest-const
mine=set('''bool int float complex str bytes bytearray memoryview list tuple dict set frozenset range slice type object property classmethod staticmethod super ord chr abs divmod pow round sum min max bin oct hex hash len iter next enumerate zip map filter reversed sorted all any aiter anext print input open format repr compile eval exec isinstance issubclass callable hasattr getattr setattr delattr dir vars globals locals id ascii breakpoint help exit quit copyright credits license'''.split())
print('实测可调用:', len(call), ' 本文档收录:', len(mine))
print('漏掉的:', sorted(call-mine))
print('多写的:', sorted(mine-call))
"
```

本文件定稿时跑出的真实结果是：

```
实测可调用: 75  本文档收录: 75
漏掉的: []
多写的: []
```

**这条命令就是 12.2 的验收标准。** 以后如果换了 Python 版本、`builtins` 里多了新名字，
只要"漏掉的"不是空的，就说明这张表该更新了。

### 12.7 下划线开头与解释器注入的名字（9 个）

它们也在 `dir(builtins)` 里，但**日常代码基本不该直接用**。

| 名字 | 一句话 |
|---|---|
| `__name__` | 当前模块名；`if __name__ == "__main__"` 靠它判断是不是被当脚本跑 |

### 12.8 一处已知的口径分歧

`dir(builtins)` 的 151 个名字**不等于**官方文档 "Built-in Functions" 页面的条目数：

- 官方那个页面**不列** 71 个异常类（异常在单独的 Built-in Exceptions 页）；
- 官方页面**列了** `__import__` 这类本文档归到 12.7 的名字；
- `copyright` / `credits` / `license` / `help` / `exit` / `quit` 来自 `site` 模块，
  官方把它们放在内置函数页里，但它们**严格说不是 `builtins` 原生的**。

所以"内置函数到底多少个"取决于你按哪个口径数。
本文档的口径写在 12.1，**以实测的 `dir(builtins)` 为准**，因为它可复现。

## 14. 本章自测

<details><summary>答案</summary>

**1.** `00_知识点总览.md` 第 11 层一共点名了多少个模块（不含 `pip`）？
—— 51 个标准库模块，加 `pip` 共 52 项

**2.** `pip` 是标准库吗？怎么用一条命令判断一个模块是不是标准库？
—— 不是。看文件位置：标准库在 `sys.prefix\Lib\` 下（如 `Lib\venv\`），
第三方包在 `Lib\site-packages\` 下（如 `Lib\site-packages\pip\`）。

**3.** 我拿到了一个别人发来的 `.pkl` 文件，用 `pickle.load` 打开安全吗？
—— 不安全。反序列化过程可能执行任意代码。只是传数据应该用 `json`。

**4.** 想在多核上把 CPU 密集的计算跑快，选 `threading` 还是 `multiprocessing`？为什么？
—— `multiprocessing`。`threading` 受 GIL 限制，同一时刻只有一个线程执行字节码，
适合等 I/O，不适合烧 CPU。

**5.** `NotImplemented` 和 `NotImplementedError` 是一回事吗？
—— 不是。前者是常量，特殊方法用它表示"我不处理这个比较"；
后者是异常类，抽象方法用它表示"子类必须实现"。

**6.** `IOError` 和 `OSError` 现在是什么关系？
—— 同一个东西，`IOError` 是 `OSError` 的历史别名（本机实测 `IOError is OSError` 为 `True`）。

**7.** 为什么 `quit()` 在脚本里不推荐用？
—— 它由 `site` 模块注入，`python -S` 启动时不存在；脚本里应该用 `sys.exit()`。

**8.** `dir(builtins)` 里不以 `_` 开头的名字有多少个？其中异常类有多少个？
—— 151 个；其中 71 个是异常类，80 个是其他名字。

**9.** 为什么本文档把异常类和函数分开列，而官方"Built-in Functions"页面混在一起？
—— 因为混在一起时最容易犯 `except int:` 这类错。分开列能一眼看出
"这个名字是拿来处理错误的，不是拿来调用的"。

**10.** 一个模块在本文档表里的「本仓库展开在哪」写着 `—`，说明什么？
—— 说明这份笔记的正文（01～12）**没有**展开它，只在这里给了一句话和链接。
这是诚实划界，不是漏写。

</details>
