## 1. 先纠正一条环境结论（重要）

`_写作规范.md` 和本目录其他文件里写着「`docs.python.org` 当前网络连不通」。
**这个结论不准确，现在有反证：**

| 取文档的方式 | 实测结果 |
|---|---|
| PowerShell `Invoke-WebRequest` | ❌ `The SSL connection could not be established` |
| `curl` | ❌ HTTP `000`（连不上） |
| DNS 解析 | ✅ 正常（`docs.python.org` 解析到 `2a04:4e42:600::223` 等） |
| **AI 工具的 `web_fetch`** | ✅ **HTTP 200，正文完整取回** |

**正确的说法是**：

> 这台机器上**命令行工具（curl / PowerShell）拿不到 docs.python.org，但 AI 的抓取工具能拿到**。
> 所以「官方文档取不到」只对"你自己敲 curl"成立，对"让 AI 去取"不成立。

### 这直接影响两件事

1. **`99_标准库索引.md` 里那句话要按这个口径读**——它把两边都摆出来了，那是诚实但不够准确。
   现在这条已经被查清：**链接是可用的，只是不能用 curl 取。**
2. **「内容来源」这件事的选项变了。** 之前 `00_知识点总览.md` 第七节给的方案 A′ 是
   「用 CC / PSF 许可的中文材料逐字转」。现在有了更好的对象：
   **官方文档本身就是 PSF 许可**（页脚原文：*This page is licensed under the Python Software Foundation License Version 2. Examples ... additionally licensed under the Zero Clause BSD License*，
   即 PSF-2.0 + 示例部分 0BSD）。
   → 也就是说「用官方文档当来源」在许可上比用 runoob 更干净：**PSF 许可允许商用、允许修改、允许闭源分发**，
   只要求保留版权声明与许可文本（0BSD 连这个都不要求）。

   ⚠️ 但**这不改变 `_写作规范.md` 第 1 条的"不逐字复制"要求**。原因不是许可，而是**用户的目标**：
   用户要的是"维护成我自己的版本"，逐字粘贴的文本他改不动、也学不会。
   所以：**事实和结构可以照着官方文档核，正文仍然自己写。**

| P0-5 | **下划线数字分隔符与数字字面量** | Reference §2.6 | `02_基础语法.md` | `1_000_000` / `0x_FF` 这类写法官方单列一节。 | ✅ 已补（第 3.5 节） |

**P0-5 已实测补充（本机 3.13.15 逐个跑过）**，`02_基础语法.md` 已据此写入：

```
1_000_000        -> 1000000                合法
0x_FF            -> 255                    合法（下划线紧跟进制前缀之后也允许）
0b_1010_1010     -> 170                    合法
0o_777           -> 511                    合法
10_000.000_1     -> 10000.0001             合法（小数点两侧都可以）
1_0j             -> 10j                    合法（复数也可以）

1__0             -> SyntaxError: invalid decimal literal   （不能连续两个下划线）
1_               -> SyntaxError: invalid decimal literal   （不能以它结尾）
```

两个容易讲错的点：**`0x_FF` 是合法的**（不是只有"数字后面"才能跟下划线）；
**非法写法的错误消息是 `invalid decimal literal`，不是笼统的 `invalid syntax`**。
