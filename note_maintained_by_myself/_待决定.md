# 待你决定的事

> 这份文件放**需要用户本人决定**的事（我不替他决定）。
> 每条都写清：现状、选项、代价。做完一条就划掉。

---

## 1. 要不要 push 到 GitHub

- **现状**：本地已提交若干 commit（一章一个），**没有 push**。交接文件明确要求"提交和推送前先跟用户确认"。
- **选项**：
  - A. 现在 push（`git push origin main`，SSH 可用，每次往返约 3.5 秒）
  - B. 先本地看一遍再 push
- **代价**：无（纯本地/远端同步）

---

## 2. 要不要把全仓库统一成 LF 换行

- **现状（实测）**：仓库 60 个已跟踪文件里，**59 个的 blob 里存的就是 CRLF**。
  全局 `core.autocrlf = true` 并没有纠正这些历史提交。
- **已做的处理**：只在 `note_maintained_by_myself/` 放了 `.gitattributes`（`* text=auto eol=lf`），
  **实测确认不影响仓库其他文件**。
- **选项**：
  - A. **维持现状**（只锁新笔记目录）——零风险
  - B. 把规则提到仓库根目录，然后 `git add --renormalize .`
    —— 会**一次性重写仓库里 59 个文本文件**，是一个很大的 commit（diff 上看几乎每个文件都被改）
- **代价**：B 的好处是彻底解决"文本文件换行不一致"；
  代价是那次 commit 的 diff 会淹没真实改动，且如果别的机器/工具依赖当前换行，可能出意外。
- **建议**：除非确实被换行坑到，否则先 A。

---

## 3. `git.worktrees/` 里 57 个 CRLF 文件要不要清理

- **现状**：`git.worktrees/` 是被 `.gitignore` 忽略的本地嵌套 worktree，
  里面 57 个文件全是 CRLF-only。它们**不入库**，但占空间、也在换行扫描里刷屏。
- **选项**：A. 不理会（反正不入库）／B. 删掉这个目录
- **代价**：B 会丢掉那份 worktree 里的本地历史与未提交内容——**删之前必须确认里面没有你想要的东西**。

---

## 4. `_HANDOFF.md` 要不要入库

- **现状**：它是给下一个维护者（AI 或你）看的交接文件，含环境事实、踩坑记录、验收方法。
  目前**未提交**（整个目录都还没提交过）。
- **选项**：
  - A. 一起提交（推荐）——下次换会话或换人接手时省很多时间
  - B. 不提交，只留在本地
- **代价**：A 会让仓库里多一份"元文档"；内容里有本机路径，介意的话选 B。

## 6. 一份 200 行的"补漏清单"要不要加

三源核对时发现，若按"必须补"的严格标准，`del` / `pass` / `type` 语句这类条目落在
`04`～`11` 的若干章里。**要么现在补，要么在覆盖表里把它们的状态从 ☑ 改回 ◐**，
不要让"全绿"掩盖"有几条其实没写"。

- **选项**：A. 现在补（推荐，趁写作者还有上下文）／B. 改状态为 ◐ 并写清缺什么
- **代价**：A 需要一轮返工；B 会让覆盖表看起来不那么"完成"，但**是诚实的**。
